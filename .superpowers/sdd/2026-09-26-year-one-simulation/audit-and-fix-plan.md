## 一、逐条核实

### 1. tick 600 ≠ 一年 —— **成立**（最严重）

- **代码证据**：`TimeAdvance` 类注原文"**一次 N 天、内部逐日**"，`advance(from, from+N)` ⇒ tick 增量 == 天数。
  `SimosTimestamp.tick` 是第一序（"tick 是第一序，calendarLabel 仅作展示"）。
- **算术**：`cycleDays = 120` ⇒ 一年 = 365 天 = **tick 365**；tick 600 = **600 天 ≈ 1.64 年**。
- **我错在哪**：报表 §〇 口径段**自己写了**"一年 = 3 个周期 + 5 天"，正文却把 tick 600 标成"一年后"——
  自相矛盾。根因是我把"取整周期读数需要关账日"与"一年"混为一谈（关账日是 120/240/360/480/600，**365 不是关账日**）。
- **正确读法**：tick 360（3 个完整周期）作年度近似，或 tick 365 报存量 + 明确"5 日 partial period"。

### 2. per-capita 单位错 1000 倍 —— **成立**

- **代码证据**：`FlowRow` 的 `@param unmetNeed` 原文："本期未满足的需求（逐商品：需求 − 实得 的逐日累加，**毫单位**）"。
- 最惨格 `(-39,-71)`：缺口 2,264,068,233 毫 ÷ 215,780 人 = **10,492 毫/人 = 10.49 粮/人**（我写成"10,492 粮"）。
- 最富格：391,537,000 毫 ÷ 4,561 人 = 85,845 毫/人 = **85.8 粮/人**（我写成"85,845 粮"）。
- **连带作废**：§4.4"231 格 >100 粮/人"实为 **>100 毫/人 = 0.1 粮/人**（门槛是 10 粮 = 10,000 毫）
  ⇒ **"双峰分布"结论不成立，必须重算**。重算见 §三.C。

### 3. MORTALITY 文案与表格矛盾 —— **成立**

表格逐周期是 `667 / 799 / 799 / 799 / 799`，正文写"五个周期**一次没掉过**"。
"死亡稳定在 62.6 万/周期"也过头：实际 `25.5万 / 50.4万 / 58.7万 / 62.63万 / 62.66万`，
只能说**第 4–5 周期趋于 62.6 万平台**。

### 4. §六 城市人/布归属串行 —— **成立**

- craft 行人口 **897,944**（≈89.8 万），我写"26 万"——数字无来源。
- craft 行布只有 **97,159 毫**；**99.8% 的布（62,136,531 毫）在 `weave` 行**。
- 且 `weave` 行人口**恒为 0**（织布劳动来自农业行的配额）⇒ 按我自己的"城市 = craft"口径，
  **城市人不能被称作那 6200 万布的生产者**。整句作废。

### 5. 死亡率口径 —— **成立**

我用的是 `本周期死亡 ÷ 期末人口`。改用期初人口（第 5 周期）：
农村 `511,451 / 8,930,555 = 5.73%`、城市 `115,115 / 1,011,382 = 11.38%` ⇒ **倍数 1.99**（我写 2.11）。
至少必须把列名改成"死亡数/期末人口"。

### 6. "产品没有通道" —— **部分成立，且实际情况比审查说的更强**

- 审查说得对：存在"同格借粮制度"，所以"完全没有通道"对**粮**不准确。
- ★ **但探针数据显示**：`EconomySettlement` 的注释原文"**布不参与同格借粮：借贷制度在本仓只对粮有规则**"
  ⇒ **对布而言"没有任何非债务通道"是准确的**。而正是布把农村压垮了（§二.B）。
- **正确表述**：粮有借贷通道但不足；**布连借贷都没有**（生产行与消费行之间零通道）。

### 7. "调参修不好" —— **成立**

我没做任何参数扰动，应改为："当前证据指向**结构性分配缺口**，而非单纯总产能不足；
即使调参能缓解数字，也不修复该结构缺陷。"

### 8. CrisisMonitor 相位敏感 —— **成立，根因已定位**

`CrisisMonitor.lightsAt()`：

```java
grainNeed  += EconomyVocabulary.cumulativeRationMilli(row.population(), cycleDays);  // 分母：整周期 120 天
grainUnmet += flow.unmetNeed().getOrDefault(commodityGrain(), 0L);                  // 分子：本周期累计（可能只有几天）
long grainSatisfaction = satisfaction(grainNeed, grainUnmet);
```

**分子与分母的时间基准不同**：周期第 5 天时，分子只累计 5 天、分母却是 120 天的需求 ⇒ **满足率系统性虚高** ⇒ 红灯不亮。
`EconomyVocabulary.cumulativeRationMilli` 的注释本就写明它是"**天的函数**（不是'周期内第几天'的函数）：调用方传**绝对天数/绝对日号**"
—— 调用方传了 `cycleDays` 这个常量，正是误用。

★ 这不是"读数陷阱"，是**相位敏感性 bug**：同一场持续灾难，周期刚切换后监控器会宣布"没有危机"。
GUI / MCP / 决策人 Agent 读到的都是这个。（我的报表把它写成"读数陷阱"并规定"只在关账日读"，是**绕开 bug**。）

### 9. "压力从未回落" —— **成立（论证方式），但探针在方向上支持它**

原文指标是逐格 `max` 的全局最大值。**探针批次级数据**（tick 600，10,881 个批次）：

| 居所 | 性别 | 年龄档 | 压力 min | P25 | 中位 | max |
|---|---|---|---|---|---|---|
| rural | FEMALE | 0-14 | 0 | 0 | 0 | **0** |
| rural | FEMALE | 15-59 | **1,233** | 1,320 | **1,345** | 2,162 |
| urban | FEMALE | 15-59 | **0** | 275 | 1,799 | 5,441 |

⇒ **农村 15-59 批次无一低于 1,233**（分布极窄），**"农村压力从未回落"成立**；
但城市分布极宽（0~5,441）⇒ 原文的"全局单调上升"表述确实不成立。**结论要按居所分开写。**

### 10. 中位亩/人未加权 —— **成立**

`meansOfProduction.LAND` 合计 **2,286,386 亩** ÷ 9,317,048 人 = **0.2454 亩/人** > 门槛 0.1755
⇒ "总量地够"**结论不变**，但论证必须换成总量口径（或"低于门槛的格承载了多少人口"）。

### 11. 年龄档变化 ✗ 死亡归因 —— **成立**

批次级字段只有 `{id, residence, sex, count, ageAtAnchorDays, anchorTick, physiologicalStress}` ——
**没有 deaths**；死亡只落在行级 `FlowRow.deaths`（不分年龄）。
⇒ **现有读口读不出 age-specific deaths**，"死的主要是 15–59 与 60+"无法用现有事实支持。

### 12. "R4 机制全部按设计工作" —— **成立（过强），且已有反例**

只验证了"字段有变化"+"两条守恒式"。探针发现两个反例（§二）：
压力更新漏掉整类批次；布满足率恒 0 使生育抑制机制**只对创世那一代人**生效。

## 二、★ 核实中**新发现**的两个缺陷（审查未提）

### A. 真 bug：压力更新漏掉"没有劳动配额"的批次

**位置**：`simos-app/.../time/PopulationEconomyTimeParticipant.java:186-189`

```java
List<IndustryId> targets = industriesOf.getOrDefault(group.id(), List.of());
if (targets.isEmpty()) {
    continue;            // ← 压力永不更新（恒 0）
}
```

`industriesOf` **只从 `economy.allocations()` 来**。而两类批次**从未有过配额**：

1. **0-14 档的创世批次**（劳动系数 0 ⇒ `EconomySeeder` 不发配额）
2. ★★ **全部新生儿批次** —— `PopulationLots.born(...)` 在创世之后产生，**永不在 allocations 里**

**证据**（探针 tick 600，10,881 个批次）：

```
rural FEMALE 0-14     799 批次  压力 min/中位/max = 0 / 0 / 0
rural FEMALE FEMALE  1600 批次  压力 min/中位/max = 0 / 0 / 0   ← 新生儿
rural FEMALE MALE    1603 批次  压力 min/中位/max = 0 / 0 / 0   ← 新生儿
urban 全部新生儿      1858 批次  压力 min/中位/max = 0 / 0 / 0
```

**无一例外**。对比同格有配额的批次：`rural:-56_-65:FEMALE:1` = **1326**、其新生儿 `...:FEMALE:b1` = **0**。

**后果**：
1. **儿童在饥荒中不死**：`mortalityPerMille` 的压力超额项对 0-14 档恒为 0，只剩基础死亡率 2‰/月
   ⇒ 与"儿童最脆弱"的常识相反，且与 R4 想表达的"社会再生产危机"矛盾。
2. ★★ **饥荒的生育抑制只对创世那一代生效**：新生儿批次 15 年后进入育龄，**仍无配额 ⇒ 压力仍恒 0 ⇒ 永远能生**。
   ⇒ 长期（>15 年）的人口动态会由"不受饥荒影响的一代"主导，**R4 的核心机制随时间自我失效**。
   600 天的窗口还没到 15 年，所以这个后果**当前数据里看不到**（探针里最早的新生儿才 1.6 岁）。

★ 这与 `applyPopulationChange` 里**已经存在**的兜底（"没有配额的批次 ⇒ 摊到它**住的那一格**的产业行"，`EconomySettlement.java:542-548`）
是同一个问题、同一个解法 —— `applyDailyStress` 漏了那个兜底。

### B. 设计缺口（后果首次量化）：布没有跨行通道 ⇒ **农村全境绝育**

**实测**（探针 tick 600）：

| 产业 | 人口 | 粮满足率 | **布满足率** | 粮库存 | 布库存 |
|---|---|---|---|---|---|
| `farm` | 8,419,104 | **99%** | **0%** | 289.3B 毫 | **0** |
| `weave` | 0 | — | — | 0 | **62.1B 毫** |
| `craft` | 897,944 | 38% | 88% | 0 | 97M 毫 |

**机制**：`PopulationDynamics.stressAfter` 的消退项是 `6 × min(粮满足率, 布满足率) ÷ 1000`。
农村布满足率 = 0 ⇒ **消退恒为 0** ⇒ 压力**只增不减**。

**后果**（这是"人口 −21%"的真主因，**不是缺粮**）：

- 农村育龄女性压力 = **1,233 ~ 2,162**（全部 > 500）⇒ `suppression = 1000 − 压力×2 = 0` ⇒ **全国农村 100% 绝育**
  （实测：rural `0/799` 能生育，urban `58/201` 能生育 —— 出生全落 craft 行，正是这个原因）
- 压力 1,345 ⇒ 超额死亡率 `(1345−300)×20‰ = 20.9‰/月` ⇒ **15-59 档年化死亡率 ≈ 26%**
- 而农村**粮**满足率是 99% —— **他们几乎不缺粮，是被"缺布"压垮的**

**定性**：这不是实现错误，是 **R3/R4 的分配留白**（布的分配原属 V8/市场）。但它**主导了人口动态**，
后果远超"留白"二字，因此必须显式裁定。

## 三、修复方案

### A. 代码修复（建议立即做）

#### A1. 压力更新补兜底（BUG-A）

- **位置**：`PopulationEconomyTimeParticipant.applyDailyStress`
- **改法**：`targets.isEmpty()` 时**不再 `continue`**，改为回落到"该批次**居住格**的产业行"
  —— 与 `EconomySettlement.applyPopulationChange` 的既有兜底**同一口径**（那里写的是 `industriesAt(base, change.at())`）。
  建议把这段兜底抽成**一个共用方法**，两处调用（否则下次还会漂）。
- **判据**：新生儿批次与 0-14 档批次在有缺口的格上**压力必须 > 0**；同格内无配额批次与有配额批次的压力**同量级**。
- **变异自证**：把兜底改回 `continue` ⇒ 断言当场红。
- **风险**：会让儿童与新生儿也开始累积压力 ⇒ **短期内死亡率上升、生育进一步下降**（这是"更真实"的方向，但要告知用户）。

#### A2. CrisisMonitor 分子分母同基准（BUG-C）

- **位置**：`CrisisMonitor.lightsAt`
- **改法**（二选一，推荐 ①）：
  1. **同基准化**：分母改用 `cumulativeRationMilli(pop, elapsedDays)`，其中 `elapsedDays` = 本周期已过天数
     （`progressDays`；周期第 0 天按 1 天算，避免除零）。分子不变 ⇒ 任何一天读都自洽。
  2. **改用上一完整周期**：需要把关账时的 flow 归档（rollup），改动更大。
- **同时**：在红灯的 `evidence` 里显式给出 `elapsedDays` 与 `cycleDays`，让读的人知道这是"部分周期的读数"。
- **判据（必须覆盖相位）**：同一场持续缺粮，在**周期第 1 天、第 60 天、第 119 天**读，红灯**类别必须一致**（现在第 1 天读不到）。
- **变异自证**：把分母改回 `cycleDays` ⇒ 相位用例红。

### B. 建模裁定（需要你定，不建议我自行改）

#### B1. 布的分配通道（BUG-B）

三选一：

| 方案 | 内容 | 代价 |
|---|---|---|
| **① 对称最小** | 给布一条**对称于粮的"同格借布"**（或让 T0 取材通道对消费品开放） | 小；但会引入"布债"，需定口径 |
| **② 归属前移** | `weave` 行的产出**直接记到同格消费者的行**（不经生产行囤积） | 中；改变守恒式的读法，影响既有断言 |
| **③ 维持留白** | 明确"布的分配属 V8"，**但把后果写进 spec**：在 V8 落地前，人口动态由缺布主导 | 零；但模拟结果不可用于人口结论 |

A1 修完，儿童与新生儿也开始累积压力 ⇒ 死亡上升。这**不是回归**，是修正了一个让儿童"免疫饥荒"的漏洞。

**迁进 V7 参数目录**，让"调参"成为 GM 的显式动作而不是改常量 —— 但这是另一个议题。

## 三、★★★ 三个问题的正面回答

### 3.1 农村布满足率变了吗？—— **变了，而且是整场改造里最大的一处**

| 量（农村 = `farm` 行） | 第一次 | 本次 |
|---|---|---|
| 布满足率 | **0.00%**（`consumed_cloth = 0`；report-v3 §一 的原话「农村 `farm` 行**布满足率 = 0%**（布堆在 `weave` 行、无任何非债务通道）」） | **96.45%**（t600；t240 起一路 96.5% 上下） |
| 缺布(匹/周期) | 3,451,958 → 3,349,910 → 3,201,116 → 3,040,108 → **2,873,101** | 3,450,448 → **115,375** → 115,585 → 117,548 → **119,510**（**−96%**） |
| farm 行布库存(匹) | **0 / 0 / 0 / 0 / 0**（五个关账日**逐值 0**） | 8,926,091 → 14,423,781 → 19,900,961 → 25,332,143 → **30,735,271** |
| 布**荒**红灯格数 | 799 / 795 / 796 / 796 / 796 | 799 → **0 → 0 → 0** → 3 |
| 全国布满足率 | 10.2% → 18.5% | 0.0% → 88.4% |
| 出生（全国/周期） | 83,427 → 80 → 211 → 879 → **1,677** | 83,427 → 35,690 → 195,134 → 211,405 → **210,360** |

★ **机制上说得通**（T4/T5/T6/T6b 的落点）：产出自本阶段起不再写进阶层行，而是按 `relation` 结算 ——
家庭纺织（`household`）的 700‰ **实物分成给劳动者**（裁定 E2），受方行由**劳动批次**定池（E24）⇒ 布落到
**真正织布的人**住的 `farm@hex|<阶层>` 行，而 `weave@hex|*` 四行（人口恒 0）**逐行 0**（I4.3）。
第一次模拟时布**99.8% 堆在 `weave` 行**（人口 0），农村一行也拿不到 —— 那一版**没有**这条通道。

★ **残余的 3.55% 缺口是"分配口径"、不是"没通道"**（逐格实测）：farm 组的缺布
**均匀分布在 799 格上**（最大 327 匹/格，均值 ≈150 匹/格），**全部来自 `landlord` 那一行** ——
布的分配是 `OUTPUT_SHARE × LABOR_AMOUNT`（按**劳动量**），而地主的劳动投入率只有 **100‰** ⇒
它的布入账 68,604 毫/格，而它按人口的周期需求是 397,800 毫/格（`consumed + unmet = 395,670 ≈ 需求`）
⇒ **劳动权重低的阶层在"按劳动分"的规则下天然吃不饱**；`middle/poor` 两行的 `unmet` 逐值 0（布反而在积压）。
—— 这是**规则/参数**的事（要不要给非劳动者一条按人口的口子），本任务**未改**。

### 3.2 人口掉了多少？—— **−5.9%（第一次是 −21.2%）**

| | 创世 | t600 | 变化 |
|---|---|---|---|
| 第一次 | 11,830,000 | 9,317,048 | **−21.2%**（−2,512,952） |
| 本次 | 11,830,000 | 11,136,611 | **−5.9%**（−693,389） |

★ **不是"少死了几个人"，是曲线的形状变了**：第一次的死亡**逐周期单调走高**（255,065 → 504,106 → 587,213 →
626,276 → 626,566，五个周期死了 2,599,226 人），出生被压到 **80 / 211 / 879 / 1,677**（近乎绝育）；
本次死亡在**第 2 周期见顶后回落**（317,033 → 339,173 → 249,768 → 263,929 → **259,502**），
出生从第 3 周期起稳在 **19~21 万/周期**（后三个周期 195,134 / 211,405 / 210,360，而第一次同期是 **211 / 879 / 1,677**）。
★ 人口账自身对得上（同一条式子，两轮都逐值成立）：`Σ死亡 − Σ出生 = 人口净减`（本次 1,429,405 − 736,016 = 693,389 ✓；第一次 2,599,226 − 86,274 = 2,512,952 ✓）。
★ **第一周期本次反而更差**（死亡 317,033 vs 255,065、出生 83,427 相同）：这正是 T6b 记下的那条信号（裁定 E26）——
E24 之后**城市行不再分到农村那一份**产出，而本阶段**没有城乡交换通道** ⇒ 第 1 周期城市多死 5,549 人
（28,936 vs 23,387）。**它没有消失，只是被后面四个周期的农村复苏盖住了**（见 3.3）。
★ 代价（如实记）：粮缺口总量**更大**（t600：9,561,177 vs 6,787,909），因为人口多留下了 182 万人吃饭；
债务本金 **106,182,340 vs 17,548,062（6.05 倍）**、红灯 DEBT **614 格 vs 23 格**。⇒ **"人不死了"目前是靠借粮撑着的。**

   （第一次是反过来的：`weave` 行持 62,136,531 匹 = 99.8%，`farm` 行 0 匹。）
2. **粮**：`farm` 行持仓 **174,862,444 粮**；`craft` 行 **0 粮**且缺口 4,483,672 粮/周期。
3. **同格、不同产业行 —— 中间没有任何一条转移通道**（V8「统一转移」尚未做，本阶段也没有城乡交换）。
   ⇒ 城市那一池人**既不种地也不在农业的劳动批次里**（E24 之后农业的给养/地租**只发给农村批次**），
   它的粮只能靠**同格借粮（欠债）**：债务本金 **106,182,340 粮**、DEBT 红灯 **614 格**（第一次 17,548,062 / 23 格）。
4. **它还在恶化**：craft 的布满足率 96.23%（t240）→ 41.92%（t480）→ **0.00%**（t600）——
   因为作坊的布是它**自己**产出的 600‰ 实物工资（`handicraft`），而作坊第 2 周期起**停工**（铁只有创世那一份 ⇒
   规模那一路恒 0，`EconomyRealScaleClothTest` 已逐值钉住）⇒ 城市**同时**缺粮、缺布，且两条都只会更紧。

★ **一句话**：这次改造把"布卡在 `weave` 行（人口 0）"那条病灶**治好了**（农村布满足率 0% → 96.5%），
但**同一族的病搬到了城市行**：城市人均缺粮是农村的 10.8 倍、死亡率 14.05 倍、布满足率一路掉到 0，

`handicraft` 那 600‰ 实物工资与作坊的铁（无冶炼）是它的两个近邻参数。

## 四、★ 读数的边界（如实记）

1. **满足率的口径**：`Σconsumed ÷ (Σconsumed + ΣunmetNeed)`，取自**同一份** `/api/economy/hex` 载荷、
   **同一窗口**（本周期发生额、关账日读；新周期第一天归零）。★ 粮的 `consumed` 含**种子/损耗/转出**（行侧口径）
   ⇒ 粮满足率是**同口径可比指数**，不是"人吃到的比例"；布没有这些干扰项，是干净的。
   ★ 基线那一列由**同一份**脚本的产物（`v3curve_tick*.json`）算出，逐值同源；只有"农村布满足率 = 0%"那一格

## 全局约束（逐字摘自计划 §四 / 信条 §二·§六）

- **铁律 2（不可协商）**：所有修改最终表示为 `Command → ChangeSet → Revision`。**不存在绕过该路径的写入口。**
- **铁律 3**：所有领域模块只拥有自己的数据。MapSimos 永远不知道 SocialSimos / UnitSimos 存在。
- **铁律 4**：Core 只负责组合与调度，不重新实现领域逻辑。
- **模块边界由 `maven-enforcer-plugin` 的 `bannedDependencies` 在构建期强制**——
  越界 = 构建失败，不是 code review 的事。
- **前置即错**：缺前置条件 ⇒ **报错**，**绝不静默兜底**。
  第三级谱：① 抛 / ② 明确失败 / ③ 静默兜底——本轮要求全部落在 ① 或 ②，**禁止 ③**。
- **同源**：同一条 `AgentTool` 定义必须**同时**出现在 GM 面与 MCP 面上，**不得两处各写一份**。
- **注释与文档用中文**，与既有风格一致。
- **门禁**：`./mvnw clean verify`（Spotless + Checkstyle + SpotBugs + Surefire + 前端 `node --test`）。
- ★ **密钥纪律**：值绝不进日志/异常/事件/argv/env/stdio；读配置只打印路径 + 长度。
  **一个 key 都不许进代码**（只许 `config/llm-providers.json`）。

## 评审要求

**产出**：一份按「判据 × 实测」组织的评审结论，**每条结论必须带可核对的位置**（`文件:行`）。
**不要复述**报告里已有的结论——报告写过的，你的任务是**独立核**；核不过的才报出来。
**没能核实的，如实写成"未能核实"**，不要写成"通过"。

**重点核这几件事**（这几处是本分支最容易出错的地方）：

1. **同源是否真的同源**：工具名 / `commandType()` / catalog 三者是否由**同一个常量**派生，
   还是三处手抄一致。**手抄一致不是同源**——若有人加第 N+1 条工具只改了两处，判据能不能红？
2. **桶算术**：`EXTERNAL_WITH_GM` 是否**真的是** `addExternalWrites + addGmWrites` 的并集
   （而非"当前恰好相等"）。★ 注意**读工具是四个桶共享的前缀**——这个事实的连带后果是什么？
3. **前置即错（信条核心）**：窄写工具的**域校验**是**真拒绝**还是**装饰**？
   ★ 已知一条：`simos.command.submit`（通用写）**绕过工具层**直接进 Core ⇒
   工具层的前置检查**不是安全边界**。那么这些前置的**真实价值**是什么？报告是否诚实交代了这一点？
4. **测试的判别力**：新增测试里，哪些**真能杀变异体**、哪些是**恒真的装饰**？
   ★ 台账有前例：M3 的 m2「原样形态不是被杀」（58 条用例全部 error 在 `@BeforeEach`，
   红的不是判据本身），实现者**主动降级**该轮、另做 m2b 才取到真红。
   核查报告在这一点上是否**降级**而非**冒充**。
5. **有没有被"全绿"掩盖的静默失败**：本仓反复记账的一族是「**把没搜到伪装成不存在**」。
   检查新增测试里有没有**永远为真**的断言（例如扫到自己写的空目录、用循环包一条断言、
   `.hasSize()` 量的是自己刚构造的集合、扫隐藏目录时默认跳过）。

**不要报的**：上面「已知的有意边界」6 条；`.superpowers/**` 里证据留档的格式问题；
M4/M5 的未完成（M4 被用户裁定阻塞、M5 只评估，都是**在案**的状态）。

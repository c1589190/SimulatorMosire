## 二、三问的读数

### ① 人口：**在跌，但跌幅逐周期收窄；出生率在第三个周期回补**
- 人口 11,598,141 → 11,359,780 → 11,349,353（第一周期 −238,361，第二周期 −10,427）。
- 死亡率 27.18‰ → 25.79‰ → **19.01‰**（红灯格从 799 掉到 41）；出生率 7.19‰ → 4.81‰ → **18.09‰**。
- ⇒ 第一周期是**最紧**的那一段（播种期的粮全被当口粮吃掉的"青黄不接"），第二周期起靠"自产 + 借粮 + 市场"
  把缺口压下去（缺口·粮 72.5M → 12.7M → 11.3M，**降 84%**）。
- ★ **城镇人口在缓慢外流**（1,306,445 → 1,149,113，城镇占比 11.3% → 10.1%）——与 §三 的"作坊停工"同向：
  城镇那批人的行业收入断了，死亡与迁出压在他们头上。

### ② 粮食：**从"大面积缺口"走到"少数格仍有缺口"，库存反而越攒越多**
- 粮库存 148.7M → 176.9M → 204.9M（每周期 +约 28M）；粮缺口 72.5M → 11.3M。
- ⇒ 总量上是"够吃"的，缺口是**分布问题**（145 个格仍在 FOOD 红灯里）。
- ★ 这是本轮最重要的**未解决**问题：`§九.4` 那条"统计窗口"的读数口径之外，缺口集中在哪些格、
  为什么借粮与市场没能覆盖它们，本报表**没有回答**（要逐格对照 `unmet` 与 `debtN` 才能说）。

### ③ 债务：**规模在指数式累积，第三个周期开始变成危机主体**
- 债条数 1,012 → 3,652 → 6,437；本金 149,654 → 3,833,682 → 15,286,474（×102）；
  新借 4.47M → 13.2M → 24.0M；已还 4.33M → 9.58M → 12.9M；**应付息 2,934 → 75,169 → 299,733**。
- 红灯构成换了主角：第一周期全是 FOOD/CLOTH/MORTALITY（799 格），第三个周期 **DEBT 275 格**（FOOD 145 / MORTALITY 41）。
- ⇒ **"借粮当最后手段"这条机构在跑**（不然第一个周期就该饿死更多），但**利息开始滚起来**：
  第三个周期的应付息（299,733）已经接近当期的还本（12.9M）的 2.3%。**是否可持续，一年不够判断**——这正是本报表的边界。

## 三、★ 产业链：**作坊在第 2 个周期起全线停工（201/201 格）**

- 判据（读 `flow.income["cloth"]`，城市格 = 有 `craft@` 产业的格）：tick120 = **201/201 格在产**；
  tick240 = **0/201**；tick360 = **0/201**。
- 旁证：**工具库存逐周期一字未动**（126,822 → 126,822 → 126,822）—— 工具是作坊的第二种产品，
  它不产 ⇒ 这一栏就是死的（工具没有消耗方，见 H5 台账的"工具可再生"那条）。
- ⇒ 与 H6-lite 台账里记的病**逐字对上**（`progress.md` "H6-lite"节）：作坊按 relation 取的是**城镇家户账**上的纤维，
  那份是**创世一次性**的（= 它一个周期的用量），第 2 个周期起没有进项 ⇒ 规模 0。
- ★★ **H6-lite（同格中间品按需求比例配给）就是为这一条写的**，它的单元级判据在主 repo 里是绿的
  （`EconomyRealScaleClothTest#contestedFibreIsRationedByNeedSoTheWorkshopNeverStalls`：作坊布入账 115,963/周期），
  但**本报表量的是 H5 的线上世界 ⇒ 这一行仍然全 0**。**H6 的线上效果本轮没有测（用户裁定只跑一年，不再跑对照批）。**

## 四、本轮如实记的边界（没做 / 没验）

1. **H6 代码态的线上对照批**：没跑 ⇒ 上面 §三 那 0/201 是**改前**的读数，
   "H6 之后作坊是否真的一年都在产"**只有单元级证据，没有线上读数**。
2. **tick 480 / 600**：没跑（用户 2026-09-27 裁定：「我本来的计划就是只跑一年……直接写报表」）。
   ⇒ 债务可持续性、第二个年头的青黄不接**都没有读数**。
3. **逐格归因**：缺口 145 格 / 债务 275 格**为什么**是这些格，本报表没做（要逐格对照 `unmet`、`debtN`、
   产业规模与 `market` 状态）。
4. **两个已知读数缺口**（`goal-close-mutations.md`）：`ΣProductionInputs` 端到端没有判别力；
   `HouseholdActors` 的**磁盘往返**没有专门用例。
5. **性能**：本批逐 120 天的推进耗时 **2:33 → 4:41 → 7:14**（同批日志实测），
   世界状态同期在涨（债条数 ×6.4、库存 +42%、家户行恒 6,392）⇒ 一年要 ~15 分钟，
   600 天要 ~1 小时以上且越来越慢。**这是一条待优化的性能账**（天内串行 + 逐日遍历 6,392 行；
   可并行的是**格间**），不是本轮的范围。

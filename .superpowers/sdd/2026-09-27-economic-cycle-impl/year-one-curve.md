## 二、三问的读数

### ① 人口：**在跌，但跌幅逐周期收窄；出生率在第三个周期回补**
- 人口 11,598,141 → 11,359,780 → 11,349,353（第一周期 −238,361，第二周期 −10,427）。
- 死亡率 27.18‰ → 25.79‰ → **19.01‰**（红灯格从 799 掉到 41）；出生率 7.19‰ → 4.81‰ → **18.09‰**。
- ⇒ 第一周期是**最紧**的那一段（播种期的粮全被当口粮吃掉的"青黄不接"），第二周期起靠"自产 + 借粮 + 市场"
  把缺口压下去（缺口·粮 72.5M → 12.7M → 11.3M，**降 84%**）。
- ★ **城镇人口在缓慢外流**（1,306,445 → 1,149,113，城镇占比 11.3% → 10.1%）——与 §三 的"作坊停工"同向：
  城镇那批人的行业收入断了，死亡与迁出压在他们头上。

### ② 粮食：**从"大面积缺口"走到"少数格仍有缺口"，库存反而越攒越多**
- 粮库存 148.7M → 176.9M → 204.9M（每周期 +约 28M）；粮缺口 72.5M → 11.3M。
- ⇒ 总量上是"够吃"的，缺口是**分布问题**（145 个格仍在 FOOD 红灯里）。
- ★ 这是本轮最重要的**未解决**问题：`§九.4` 那条"统计窗口"的读数口径之外，缺口集中在哪些格、
  为什么借粮与市场没能覆盖它们，本报表**没有回答**（要逐格对照 `unmet` 与 `debtN` 才能说）。

### ③ 债务：**规模在指数式累积，第三个周期开始变成危机主体**
- 债条数 1,012 → 3,652 → 6,437；本金 149,654 → 3,833,682 → 15,286,474（×102）；
  新借 4.47M → 13.2M → 24.0M；已还 4.33M → 9.58M → 12.9M；**应付息 2,934 → 75,169 → 299,733**。
- 红灯构成换了主角：第一周期全是 FOOD/CLOTH/MORTALITY（799 格），第三个周期 **DEBT 275 格**（FOOD 145 / MORTALITY 41）。
- ⇒ **"借粮当最后手段"这条机构在跑**（不然第一个周期就该饿死更多），但**利息开始滚起来**：
  第三个周期的应付息（299,733）已经接近当期的还本（12.9M）的 2.3%。**是否可持续，一年不够判断**——这正是本报表的边界。

## 六、未成交原因归因（M0.4）

> **本节只追加，不改上面任何一行。** 完整报告（口径、逐国分表、三问、交叉校验、边界）见
> **`.superpowers/sdd/2026-09-27-m0-instrument/m04-attribution.md`**；
> 逐格归因脚本 **`.superpowers/sdd/2026-09-27-m0-instrument/m04_attribution.py`**（纯 `python3`，
> 不跑 Maven、不联网、不改任何 `simos-*`）。
> **一行复算**：`cd /home/cna/SimulatorMosire && python3 .superpowers/sdd/2026-09-27-m0-instrument/m04_attribution.py`

**做法**：把 799 格 × 3 个 tick（2,397 格次）按「先满足者胜」逐格判进**恰好一档**
（`NO_MARKET` / `NO_NEED` / `SUPPLY_ZERO_*` / `NO_PURCHASING_POWER` / `LOCAL_SUPPLY_SHORT` /
`ALGORITHM_UNCOVERED` / `RESOLVED`），用 `Σ classes[].flow.unmetNeed["grain"]` 当整周期缺口，
`max(0, grainStock − grainDailyConsumption × 120)` 当可售余量，
`actorMoneyTotal["silver"] × 1000 ÷ 价格` 当有效购买力。
**全档缺口与逐格缺口用两条独立代码路径逐值对平，差 0**；本报表 §一 的
「本期缺口·粮」72,499,138 / 12,656,403 / 11,271,777 也**逐值对上**。

**三条结论（缺口占比按 tick 120 / 240 / 360）**：

1. **「世界没余粮」只在第一周期成立**：tick 120 全球可售余量 39,768,997,764 毫粮只够缺口
   72,499,138,932 的 **54.85%**（主角是 `LOCAL_SUPPLY_SHORT`，占缺口 **53.62%**）；
   tick 240/360 全球可售余量反而是缺口的 **5.57 / 8.68 倍**，此时八成缺口卡在
   **`SUPPLY_ZERO_*`（82.59% / 82.21%）**，即「账上有粮、但按自留额口径一粒不卖」
   —— 这 326 个格次**没有一格是库存为 0**，全是「库存 > 0 而可售余量为 0」。
2. **购买力封锁 = 0**：`NO_PURCHASING_POWER` 三个 tick 全空（0 格、0 毫粮、占 0.0000%）。
   候选集（可售余量 > 0 的格）里**最穷的一格**也有 68,604,000 毫粮的购买力，离判据阈值
   （买不到 1 毫粮）差 7 个数量级 ⇒ 在这批一年期读数里，**粮食缺口与「没钱」无关**。
3. **算法确实漏了**：`ALGORITHM_UNCOVERED`（本格 `可售余量 ≥ 缺口` 且有钱、却仍欠账）
   占缺口 **20.55% / 7.29% / 8.05%**（237 / 69 / 77 格）；这些格自己的可售余量合计
   每一档都**大于**自己的缺口合计（如 tick 120：18,529,663,230 vs 14,899,580,238）
   ⇒ 「供得上而没成交」是撮合问题，不是稀缺问题。

**首都格 `(q=-39, r=-71)`**：★ 任务书称它属奥斯特马克侯国，**数据实测属「德意志第二帝国」**
（三个 tick 都是），本报告以数据为准。它三个 tick 全落 `SUPPLY_ZERO_NO_SELLER`：
缺口 1,736,551,217 / 3,269,846,974 / 2,924,107,350 毫粮，粮库存 236,854,357 / 173,377,831 /
177,429,181 毫粮，而自留额 3,645,720,360 / 3,392,990,280 / 2,892,030,240 毫粮
⇒ 可售余量恒为 0。**它很有钱**（`silver` 4,387,092 毫，购买力 4,387,092,000 毫粮）
⇒ 卡在「一粒不卖」，不是「买不起」。

**如实记的口径问题**（详见报告 §1.3 / §1.5 / 附）：
① 任务书里档 3 `SUPPLY_ZERO_ALL_RESERVED` 的判据是档 2 的**真子集** ⇒ 字面序下**恒空、不可达**
（本报告用字面序出正式数字，另给「意图变体」表，`SUPPLY_ZERO_*` 合计两读法下相等）；
② 档 7 `RESOLVED` 在 tick 240/360 **全部**是「本周期无欠账但仍想买」的格，**不是**「已解决」；
③ `unmetNeed` / `naturalNeeds` 是**稀疏字典**，必须按缺键=0 处理；
④ 周期天数自检的最大相对偏差 **1.578180% / 3.070161% / 5.336398%**（方向一律偏高）——
已用「换自留额口径重算」的敏感性表（§2.4）量过：`SUPPLY_ZERO_*` 126/103/97 → 121/100/96，
**三条结论都不翻转**。

**边界**：这一档归因是**事后从 tick 快照的状态倒推**的，不是结算当时的记账 ⇒ 回答的是
「当时为什么没成交」的**必要条件而非充分条件**；`LOCAL_SUPPLY_SHORT` **分不开**
「隔壁有余粮但没路」与「世界上真没有」（数据里没有邻接与运输这一维）；
本节的三个 tick 是**三个独立快照**，`126 → 103 → 97` 说的是**格数**，不是同一批格陆续脱困。

## §0 三问直答（先给结论，数字出处见括号）

> 用户原话：「**饿死就饿死了，怎么着，梁文峰也饿死了？我认为是你这个小世界经济的必然结果，没有国家的再调度贫民哪来的粮食？——再来查看一下财富聚集情况！**」

**① 聚集到什么程度？—— 极端聚集，而且是"货随格走、钱随国库走"。**

- `small-world`：粮的 **Gini 0.343（day0）→ 0.971（day600）**，Top1% 份额 8.75% → **77.17%**，中位数 3,125,000 → **0**；day600 **只有 16/105 户还有粮**，其余 89 户**一粒不剩**（§2.1 T1、T2）。
- `small-world` **99.9999% 的粮物理上堆在首府格 `0_0` 一个格**（330,425,325 / 330,425,632 毫；§2.1 T3）。其余 18 格合计 307 毫（= 0.3 个单位）。
- **国库**（国库户 + 官吏户）持 **97.42% 的全部银**（262,750 / 269,700 毫）与 **39.60% 的全部粮**（216,634,599 / 547,060,231 毫）；官吏/国库户**自己一厘税都不交**（§2.1 T4、§2.3）。
- `three-powers`：粮 Gini 0.306 → **0.870**，Top10% 18.82% → 75.29%；政府口持 92.60% 的银、0.32% 的粮（§2.1 T4-tp）。

**② 饿死的是谁？—— 不是"最穷的先死"，也不是"不分贫富都死"，而是「**不在首府格 / 不在市场能跑到的那一格的，全死**」。**

- `small-world` 死 1,920 人（饿死 1,844），人口 4,800 → **3,308（−31.1%）**；`three-powers` 死 2,596 人（饿死 2,490），人口 6,350 → **4,297（−32.3%）**（§2.2）。
- `small-world` **按格**：首府格 `0_0` 死亡率 **66.7‰**（10 户 / 900 人 / 60 死）；**其余每一格 410–525‰ —— 6–8 倍**（§2.2 M2）。**按阶层**：贫农(乡) 最惨 632.2‰，但地主(乡) **400.0‰ 正好等于世界平均**、富农(乡) 312.3‰（§2.2 M1）。
- ★★ **"梁文峰"的直答（★ 用"并列全取"的无歧义口径，理由见 §2.2 M3 的并列陷阱）**：
  `small-world` **day0 人均粮最高的 21 个户行（21 户并列在 312,500 毫/人 = 最大值，全是地主户）**：600 天死 **86 人 / 240 人 = 358.3‰**，**低于世界平均 400.0‰**；但 **21 户里 4 户彻底灭门**（末人口 = 0），**19 户的结局是"人没了或只剩个位数"**。
  只挑其中 10 户（按 id 前 10）能得出 **590.0‰**、挑另外 10 户（按 id 后 10）能得出 **228.6‰** —— **同一个富户集合，换 10 个样本数字差 2.6 倍**。⇒ **"最富的比平均死得更狠"这个说法不成立；正确说法是"富不保命"**：
  · 按阶层：地主(乡) **400.0‰ = 世界平均 400.0‰（一模一样）**、富农(乡) 312.3‰、贫农(乡) 632.2‰（§2.2 M1）；
  · 按格：首府格 **66.7‰** vs 其余每格 **410–525‰**（§2.2 M2）—— **这一格之差比任何阶层之差都大**；
  · 21 个最富户行里唯一活得好的，是 `hh-0_0-rural-landlord`（0 死 / 末粮 175,986,575）—— **他在首府格**。
  `three-powers` 同理但更轻：40 个并列最富户行 **124.2‰**（世界平均 408.7‰），**但 8/40 户彻底灭门**；三个首府格 **192.8‰** vs 其余 34 格 **461.6‰**（§2.2 M2-tp）。
  ⇒ **财富本身不保命；位置保命。"最富的那批"没有被豁免 —— 但他们也没有被特别针对。**
- ★ **挨饿面**：`small-world` day600 **3,308 人里 2,372 人（71.7%）所在户饱食度 = 0**，而这 2,372 人**恰好就是首府格以外的全部人口**（0_0 的 936 人全部 satiety=1000）；`three-powers` 4,297 人里 **3,208 人（74.7%）** 饱食度 = 0 且粮 = 0（§2.1 T5）。
- ★ **不是没有粮食**：`small-world` day600 市场轮里**卖方挂了 317,413,990 毫粮（317,414 个单位）**、买方需求 12,985,087 毫（12,985 单位），**成交只有 44,257 毫（44 个单位）**——因为**粮价在 day525 归零并再没起来**（§2.3 F3）。**粮堆在场上，人在旁边饿死。**

**③ 有没有"再调度"？—— 有"抽"没有"调"。从贫户/乡村抽到国库的通道是实的；从国库回到贫户的通道根本不存在（0 件事、代码里没有这个位）。**

- **`small-world` 实测（600 天，历史累计发生额）**：税**评** 855,663,752 毫粮 → **实收 213,912,008 毫粮**（25.00%，其余 75% 因 `administrationPerMille=0` 作为"行政缺口"落空）+ 实收银 93,971 毫（§2.3 F1）。
- **国库付出去的只有俸禄**：600 天共付 **583,200 毫粮**（= 384,000 毫 `ADMIN_SALARY` + 199,200 毫 `ADMIN_STIPEND`）+ 38,400 毫银，全部付给**两个官吏户（共 4 人）**（§2.3 F2）。
  ⇒ **抽进来 213,912,008，发出去 583,200 —— 0.27%。99.73% 留在国库。** 账对得上到 1 毫：省国库粮 1,000,000 → 214,620,408（**+213,620,408 = 213,912,008 − 291,600**，精确相等）。
- **救济 = 0 件事**：两个世界各 600 天日志里，`relief|subsid|welfare|allowance|dole|救济|补助` **大小写不敏感命中 0 行**。代码里**没有这个位**：日循环政府段只有「税 → 预算规划 → 行政俸禄 → 军俸/工资 → 持久周期规则」（`simos-app/src/main/java/io/mosire/simos/app/time/PopulationEconomyTimeParticipant.java:815`），预算类别词表只有 5 类且**没有救济类**（`simos-gov/src/main/java/io/mosire/simos/gov/GovBudgetCategory.java:15-31`），`CrisisMonitor` 明写「起义、逃亡、抢粮、请愿、**救济一律留给以后的政治系统**」（`simos-app/src/main/java/io/mosire/simos/app/crisis/CrisisMonitor.java:29`）。★ 代码里的"救济通道"一词指的是**家户自救**（市场 → 借粮 → 还债），不是政府转移（`simos-economy/src/main/java/io/mosire/simos/economy/time/EconomyHouseholdGap.java:12`）。
- ★ **`three-powers` 干脆一分税都没收**：`TAX_DAILY_END` 600 天全部为 0，三个 gov 单元每天一条 `TAX_UNIT_SKIPPED reason=no-rated-region`（共 1,800 条）。它**照样饿死 2,490 人**。
  ⇒ **"没有再调度"在两个世界里都成立；但"饿死"不是税造成的 —— 税只是让 `small-world` 更糟，`three-powers` 没税也一样饿死。真正的杀手是市场/物流（§2.3 F3、§4 D2）。**

### 2.1 财富分布

**口径声明（重要）**：
- **集中度一律用"固定面板"** = **day0 人口 > 0 的家户行**（`small-world` **105** 行 / `three-powers` **200** 行）。理由：`small-world` 有 **73 行在 day0 就是"空壳行"**（每格都有 `urban-*` 四行，但世界只在两个城市格播了城市人口 ⇒ 19 格 × 4 个 urban 类里绝大多数恒为 0 人 0 货）。不固定面板，Gini 的变化就会混进"样本变化"。
- ★ **"户"= (格, 阶层) 户行，不是一个家庭**。逐户从 `hh-<q>_<r>-<阶层>` 命名可见；日志 `MIGRATION_MOVE source=hh--2_1-rural-rich_peasant target=hh--2_1-rural-poor_peasant population=1 reason=PROFIT_WEIGHTED`（201 次）证明**人是可以在户行之间滑动的**（阶层滑落 / 经营方式迁移）。⇒ 报告里的"户"请读作"格上的阶层户行"。
- **折值口径**：★ **本世界在 day600 没有可用的价格向量** —— `marketTables.prices = {grain:0, cloth:0, fiber:0, tool:0, iron:0, haul:4}`（`small-world` day525 起、`three-powers` day300 起粮价为 0）。而且 **全仓无汇率**（`GOV_BUDGET_FOREIGN_CURRENCY_EXCLUDED note=预算帽 = 单一币种口径：其他币种既不相加也不折算（世界无汇率）`，1200 条）。⇒
  - **不做跨币种求和**（银/铜/金各自列）；
  - **不做"商品按牌价折成钱"**（牌价是 0，折出来就是 0，那是把口径当结论）；
  - **主口径 = 实物**：粮（口粮，直接决定生死）、银（逐币种）、**土地份额 LAND**（生产资料的产权量，`assetShares.quantity`，`assetRule.pledgeable=true`）。
  - **折不了的逐项点名**：① 银↔铜↔金无汇率；② `assetShares` 的 `quantity` 是**该产业产能的份额单位**，跨产业不可加（`farm@h` 与 `weave@h` 的 1 份不是同一个东西）—— 本报告只在**同资产种类内**（LAND / TOOL）求和，且明说这是**份数**不是货币价值；③ `productionOrganizations`（68 个）与 `relations`（145）里的**经营权**没有价值字段，无法折；④ `industries.capacity` 为空表（产能按流水算），无法折。

### 问 1：「财富聚集到什么程度（钱/货/资产在谁手里）」

1. **粮**：`small-world` 粮 Gini **0.343 → 0.971**，Top1% 份额 **8.75% → 77.17%**，中位数 **3,125,000 → 0**，day600 只有 **16/105 户有粮**（§2.1 T1，**时点快照**）。
2. **空间**：day600 **330,425,325 / 330,425,632 毫粮（99.9999%）在首府格 `0_0` 一个格里**；其余 18 格合计 **307 毫**（§2.1 T3，**时点快照**）。
3. **钱**：家户手里的银从 **67,200 毫 → 6,905 毫（−89.7%）**；国库+官吏户持 **262,750 / 269,700 = 97.42%**（§2.1 T4）。
4. **资产**：土地份额是**唯一没被进一步集中**的 —— Gini **0.830 → 0.748**，持有人 **19 → 38 户**（§2.1 T1）。**聚集的是钱和货，不是地。**
5. **向国库聚集**：政府口粮占比 **0.55%（day0）→ 49.57%（day240）→ 39.60%（day600）**；政府口银占比 **74.85% → 97.42%**（§2.1 T4）。**是，而且是单向的。**

### 问 2：「饿死的到底是谁（最穷的先死？还是不分贫富都死？Top N 有没有饿死？）」

   - **`small-world` day0 粮总量 Top10（绝对大户）：死亡 155/1,095 = 141.6‰，但 4/10 户彻底灭门**；Top50 **289.6‰，18/50 户彻底灭门**（§2.2 M3）。

## §5 未做 / 未验证项（★ 不许读成"通过"）

1. **"底部分位户的存活率"没给干净数**。理由：`small-world` 有 **73 个 day0 人口=0 的空壳行**，排在"最穷"的最前面，分母为 0；`day0 粮` 同阶层 19 户数值完全相同 ⇒ 分位在并列里是任意序。⇒ 本报告用**阶层**（§2.2 M1）与**格**（M2）代"分位"，并明说"财富分位对死者是弱判别力"。
2. **Top N 的并列敏感性只做了"两端"**。`day0 人均粮` 最大值并列 21 户（sw）/ 40 户（tp），本报告给了**并列全取**与**并列内按 id 前 10 / 后 10** 三个值（228.6‰ / 358.3‰ / 590.0‰），**没有**做"随机抽 10 户跑 N 次"的完整分布。`day0 粮总量` 的并列块也很大（5,250,000 有 19 户、4,500,000 有 20 户），**Top50 的边界落在并列块中间 ⇒ Top50 名单仍有任意性**（Top10 没有：它全部落在 7,875,000 以上的唯一值区）。
3. **`D10`（首府格逆向抽水的机制）未定位**。只证明了"粮单向汇到 0_0、运力只在 2 个城市格"，**没有**证明这两件事之间的因果链。判别实验未做。
4. **D3 的根因未定位**：为什么 17 个格没有 `haul` 牌价（`marketTables.prices` 是**一张表一份价**还是**逐格一份**）没有回代码读透。
5. **`consumed` 没拆成"口粮/衣着 vs 周期投入（种子/原料）"**。`FlowRow` 类注明写两者混在一起（`FlowRow.java:60-62`）⇒ 本报告的物资守恒只给"离开家户账"的总数，没给"吃掉多少"。
6. **没有做"格内交易"与"跨格交易"的成交额分离**。`MARKET` 事件只给 `fills` / `immediateCrossHex` 件数（sw 240 轮 Σfills=2,525、ΣimmediateCrossHex=147），没给逐类型的金额。
7. **官吏户作为"债权人"这件事未回代码核**。§2.4 D4 的 93.5% 应收挂在 `hh-unit:gov-central/province` 上，看起来不合常理（官吏户放贷 2.7 × 10¹⁴）；本报告**只报读数，未核 `creditor` 字段的写入路径**。
8. **`three-powers` 的"按市场区"分组没做成**（因为 D7：三张价表 hexes 为空），本报告用政区代分组 —— **口径不同，不可与 sw 的"按格"直接并排比**。
9. **未做逐笔税率归因**：`TAX_DAILY_END` 只给聚合（评/收/短），逐户税负是从 `flows.taxPaid` 还原的；**没有**逐户 × 逐日的税率核验。
10. **W6 的 `daily/*.jsonl.gz` 已复用做交叉核对，但本报告的 601 天逐户读数没有与 W6 的逐日聚合读数逐日对比**（只对拍了 6 个网格日的全量状态 md5，全部一致）。逐日对比未做。
11. **没有跑任何"设了救济会怎样"的反事实**（例如给 gov 加一条转移规则）—— 属于改世界设定，超出只读调查范围。

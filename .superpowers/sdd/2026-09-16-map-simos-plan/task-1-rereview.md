### 3.3 `round` 末支 `else` 的省略是否行为等价 —— **理由成立，且是"永不分叉"**

**独立判断：理由成立，且比实现者说的更强 —— 对任意输入**永不分叉****。

**(a) 逻辑依据**：该 `else` 分支体（草图版 `rs = -rq - rr;`）**只给 `rs` 赋值**。而 `rs` 在 if 链之后的**唯一**读取点是链**之前**的 `ds = Math.abs(rs - s);`——链后到 `return new HexCoord(rq, rr);` 之间**没有任何一处读 `rs`**。返回值只由 `rq`/`rr` 决定 ⇒ 这个赋值是**死存储**，删掉它**不可能**改变返回值。所以"永不分叉"，不是"实测没分叉"。

**(b) 实测（三重输入面，与实现同一套浮点运算的模型，`jround = floor(x+0.5)`）**：

```
密集网格 [-3,3]² 步长 0.05                    14641 点 → 分叉 0 处
随机 double [-1000,1000]                     200000 点 → 分叉 0 处
半整数 x.5 网格（含全部并列点，i,j ∈ [-60,60]）58564 点 → 分叉 0 处
```

**(c) 两种实现会分叉的输入：不存在**（由上 (a) 的论证覆盖全输入域）。补一句实现者表述的精确化：它说"若在此改动 q/r 反而错"——**实测支持**：把末支写成 `else { rq = -rr - rs; }` 后，密集网格 14641 点中 **1142 点**返回的格**明显更差**（最大差距 **0.5**，例：`round(-3.0, -2.5)` 得 `(-4, -2)` 距离 1.0，而最近格 `(-3,-3)/(−3,−2)` 距离 0.5）。

# 设计要点：R1.5（开读口 —— 让批次可见）

> **给实现者**：本文只给**判断与判据**，代码你写、测试你跑。
> 判据出处：`docs/superpowers/specs/2026-09-26-population-economy-v3-design.md` 的 §三/§八/§十。
> 前序：R1 已关账（提交 `69487db`，全仓 **2197 用例 / 0 失败**）。其台账在 `.superpowers/sdd/2026-09-26-population-r1/brief.md`（**先读**）。

## 为什么有这一轮

R1 把 `PopulationGroup` 落地了（每格 6 个批次：农村/城镇 × 男/女 × 三个年龄档），**但读口没开**：

> `/api/social/population` **仍然只读农村序列**；批次**未进任何读口 / GUI / MCP**。

⇒ **年龄与性别目前在报表里看不到**（数据有了、面没开）。本轮就是**把面打开**——这是纯读侧改动，成本低，而它正是"更全面的模拟结果"的第一步。

## 范围（**只做读侧**，不要动状态形状）

### T1：`social` 侧新增三个**派生纯函数**（不加字段）

在 `SocialData`（或一个包内 helper）上，按格/按城算：

- `ageStructureAt(HexCoord)` → 三个年龄档的人数（**用 `PopulationGroup.ageDaysAt(nowTick)` 现算**，不是另存一档）
- `sexRatioAt(HexCoord)` → 男/女人数
- `urbanRuralAt(HexCoord)` → 城镇/农村人数

★ **判据**：
- 年龄档边界**复用 R1 已落地的 `AGE_BRACKET_MAX_EXCLUSIVE_DAYS`**（不要另写一套边），档名与 D4 一致（`0-14 / 15-59 / 60+`）。
- **必须是现算**（`ageDaysAt`），**不得**在 `PopulationGroup` 上加"当前档位"字段——那会让档位变成第二份真相。
- **零人口的格**要返回三个 0（不是缺键），与 R1"有序列的格 ⇔ 有批次的格"同款。

### T2：暴露到读口（**GUI 与 MCP 共用一份视图**）

- 扩展现有 `/api/social/population` 的响应（加年龄结构/性别比/城乡），**或**新增一条端点。二选一由你定，但**必须在报告里说明选了哪个、为什么**。
- ★ **视图只有一份**：体由 `ApiViews` 装配，GUI 路由与 MCP 工具**共用同一个函数**（`AGENT.md` §8.3 的硬规矩）。**不许**在路由层另拼一份。
- 若新增 MCP 工具 ⇒ 四处命令/工具清单守卫要同步（`McpCoverageTest`（EXPECTED_COMMAND_TYPES + MINIMAL_PAYLOADS）、`SimosToolsTest`、`AdjudicateTickToolTest`、`CatalogTool`）——**R1 刚踩过，清单在它的报告里**。
- ★ **权限**：新读口要沿用**实际运行的权限判定**（`ToolSupport.hexVisible` 一族），**不许**另造一个更宽的；未授权默认拒，且"不可见"与"格不存在"**拒因逐字相同**（不给存在性侧信道）。

### T3：把"两侧人口一致"变成**读得出**的

R1 只把 `Σ group == 经济侧总人口` 做成了**构造性相等 + 测试断言**。本轮让它**读得出来**：

- 在**同一个响应**或**相邻两个响应**里，能同时拿到"该格 social 侧批次求和"与"该格 economy 侧各行求和"。
- 加一条**跨模块验收用例**：真档 138 格（或全 799 格）逐格断言两者相等。
  ★ 这是 R1 的 `PopulationSeederTest` 那条"构造性相等"的**读侧对照**——两者都要有，因为前者守"创世算得对"，后者守"读出来也对"。

## 不做（留白，不是遗漏）

1. **不改状态形状**：`PopulationGroup` / `SocialData` 的组件**一个都不加**（那是 R2+ 的事）。
2. **`ClassRow.population` 不降级**：运行时同步需要跨切片协调器，属后面轮次。本轮只做读侧对照。
3. **不做 GUI 面板**（报表由控制器直接从 HTTP/MCP 取数；面板留给以后）。
4. **不动 `simos-ledger`**；**不做出生/死亡**；**不做 `LaborAllocation`**。

## 铁律

- **不许放宽断言**；合法改法只有"按新口径重算期望值"（算式写进注释）与"修夹具"。
- **期望值优先写成由常量推出的算式**，注释里复述算式。
- **每条护栏配变异自证**：改坏判据 ⇒ 必须**红** ⇒ 用 **Edit 反向重写**还原（**不许** `cp`）⇒ 复绿。
- ★★ **判别力声明必须真的成立**：写完"由 X 承担判别力"，X 必须**存在**且**真的会红**；**逐条自检并报给我**。
  ★ **特别小心空夹具**：R1 的实现者在这里栽过——`populationAt` 的夹具**全是农村**，于是"只看农村"的实现**照样绿**。
  本轮做年龄/性别/城乡三个派生量，**夹具必须刻意混合**（每格都同时有男有女、有城乡、有不同年龄档），否则同样是假绿。
- ★ **验证工具本身**：报"零命中/全绿"前先证明读取模式对。**禁止 `2>/dev/null` 吞工具错误**。
- **一次只能跑一个 Maven**；判过不过看 `target/surefire-reports/*.txt` 的 **mtime 落在本轮**，不看 rc。
- 改完跑 `./mvnw -q spotless:apply`；若它动了你没改过的文件，**停下报告**。
- **收尾前台跑 `./mvnw clean verify`**，把 **Reactor 逐模块结果**（显示名那栏）抄进报告。
- ★ **机械改动逐个 Edit，不要用批量脚本**（R1 的实现者用批量脚本**误伤 8 个测试文件**、只能从 HEAD 恢复重做）。
- **不要 `git commit`**。

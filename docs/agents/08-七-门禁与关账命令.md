## 七、门禁与关账的常用命令

```bash
node simos-app/src/test/js/run-gate.cjs          # 前端门禁（下界见 run-gate.cjs，当前 402）
./mvnw test -pl simos-app -am                    # 全量测试（含前端门禁那一步；不动 jar）
./mvnw -q -Dspotless.check.skip=true -DskipTests package 2>/dev/null   # 见 §二「产物」——本仓无 shade 开关
./mvnw clean verify                              # ★ 关账：Spotless+Checkstyle+SpotBugs+Surefire+前端门禁
```

★ 报"测试数"之前**先 `rm -rf */target/surefire-reports`**（否则读到两轮的并集，见 §三.1）；
★ `simos-app/target/surefire-reports/` **可能整个目录不存在** —— 那说明 app 侧这一轮**没跑到 test 阶段**
（编译或前置模块失败、或被中断），**不能读成"app 没有测试"**，更不能拿上游 10 个模块的绿当 app 的绿。
★★ **追加（2026-09-27，M0 收尾查清的一处夹具 bug —— 凡"一年末"读数必看）**：
`EconomyRealScaleClothTest` 的 `YEAR_DAYS` 曾是 **365**，而本仓的"一年末"一律是 **第 360 天**
（`CYCLE_DAYS = 120` 的第 3 个关账日；一年期真档推进 = tick 120/240/360）。365 落在**第 4 个周期的第 5 天**，
而周期第一天就把现扣投入划走 ⇒ 缸里的纤维被取空 ⇒ 当年读到"年末纤维 = 0"，
并被**误诊成"推进路径造成的相位差异"**（实为时点错；M0.1 已证路径无关）。
实测：第 0 天 20,700,000 → 第 1 天 0 → 第 120/240/**360** 天 **18,042,000** → 第 365 天 **0**。
⇒ **纪律：`YEAR_DAYS` 一律 360；写一年末断言前先问"这是第几天"**。
★ 连带教训：**"上界"式区间断言（`isBetween(0, X)`）会把时点错掩盖成"相位差异"** ——
能收紧就收紧，收不紧要写明理由。

★★ **追加（2026-09-27，M0 批实测踩到，代价三轮返工）**：
① **`-Dtest='A+B'` 是 JUnit5 的 tag 表达式、不是"或"** ⇒ 不匹配任何类、surefire **一条不跑**、
打印 `test` 目标、**退出 0**。正确写法是**逗号**：`-Dtest='A,B'`。**差一点把"一条都没跑"当成"测试通过"。**
② **Maven 增量编译不可全信**：实测 `simos-economy` 的类文件比源文件**新 21 秒**却没重编
（`-pl simos-app -am` 下没有 `Recompiling the module`）⇒ 两轮诊断都跑在**旧字节码**上。
**纪律：改完生产代码，先 `rm -rf <模块>/target/classes`（或 `target/test-classes`）再跑测试。**
★★ **追加（2026-09-27 实测踩到三次）：阶段边界的门禁要跑「全仓 `verify`」，不是模块级。**
`verify -pl <某模块> -am` 只对**该模块及其上游**跑 Spotless/Checkstyle/SpotBugs ⇒ 我在别的模块欠的格式账
（`simos-social` / `simos-actor`）**跨了两个批次都没被发现**，直到一次全仓 verify 才暴露。
⇒ 三件事一起记住：① 跑了 `spotless:apply` **必须**跑 `verify`（不是 `test`）；
② **`-am` 不能省**（`verify -pl simos-app` 不带 `-am` 会用 `~/.m2` 的旧 SNAPSHOT，报"找不到包"的**假红**）；
③ **门禁是三项**（Spotless + Checkstyle + SpotBugs）——只跑前两项**不等于**绿（实测：5 条 SpotBugs 就是这么漏过去的）。
★ 全仓工具（`spotless:apply`）跑完后，按 §五.1：**`git diff --name-only` 列全**再逐条确认后提交。
★ 迭代时只跑相关单条：`./mvnw -q -Dtest=<类名> -Dsurefire.failIfNoSpecifiedTests=false test -pl <模块> -am`。
★ 中文 Javadoc 的折行由 **google-java-format**（Spotless）决定：**不要手工调行宽**（手工断行处会留下接缝空格），
改完跑 `./mvnw -q spotless:apply`；`~/ProjectMosire` 同为该形态。

★★ **追加（2026-10-15 实测，测试代理自己纠正的读数错误）：「门禁是三项」有先后 —— `spotless` 在前，
它一红，后面的 `SpotBugs` / `Checkstyle` 在**该模块**根本不跑。**
- 现场：`clean verify` 报 `spotless:check FAILURE @ simos-app` ⇒ 同一轮里 `simos-app` 的
  `spotbugs:check` **没有执行**（不是"执行了且为 0"）。当时的台账把这两项当成"都跑过了"来读 —— **读错**。
- ⇒ 纪律两条：① **`spotless` 一红，就必须 `spotless:apply` 后整轮重跑**，不能把那一轮其它项的"没输出"当成"通过"；
  ② 报数时写清"本轮哪些模块的哪些项**真的跑过**"，**没跑的不许写成 0 违规**。
- ★ 另：SpotBugs 真实报数的是 **16 个 jar 模块**（不是"全部 17 个 reactor 条目"）——写数字前先数清。
- ★ 同一批还实测到一次**并发污染**：把"最终门禁"与一条**变异测试**并行跑 ⇒ 那一轮红在被变异的生产文件上，
  **整轮结果作废**。⇒ **门禁与变异自证必须串行**；作废要明说作废，并确认 `md5sum -c` 全 OK、无 Maven 残留后重跑。

## 七.1 ★★ 多 tick 全真世界模拟的**独立跑法**（批 M，2026-10-15 用户裁定）

> ★★ **用户原话（逐字，2026-10-15）**：「先停一停，我不是说，测试class里不要塞多tick吗？要跑全真世界模拟自己额外创世界跑，别塞进测试里！」
> 判据落盘：`docs/superpowers/plans/2026-10-15-batch-M-multitick-out-of-tests.md` §2.1（**≥2 段 或 ≥60 tick = 违规**）。

### 怎么跑（就三条命令）

```bash
tools/multitick-sim.sh                          # 三个 case 全跑（★ 实测 1m31.7s，rc=0）
tools/multitick-sim.sh economy-cycle-health      # three-powers 真世界 240 天 + 96 轮市场指纹（实测 36.4~37.2s）
tools/multitick-sim.sh gov-genesis-120d          # 小世界 120 天逐日推进（实测 40.0~40.3s）
tools/multitick-sim.sh segment-equivalence       # 30 天一次推进 vs 30 次逐日（实测 12.6~17.1s）
SIMOS_MULTITICK_SKIP_BUILD=1 tools/multitick-sim.sh …   # 跳过 test-compile（刚编过时）
```

- **跑多久**：全跑 **1 分 32 秒**（三个 case 串行，实测 1m31.7s；单跑见上）。★ 落盘体积：跑一次约 **211 MB**
  （economy-cycle-health 155M / gov-genesis-120d 37M / segment-equivalence 19M，全是可重建的 store 与摘要）
  —— 空间紧时 `rm -rf test-world/multitick/` 即可回收，下次跑重新创世。★ 它**不进** `clean verify` —— 跑的是 test-scope 的
  `io.mosire.simos.app.sim.*Sim` / `MultiTickSimRunner`（`main`），surefire 的缺省 include 只收「Test 前缀 /
  Test 后缀 / Tests / TestCase」四种类名，**门禁永远收不到它们**。
- **看什么**：① 每个 case 的 `[PASS]/[FAIL]` + 用时；② 失败时原样打印的那条断言消息（含 `as(...)` 里的人话读数）；
  ③ 退出码（0 = 全过，1 = 有 case 红，3 = 用法/编译错）。经济循环那条还会把**逐段摘要**打到 stdout 并落
  `<store根>/economy-cycle-health/summary.txt`（人口 / 粮 / 布 / 债务本金 / 逐币种货币总量 / 当日成交 / 未成交 top3）。
- **隔离**：每个 case 一个**自己的空 store**，落在 `test-world/multitick/<case>/store`（跑前清空 ⇒ 真创世），
  端口一律 `0`；**不碰** `test-world/store`（`simos-testworld` 服务在用，18Lvt 副本），更不碰 `~/Simos-18Lvt/world`。
  换落点：`tools/multitick-sim.sh all --store-root=/tmp/x`（或 `SIMOS_MULTITICK_STORE_ROOT=/tmp/x`）。
- **它为什么不用 test-world 那份 store**：这三个 case 的判据都以**本跑法自己刚播的创世**为基线
  （逐币种货币守恒的基线、96 轮分布指纹、`head=121` 的逐日 revision 计数）——18Lvt 副本是**已推进过**的另一座世界，
  拿它当基线判据会失真。⇒ 隔离落在 `test-world/` **那一侧**（同目录树、独立 store、独立进程），不是复用它的世界本体。

### ★ 扫描器（V1：门禁里不许再有推进 ≥2 段 或 ≥60 tick 的用例）

```bash
python3 tools/scan-multitick-tests.py              # 全树扫描（缺省 table；--format=json / --include=… / --quiet-ok）
python3 tools/scan-multitick-tests.py --self-test   # ★ 自证：18 个已知样本逐值对期望（含"独立跑法不是用例"4 条）
```

- **口径**：`ticks ≥ 60` 或 `多日段 ≥ 2` ⇒ `VIOLATION`；`≥2` 次推进但按上面口径不违规 ⇒ `BOUNDARY`（列出给人复核）；
  解不出的推进 ⇒ `UNRESOLVED`（**非零退出**，绝不当作 0）。★ 「多日段」只数**跨 >1 天**的推进 —— 逐日推进算 tick
  （依据：设计书 §1.3「52 个类用它，绝大多数是 1 tick 契约验 ⇒ 别误伤它们」；两条判据各管一种坏形态）。
- **两条引擎契约已内建**（不是猜）：缺 `to`、以及 `N > MAX_ADVANCE_DAYS` 的推进都是 `TimeAdvance.java:231-245`
  在④第 0 项**纯语法层**就拒的 ⇒ 一天都不会走，计 0 tick。
- **具名豁免表** `tools/multitick-scan-attestations.txt`：`<相对路径>#<方法名> | <理由>`，理由必填；被豁免的条目
  **照样打印**（`VIOLATION(ATTESTED)` + 理由），**过期条目**（匹配不到任何用例）让扫描 **rc=3** 退出。
  当前只有 2 条（2026-10-15）：一条是扫描器假阳性（推进根本没执行 = 0 tick），一条是 `simos-core` 的**玩具夹具**
  急停/续推契约验（10 tick、M3 合规口径，★ 已在批 M 台账里点名上交控制方复核）。

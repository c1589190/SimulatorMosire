# 项目维护裁定台账

> **性质**：本文件只收**项目维护**相关的用户裁定：文档系统、Skill 系统、门禁/验证、工作流、协作、环境、提交/归档。
> **不在这里写**：模块边界、数据所有权、命令/载荷、运行时阶段、领域公式、工具归属等**项目设计裁定**。
> 项目设计裁定正本在 `docs/superpowers/specs/2026-10-02-architecture-design-source.md` 与专题设计；索引见
> `docs/superpowers/DESIGN_RULINGS.md`。
>
> **登记规则**：新增条目用 `M-xxx` 编号；原话逐字保留，注明日期、来源、影响、正本落点和状态。已被取代的条目不删，
> 只改“状态”字段并指向取代者。

## M-009 Worktree 根目录规范：统一放顶层 `worktree/`

- **日期**：2026-10-23
- **用户原话（逐字）**：
  > 「然后是worktree迁移，为啥worktree一直顶着.claude的名号？很烦人吧，把以后的worktree规范目录迁移到.agents里，或者干脆开一个worktree文件夹来放，我建议后者，你改改相关文档」
- **分类**：项目维护（工作树/环境/协作文档）
- **裁定**：
  1. 未来所有 git worktree 的规范落点 = 仓库根下的 **`worktree/<name>/`**；
  2. 不再使用 `.claude/worktrees/` 作为新工作树目录；`.claude/` 只保留本机工具自己的设置；
  3. 已有工作树按 `git worktree move` 迁移，不手工 `mv`，保留分支、dirty 与未跟踪文件；
  4. `/worktree/` 进 `.gitignore`，不把整棵工作树入库；相关路径引用按新目录更新。
- **当前正本**：`docs/agents/ENVIRONMENT.md`、`docs/agents/VERIFICATION.md`、`.gitignore`
- **状态**：有效（2026-10-23 已迁移现有工作树）

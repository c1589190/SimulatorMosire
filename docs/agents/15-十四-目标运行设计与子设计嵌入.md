# §十四 目标运行设计与子设计嵌入（2026-10-19 用户裁定）

> 用户原话（2026-10-19，逐字）：
>
> 还可以加一个关键目标原则，例如在修改什么什么模块/什么什么类型代码的时候，必须遵循怎么样的规范，或者某些细化设计；其他没啥问题，把如此原则加进AGENTS.md和其引导的技能集，记得在其中提醒办事的责任区子agent写中期设定也要遵循

## 一、核心原则

**先写“目标世界里代码实际怎么跑”，再写裁定、再写子设计。**

一份用于派实现子 Agent 的开发计划、架构设计或中期确认文档，不能先从孤立裁定项开头；必须先给出该责任区的**目标运行序列**：

```text
阶段/顺序 → 每阶段读什么、写什么 → 数据所有权 → 失败语义 → 日志锚点 → 验收锚点
```

然后才是：

```text
用户原话/裁定附录 → 子设计嵌入点 → 对父序列的影响 → 当前实现差异
```

这条原则的目的不是增加文档，而是让“裁定都对、组合起来断路”的问题在派单前就暴露出来。

## 二、文档层次与唯一权威

### 1. 目标运行序列（父文档）

每个主题/模块先有一份目标运行序列。它回答：

- 世界里有哪些阶段，触发条件是什么；
- 谁先谁后，是否同一 tick；
- 每个阶段读哪份状态、写哪份状态；
- 数据所有权归谁，谁是唯一写口；
- 业务拒绝、契约故障、失败回滚分别是什么；
- 哪些是瞬态（不进 Codec/ChangeSet），哪些必须同 revision 落盘；
- 哪些日志/测试锚点对应该阶段。

目标运行序列只写**语义级运行顺序**，不写逐文件施工图/类方法清单。

### 2. 裁定/口径附录

用户原话、工程裁定、数值标定必须保留，但作为**来源和影响映射**，不放在目标运行序列之前。每条裁定至少写：

```text
裁定结论：
原话/出处：
影响阶段：M3/M4/...
运行后果：
不涉及的阶段：
是否已被更新文档取代：
```

### 3. 子设计/约束设计

子设计不是第二份完整设计，只写本责任区的增量。开头必须有：

```text
父设计锚点：<目标运行序列文件 §阶段>
嵌入位置：<在哪个阶段之前/之后/内部>
新增/修改的输入输出：
状态所有权：
对父序列的影响：
  - 顺序：是否新增/移动阶段
  - 预算/冻结：是否共享/新增
  - 身份/持久化：是否新增组件/字段/Codec/ChangeSet
  - 失败/原子性：新增哪些拒绝/回滚
  - 日志：新增哪些阶段/事件
  - 测试：新增哪些正例/负例
不包含：<明确非目标>
```

### 4. 中期确认/状态/交接文档

只写三件事：

- 目标运行序列的当前 delta；
- 实际代码与目标的差异；
- 验收证据、未验证项和 blocker。

不重抄父设计，不把“已编译”写成“已验收”。

## 三、改模块/类型时必须遵守的细化规范

下表是“改什么代码，必须先看/必须写什么”的最低清单。子设计可以更细，但不能低于本表。

| 改动面 | 必须先确认的目标运行阶段 | 必须遵守的规范 |
|---|---|---|
| `simos-economy/time/**` 的 tick/结算阶段 | M0–M9 | 先更新目标运行序列；阶段顺序/触发/读写/失败语义必须写清；不得新增第二套市场、债务、工资或生产权威；新增/修改阶段必须有 INFO/DEBUG/TRACE 日志；economy main Java ≤1000 行 |
| 统一市场/商品/土地订单/撮合 | M3/M4 | 商品与土地是同一订单簿/同一撮合入口的订单变体；共享预算/冻结；土地整块、区级价、`empty ≠ 0`；不得保留两个 runner 级 matcher；新土地本轮不可用 |
| `EconomyData`/`EconomyChangeSet`/Codec/持久组件 | 全阶段 | 一个事实一个写口；组件数/字段数同步；完整状态往返不变式；Alpha 不兼容旧档、不写迁移/兼容位；构造/变更集/Codec 同批改 |
| 债务/工资/账户落账 | M2/M8/M9 | 债务本金只货币；无 Pledge/抵押/担保；债权人纯库存财富序；工资只现金、未付成普通 0‰ 货币债；账户仍走唯一 `applyTransfer`/ChangeSet 路径 |
| `ProductionRuntime`/production.contract | M3/M6/M7 | production 只拥有定义/配方/经验/实例物理状态/预计实际物理产出；economy 只读 contract，不复制效率/配方公式；预计/实际同源；不得把经济关系塞回 production |
| LAND/土地市场 | S1/S3/S7 | LAND 不进普通 `HouseholdGoods`；按 `(owner, hex, quantityMilliMu)` 标量持有，无 block id，任意数量转移/成交；区级 `OptionalLong landPrice`；0 价市场成交合法但债务清算中不自动冲本金；新取得土地只排除当前生产轮，下一生产 tick 可用 |
| 工资锚/WageDemand/WageSettlement | M3/M6/M8/M8b | 锚键 = 市场区×生产方式×位置；缺锚 ≠ 0；本 tick due 不追改；非市场日不动锚；工资债下一市场轮 M2 同池 |
| `simos-app` 时间参与者/桥接 | M0/M1/M9 | 只编排/桥接/账户会话/提案汇合；不实现领域公式；Social 先；`PendingFamineFacts` 单槽内存且失败不覆盖 |
| `EconomySeeder`/worldgen/初始数据 | M1b/M3/M7 | 只面向新世界（Alpha 不兼容旧档）；初始土地/锚/需求/roster 必须显式；不得保留旧阶级 mode/tenancy/rent 默认；初始数据要可复现 |
| 测试/验证 | 全阶段 | 测试 owner 按目标运行序列的验收锚点写，不按代码反推；写代码 Agent 不写/不跑测试；新架构新测试，旧架构旧测试删/迁移 |
| 文件拆分 | 全阶段 | 先拆后改行为；拆分不改公式/状态形状/公开 API 语义；每个 economy main Java ≤1000；拆分后立即编译 |

## 四、责任区子 Agent 的中期设定

办事/写代码子 Agent 在写 `impl-ledger.md`、中期报告、阶段性设计时，**同样受本规则约束**，不能因为是“中途文档”就只列已做事项：

1. 先写“本责任区目标运行段落”——它嵌在父序列哪个阶段、上下游是谁；
2. 再写“我实际怎么实现、偏离了什么、为什么”；
3. 再写“对父序列的影响”——顺序/预算/身份/持久化/失败/日志/测试；
4. 最后写“未做/未验证/blocker”。

中期设定如果只写“我改了哪些文件/编译过了”，没有父阶段锚点和影响表，控制方应视为**交账不完整**，不得据此进入下一责任区。

## 五、派单门槛

派实现子 Agent 时，任务书必须包含：

- 目标运行序列文件路径 + 阶段号；
- 本责任区的嵌入位置和影响表；
- 关键形状原样复述（不能只给链接）；
- 允许/禁止文件；
- 编译命令与“不写/不跑测试”纪律；
- 中期设定/账本必须遵守本规则。

**缺目标运行序列或子设计影响表的派单无效，子 Agent 有权拒绝并指出缺文档。**

## 六、与既有纪律的关系

- 本规则是 `docs/agents/02-一-并发.md` §一.8“约束设计书”的**上层运行设计**补充：约束设计书写“世界必须长成什么样”，目标运行序列写“代码实际按什么顺序跑”，子设计写“本段怎么嵌入”。
- 用户原话逐字收录、五条铁律、模块边界、Alpha 不兼容旧档、测试最后统一做、文件 ≤1000 等既有纪律**全部继续有效**。
- 目标运行序列不能替代用户原话；用户原话仍然最高权威。发现冲突必须上报用户，不得由子 Agent 自裁。

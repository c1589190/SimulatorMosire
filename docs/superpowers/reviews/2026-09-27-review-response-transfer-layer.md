## 三、关键矛盾（把 13 条收敛成 4 条）

### 3.1 矛盾一：一个事实、两本账、**其中一本没人读**

产出离开 `ClassRow` 后走的是：`harvest` → **`+净产 → operator`（actor 账）** → 按 `relation` 结算
→ `cohortIntake` → **`ClassRow.goods`**（`EconomySettlement.java:1482-1516`）。于是：

- **行侧账**（`ClassRow.goods`）是**消费**真正读的那一本（`settleHexes:1250-1273`：`eaten = min(stock, need)`）；
- **actor 侧账**（`GoodsAccount`）是**新产权模型的"唯一真源"**（S1 spec 追加-1）——
  但实测**没有任何经济决策读它**：写它的是 app 的 `OwnershipBooks.apply`（`OwnershipBooks.java:51-82`），
  读它的两处（`EconomyOwnershipTimeParticipant.java:113,139`）**只是声明读写地址集**，不是算任何东西。

⇒ 结论：**"唯一真源"目前是一本只写不读的账**。它的直接后果是：**积累没有行为后果**
（即使 actor 手里有 5,403,872 匹布，也不会改变它下一周期的任何行为）。评审第 8 条（地主缺布）与
第 9 条（储蓄）的**共同答案在这里**，而不在 `receipt = min(...)` 那句规则上。

★ 这也解释了 `E1`（裁定：守恒式必带 `ΔΣRowGoods` 项）：**过渡期两套账并存不是"多一个项"，而是"多一本没人读的账"**。

### 3.2 矛盾二：转移不是一等公民 —— **商品身份决定制度**

现在"东西怎么移动"有三条互不相干的实现，**没有一条是通用的**：

| 路径 | 形状 | 谁→谁 | 商品范围 | 出处 |
|---|---|---|---|---|
| 结算转出/入账 | `−paid` / `+paid` 双分录 + cohort intake | operator → actor/cohort | 由规则指名 | `ProductionSettlement.java:203-240` |
| **同格取料** | 行 → 行的无偿搬运 | `ClassRow` → `ClassRow`（同格、**跨产业**） | ★ **明文挡粮**：`if (commodity.equals(GRAIN)) continue;` | `EconomySettlement.java:1086-1091` |
| **同格借粮** | 行 → 行的**有偿**搬运（记债） | `ClassRow` → `ClassRow`（同格） | ★ **只对粮** | `EconomySettlement.java:1294-1335` |

★ **这两条互相排斥的分支就是评审那一句"图上没有边"的准确形态**：不是没有边，而是
**"这条商品走哪条边"被写死在代码里** —— 粮走"要还的边"、非粮走"不用还的边"，**制度不是可配置的，商品才是**。
这比"缺一个市场模块"更难修，因为市场接进来以后，它会是**第四条**互不相干的边。

**同格借粮的完整形状**（评审第 10 条要的细节，逐条读码）：
债务人 = 缺口行的 `ClassKey`、债权人 = 同格出粮行的 `ClassKey`（**都不是 actor、不是 cohort**）；
债权人序列 = 地主 → 富农 → 中农（贫农不放贷，`LENDER_SLOT_PRIORITY`）；
上限 = 逐日缺口 ×（库存 − 整周期口粮）；利率 20‰/周期、**周期末并入本金（复利）**；
**偿还完全不存在**（`FlowRow.repaid` 无写入点、`Debt.dueCycle` / `defaulted` 无读点，`Debt.java:22-24` 自述）。

### 3.3 矛盾三：身份与要素**两头都没闭合**

- **身份**：`CohortKey = (格, 阶层)` 不含 rural/urban（`CohortKey.java:34-40` 自述这是 R9 未合并的残留），
  而**行键**仍含 industry（`ClassKey = (industry, 阶层)`）⇒ 同一批人今天要靠"行"来区分城乡。
  评审第 4/5 条说的就是这个：**"人先存在、然后人才去参加产业"还没做到**。
- ★ **评审完全没提的一条**：**"在哪里劳动"是静态外生的**。劳动配额只在**人死亡时按比例缩**
  （`scaleLaborOfIndustry:820-828` 自述"**它只覆盖'人死了'这一侧**；出生**不放大**配额"），
  没有任何再配置/迁移/劳动市场 ⇒ **作坊停工以后，城镇批次仍然只供给作坊**：
  这批人既不能去种地，也没有别的活干，**结构性等着饿死**。
  ⇒ 城市 16.44% 的死亡率里，有相当一部分不是"缺交换"，而是**缺要素再配置**。

### 3.4 矛盾四：判据体系**没有城市这一支**

S1 §七 的 V1–V10 里，**只有 V10 是目的性判据，而它只覆盖农村**（"农村布满足率显著 > 0，
`rural` 育龄压力不再全部 > 阈值"，S1 spec `:352`）。⇒ 模拟里**最响的信号**（城市死亡率 14 倍、
布满足率归 0）**不归任何判据管** ⇒ 它既不会被验收红，也不会被当成回归。

## 五、真正的原因：**同一层设计了三遍，一次都没落地**

这是我在核查中最重要的发现。评审问"为什么数据模型没有成为理想中的样子"——我的答案与它不同：

| 版本 | 它把"转移"设计成什么 | 落地情况 |
|---|---|---|
| **v1**（`POLITICAL_ECONOMY_DESIGN.md` §6.2） | 逐主体 `Account` + 订单簿 + `Transfer` 流水；"交易不创造商品货币" | ★ 该文件 **2026-09-25 有取代声明**：逐主体部分（含 market / ledger 逐主体账户）**已被聚合式 economy 取代** |
| **v2**（`2026-09-25-aggregate-economy-v2-design.md` §五） | **`SurplusClaimSource` 协议**：提索取 → 统一决议 → 落回自己；**"扣不动就记欠（欠税/欠薪/欠租），不凭空造粮"** | **源码 0 实现**（`SurplusClaim` 全仓 grep 0 命中） |
| **v3**（`2026-09-26-population-economy-v3-design.md` §六 V8） | **`ResourceRequest → OwnInventory / Loan / Market / Ration → EconomicTransfer`**；"地租/税/工资/借贷**走同一条转移原语**" | 只落了 **T0 最小形态** = 今天的 `transferIntraHexInputs`（同格、单向、按需、**不含粮**） |
| **S1**（spec §八） | 明确**预留**给 S3（同 Hex 市场），本轮不做 | 阶段 6/7 未写计划 |

★★ **而 v3 §六 已经把评审的两条核心结论写出来了**（逐字）：

> 「最终不该让消费逻辑自己知道"先吃库存、再向地主借、再向富农借"」
> 「`simos-ledger` 的 `Transfer` 形状接近，但**被主体类型堵死**：它的 `from`/`to` 是 `ActorRef`，
> 而 `ActorKind` 只有四档 —— **没有"阶层行"这一档**；而 economy 的 `Debt` 用 `ClassKey`
> ⇒ **两套债务模型并存、主体类型不兼容**。**且 D1 未裁**」

⇒ **结论**：这不是"设计缺失"，是**决策未落**。更准确地说是一条**可复现的推迟链**：
**每次要落地转移层，都要先裁"转移的两端是谁"；而这条裁决每一次都被下一轮的建模变化重新打开**——
v1 时主体是"逐主体账户"、v2 时是"阶层行"、v3 时发现两者不兼容、S1 又把商品搬进了 actor。
**所以每轮都停在"再等等"。**

★ **而 S1 恰好把这条裁决的前提变清楚了**：今天的**产权主体已经是 actor**、
**cohort 只收消费流量**（receipt）。⇒ v3 §六 那条"主体类型不兼容"**已经被 S1 改写成一个新的、更简单的形状**
（转移的两端 = actor；cohort 不再是转移端，它只出现"消费取得"这一步）。**这是现在落地的最大理由。**

## 六、解决方案骨架（分层 + 时序）

> ★ 只给**结构与判据**，不给代码（用户本轮要求）。每阶段的正式计划开工前另写。

### 层 0：**收口身份与观测**（前置，不改变经济行为）

| 动作 | 判据 |
|---|---|
| `CohortKey` 补上缺失的那一维（批次 / 居住类型），`laborOfCohort` 随之分池；行键与 cohort 键的关系写死 | **V9 / I1.2 成立**（同一 cohort 兼两 activity ⇒ 只有一个身份）+ **E28 收口**（并池消失）；I1.1 那条"迁移前后逐值相同"作为行为不变的锚 |
| **补产权读口**：actor / 所有权 的读工具（GUI + MCP）与聚合脚本纳入 actor 账 | 任一次 600 天读数都能同时给出"行侧 + actor 侧"两张图（否则今天每个结论都只有半张图，§二-附 就是后果） |
| **补主体播种**：收租者 / 佃农家户 / 工匠家户的 actor（含 `AssetHolding`） | 地租有落点 ⇒ **阶段 7 的前置阻塞解除**；`ASSET_QUANTITY` 从"构造性死亡"变成"有输入" |
| **把资产纳入收窄范围**：`ClassRow.meansOfProduction`（生产能力）与 `AssetHolding`（所有权）的关系要写死 | I7.1 现在**只覆盖 `goods`/`money`/`debts`**（`breakdown:173`）⇒ 不动它，阶段 7 之后"谁拥有土地"仍是行口径（§四-2） |

### 层 1：**一个转移原语**（= v3 的 V8 薄版本）

- 形状：`source holding → transfer → destination holding`，**双分录 + 守恒校验 + 声明制度原因**；
- ★ **一次到位的要求**：**现有三条搬运路径（结算转出 / 同格取料 / 同格借粮）改为调用它**，
  **不是并存** —— 否则市场接进来会是第四条边（§3.2）；
- 判据：① 三条路径改道后**行为逐值不变**（重构，不是改行为）② **新增不变量：任何库存变动必有对应转移记录**
  （今天借粮那笔"放贷行扣库存但不进它的 `consumed`"是**刻意的不对称**，正是这条不变量要钉的东西）。

### 层 2：**取得与索取权**（`entitlement / payable / receipt`）

- 采纳 v2 §5.2 那条已设计的规则：**"扣不动就记欠"，不静默抹掉**（评审第 7 条要的正是这个）；
- 与层 1 的关系：**欠 = 没有发生的转移 + 一条索取权**（而不是"实付 = 产出"）；
- 判据：制度规定 30% / 实付 17% ⇒ 读数里能**分别报出** 30%（应得）、17%（实付）、13%（欠）。

### 层 3：**钱**（S2）→ **同格市场**（S3）

- 货币工资/地租**结算起来**（今天只定义不结算）；
- 判据：城市缺粮缺口收敛（这就是 `V10` 的城市版，见 D8）。

### 层 4：**信用回归本位**

- 债务只在"有未来收入"时发生；补**偿还 / 到期**；**禁止它承担交换职能**；
- 判据：**把交换通道关掉，债务不应增加**（今天这条一定红：借粮就是交换通道本身）。

### 层 5：**要素与产业链**

- 劳动再配置（至少"闲置劳动可回流农业/迁移"）；铁/工具改成**可再生产**（见 D7）。

## 七、决策点（**需要你裁**）

> 我把**卡住"下一步能不能开工"**的四条放在前面（D1–D4），其余五条可以稍后裁。
> 每条给"争点 / 选项 / 代价 / 我的建议"。

### D1（最要紧）转移原语的两端是谁？

- **A. 只认 actor**：产权主体一律是 actor；cohort 只出现在"消费取得 receipt"这一步，**永远不是转移端**。
- **B. 联合主体 `(ClassKey | ActorRef)`**（= v3 §六 的原推荐，写它的时候商品还住在行里）。
- **C. 只认 cohort/行**：回到"行是产权主体"（推翻 S1）。

**代价**：A 需要**补 actor 播种**（收租者/家户），否则地租无处落；B 让行继续当产权主体，
与 S1 spec 追加-1 直接冲突，且要复活 `ledger.Account`；C 等于回退 S1 阶段 4+5。
**我的建议：A**。理由：S1 已经把产权定为 actor（追加-1），而且它**正好解决**了 v3 §六 留下的那条阻塞
（`ledger.Transfer` 的 `ActorRef` 主体缺"阶层行"这一档 —— 在 A 下这个问题**不存在了**，因为行不再是转移端）。

### D2 `simos-ledger` 退不退？（= v3 的"待裁 3 / D1"，它**直接卡住转移原语的形状**）

- **A. 退役**，把 `Transfer` 的**形状**（不是它的主体类型）搬进 `economy-api`（v3 的原推荐）。
- **B. 复活它**，让 `Account` 成为唯一真源，`GoodsAccount` 退役。
- **C. 不裁**，转移原语另起一套。

**代价**：A 要写一次迁移与一次删除（`LedgerCodec` / `LedgerChangeSet` / 三个测试）；
B 推翻 S1 追加-1，并把 S2 的 `money` / `reserved` 一大坨未裁领域提前拖进来；**C 会产生第四套**。
**我的建议：A**。★ 顺带要一起裁：**一腿一条 vs 腿集**（v3 已指出 `ledger.Transfer` 一腿一条、
多方交易要拆多条，且**守恒校验/幂等键/原子性三项全无**）。
★ 还有一条**同族未裁项**（v2 设计 `:444` 列为待裁 D2/D3/D4）：**市场是不是独立切片** ——
v1 文件把 `market` 的订单簿列为**已被取代**，v2 又把它列为**未裁** ⇒ 这一层的最终归属在文档里**没有收敛**。
⇒ D2 实际上要一次裁**两件**：`ledger` 的去留 + **市场住哪**。

### D3 cohort 能不能持有？（阶段 6/7 的方向）

- **A. 按现计划**：cohort 无库存；`receipt = min(应得, 需求)`；超出留 operator（S1 spec §2.5）。
- **B. cohort 有余额**：推翻 §2.5。
- **C. actor = 家户持有者，cohort = 该家户的人口视图**（一一对应）：消费走 receipt，**积累走 actor**。

**代价**：A 的后果已经在数据里（地主结构性缺布、无人能储蓄）；B 与用户 2026-09-26 的裁定冲突；
C 需要"家户 actor ↔ cohort"的映射与播种（**与 D1-A 是同一件事**）。
**我的建议：C**。理由：它**同时**满足"cohort 不能积累"（S1 裁定保留）与评审第 8/9 条
（地主可以买布、劳动者可以积累），因为**积累发生在 actor 上**，而 actor 是可以被赋予购买行为的。
★ 落点就是阶段 6/7 的计划 —— 所以**D1/D3 应该在写阶段 6 计划之前裁**。
★ 附带必须一起裁的：**"行"在收窄之后还剩什么职能**（人口 / 劳动配额 / 消费需求 / 压力自然是留的；
`meansOfProduction` 与"行即产业"这一层关系必须表态，否则 I7.1 的清单是不完整的）。

### D4 时序：钱先还是货先？

- **A. 先落层 1（统一转移，实物）**，市场/价格后做 —— 城市靠"以布换粮"活下来。
- **B. 先做 S2 货币 + S3 同格市场** —— 城市靠"工资 → 买粮"活下来。
- **C. 层 1 原语先落，货币作为它的第一个 policy 紧随**（不中间插一个会作废的实物市场）。

**代价**：A 里那个"实物市场"很可能在 S2 到来时被作废（价格、货币一进来，以物易物的规则就要重写）；
B 让城市多死几个周期，且转移原语缺席时市场会是"第四条边"。
**我的建议：C**。
★ **一条硬提醒（评审也提到了，但没算到底）**：**只做交换救不了城市** —— t600 城市布满足率 **0.00%**、
库存 **0**（`sim600-curves.md:59`），因为作坊第 2 周期就因缺铁停工（评审第 13 条）。
⇒ 到 t600 城市**已经没有可卖的货**了，交换层再好也换不出粮。**必须先回答"城市有什么可卖"**
（劳动？工资？—— 正是 D7 与层 3）。
★★ 而且这一点**本仓的设计早就写明了**（`POLITICAL_ECONOMY_DESIGN.md:147`）："**自然缺口**不等于**有效买单**…
无钱、无货、无信用的人可有 10 粮自然缺口而只有 0 有效需求。**市场有粮仍可能有人饿。**"
⇒ 若把 D4 选成 A（实物市场优先），**很可能做出一个"有粮但没人买得起"的市场**，
然后仍然要回过头来做工资/劳动 —— 这正是我建议 C 的理由。

### D5 DSL 语义：`basis` 的"池"与"权重"要不要拆开？

- **A. 只改注释/文档**（把 `NET_AFTER_INPUTS` 的真实含义写死）。
- **B. 拆成两个正交字段**：`pool ∈ {GROSS, NET, OPERATOR_SURPLUS, FIXED}` × `weight ∈ {NONE, LABOR, ASSET, EQUAL}`。
  ★ **现有六档 basis 全部可无损映射**（逐档核过 `Basis.java:22-38` 与 `ProductionSettlement` 的公式表）：
  `GROSS_OUTPUT = GROSS+NONE` · `NET_AFTER_INPUTS = NET+NONE` · `OPERATOR_SURPLUS = OPERATOR_SURPLUS+NONE`
  · `LABOR_AMOUNT = NET+LABOR` · `ASSET_QUANTITY = NET+ASSET` · `FIXED_AMOUNT = FIXED`（权重不适用）。
- **C. 再加"共享池"声明**：多条规则声明同一个 `poolId`，池只被请求一次、按权重分。

**代价**：A 不改代码但**错误会复现**（"四条同 basis 的规则 = 四个人共享一份池"这个误读今天就在源码注释里发生过一次）；
B 是破坏性契约变更（`Basis` 是 `economy-api` 的公开契约，要迁移旧档）；
C 最贵，但它能让"给四个人各写一条 `NET_AFTER_INPUTS`"这种**表达错制度的写法变得不可写**。
**我的建议：B（C 留到有第二种"共享池"制度时再上）**。理由：B 让"池"与"权重"各只有一处拼写点，
且**行为逐值可验证不变**（这是一次纯重构）。

### D6 债务的定位

- **A. 保持"同格借粮"作为信用制度**，补上偿还/到期/违约，并让放贷方拿到**债权资产**。
- **B. 降级为最后手段**：交换/配给/工资之后才轮到它，且**禁止它承担交换职能**。
- **C. 先建交换层，再看债务还剩多少，然后按观察重定参数**（参数值留作 GM 可调 —— 信条十二
  "代码不替 GM 做价值判断"，`design-creed.md:124-136`；★ 注意"参数值属判断结果"是对它的**引述口径**，
  不是信条原文）。

**我的建议：B + C**。理由：今天的债务**不是信用**，它是"城市唯一的粮食通道"
（本金 4,557,186 → **106,182,340**、红灯 0 → **614 格**，`sim600-curves.md:34,92`）。
交换层一落地，"为什么必须借"这个问题才会露出真实答案。

### D7 生产资料与劳动再配置（评审第 13 条 + 我增补的 §3.3）

- **A. 加采矿/冶炼/工具产业链**（内容最大）。
- **B. 把"铁"从**一次性投入品**改成**可折旧、可再生产的资产**（工具），去掉外生断点**。
- **C. 加"闲置劳动可回流农业/迁移"的最小兜底**（消掉"城镇批次结构性饿死"）。
- **D. 什么都不做**，如实写进读数边界。

**我的建议：B + C（先）**，A 留到产业链那一阶段。理由：B 与 C 都小、都能立刻从曲线上读出来，
而 A 是内容量最大的一块，在"钱"没到位之前做，很可能要返工。
★ **C 不是新提议**：`POLITICAL_ECONOMY_DESIGN.md:151` 一开始就把"**出售劳动**…或**迁移**"写成缺粮时的正常出路
（"例如库存 300 粮、每日用 3、离收获 120 天…当前也必须出售劳动、购买、借粮、出售/抵押资产或迁移"）。
今天的代码里**这四条一条都没有**（借粮有、其余三条无），而劳动配额只会随死亡缩小
（`scaleLaborOfIndustry:820-828`）。

### D8 城市要不要进判据？

- **A. 加一条目的性判据**（例：S3 之后城市缺粮缺口收敛到 X 以下 / 城乡死亡率倍数 < Y）。
- **B. 不加**，把城市死亡率当作"pre-market 阶段的已知后果"，写进读数边界。

**我的建议：A**。理由：`AGENT.md` §三 的验收原则是"判据在阶段边界由控制方自己跑"，
而**没有判据的东西不会被验收** —— 城市 16.44% 的死亡率今天**不归任何判据管**，
这正是"局部守恒、全局很怪"能长期存在而无人负责的机制性原因。

### D9 `laborOfCohort` 并池 / V9 的时序（与 D1 强耦合）

- **A. 现在做**（并入层 0）：口径会变 ⇒ `LABOR_AMOUNT` 的分子分母跟着变 ⇒ **真档数值会变**。
- **B. 与阶段 6/7 一起做**。
- **C. 继续推迟**（第三次）。

**我的建议：A**。理由：D1 选了 A 之后，"受方是谁"必须无歧义，
否则转移原语的受方还会继承今天这条"受方按劳动批次定池、计权却并池"的不对称（E24 vs E28）。

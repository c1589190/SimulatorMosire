### 4.3 机制（证据链）

1. 全国粮**不缺**：m2@360 粮食供给（卖单）**134.8B** > 周期生理需要 **120.1B**；缺口不是"没粮"。
2. 市场却几乎冻结：粮成交从 2.39B 掉到 **63.0M**；未成交 **卖方侧 `no_budget`** 大量出现
   （布 4,896 次、粮 3,596 次、纤维 828 次，按区计）—— 即"有粮可卖，但没有买得起的买家"。
3. 买家为什么买不起：**城镇现金被抽干**（7.40M → 231k；人均 5.8 → 0.2）。
4. 钱去哪了：**农村**（135.4M → 142.1M）。城市买粮的银单向流入农村；而农村几乎**不回头买布/工具**
   （布成交 224,004，对 32B+ 的供给）⇒ **循环不闭合**。
5. 结论：**M2 的市场机制本身没坏**（上半年把缺口从 725 亿压到 0.6 亿），坏的是**货币回流**——
   没有把银带回城市的通道（工资/地租/对城市商品的需求），城市花光现金后重新陷入"买不起"。

### 4.4 对计划判据的结论

- **M2.2 判据**「作坊**能卖掉布与工具** ⇒ 形成销售收入循环」：**一年尺度未达成**（布成交仅 22 万毫，卖不掉）。
- **M2 退出条件**「两格粮布/纤维循环成立，**不靠财政兜底**」：**上半年成立、一年不成立** ⇒ **M2 不能关账**，
  需一轮针对"货币回流/循环闭合"的修正（修正必须来自经济关系本身；国库/税属已裁的后置国家模块，**不许当兜底**）。
- 与基线的比较（同日 360）：M2 **更好**（缺口 6.19B vs 11.27B；缺口格 202 vs 212；人口 11.54M vs 11.35M），
  但**同一类病**；不同的是：基线看不到病灶（它连"粮能卖出去"都做不到），M2 把病灶暴露成了"货币单向流"。

2. **未做**缺口逐商品/逐区/逐阶层归因（本报告只有城乡二分与三国汇总）。
3. **读数口径提醒**：`MarketReadout` 是**每格携带整区读数**（成员格各自一份）⇒ 跨格求和会**重复计数**；
   本报告全部按 `regionId` 去重（208 区）。以后报表脚本必须照此去重。
4. **运费恒 0**：创世没有 `ORGANIZATION` 承运主体 ⇒ 按设计"没人收就不收"（只记未收量）。运费回流机制**未被检验**。
5. **跨区限制**：M2.3 第一版只考**直接邻接供应区** ⇒ 远区余粮到不了缺口区（纤维 `no_adjacent_supply` 在 180 已可见）。
6. **进程内读数**：`marketReadout.match`（成交/未成交）来自进程内 `MarketReport`，重启/回读旧 revision 时缺失并具名标注；
   本报告的成交数字取自 dump 那一刻的同一进程，可信。
7. **人口/口径**：`cycleNaturalNeedMilli` 用逐日日初人口；dump 的 `population` 是日末口径（丙条）——本报告不把二者并排当同一时点。

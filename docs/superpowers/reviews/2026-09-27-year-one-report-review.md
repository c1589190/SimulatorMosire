## 一、报告里最不合理的一张图：**首都格吃不上饭，而全国在攒粮**

| 读数（tick360，三国） | 值 |
|---|---|
| 全国人口 / 耕地 | 11,349,353 人 / 2,286.4 万亩 |
| 全国本期粮缺口 | 11.27 亿毫 = **112.7 万单位** |
| 粮库存 | 204,931,708 毫 = **204.9 万单位**（逐周期**在涨**：148.7 → 176.9 → 204.9 万） |
| 拐点格 | 德意志 `(-39,-71)`：总人口 **273,770**（城镇 **259,184**），耕地 **3,100 亩** |
| 该格本期粮缺口 | **2,924,107 单位**（= 三国总缺口的 **26%**） |
| 该格生理压力（social 侧） | **平均 2,835‰**（`PopulationDynamics.STRESS_MORTALITY_THRESHOLD = 300`） |

**这一格不是"某个环节没调好"，是结构性错配**：它的人口是德意志全国的 **4.6%**（430 格里的 1 格），
耕地却只有 3,100 亩（与其它格同量级）⇒ 本地粮食产出（满种 3,100 × 67 = 207,700 单位/周期）**不到需求的 1/10**。
它靠的是**本格市场**（同格内有农村四行，可卖余粮）—— 但同格农村的库存只有 178.9 万单位，
而**它一年要吃 290 万单位**：本地根本不够。

★ 更值得警惕的是：**全图粮库存逐周期增长（+28 万单位/周期）**，说明"总产量 ≥ 总需求"（满种毛产 153.2 万单位/周期，
年耗 113.6 万）—— **缺口是分配问题，不是产量问题**。而分配问题的**唯一制度性出口**（跨格贸易/运输）在计划里
被明文列为"下一阶段不做"（`plans/2026-09-27-economic-cycle-implementation-plan.md` §八.2「跨格贸易 / 运输 / 在途（S4）」）。

### 这条暴露的缺陷
**A-1（世界生成假设与实现的缝隙）**：`config/worldgen/v17levant-nations.json:82` 明写
「首都吃 politicalCentralization 的大头 —— **解释首都为何能远超本地农业承载（靠税赋/贸易/国家网络输送）**」，
而这三条通道今天的实现状态是：

| 通道 | 实现状态（回代码核） |
|---|---|
| 税赋 | **零实现**：`FlowRow.taxPaid` 恒 0（政府/税/财政支出在计划 §八.3 明文列为"留给政府轮"）；`sd.CreateNation` 的 `adminBudgetPerTick` 置 0 |
| 贸易 | **只有同格**：`MarketSettlement` 的 `rowsByHex` 按格分组 ⇒ **跨格没有一条腿**；跨格属 S4（未做） |
| 国家网络输送 | **不存在** |
| 城市人口的收入 | 实测 tick360：**全部 3,196 行城镇家户的 `FlowRow.income.grain` 一篇都没有**（逐格校验，0 命中）；上限只有 `handicraft` 的货币工钱（只覆盖城镇四行里的一行、且以**货币**计价） |

⇒ **世界生成器按"有税赋/有贸易"造出了一个 26 万人的首都**，而经济层还不具备喂它的任何一条横向通道。
这不是"曲线不好看"，是**两个阶段的接口没有对齐**——由 `_era`/`_shared` 那类冻结输入的一致性检查兜不住。

## 二、口径与量具（B 类：不改代码也必须改报表）

### B-1 报表把"死亡"当成了饥荒信号，而**饥荒致死是关着的**
- `EconomySettlement.FAMINE_MORTALITY_PER_MILLE = 0`（默认不致命；`ApiViews` 的注释也明说"V4 起默认路径上 `deaths` 恒 0"）。
- ⇒ 报表里 315,275 / 292,959 / 215,753 这些"死亡"**不是经济侧饿死**，是 social 侧
  `PopulationDynamics`（寿命表 × 性别 × **生理压力**）的产物。**报告的小标题写反了归因。**
- ★ 实测的**真实因果链**（这才是经济短缺的致命通道）：302/799 格生理压力 > 0（承载 **51.8%** 人口），
  最坏格 **2,835‰**（= 门槛的 9.4 倍）⇒ `mortalityPerMille = base + (stress−300)×20‰`，压力项在这一格 ≈ **50.7‰/月**
  （基础项约 0.6‰）⇒ **单这一格每周期就多死上万人**。
  同时 `birthsOf` 受压力抑制（`FERTILITY_SUPPRESSION_PER_STRESS`）⇒ 这也解释了出生率在压力下塌到 4.81‰。
- ⇒ 报表必须改述为「**死亡（人口模块：寿命表 + 生理压力）**」并**单独列一行"压力致死死（推算）"**，
  否则读的人会把 27‰ 当成"饿死率"。

### B-2 `consumed` 是**混合桶**，不能用来读"吃掉多少"
- `EconomySettlement` 的类注自己写着：`consumed` = 日耗 + **生产投入（含播种日扣的种子）** + 同格取材的转出。
- 实测（tick360）：**3,931 行**满足 `consumed.grain > 3 × naturalNeeds.grain`（样例：人口 674 的一行 `consumed=6,660,000` vs `needs=56,000`）。
- ⇒ 任何"用 `consumed − naturalNeeds` 反推吃了多少"的写法都会得出荒谬结论（我在评审过程中就先踩了一次）。
  **这是 `AGENT.md` §九.4 那条"口径/窗口"教训的第 6 次同族**（前 5 次都在台账里）。

### B-3 同表混装不可比的窗口
报表把三种窗口并排放：`unmetNeed`/`deaths`/`births` = **本周期累计**（关账日归档、次日清零）、
库存/债务 = **时点快照**、`repaid`/`newBorrowing` = 本周期发生额。★ 更关键的是**一年只取 3 个关账日**
（都是收获后、仓库最满的那一天）⇒ **"青黄不接"的那 60-90 天在整个报表里看不见**（这正是 §九.4 记过的"5 天采样当年度特征"同族）。

### B-4 crisis 阈值太粗，会把"极端但接近满足"的格藏起来
`CrisisMonitor.FOOD_CRISIS_PER_MILLE = 900`（满足率 < 90% 才红）。首都格满足率约 **99.2%**
（吃了 2410 万、缺 292 万）⇒ 它**不是 FOOD 红灯**，却是全图压力最高、缺口最大的那一格。
⇒ 报表应同时给"绝对缺口 Top-N 格"，别只用红灯计数（红灯数 799 → 145 的改善会被误读成"问题解决了"）。

## 三、代码缺陷（A 类）

### A-2 **城市人口没有一条"食物收入"制度**（与 A-1 互为表里，但要单独修）
城镇四行的粮食来源只有：① 同格市场买入（要有钱 + 同格有卖家）；② 借粮（H5 的软上限 = 未来收入 × `LOAN_INCOME_MULTIPLE_PER_MILLE`，
而城镇的"未来收入"只有货币工钱 ⇒ **信用线几乎为 0**）。⇒ 城镇缺口只能靠**本格农村的库存**兜。
一旦某格是"大城市 + 薄农村"（首都格正是），那批人永久处于缺口-压力-死亡螺旋。
★ 这也解释了**城镇人口逐周期下降**（1,306,445 → 1,249,343 → 1,149,113，−12%）。

### A-3 **复利没有出口**：计息并入本金，但没有偿还制度、也没有债权人那一侧
- `chargeInterest`：`principal' = principal + interest`（**复利**）、`BORROW_RATE_PER_MILLE_PER_CYCLE = 20`（2%/周期 ⇒ 显性年化 8%）。
- 债权人**不记**（类注明说"本批不记"）；偿还行为（`Debt.dueCycle`）**没有任何代码读**。
- 实测：本金 **×102**（149,654 → 15,286,474）、应付息 2,934 → **299,733**，而 `repaid`（12,855,961）≠ 计划里的"偿还"。
⇒ 这是一条**只进不出的账**。第 3 个周期 DEBT 红灯 275 格 ⇒ 一年之内就从"没有债务危机"走到"债务是主角"。
★ 结合 A-1：**债务是首都格买粮的唯一通道**（它买了 2410 万、缺 292 万），所以这两个缺陷会互相放大。

### A-4 **"留位商品"与"死商品"**（`AGENT.md` §三 明令禁"看起来在记、其实永远是 0"）
- `wood`：在 `commodityIds` 里（6 种之一），但**全仓没有任何生产者或消费者**（`grep` 生产/消费两侧 0 命中）⇒ 库存与缺口恒 0。
- `iron`：库存三期一字不动（263,410），只在作坊配方里有读者（H5 已把作坊投入改成 `{FIBER, TOOL}`）。
- `tool`：库存三期一字不动（126,822）—— 因为**作坊全线停工**（见 A-5），工具既不生产也不消耗。
⇒ 报表里"商品清单"那一行应当标注**哪几种今天没有任何流动**，否则读者会把"6 种商品"当成活的产业链。

### A-5 **H6-lite 的边界就是"断供即永久停摆"**（设计缺口，已被台账自认）
作坊在 H5 基线里**201/201 格第 2 周期起停工**（本报表 §三），修它的 H6-lite 只在**同格有争用**时才开池；
而它自己如实记的边界是："**只有城市的格**（无农村人口 ⇒ 没有织机 ⇒ 纤维无人争用）里的作坊**照旧停工**——
那一格没有任何一条 relation 把乡下的纤维指给它"。
⇒ 缺的是一条通用制度：**关系断供时的替代来源（市场/跨格）**。今天"谁出料"完全由数据里的 relation 决定，
一条 relation 指错/指空 = 一个产业**结构性死亡**，没有任何回退路径。

## 五、下一阶段的建议优先级（按"一年期报表的痛点"排）

1. **P0 — 先决定"世界生成 vs 经济层"的对齐口径**：要么把城市人口上限压到"本地 + 同格农村可承载"，
   要么**承认首都必须靠外部输入**并把「税赋 → 国家粮库 → 城市配给」做成下一阶段的第一件（它同时给 A-2 兜底）。
   ★ 在它落地之前，任何"600 天/多年曲线"都会被这一格主导（它一个人占 26% 的缺口）。
2. **P0 — 给城市一条食物收入**：最便宜的做法是让 `handicraft` 的工钱**以粮计价的一部分**（或让城镇家户持有一块地）。
3. **P1 — 偿还制度 + 债权人那一侧**（A-3）：现在债务只进不出，且复利 ⇒ 时间越长越不可信。
4. **P1 — 报表口径修正**（B-1~B-4）：死亡归因、`consumed` 拆分（给出"纯日耗"读数）、窗口标注、

5. **P2 — 跨格贸易（S4）**：它是"总产够、地方饿"的**唯一**根治；在它之前，先做 P0-1 的兜底。

## ★★ 追加更正（2026-09-27，用户裁定后复核）—— 三处错 + 一处真缺陷

**用户点名三处，逐项复核，全部成立**：

| # | 本评审原说法 | 复核结果 |
|---|---|---|
| 1 | "地主粮库存占**农村 73%**" | ★ **错**。实测：rural 四阶层分母 **57.64%**（96,937,218/168,185,161）；八阶层分母 57.20% |
| 2 | "复利**没有出口**……无偿还制度" | ★ **表述错**（与本文 §二-4c 的"偿还"自相矛盾）。实测：**本金偿还在跑**（`repayDebts` 债务人→债权人）；**计息只记债务人**（`chargeInterest` 自述"债权人这一侧本批不记"）⇒ 准确说法是"**本金偿还机制在跑；利息既不为债务人形成待偿项（并入本金），也不计入债权人**" |
| 3 | "劳动**不是紧约束**（分配率 86% ⇒ 14% 闲置）" | ★ **推论过头**。那 14% = 行侧毛劳动 − Σ(毛劳动×参与率)，是**按参与率折算后的差额**；而配额预算是按**毛额**发的 ⇒ 它**证明不了**任何格/任何产业不缺劳动（要看劳动能否在相应时间地点实际投入） |

**顺带查出的真缺陷（M-4，用户口径的直接后果）**：
`participationPerMille`（贫农 950‰ / 中农 900‰ / 富农 750‰ / **地主 100‰**）**写进了字段与视图，却不进任何计算** ——
配额预算用 `grossLaborMilli`（`EconomySeeder.java:1083/1132`），真档实测四阶层 `labor/pop` **全部 = 562.8**（完全齐次）。
⇒ "地主只有附带劳动"这件事**在数据里看得见、在结算里不存在**。修复落 `relations-first-architecture.md` 第 2 步。

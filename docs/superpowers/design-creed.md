## 一、次序：先找错，再改错

> 「检查一下当前目录下的项目，新写了一个经济模块，你待会要做的是改bug和细化开发，但是现在，你应该先找错——找你所有认为不符合设计要求、不符合政治经济学设定、不符合代码编写原则的代码设计，允许并建议大量使用子代理以节省上下文。」
> —— 2026-09-25

- **先穷尽找错，再动手改**。找错的判据是**三类**：① 不符合设计要求 ② 不符合政治经济学设定 ③ 不符合代码编写原则。
- **鼓励大量派子代理**，理由是省控制器的上下文（不是省力气）。
- 〔解读〕这条与 [`AGENT.md`](../../AGENT.md) §五.3「已确认的发现，若修复比描述还短，当场修」**有张力**：用户在本轮明确要了"先找错"的次序。⇒ 当场修之前要能回答"这属于他说的'先找错'范围，还是属于允许当场修的那类"；拿不准就问。

## 二、做「数」，不做「判」

> 「可以先不做什么饿死人系统、青黄不接系统，但是产量、饥饿的对应原本状态（用唯物主义说就是量变到质变的临界状态），以直接数值表现出来，我的想法是先让这些现象有产生的数学基础，再去根据产生的现象推判断条件和结果——毕竟还在开发阶段」
> —— 2026-09-25

- **先给出数学基础（量），再去推判断条件与结果（质）**。质变的临界状态要**以直接数值表现出来**。
- 开发阶段的默认取舍：**不预设后果**。
- 〔解读〕判据是"它是**数**还是**判**"：需求、供给、缺口、库存、守恒、计息 → **数**，现在做；饿死、阶层流动、产业转换、有效需求的支付力门槛 → **判**，留位不做。
- 〔解读〕边界由**时序**与**规则**承担的地方不算"判"：播种日先扣种子是**农时**（时序），放贷方留口粮是**制度规则**——都不是预设后果。**这条边界是我划的，见 §十二 争议点 1。**

> 「你说的这些判断结果我觉得没啥问题，就这样即可现阶段」
> —— 2026-09-25（对上述边界表的确认）

## 三、Rule 的本质 = 「谁定的」+「管到哪」

> 「我想详细讨论一下这个问题。这个Rule本质是什么？国家机器能决定的社会运作规则，那就存在国家模块这一层，基础的社会经济规则，那就存在社会经济这一栏，原则上我认为应当分模块和作用域……但是实际上呢？」
> —— 2026-09-25

- 参数（Rule）按**决定者**归属模块：**国家机器能决定的 → 国家模块**；**基础的社会经济规则 → 社会经济模块**。
- 原则上**分模块 + 分作用域**。
- 〔解读〕决定者是谁 → 决定**模块**；决定者管到哪 → 决定**作用域**。二者是同一维度的两面，不是两个独立维度叉乘。
- 〔解读〕按决定者分，落成**三层**：**物理层**（无主体：亩产、口粮）/ **制度层**（生产关系双方：分配权重、租佃）/ **政治层**（国家机器：税率、禁令）。
- 〔解读〕"层"是**约束叠加**，不是存放位置——反例：地租 = `min(合同地租, 政府上限)`，这个数不存在于任何单独一层。
- 〔解读〕**"逐层"在两层含义不同**：政治层 = 权力层级（国家→下级）；物理层 = 空间层级（全球→格）。
  ⇒ **"某国覆盖自己的亩产"是语义错误**；技术进步的**正确建模是生产资料存量变化**。

## 四、参数的最小作用域由性质决定

> 「C，最好不要做什么全局税收调整，最小调整单位就是国家——我操了，收税的不就是单个国家吗？怎么着，全世界一起收税，大肥鱼你想统治世界了？」
> —— 2026-09-25

- **不做全局税收调控**；**税收的最小调整单位是国家**。
- 〔解读〕推广成一条原则：**每个参数自带"最小作用域"，由参数性质决定下界**（税率下界=国家、亩产/口粮下界=全局），**API 层据此自动拒绝在更粗的层写它**，不靠人自觉。

## 五、改动即分岔节点

> 「A，改参数的所处tick就地算一个节点，方便分岔管理」
> —— 2026-09-25（对"立即生效 / 下周期生效 / 可回溯"三选一的答复）

- **生效语义 = 立即生效、只管未来**（已结算过的日子一个数都不改）。
- **改参数的那一 tick 就地算一个节点**，目的是**方便分岔管理**。
- 〔解读〕硬约束：参数**不能是配置文件或全局变量**，必须是被 revision 带着走的**切片状态**——否则两条分支共用一份参数，分岔管理失效。
- 〔解读〕v1 **不做回溯重算**（不存每次结算的参数快照）。

## 六、接口要全面，不给单个模块开后门

> 「AAA，然后是后续为各个模块流的空步——你就不能费点事，写个全面的代码接口吗？不单单是标准的政府，可能军队也会临时从当地调粮食呢？怎么办？」
> —— 2026-09-25

- 拒绝"为某一个模块预留专用空步"的做法——**那不是接口，是后门**。
- 要写**全面的代码接口**：不止政府，军队也可能临时从当地调粮。
- 〔解读〕落成**双向**协议：`claimsIn()`（提索取）+ `settle()`（按实际满足量落回**自己的切片**）。单向不够——东西得有地方落，而经济切片不能写别人的切片（铁律 3）。
- 〔解读〕这与项目既有的 `Facet` / `TimeParticipant` 同族，是第三次用该模式。

## 七、先复用已有能力，别另造

> 「存在军队啊，Unit系统不是早就允许为单个单位添加装备了？」
> —— 2026-09-25

- 提方案前**先查已有模块有没有现成机制**（例：`Unit.equipment` 早就能逐单位挂装备，军粮直接用它，不必新主体/新切片）。
- 〔解读〕同族事实（本轮评审查到的）：`TerrainType.food`（地形产能，map 已有 6 档）、`Utils` 的 `Facet` / `TimeParticipant` / `WorldTimeProposal` 协议族。**先查再设计。**

## 八、同一物不因职能分裂成两个

> 「种子粮也应该是商品，我甚至建议现在不要把吃的粮食和种子粮分开算——正好测试一下生产资料/生活资料区分判断的健壮性」
> —— 2026-09-25

- 种子粮**是商品**，且**不与口粮分成两个商品**算。
- **故意让它去压测**"生产资料 / 生活资料"的区分判断够不够健壮。
- 〔解读〕理论依据：生产资料/生活资料的区分是**同一物在循环里承担的职能**，不是物的物理属性。做成两个商品 id = 把职能差别固化成物的差别，并造出"剩的种子能不能吃"这类现实里不存在的假问题。
- 〔解读〕代价是必须有**播种时序**（周期第 1 天先扣种子），否则每天先吃饭会把种子吃光 ⇒ 永远播不了种。**种子的优先性来自时点，不来自"种子神圣不可吃"的规定。**

## 九、先跑通主干，支线暂缓

> 「耕牛系统觉得复杂现阶段就别做」
> 「这个可以暂缓测试流程，先把经济模拟跑通」
> —— 2026-09-25

- **复杂度高的支线，现阶段不做**（例：耕牛）。
- **先把主干（经济模拟）跑通**，集成与测试流程可以让路。

## 十、债记下来，不顺手扩大战场

> 「关于int-long问题，这就是当时写unit的Agent的问题了，记下来就行」
> —— 2026-09-25

- 发现别处（别的轮次）留下的债：**记下来，不在当前战场顺手修**。
- 〔解读〕与 [`AGENT.md`](../../AGENT.md) §五.3「修复比描述还短就当场修」的分界：**跨模块、动核心类型的债记；本模块一行能修的不留。**

## 十一、表达：逐条说、英文标识符配中文语义（**只适用于对话**）

> 「问题真的太多了，你一个一个说，每一个英文变量在括号里上中文有语义解释，说的通俗易懂一些」
> —— 2026-09-25

- **问题多时一条一条说**，不要糊成一大段。
- **每个英文标识符后面在括号里给中文语义解释**（例：`outputPerUnit`（每亩基准产出））。
- 要**通俗易懂**。

> ★ **适用范围（2026-09-25 用户裁定）**：「第一条肯定不用啊，那是因为我是个老傻子，看不懂这些变量名」
> ⇒ **本条只管对话**（对用户解释时）。**书面 spec / plan 不要求**逐标识符加括号中文——写这些文件时按项目既有体例（中文行文 + 必要的解释）即可。
> 〔解读〕记这条的**理由**很重要：它是一条**沟通适配**要求（用户读变量名吃力），不是一条文档规范。日后有人拿它去要求 spec 逐行加注，是把它用错了地方。

## 十二、代码不替 GM 做价值判断；项目代码应当是自由的

> 「我认为全都应该算GM可以改的行为预设——GM是不是老傻子是GM的事，项目代码应当是自由的」
> —— 2026-09-25

- **凡是"行为"就都是 GM 可以改的预设**。"这个行为合不合理"不是代码该管的事。
- **代码不该写死任何行为**——该做的是**把旋钮给出去**。
- 〔解读〕这条**修正了信条二的边界**：「不做判」= **不预设判断的结论值**，**不是**「不实现判断的机制」。
  ⇒ 机制要有、参数位要有、GM 可调要有；**默认值可以保守（甚至关闭）**，但**不写死**。
- 〔解读〕落到设计：像「放贷方要不要留口粮」「播种该不该先于吃饭扣种」这类，原先是"我替你决定算不算判"，
  现在一律**做成参数**（默认值给保守的），而不是在代码里选一个"聪明的"行为钉死。
- 〔解读〕这与信条二并读的正确姿势：**先做数学基础（数）**，同时**把行为留成旋钮（判）**，
  而**"现象对应的质变临界值"由观察者事后定**——不是由写代码的人替 GM 定。

## 十三、用这份信条核对过什么

### 2026-09-25 核对 `2026-09-25-aggregate-economy-v2-design.md`

**符合的**：§二（做数不做判）、§三（三路瓶颈 = 先有数学基础）、§4.1/4.3（三层 + 最小作用域）、§4.4（改参 tick 即 revision）、
§五（双向协议，非政府后门）、§3.1（读 `TerrainType.food` 而非另造）、§3.2（一个商品 + 播种时序）、§十.2（`equipment` int 债只记不修）。

**核对出的问题 —— 已当场修（3 条）**：

1. **§五 的协议与既有 `simos-util/spi` 协议族的形状不一致** —— 违反信条七（先复用已有能力）。三处都改了：
   - 既有的 per-module 变更是 **`Map<String, ChangeSet>`**（`WorldTimeProposal.java` 第 2 个组件），原稿自造了个 `ModuleChange` ⇒ 已改为复用；
   - `WorldTimeProposal` 构造期**明令"空提案是装配错误，无事的参与者要交不变变更集"**，原稿写成 `Optional.empty()` ⇒ 已改；
   - 既有 `TimeParticipant` 要声明 **`reads` / `writes`**（canonical 地址，供冲突检测），原稿缺 ⇒ 已补。
2. **`Claim` 撞名** —— `simos-ledger/model/Claim.java`（债权）已存在。协议已改名 `SurplusClaim`（剩余索取）/ `SurplusClaimSource`。
3. **物理层参数没有落脚切片** —— 违反信条三与铁律 3 的落地要求。已补 §4.1.1：地形产能归 `map`（原地不动），其余住 `economy` 的 `worldParams`（世界参数）子表，并要求它与"主体的数据"在语义上分开。**待你确认这个落法。**

**核对出的问题 —— 待裁 3 条 → 用户 2026-09-25 已全部裁定**：

4. **spec 是否也要逐标识符中文标注** ⇒ **不用**（信条十一只管对话，见 §十一）。本条**不是 spec 缺陷，是核对误报**。
5. **V1~V9 的顺序与"参数 API 首先"的张力** ⇒ 用户选 **甲**：V1 常量上移 → V2 产能 → V3 播种 → V4 缺口 → V5 流水 → V6 债务 → **然后** V7 参数目录 → V8 索取源。即**先让经济跑对，参数与协议随后**。
6. **§二 的边界解释权** ⇒ 用户裁定（信条十二）：**全都算 GM 可以改的行为预设**。
   ⇒ 原先把「播种先扣种子」「放贷留口粮」当作"数学基础"就地实现的口径**不成立**：它们要**做成参数**（默认值可保守），不该由代码替 GM 选一个行为钉死。
   ⇒ §4.7 的两类参数（覆盖式 / 实例式）用户未反对，**保留**。

**这条裁定连带影响的既有设计**（已在 v2 spec 内改）：
- `applyFamine`（饿死结算）+ `FAMINE_MORTALITY_PER_MILLE`（致死率）：原计划**删除** ⇒ 按信条十二改为**机制保留、默认致死率 0‰（不生效）、GM 可调**。
  〔解读〕这与信条二「可以先不做什么饿死人系统」不矛盾："先不做" = **默认不生效**；信条十二要求的是**旋钮要在**。
- 播种时序（`plantingDrawsBeforeConsumption`）、放贷方留口粮（`lenderSubsistenceReservePerMille`）⇒ 各自参数化，默认值待定。

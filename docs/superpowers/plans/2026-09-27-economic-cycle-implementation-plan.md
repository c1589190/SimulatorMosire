## 一、目标与范围（用户 2026-09-27：「把目前所有已规划内容都列入实现目标」）

把经济系统从**今天的"单轮实物流转"** 改造成**目标循环**：

```
今天： 人口 → 劳动 → 产业 → 分配 →【行（两本账、一本没人读）】→ 消费 → 人口
                                    └ 唯一横向通道 = 借粮（要还、无偿还）

目标： 人口 → 劳动 → 产业 → 分配 → 家户（一本账）→ 市场 → 消费 → 人口
                                    └ 信用（最后手段，有偿还）
```

## 三、★★ 关键裁定（**必须在写代码前拍死**，附"错了的代价"）

### K1 家户的账住哪 —— 会话工作副本，不是第二本持久账

**问题**：D3-C 说"家户 actor 持有"，但**铁律 3** 说"economy 切片不认识 actor"，
而**消费与投入发生在 economy 的日循环里**（`settleHexes` 每天要读库存）。

**裁定**：**持久真源 = actor 切片的 `GoodsAccount`（键 `(actor, location)`）；
economy 的 `EconomyDayStepper` 会话对象持有一份"家户账工作副本"**，
由 app 协调器在推进开始时从 actor 侧**载入**、逐日就地更新、`finish()` 交出、协调器**逐日落回 actor**。

- ★ **它不是第二本账**：**不进 `EconomyData`、不进变更集、不跨 revision 存活** ——
  与 `EconomyDayStepper` 今天已经持有的 `flows` 累加器**完全同形**（有先例，不是新形态）。
- ★ 协调器（`PopulationEconomyTimeParticipant`）本来就是"唯一同时看得见两片"的地方，职责不变。

**错了的代价**：若改成"economy 里持久存一份家户库存" ⇒ **回到两本账**，I7.1 与"过渡项消失"两条判据
**结构性开不了账**，而且两本账会漂。

### K2 行键 = 家户键（`ClassRow` 只留人口/劳动/需求/压力）

**裁定**：`ClassRow` 的键从 `ClassKey = (industry, 阶层)` 改成 **`CohortKey = (格, 居住类型, 阶层)`**
（= 家户的身份键），并**移出 `goods` / `money` / `debts` / `meansOfProduction`**。
⇒ V9/I1.2 达成、E28 消失、E24 的"受方产业集"过滤消失（受方就是家户，不再有歧义）。

**错了的代价**：低。这是**净简化**（今天三处绕行逻辑 `receiverIndustriesOf` /
`classRowsOfCohort` / `laborOfCohort` 的并池**全部删除**）。

### K3 产能从行搬到产业（代价要认）

**裁定**：`ClassRow.meansOfProduction`（亩/织机/作坊）删除，**产能搬到 `Industry`**
（该格的产能总量，作为产业的技术属性）。
⇒ 与"产业只回答投入多少、产出多少"一致，且补上 I7.1 的漏项。

★ **代价（如实记）**：今天 `scaleOf` 用 **Σ各行的产能** ⇒ 隐含"贫农缸空 ⇒ 它的地荒着"的阶级差异。
搬到产业之后这条**不再由产能表达**，改由 **C3 的"投入由谁出"栏**表达
（佃农家户出不起种子 ⇒ 该格规模缩小）。**这会在真档数值上改变分配**，属预期行为变化。

### K4 转移原语只认 `ActorRef`（无联合类型）

**裁定**：`Transfer(from: ActorRef, to: ActorRef, goods: Map<CommodityId,Long>, money: Map<CurrencyId,Long>, reason, settles?)`
住 **`simos-economy-api`**（它已依赖 `actor-api`，`Industry.operator` 就是 `ActorRef` ⇒ **无循环依赖**）。

⇒ D1-A 的红利在这里兑现：**不需要 `(ClassKey | ActorRef)` 联合类型**（v3 §六 当初就是被这个堵死的）。

### K5 货币与市场**必须同批**（修正 D4-C 的"紧随"为"同批"）

**理由**：没有货币，市场池的"有效需求"恒为 0 ⇒ 市场是死的（本仓设计原话："市场有粮仍可能有人饿"）。
⇒ `FIXED_MONEY_*` 真的结算 + 市场池**同批**落地，否则中间态没有意义。

### K6 工具的配方（去掉外生断点）

**裁定**：作坊（`handicraft`）的 `inputPerUnit` 由 `{FIBER, IRON}` 改为 **`{FIBER, TOOL}`**，
产出保留 `{CLOTH, TOOL}` 并**调参数使 TOOL 净产出 ≥ 0** ⇒ 工具存量**可再生**，外生断点消失。
`IRON` 商品**从词表与播种中移除**（保留会变成"看起来在记、其实没人读"的死字段——
本仓明文反对）；采矿/冶炼产业链留到以后那轮再加回（已裁 A 暂缓）。

### K7 既有用例变红 ⇒ 按新口径**重算**，不许删/放宽断言

照 S1 先例（`AGENT.md` §9.3）：先判"护栏错"还是"夹具/口径错"，多数是后者；**修夹具或重算期望值**，
并把"为什么这个夹具必须长这样"写进注释。

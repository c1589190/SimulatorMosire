## 3. B2：路径效应修复（**约束设计书**）

### 3.1 问题现场（实测）

- 同码同世界：1 段（0→360）vs 3 段（0→120→240→360）推进到 tick 360 的状态 dump **差 18,538 叶**；
  1 段 vs 逐 tick 差 **25,673 叶**；3 段连跑两次 dump **逐字节相同** ⇒ **路径效应，非随机**。
- 第一次分叉：1 段 vs 3 段在 **day 150** 的 `LIQUIDATION_PLAN`；1 段 vs 逐 tick 在 **day 60**；
  **分叉 tick 随分段位置平移**。差异叶子 = `classStanding.consecutiveDebtStressCycles`（阶层真下滑）。
- 根因（已修一半，提交 `de16fe13`）：`EconomyLiquidationSettlement` 的"连续压力周期"计数器拿
  `context.base()`（= **本次 advance 的 `range.from` 快照**）当增量基准 ⇒ 把"关账周期数"偷换成"调用次数"；
  单段推进下阈值 2 不可达 ⇒ E5b 支路**永不开火**。
- **剩余源头**（本批要修）：迁移/排序路径整条读段首 `base`
  （`ModeMigrationPolicy.plan(base,…)` ← `EconomySettlement:3417-3433`，再传 `prospect` /
  `hasMerchantCapacityAt` / `PrimaryModeRanking` / `base.industries()`）；另有
  `ExpectedProfitBook:974`、`MerchantCapacityPool:566/584/634` 等"混合日视图"风险点。

### 3.2 冻结口径：**当日视图（per-day view）**

1. 逐日循环的**每一天开始时**，派生一份**当日视图**：它是**当刻工作状态的只读门面**（引用/窄读口），
   **不是拷贝、不是快照、不落盘**；`advance` 段首的 `base` **只允许**用于段级语义（审计/差分/回放起点），
   **禁止**逐日读者用它。
2. 所有逐日读者（迁移/择业/清算/前瞻/运力/市场装配/日志）改从**当日视图**取"当刻状态"。
3. 仍**允许**读 `base` 的地方必须**在代码注释里写明理由**（例如"这就是段起点语义"），并在账本列出清单。
4. 语义判据：任何"**累计计数**"（连续 N 周期、累计 M 次）与"**当刻位置/归属**"必须只依赖世界历史，
   不得依赖"这次调用从哪天开始"。

### 3.3 契约与验收判据

| # | 判据 |
|---|---|
| P-1 | `0→60` 一次 vs `0→30→60` 两次 vs `60 × 1 天`：tick-60 dump **md5 逐字节相同** |
| P-2 | `0→360` 一次 / 3 段 / 12 段 / 逐 tick：四份 dump **md5 相同** |
| P-3 | 单段长推进下出现 `consecutiveDebtStressCycles ≥ 2` 的真实样本（今天恒 ≤1） |
| P-4 | **变异自证**：把任一"当日视图"改回段首 `base` ⇒ 判据 P-1/P-2 当场红 |
| P-5 | 现有门禁 `clean verify` 全绿（3416 条基线不回退） |

### 3.4 ★ 性能红线（用户原话："不要出现就算批量推进也算一天存一天的问题"）

1. **当日视图是内存里的只读门面**：零拷贝、零序列化、零 ChangeSet、零落盘、零 Revision；
   它的构造成本必须与"当刻状态规模"无关或极低（引用级）。
2. **一次 `advance` 仍只产生它原本该有的落盘/Revision**（今天就是段级一次；**不得**变成逐日一次）。
3. **验收**：① 记录同世界 `0→360` 单段推进的**墙钟耗时与 Revision 数**，与改前基线对比——
   Revision 数**必须不变**、耗时**不得显著劣化**（给出数字，劣化 >10% 必须解释或回退实现）；
   ② `git grep` 证明"当日视图"路径不出现 `save/checkpoint/persist/codec/changeSet` 一族调用。
4. 若某处为了正确性**必须**逐日落盘 ⇒ **停手上报**（那是架构级冲突，不是本批能顺手决定的）。

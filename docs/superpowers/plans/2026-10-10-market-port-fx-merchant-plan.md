## 1. 全链数据流（一段话一层职责）

```
① 供给   生产 → 卖单（供给层；本区自产的货不受口岸影响）
② 报价   价格表逐格、以本格计价币计；"没定价的商品不交易"（现规则）
③ 口岸闸 跨区候选按两侧开放度节流：可通过 = transit × E_源 × E_目的 ÷ 1e6（§12）
         被拦下的不进候选集；家户与商户**都**选不上（§10/§11）
④ 过境税 出口税（源区政府）+ 进口税（目的区政府）；货值计税、运费不计（§13）
⑤ 商户   决策步看**节流后**的候选 → 承运承诺表（不许超发）→ 撮合（A1 资产大者优先 / A2 无承诺倒掉）（商户 §10.2/§10.3）
⑥ 政府   采购优先级置顶（最先卖/最先买），消耗行政力池，见底硬停（§16.3/§17）
⑦ 结算   货款（买方币）+ 运费（承运方）+ 三层税（进两侧国库户）——全部走唯一写口
⑧ 汇率   家户持币 → 按**自己的生活消费品需求**算购买力 → 自然议价挂单（弱→强）→ 部分成交、下一轮继续（§19/§20）
⑨ 读口   币种列（P-T4）：成交报告/世界成交额/单位收入都必须带币种，禁跨币种求和
```

## 2. 冻结契约

### 2.1 市场层（订单与币种）

| 项 | 冻结口径 |
|---|---|
| **订单可选币** | 买方可指定支付币、卖方可指定收款币（**前提**：币种过滤已生效）。候选成立条件：`买方支付币 ∈ 卖方接受的币集合 ∩ 买方持有（可花）币集合`；空集 ⇒ 候选不成立（**具名归因**，不静默丢） |
| **价格尺度** | `Market.numeraire` **不动**（一格一张价表、一个尺度）；跨币种金额一律经**同一份** `CurrencyValuation` 折算（同一 tick 只算一份，禁两套估值漂开） |
| **可负担量/预算** | 按**买方支付币**折算后判（不得再把本格币的可花额当买方币） |
| **匹配期假设** | `matchRoute` 里"同一路线卖方同币"的假设**必须放宽**（否则混合币组的单价无意义） |
| **订单不落盘** | `PlannedOrders` 仍是逐轮瞬态（不进状态、不进变更集）⇒ 本项**不触碰铁律 5** |

### 2.2 口岸层（政策、闸、税、优先级）

| 项 | 冻结口径 |
|---|---|
| **政策形状** | `GovPortPolicy` 每类**四个数**：入口限制‰ / 出口限制‰ / 进口税 / 出口税；税**从量与从价都支持**（每条规则各自指定；缺省 0） |
| **闸（两侧相乘）** | `可通过 = ⌊transit × E_源 × E_目的 ÷ 1e6⌋`；**被拦下 = transit − 可通过**，**不进候选集**；`E` 用**区级**（按暴露边加权平均，§4.3 不变） |
| **无政府一侧** | 开放度 = 1000（没有口岸可管）；该侧**无税** |
| **三层税** | 出口税（源区政府）+ 进口税（目的区政府）+ 区内市场税（市场层，降级后的 `MarketRegulation`）；**每层只收一次**；读口逐项列出（含币种） |
| **计税基** | **只对货值**；运费不计税 |
| **税入国库** | 进**对应政府的国库户**（`hh-gov-<govUnitId>`，权威来自 `Government.treasury()`）；买方多付、卖方仍收原价 ⇒ **货币守恒**（转移，不销毁） |
| **采购优先级** | 政府要求管控 ⇒ 可在**行政力池**余量内把自己的挂单**置顶**（最先卖、最先买）；每超越一户消耗一份；**见底硬停**（fail-closed，不许先超后欠）；**只改顺序、不改价格**；政府可选**扩编官僚队伍**抬高池子 |
| **`MarketRegulation` 降级** | **删** `referencePrices`/`open`/`rules`/`quotaPerWindow` 与**限价机制**；只剩 `tariffPerUnit`（收税）+ 采购优先级参数 |
| **删死代码** | `PortRegimeAggregation.split` / `SmugglingSplit` / `SEIZURE_BASELINE_MILLI`（"走私"这一档已被取消） |

### 2.3 汇率层（民间簿 + 自动换汇）

| 项 | 冻结口径 |
|---|---|
| **民间 FX 簿** | 家户（与商号——见 Q-5）可**自己挂** FX 单，**不再依赖政府窗口报价**；政府窗口仍是"强力信用主体"之一，不是唯一报价源 |
| **触发** | 每轮**先挂生产需求**，之后：看手里有哪几种币 → 按**购买力**比较 → 自动挂单把**弱**的换**强**的 |
| **购买力口径** | 对每种持有币，算"**付清自己的生活消费品需求**要付多少"（需求篮子 = Social 的 `naturalNeeds`，**不得**另造第二本权威）；**付得最少的那种 = 购买力最强** |
| **价格来源** | 该币**法定区**的价格表；**缺价 ⇒ 该币算不出购买力 ⇒ 不换**（不猜） |
| **换汇顺序** | 最弱先换；同强度按**币种 id 升序**（I7） |
| **换多少** | **挂单全部**（不扣生活/生产储备）、**能换多少换多少** |
| **限价** | 按 F-1 的**价格**口径给（不用家户估值表）；无价可比 ⇒ 不挂 |
| **匹配** | **市场自然议价**（价格优先、同价按既有 canonical 序）——**不另设特权队列** |
| **循环** | 未成交部分**下一轮继续挂**（允许部分成交） |
| **时点** | FX 轮在商品撮合与信用**之后**（现状不变）；`信用与 FX 是否合并成一本簿` **未决**（Q-6） |

### 2.4 商户层（M1–M5）

| 子批 | 冻结口径 |
|---|---|
| **M1 利润** | `利润 = 运费收入 + 差价收入 − 劳动机会成本 − 本钱占用 − 损耗 − **出口税 − 进口税 − 区内税**`（★ 税是**真成本**；被撤掉的"走私成本楔子"**不得**加回来） |
| **M1 落点**（★ 只读调查结论） | **钱货一律落参与家户的账**；**商号行（`MerchantFirm`）不持账**——`ActorKind` 明写"**只有 HOUSEHOLD 允许持有账户**"（`ActorKind:17-21, :30-37`），`holdings` 与 `GoodsAccount` 已退役 ⇒ **不新增组织账户、不触碰铁律 5**。"差价"由**本金主家户/参与家户**的买卖实现，商号提供**运力 + 承运承诺** |
| **M0 商号 = 家户**（★ 用户 2026-10-10 追加裁定） | 商号的本质 = **提供运力的家户**（**不新增组织账户、也不新增"商号行"**）；**"选择跑商"本身就是提供运力**；**逐 hex 汇总**该格跑商家户的**每轮算出**的运力 ⇒ 该格**跨格商品硬上限** |
| **M0c 商号行退役**（★ 追加裁定 4） | **`EconomyData.merchantFirms`（第 30 个持久组件）退役**：运力是**派生量**（劳动 + 工具，生产环节统一兑现、收益自动算）；`tier`/半径降为派生读数、`last*` 降为每轮读数（进报告/日志）。旧档该键 ⇒ **忽略 + 具名 INFO**（不迁移） |
| **M0b 跑商门槛 = 工具**（★ 追加裁定 2） | **单次跑商消耗大量 `tool`**（准入门槛）；**运力不可储存、不可转卖**，**只能计算后在「生产环节」统一兑现、自动算收益**；运力**每轮按投入算**（劳动 + 工具），**不累积** ⇒ `MerchantFirm.capacityPerRound` 的 ±5 自增长**作废** |
| **M0d 运力可计算可购买**（★ 追加裁定 5） | 家户**每需求一个商品**产生一份**运力需求** → **汇总**总量 → 向**市场上最低价的运力提供商买运力**（提供者**自报价**）；"**运力过来同样需要运力**"⇒ **深度 1 + 固定附加费**（不递归展开）；购买语义 = **满足全部需求 + 没钱全算债务**（与既有 D-031"借款人无上限、上限=放贷人可借池"同向；★ 池空时"全部"是否成立取决于 K-3：维持 D-031 还是允许**卖家赊购**） |
| **M1 利润**（★ 追加裁定 2 改写） | **纯商号**：`利润 = 差价收入 − 劳动力成本 − 本钱占用 − 损耗 − 出口税 − 进口税 − 区内税`（**没有"运费收入"腿**）；**顺便跑商**：运费**独立计算**并由**货主付给跑商家户**；**只有纯商号能免运费拿货** |
| **M2 分配（取代六步决策步）** | 分配顺序 = **运力提供方的市场议价权**（不是货主挑商号、不是先到先得）；**超出的部分不计入本 hex 的家户商品价格表**（两侧都剔） |
| **M3 结算** | **纯商号自运免运费**（成本直接按劳动力计）；**顺便跑商**运费独立计算（货主 → 跑商家户）；运输靠**在生产环节支付劳动力**兑现；不变量退化为"**分配总量 ≤ 运力总量**" |
| **M4 运力/半径** | 运力**= 劳动**（去外生化）；`serviceRadiusHex` **由规模派生**（`tier` 只作读数） |
| **M5 家户进出（★ 追加裁定 3 改写）** | **不新增状态**：主业 = 既有 `currentPositionId`、副业 = `participatingPositionIds`；**生产方式排序表**（输入 = **市场议价权 + 库存**）的**第 1 项即主业**；**第一项是跑商 ⇒ 主业为商户**；副业赚钱 ⇒ 走既有 A 规则**加速流向** ⇒ 主业随之改变。★ 仍需补的一半缺口：加入 merchant 位置**不建商号行** ⇒ 有主业无运力 |
| **与口岸的关系** | 商户**也**不能选被管住的货（节流在候选生成阶段就完成）；跨区差价必须扣**两侧税**（M1） |

### 2.5 读口与会计（P-T4）

| 项 | 冻结口径 |
|---|---|
| **成交报告** | 每条成交必须带**币种列**（单价币、实付币、各层税的币与额） |
| **禁跨币种求和** | 世界成交额 / 格成交额 / 单位收入等**一律按币分列**；不得把不同币的金额直接相加 |
| **持久账** | `OperatorCondition.cycleRevenueMilli` 一类的**落盘字段**必须按币分列（或具名排除外币，照 `EnterpriseProfitBook` 的先例） |
| **税读数** | 能回答"这笔货被抽了哪些税、各多少、进哪个国库、什么币" |

### 2.6 一 tick 内的固定次序（**冻结**）

```
1. app：口岸聚合（政策 × 政府效率）→ 逐区逐类 E + 税 + 优先级参数（逐轮瞬态注入 economy）
2. 订单生成：生产投入/生活需求/政府授权单（**生产需求先挂**）
3. 跨区候选装配 → **节流**（E_源 × E_目的）
4. **商户决策步** → 承运承诺表（不许超发）
5. **政府采购优先级**置顶（消耗行政力池；见底硬停；只改顺序不改价格）
6. 撮合（区内 → 跨区）
7. 结算：货款（买方币）+ 运费 + 出口税/进口税/区内税（进两侧国库户）
8. 信用轮（现状 `creditRound`）
9. **FX 轮**：民间簿 + 家户自动换汇（弱→强；部分成交下一轮继续）
10. 未成交归因（含"被口岸拦下""无承运商""币种不接受"等具名原因）
11. 读口/日志：全部带币种（P-T4）
```

★ 排序纪律：第 3–6 步的每一个排序都必须是**内容的纯函数**（价格 → canonical 序 → 币种 id），
禁止用 `Map.copyOf`/`Set.copyOf` 迭代序或任何 per-JVM 盐（I7）。

## 3. 不变量（本链新增，与既有不变量并列）

| # | 不变量 |
|---|---|
| I-C1 | **货币守恒**：货款 + 运费 + 三层税（买方多付部分）= 买方总支出；税进国库、运费进承运方、货款进卖方；FX 两腿等值 |
| I-C2 | **未设限制/未设税 ⇒ 逐值不变**（缺省 0；旧世界 md5 级对照） |
| I-C3 | **禁双重计税**：同一笔成交的三层税各自只算一次；读口逐项列出 |
| I-C4 | **承诺不许超发**：`Σ 承诺运力 ≤ 运力上限`（A3） |
| I-C5 | **确定性**：全部排序键是内容的纯函数（含币种、利润、承诺、换汇顺序） |
| I-C6 | **需求权威在 Social**：生活消费品需求一律读 `naturalNeeds`，economy 不造第二本 |
| I-C7 | **不新增政策层**：口岸/税/优先级都是"法律规定层 + 市场行为层"，政府的经济动作仍是**挂单** |
| I-C8 | **权限单调性**：GM 工具不得因本链新增而放宽（税率/限制的设置面仍受既有授权约束） |
| I-C9 | **铁律 5**：新增**持久状态**（若有）必须走 Codec + ChangeSet + 往返不变式；本计划的"订单带币/FX 民间簿"路线**不需要**新增持久状态 |
| I-C10 | **读口不混币**：任何金额读数必须带币种（P-T4） |

## 5. 验收判据

### 5.1 正向

| # | 判据 |
|---|---|
| T1 | **两侧闸**：一侧设限、另一侧不设 ⇒ 可通过量按 `E_源 × E_目的` 下降（贴前后数值）；两侧都不设 ⇒ 与改前逐值相同 |
| T2 | **税真收**：设出口税 ⇒ 国库户余额增量**逐值等于** `Σ 成交毛量 × 税率`；目的区国库另收进口税 |
| T3 | **三层各一次**：读口能逐项列出三层（出口/进口/区内）各自的额与币种，且总额 = 买方多付部分 |
| T4 | **换汇循环**：某户持有弱币 ⇒ 下一轮出现它的 FX 挂单；部分成交后**下一轮继续**；换完后不再挂 |
| T5 | **购买力口径**：同一户对两种币算出的"付清需求所需额"与手算一致；缺价的币**不挂单** |
| T6 | **订单可选币**：买方指定支付币 ⇒ 成交后卖方收到的就是该币（不再强制本格币） |
| T7 | **商户差价扣税**：同一 lane 上税率抬高 ⇒ 该 lane 的商户利润排序**下降**（政策→商户行为端到端） |
| T8 | **承运承诺**：同一单被两家商号看中 ⇒ **资产规模大者**得；无承诺的跨区单 ⇒ **倒掉**（`NO_CARRIER`） |
| T9 | **政府置顶**：政府要求管控 ⇒ 其挂单排在**最前**成交；超越户数 = 消耗的行政力；池空 ⇒ 后续不再置顶 |

## 6. 第二轮全链复核（市场 → 口岸 → 汇率 → 商户套利）

★ 结论：**四段能接起来**，但以下 11 处必须在派单前钉死（前 8 条已给冻结口径，后 3 条见 §7 待裁定）。

| # | 发现 | 处置 |
|---|---|---|
| **V-1** | **币种过滤与"订单可选币"是一对**：买方选的币必须被卖方接受。只做其一 ⇒ 要么换完花不出去，要么过滤无落点 | 已冻结候选成立条件（§2.1）；两条**必须同批或相邻批**（3c 在 P-T1 之后） |
| **V-2** | **税项跨币种**：卖方参考价在源区币、进口税在目的区币 ⇒ 不能直接相加 | 冻结：**每项按收税政府的法定币计，再经同一份估值折成买方支付币**；实现方须在账本给出**具名折算次序** |
| **V-3** | **节流与承诺的先后**：若先承诺再节流，"承诺量"会超过实际可流量（违反 A3 超发禁令） | 已冻结次序：**节流 → 承诺 → 置顶 → 撮合**（§2.6） |
| **V-4** | **采购置顶与承运承诺的交互**：置顶改撮合序，可能让"已承诺承运的货"失去买主 | 冻结：置顶**只改撮合顺序**，**不撤销**已成立的承诺（承诺是运力预留）；若两者冲突以**承诺优先**并具名记录 |
| **V-5** | **FX 与信用的次序**：现状 FX 在信用之后 | 维持（F-5）；合并成一簿 = Q-6 |
| **V-6** | **"换汇点在购买环节"与"FX 在商品之后"**：用户说"下一轮才处理" | 冻结为**现状时点**（同轮 FX 段用本轮商品结算后的持币）；若用户要严格延后一轮 ⇒ 改一处入参（F-6，默认不延后） |
| **V-7** | **缺价处置**：需求篮子里某商品在该币法定区无价 | 冻结：该币**整币不可比 ⇒ 不换**（不猜、不静默按 1:1） |
| **V-8** | **行政力池的口径**：池 = 编制劳动力（既有行政维 `c = 编制 ÷ demand`） | 冻结：余量 = 编制 − 已用（含插队）；见底硬停；**扩编**要有命令面（Q-7） |
| **V-9** | **商号是否能持货自营**（"买低卖高"要有落点） | **待调查回填**（§7 Q-1）——这是 M1/M2 的硬前提 |
| **V-10** | **商号是否也自动换汇** | 待裁定（Q-5）；默认：本轮只做**家户**换汇，商号按估值折算 |
| **V-11** | **三层税的价格构成与运费关系**：运费由买方付、不计税 | 冻结：`买方实付 = 货款 + 出口税 + 进口税 + 区内税 + 运费`；税基只含货款（§2.2） |

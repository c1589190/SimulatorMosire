## 2. 用户最新裁定：家户需求是价格接受者

用户原话：

```text
需求被允许挂价了吗？家户提的需求，面对市场不管多贵都会直接接受的；其他没啥问题，记录一下你的修复方案，开始吧
```

### 2.1 裁定解释

- **家户提出的需求（BUY）是数量型价格接受者**：需求数量由真实缺口/账单决定，不由挂单价、现金余额或预算余额截断。
- 市场无论报什么非负价格，家户都接受；成交后先用现金支付，现金不足的货款立即成为普通货币债（按既有债务规则）。
- 无供给 ⇒ `unmet`，不记债；有成交但现金不足 ⇒ 普通债。
- 需求价格不是“允许挂一个上限”的字段；目标语义里 BUY 不应有价格上限/预算上限门。
- 这条裁定覆盖 v2 中任何把 `price/budget` 当作买盘门槛的旧表述；v2 的“商品+土地同簿、5 tick 市场、本 tick 工资债 cutoff、0 价合法”等其余口径不变。
- SELL 侧的最小价/定价语义不在本裁定中改变；本裁定只针对家户需求（BUY）。

### 2.2 对实现的影响

| 影响面 | 必须改成 |
|---|---|
| `MarketIntent` BUY | 不再用 `limitPrice`/`budgetMilli` 作为需求门；内部 BUY 形状应表达“数量 + 币种 + 主体/地点 + 来源”，价格由市场撮合决定 |
| `MarketIntentBook` | 对每个 gap 生成全额 quantity，不按 `ask`、`remainingBudget`、`maxSpend` 截断；`ask=0` 也生成 |
| `SettlementDayMarketPipeline` | 把 BUY 转成买订单时使用“无价格上限/无预算上限”的边界值，不能把需求数量折成现金可买量 |
| `MarketOrderPlanner` | 家户需求订单数量 = 完整缺口；现金只影响支付腿/债务腿，不影响挂单数量 |
| 土地 BUY | 同样由真实缺口派生，不能因现金/预算不足而不挂；成交现金不足走普通债；SELL 侧仍可保留最低价 |
| 日志 | BUY 生成、成交、`unmet`、普通债要能按 `(actor, commodity, side)` 读出原因 |

## 4. F1 约束设计（本批唯一写代码范围）

### 4.1 问题现场

- `MarketIntentBook.java:80-148`：BUY 量先按 `naturalNeeds×5 - onHand`，再被 `remainingBudget`、`market.askPriceOf`、`maxSpend` 截断；
  `ask=0` 时 `maxSpend=0`，需求直接消失。
- `MarketRoundRunner.java:761-799`：对出现任一 M3 商品意向的 actor，删除该 actor **全部**自动买卖腿。
- `MarketIntent.java:36-66`：内部 BUY/LAND 意向把 `limitPrice`/`budgetMilli` 当作统一字段；BUY 价格没有区分“价格接受者”。
- `MarketLandIntentBook.java:242-312`：土地 BUY 也带 `limitPrice`/`budgetMilli`；现金/预算会在上层表达成门。
- `MarketOrderPlanner.java:298-319`：已有 0 价正确路径（`referenceInPay=0 ⇒ cashAffordable=Long.MAX_VALUE`），但 M3 的现金门把它绕开。

### 4.2 F1 必须达到的行为

1. **BUY 全额生成**：每个真实商品缺口/土地缺口都生成一条 BUY，数量不因 ask=0、现金=0、预算=0 减少。
2. **BUY 价格接受**：商品和土地的 BUY 不接受任何价格上限；撮合价无论多高都接受（非负整数范围内）。
3. **现金只影响支付腿**：成交时先付现金，未付部分按既有普通货币债路径记录；不阻塞挂单。
4. **SELL 不变**：卖单的最小价/接受币种/实际盈余语义不改。
5. **同键替换**：`MarketRoundRunner` 只替换 `(actor, commodity, side)`；actor 其它商品/方向的自动腿保留。
6. **单一订单簿**：商品和土地仍进入同一 `MarketRound` / `MarketMatcher.matchAll`，不新增第二 matcher。
7. **不新增持久组件**：`EconomyData`/ChangeSet/Codec 不改；本批只改瞬态市场意向/订单组装。
8. **日志**：BUY 生成/替换/成交/未成交/普通债至少各有可 grep 的 INFO/DEBUG 证据，字段含 actor、commodity/land hex、side、quantity、reason。

### 4.4 F1 验收锚点（测试代理后补，不在本批运行）

正例：

- `ask=0` 且家户有 grain gap ⇒ 仍生成 BUY quantity=完整 gap；
- `cash=0`、`budget=0` ⇒ BUY quantity 不变；
- 成交价任意高 ⇒ buy order 仍可进入撮合，支付腿现金不足部分成普通债；
- actor 同时有 cloth BUY intent 和自动 grain BUY/SELL ⇒ 只有 `(actor, cloth, BUY)` 被替换，`(actor, grain, BUY/SELL)` 自动腿保留。

负例：

- 无供给 ⇒ `unmet` 增加，不新增债务；
- 0 价成交合法，不能被当成“无价/不交易”；
- 自买自卖仍被拒；
- 未定价商品仍不生成订单（“无价”和“0 价”不同）。

## 5. 后续责任区的高层约束

### F2 生产输入/劳动

- M6 位置/劳动选择不能把“本 tick 尚未 `drawActualInputs`”读成 `NO_INPUT`；
- 不得因 `NO_INPUT`/idle 把既有 farm commitment 无条件清掉后永不恢复；
- M7 只对实际被选中/实际有劳动的单位扣种子；
- 种子不得按整周期计划规模一次性清空户粮；同 hex 多户不得合成种子池；
- v2 S4 的 `DailyDemandBill`/实际播种面积/日效率是正式方向。

### F3 土地组织

- 土地抵债/买卖后，下一生产 tick 新 owner 的 unit/roster/plannedLabor 必须接上；
- 旧 owner 无地时显式退役/改绑，不能每 tick `asset-location-scope-missing` 冻结；
- 不得把土地整块或 `AssetShareId` 块语义重新引回。

### F4 卖盘/土地/运力

- 商品卖盘从实际库存盈余派生，不再只从 `outputSupplyByOrganizer`；
- 土地 BUY 的最小地块路径不能在 M3 依赖未初始化的 `ctx.hexToIndustries`；
- 运力用 v2 P1-05 的确定性函数，不新增运输生产方式。

### F5 债务读数

- 工资算法不改；让债务报表按 `DebtSource` 拆分；
- `debtContractCount` 是合同版本数，不是义务数；
- 不再让市场赊购/货币市场贷款冒充工资债。

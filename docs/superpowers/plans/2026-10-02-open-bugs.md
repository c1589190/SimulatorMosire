## 一、未修复缺陷（BUG）

### BUG-2026-10-02-01 区域查看：`Nation` 标签与"国家全疆"显示


**用户原话**：

> GUI 上，区域查看点击 tag 国家，还是默认显示各个政府的辖区，理想情况下 Nation 标签只显示一整个的国家范围，
> 而底下多了什么不知所云的 `nation:XXXXX`，把这个删掉，国家全疆就是 Nation。

**现象（用户实测）**：

1. 区域查看（右栏按 `RegionMeta.tag` 分组）里点 `Nation` 标签，看到的仍是**各个政府的辖区**，而不是"一整个国家"。
2. 标签列表里混着 `nation:大蜀`、`nation:西陵` 这类原文，用户认为不知所云，要求删掉；"国家全疆就是 `Nation`"。

**只读证据（代码 + 实时世界，2026-10-02）**：

- 世界 tag 分布（`GET /api/map/regions/summary`，head 151）：
  | tag | 条数 | 例子 |
  |---|---|---|
  | `Nation` | 247 | `东境总督区`(111 格)、`东岗伯国`(38 格)、`大蜀北谷占领区`(82 格)、`奥斯曼属瓦拉几亚占领区`(146 格) |
  | `province` | 42 | `大蜀__P01`…（province.apply 建的省区） |
  | `nation:大蜀` | 1 | `大蜀`，323 格 |
  | `nation:西陵` | 1 | `西陵`，126 格 |
  | `nation:<其它国>` | 各 1 | `nation:奥斯特马克侯国` / `德意志第二帝国` / `霍赫兰伯国` |
  | `null` | 5 | `大蜀__CAP` 等首都区 |
- 也就是说：**同一"国家"概念在数据里有两种 tag**——worldgen 的 `Nation`（国家区域，247 条，其中也含占领区）与 SDSimos 建国的 `nation:<id>`（每国 1 条，如 `大蜀` 323 格）。
- 右栏 tag 分组与按钮直接用 `meta.tag` **原文**：`readout.js` 的 `normalizeTag`/`groupByTag` + `panel-right.js:75-88`（`text: group.tag`）⇒ `nation:大蜀` 原文直接进 UI。
- 点 tag 只调 `setHighlightRegions(ids, "group")`（`panel-right.js:83-87`、`app.js:79-89`），**不改变图层状态**；而"GOV 辖区"是独立图层 `govJurisdiction`（`worldmodel.js:20`、`:37`、`:92-100`；数据由 `map.js:293-359` 构建）⇒ 点 `Nation` 不会关掉辖区、也不会把同国区域合成一块。
- 世界总览的"国家卡片"只按 `meta.tag = nation:<id>` 归并（`panel-right.js:450-454`）⇒ tag 为 `Nation` 的国家区域（如占领区）不入卡，加剧"国家全疆"对不上。

**待用户解释/重设计（本清单不做设计）**：

1. "国家"的权威数据源：worldgen 的 `Nation` 区域，还是 SDSimos 的 `nation:<id>` 区域？两者的关系、合并或退役策略？
2. `nation:XXXXX` 是要**删标签**（改显示/归组）还是**迁数据**（retag）？删掉后 `大蜀`(323 格)/`西陵`(126 格) 这类区域如何处理？
3. `Nation` 标签的期望行为：只做高亮（现状），还是"整国合并显示"（跨区域并集）并联动图层（关 `govJurisdiction`）？
4. 占领区（`大蜀北谷占领区`、`奥斯曼属瓦拉几亚占领区`）tag 用 `Nation` 是有意口径还是历史遗留？

**关联**：`2026-10-02-mcp-admin-gaps.md`（区域归属/迁都）、`2026-10-02-undeveloped-features.md`（单格命名/区划）。

### BUG-2026-10-02-02 重叠区域：重叠显示 + 定位修改（MCP 工具面）

**用户原话**：

> 现有标准区域处理，能不能进行重叠部分显示、针对性修改？例如允许外部 Agent 操作 MCP 找到重叠区域，
> 然后用另外的区域编辑工具直接让其归属某一个区域。

**现状（代码事实）**：

- **重叠是设计内正常状态**：前端区域编辑器明写"重叠是正常状态，前端绝不加'禁止重叠'的校验或提示"
  （`map-regioneditor.js:34`）；`map.CreateRegion`/`map.UpdateRegion` 也不做区域互斥校验。
- GUI 编辑器已能做"并集/剔除"：合并 = 选区 ∪ 焦点区域、剔除 = 焦点区域 − 选区，各落**恰一条** `map.UpdateRegion{regionId,hexes}`
  （`map-regioneditor.js:465-517`、拖点 `:413-428`）。
  ⇒ GUI 内可以把重叠格从 A 剔除/并入 B，但"归属切换"要 A 减 + B 加**两条命令**才完整，非原子。
- MCP 读：`simos.map.region` 返回单区域的 `hexes`（`MapRegionTool`），`simos.map.hex` 返回单格的区域 id 集合
  ⇒ 外部 Agent 理论上可自行求交找出重叠，但**没有"列出重叠区域/重叠格"的专用读口**。
- MCP 写：`simos.map.update`（固定 `map.UpdateRegion`）可整份替换某区域 `hexes`/`meta`；
  **没有** `map.ReassignHexes` / `map.RemoveHexes` 这类"把某些格从 A 划给 B"的语义命令；
  跨区域一步完成需要 `submitBatch`（Core 已有，但只有专用组合工具在用，**无通用 GM 工具**）。
- 显示：前端目前只在多处写"区域重叠会重复计入"的 caveat（`panel-right.js:304-454`），**没有**重叠的专用显示形态。
- 下游：换 hex 后 GOV `jurisdiction` / 城市 `region` / 税率键 / `GovDemand` 配编要人工重算
  （见四线调查 D 线 D3；税率悬空会静默 gap、双辖权会重复征税）。

**待用户解释/重设计（本清单不做设计）**：

1. 重叠**显示**形态：同色叠加、交叉纹理、独立"重叠"图层，还是只做只读清单？
2. 是否新增读口（如 `simos.map.overlaps`：返回重叠区域对/重叠格/涉及区域），供外部 Agent 定位？
3. 是否新增写口（如 `map.ReassignHexes{from,to,hexes}` 或 `map.RemoveHexes`），一条 revision 原子完成"归属某区域"？
   修改后是否同批重算 GOV 管辖/城市归属/税率/编制？
4. 与已登记的区划缺口（`map.MergeRegions` / `map.SplitRegion` / `map.ReassignHexes`）是否合并为同一个区划批次？

**关联**：`docs/superpowers/reports/2026-10-02-undeveloped-features-code-investigation.md` §2.4（D3）、
`2026-10-02-undeveloped-features.md` 的行政/区划条目。

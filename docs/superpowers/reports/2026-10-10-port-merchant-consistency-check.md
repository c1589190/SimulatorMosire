## 0. 结论（一句话）

**范围上自洽（两条线明确分期、互斥），接口上未定义**：
商户设计书自己把"口岸/关税/结汇/走私"列为**阶段 3 非目标**，口岸设计书把"商户阶梯"只当**同层邻居**——
⇒ 两份文档**不重叠**，这是它们自洽的部分；
⇒ 但作为一个**体系**看，两边对"跨区货到底怎么走"各有一套隐含假设，**其中 1 处是真冲突**（X1），
另有 3 处接口缺口（X2–X4）、3 处必须写死的口径（X5–X7）、3 处刻意简化要写档（S1–S3）、
以及 1 组联合验收判据缺失（§6）。

## 1. 自洽的部分（先认下来，三条）

1. **分层清晰、不越界**：口岸 = **法律规定层**（口岸/禁运/效率聚合，G9），商户 = **市场行为层**（挂单/承运/撮合）。
   口岸红线禁止新增"政策层"（§4.5 G8），商户设计禁止碰"口岸/关税/摩擦"（§8 禁止碰）。
2. **默认世界逐值不变 ⇒ M1–M5 可以在无政策世界上跑而不冲突**：限制强度缺省 `s = 0`
   ⇒ `openness = 1000` ⇒ `E = 1000` ⇒ 走私量 0、成本楔子 0（`PortRegimeAggregation:84, :142-144`；不变量 I-P1/I-P8）。
3. **存量耦合是对的**：罚没基准刻意锚在运费表上（`SEIZURE_BASELINE_MILLI = 3 × CommodityFreightBase.TOOL_MILLI`，
   `PortRegimeAggregation:58`）⇒ 运费表调档，罚没基准跟着走（单一来源，不造第二张魔数表）。

## 2. ★ X1：结构性冲突——"走私量"与"没人承运就倒掉"对同一批货给出不同结论

| 侧 | 规则 | 对"没有商号承诺承运的跨区货"的结论 |
|---|---|---|
| **口岸** | 走私 = 规模现象：`可正常进出 = ⌊总过境能力 × E ÷ 1000⌋`、`走私 = 总量 − 可正常进出`（`:25-27, :130-146`） | 隐含：**这份货过境了**（只是"没被管住"） |
| **商户** | **A2**：没人承运的跨区单 ⇒ **倒掉**（不成交，具名 `NO_CARRIER`）（商户 §10.3） | 明确：**这份货没动** |

⇒ 若阶段 3 把两边直接接上，**同一批货在口岸账上是"走私过境"、在商户账上是"倒掉"**。
⇒ 两种自洽接法（须用户选）：

- **甲（控制方推荐）**：走私**不是独立搬运者**，而是"这一份货没被管制拦住"的**属性**；
  `transitCapacityMilli` 定义为**本 tick 已承诺承运的跨区货量** ⇒ 无承诺的单在进入口岸算式**之前**就被 A2 倒掉了，
  两者不再打架。走私只决定"这批货被罚/加楔子/免检"。
- **乙**：走私 = "无承运但强行过境"的第四条路径 ⇒ 必须给走私一个**无人格搬运者**，
  与 A2 冲突，且**凭空移动货物**（与 I-F5"运力不许凭空生"的精神相悖）。

## 3. 接口缺口（未定义，不定会各做各的）

### X2 成本楔子记在谁账上

- 口岸给出 `wedge = (1000 − E) × 罚没基准 ÷ 1000`（毫/商品单位，`:142-144`），但**没说谁付**。
- 商户 M1 的利润算式**没有这一项**：`利润 = 运费收入 + 差价收入 − 劳动机会成本 − 本钱占用`（§4.3/§10.5）。
- ★ 关键线索：**币种维已经选了"家户侧"**——enforcement 进的是**家户对外币的估值减项**（`CurrencyValuation:292`）。
  ⇒ 商品维若**同侧**（被管制商品在买家眼里更贵/更不愿买），则**商户不需要新增成本项**，政策会经由"出价变差"自动压掉那条 lane。
  ⇒ 控制方建议：**商品维与币种维同侧（需求/估值侧）**；楔子只做"读口 + 可能的价格加成"，不做商号的额外扣项。
  ⇒ 若反过来选"承运方承担"，则 **M1 必须改成**：`… − 过境成本(E, 货值)`，且 M2 的利润排序与 M3 的承诺都要跟着改（批次变大）。

### X3 商号的多币种利润怎么计价

- M1 要算 `利润 = 运费 + 差价 − …`，但跨区经营 ⇒ 商号手里会有**多种货币**；**没有统一计价单位，这个"利润"没有定义**。
- 商号是**组织**（`ProductionOrganizationId` + `ActorRef`），不是家户；而 `CurrencyValuation` 目前的输入是**家户行**
  （`rowsByHex` → `householdMoney`）。
- 商户 §2.2 又把"结汇"列为阶段 3 ⇒ 现在没有口径。
- ⇒ 控制方建议：① 商号**与家户共用同一份 `CurrencyValuation` 实例**（同一 tick 一份，别各算一份——本仓已有"两份估值会漂开"的教训）；
  ② 利润的**计价单位**写明（建议：本市场区记账币/商号主币），跨币收入按同一份估值折算。

### X4 `transitCapacityMilli` 由谁提供

- `split(E, transitCapacityMilli)` 需要一个"想过境的总量"，**今天无人提供**（实测：`split`/`SmugglingSplit` 全仓零调用者）。
- 若按 X1-甲，供给方 = **M2 产出的承运承诺表**（已承诺的跨区货量）。
  ⇒ 这同时把"口岸 → 商户"的接口钉死了：**M2 承诺量 → 口岸拆分 → 正常/走私两份 + 楔子 → 结算**。
  ⇒ 建议写进 P-T1 与 M2 的**联合契约**。

## 4. 必须写死的口径（不写死会做歪）

### X5 同 tick 的固定次序

- 口岸注入有**一 tick 滞后**的既有事实（`EconomyDayStepper:234`："本批注入的口岸管制作用于**下一次**市场轮"）。
- A3 要求"**承诺在本轮内有效**"（商户 §10.3）⇒ 承诺一旦发出，其**全部输入**（E、费率、需求）必须在**承诺那一刻冻结**。
- ⇒ 必须写死次序：**口岸注入 → 商户决策步 → 承诺表 → 撮合**；不许"决策步读上一轮的 E、结算用本轮的 E"。

### X6 `E`（开放度）**不许**进运费公式

- 同一条运费公式里已有**两个 ‰ 乘子**：`基础费 × (1000 + 路线费率‰) × (1000 + 承运成本‰)`（商户 §4.1）。
- 口岸侧还有三个名字相近的 ‰：`e`（口岸行政效率，**不封顶**）、`E`（开放度，1000 = 全开）、`enforcement`（管制力）。
- ⇒ 写死：**`E`/`enforcement` 不进 `freightUnitMilli`**；要影响行为只能走"需求侧估值减项"（X2-甲）或一个**具名过境成本项**，
  且方向在注释里写死（`E` 越高越通畅，`enforcement` 越高越堵）。

### X7 商品维与币种维**独立**，不合并

- 两条维各自算 `E`（`aggregateCommodity` / `aggregateCurrency`，`PortRegimeAggregation:107-119`），
  一趟跨区运输若同时涉及"被管制商品"与"被管制币种"，**分别**受两个 E 影响，不存在合并口径。
- ⇒ 写死：两维独立；且"**货到了钱收不到**"**不许**实现成硬拦（币种维的作用形态是**估值折价**，不是拒付）。

## 10. v2（2026-10-10）：用户裁定后的更正（本条**取代** v1 的部分建议）

用户原话（逐字；已收录进口岸设计书 §10.1）：

> 我认为走私的计算存在于供给层，口岸首先限制的是市场选择，如果口岸运转管制，一批货物压根就不应该被市场区内的家户选上，包括商户

| v1 的条目 | 裁定后的答案 |
|---|---|
| **X1** 走私口径（甲/乙） | **问题形态消失**：走私 = **未进选择集**的那一份（供给层读数）；既然"家户与商户都选不上"，就不存在"另一条搬运通道"，与 I-P7（不新增走私者实体）一致 |
| **X2** 楔子记谁账（v1 建议需求侧估值减项） | **被取代**：机制是**选择集过滤**，不是成本项；楔子降级为读数或撤（新 X-R7）。★ v1 的"需求侧估值减项"是控制方的错方向 |
| **X3** 商号多币种计价 | **未变**（仍待裁 X-R3） |
| **X4** `transitCapacity` 供给方（v1 建议 M2 承诺表） | **被取代**：走私算在**供给层** ⇒ 过境量 = "想入区的货量"（跨区供给），不是承运承诺表 |
| **X5** 同 tick 次序 | **细化**：**口岸过滤 → 商户决策步 → 承诺表 → 撮合** |
| **X6** `E` 不进运费公式 | **不变，且更强**：`E` 的作用面是**选择集**，不是价格 |
| **X7** 两维独立 | **补充**：独立**且形态不同** —— 商品维 = 选择集过滤；币种维 = 家户估值减项（已落 `CurrencyValuation:292`） |
| **J1** 验收判据 | **改写**：设限后不是"利润变差"，而是"**该 lane 上根本不出现该商品的候选**" |
| X-R1 / X-R2 | **关闭**（由本条取代） |
| X-R3 / X-R4 / X-R5 | 仍未决（随 P-T1/M2 裁） |
| 新增 | **X-R6**（走私那份的归宿）/ **X-R7**（楔子去留）/ **X-R8**（只拦入区还是也拦出区）/ **X-R9**（与 `MarketRegulation` 的次序）——见口岸设计书 §10.4 |

★ 落点（实测）：供给层 = `MarketSettlement.planOrders`（`:1114`）产出的卖订单；
过滤必须加在**跨区候选配对**处（`MarketSettlement.matchAcrossRegions`，`:4072`），
**不许删卖单本身**（那会把本区买家的选择一起删掉），且本区自产的货不受口岸影响。

## 11. v3（2026-10-10）：第二条裁定——**"走私"这一档取消**

用户原话（逐字；已收录进口岸设计书 §11.1）：

> 走私本质上不就是口岸没管住？没管住就是流入市场了，凭啥还要额外记录？按正常供给给家户算

| 条目 | v3 的答案 |
|---|---|
| **X-R6**（走私那份的归宿） | **关闭**：没管住 = 流入市场 = **正常供给**，不额外记录 |
| **X-R7**（成本楔子去留） | **关闭**：**撤**（"凭啥还要额外记录"）⇒ 商号利润不许加这一项 |
| 口岸的真实作用 | **节流跨区流入**：`流入 = ⌊transit × E ÷ 1000⌋`（普通供给）；`被管住 = transit − 流入`（不进市场） |
| ★ **命名更正（v1 未发现）** | 设计书 §4.4 与代码把两侧**叫反了**：`split` 的 `normal`（`transit × E`）**就是"流入/没管住"那份**，`smuggled` 实际是**被拦下量**。术语统一为"流入量 / 被拦下量"，"走私"不进代码与读口 |
| **J2** 判据 | 简化：无承诺的跨区货 ⇒ 倒掉（`NO_CARRIER`）——**不再涉及走私口径**（没有那一档） |
| **J1** 判据 | 保持 v2 改写：设限后该 lane 上**只出现节流后的候选**（`E=0` ⇒ 零候选） |
| 清理项 | 删 `PortRegimeAggregation.split` / `SmugglingSplit` / `SEIZURE_BASELINE_MILLI`（**实测零读者**，含 test） |
| X-R8 / X-R9 | **仍未决**（默认：只拦入区；次序 = 定价存在性 → 口岸节流 → 撮合） |
| 币种维 | **不变**（仍是家户对外币的估值减项） |

★ 至此 v1 的 X1（走私 vs A2 倒掉）**彻底消解**：不存在"另一条搬运通道"，被管住的货不进候选集、
没管住的货就是普通供给，A2 只对"没人承运"生效 —— 两者不再有任何交界。

## 12. v4（2026-10-10）：第三条裁定——**出入两侧都拦，两侧都要过**

用户原话（逐字；已收录进口岸设计书 §12.1）：

> 出入都设规则拦，分别按口岸效率算，最终一批货要过境，不管是效率漏了走私的，还是通过的，都需要两边都过才能跨区；

| 条目 | v4 的答案 |
|---|---|
| **X-R8**（只拦入区 / 也拦出区） | **关闭：出入都拦**，两侧各自按自己那一侧的政府口岸效率算 |
| 过境条件 | **两道闸依次都要过**：`可通过比例 = E_源 × E_目的 ÷ 1e6`（控制方口径：串行=相乘，不取 min） |
| "漏过一次" | **不等于过境**：源区没管住的那一份仍要过目的区那一关；两侧都过的那份才是**普通供给**（§11） |
| 只有一侧是市场区 | 无政府那一侧开放度 = **1000**（没有口岸可管） |
| E 的粒度 | 仍用**区级** E（按暴露边加权平均）——与"货从多路涌来"的原有裁定同源；lane 级另裁 |
| P-T1 节流因子 | `E` → **`E_源 × E_目的 ÷ 1000`**（`PortEnforcementInput` 逐区逐类，查两次即可） |
| 新增判据 | 两侧都 1000 ⇒ 逐值不变；**任一侧 = 0 ⇒ 该 lane 零候选** |
| X-R9（与 `MarketRegulation` 的次序） | 仍未决（默认 定价存在性 → 口岸节流 → 撮合） |

★ 与商户体系的关系不变：节流后的候选才是商户决策步（M2）的输入；A2 只对"没人承运"生效。

## 13. v5（2026-10-10）：第四条裁定——**过境要收税（出口税 + 进口税）**

用户原话（逐字；已收录进口岸设计书 §13.1）：

> 哦对了，供给不是还要额外算出口税吗？暴露给市场区外的价格可以直接加上了，然后进来的时候可以再加一笔；

### 13.1 ★ 与 X-R7（撤掉走私楔子）的关键区分

| 项 | 结论 | 对商号 M1 利润的影响 |
|---|---|---|
| **走私成本楔子**（罚没风险，`SEIZURE_BASELINE_MILLI`） | **撤**（§11；"凭啥还要额外记录"） | **不许加** |
| **过境税**（出口税 + 进口税，真进国库） | **要收**（本条） | **必须加**：跨区差价 = 目的区价 − 源区价 − **出口税 − 进口税** − 运费 |

⇒ 一句话：**"没管住"不花钱，"过关"要花钱。** 前者没有任何账，后者是真转移（买方多付、国库收钱、卖方仍收原价），
所以商号的买卖差价算式**必须扣掉两侧税**，否则 M2 的利润排序会把"税重的 lane"排得比实际更赚。

### 13.2 现成钩子（不必新造）

- `MarketRegulation.tariffPerUnit`（区级、瞬态、**"本批只累计读数，不搬钱"**）；
- `MarketReport.regulatedTariffMilli()`（`MarketReport:170-320`，逐票按**成交毛量**折税，读口**已把它加进到货价**）。
⇒ 本裁定 = 把它升级为"**分出入两侧 + 真搬钱**"（钱进两侧政府国库户 `hh-gov-<govUnitId>`）。

### 13.3 对复核结论的其他影响

- **I-P8 仍成立**：税率缺省 0 ⇒ 旧世界逐值不变。
- **币种维不受影响**（仍是估值减项）；税用**计价币种**（区内记账币）计收——若将来要按币种分税，另裁。
- **X-R9（与 `MarketRegulation` 的次序）升级为 T-4**：建议**合并成一套税**（同一笔 fill 只算一次），
  否则同一批货会被读口与国库双记。
- **新增待裁定 T-1..T-5**（从量/从价、计税基是否含运费、谁付谁收、是否合并、政策形状四元组）——
  见口岸设计书 §13.5；控制方默认：**从量、只对货值计税、买方付、出口税进源区国库、进口税进目的区国库**。

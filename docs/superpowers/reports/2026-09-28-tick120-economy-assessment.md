## 3. 经济效果：当前系统仍处于“总量够、分配坏”的状态

### 3.1 人口

| 项 | 值 |
|---|---|
| tick0 人口 | 11,830,000 |
| tick120 人口 | 11,621,928 |
| 变化 | **−208,072（−1.76%）** |
| 本周期 births | 99,482 |
| 本周期 deaths | **307,554** |
| 当前周期 grain unmet | 71,501,715,759 毫 |
| 当前周期 cloth unmet | 3,888,454,869 毫 |

### 3.2 粮食总量与分布

| 项 | 值 |
|---|---|
| 全球 grain 库存 | 150,301,673,963 毫 |
| 全球日口粮需要 | 981,711,332 毫/日 |
| 全球覆盖 | **约 153 天** |
| 最差 hex 覆盖 | 14 天 |
| 中位 hex 覆盖 | 172 天 |
| 覆盖 <5 天的 hex | 0 |
| satisfactionPerMille | min 341 / median **383** / max 450 |
| 799 格中 satisfaction <500‰ | **799 / 799** |
| 799 格中 satisfaction <900‰ | **799 / 799** |
| Σ unmetPersonDays | 861,466,059 |
| Σ importDemand | 71,501,715,759 毫 |

**解读**：全局库存可覆盖约 153 天，但所有 799 个 hex 的粮食满足率都只有 34%–45%，中位 38.3%。
这不是“总量不足”，而是**分配/购买力/市场出清问题**：
- 大量粮食沉淀在有库存的格/主体；
- 缺粮格的有效需求受货币、市场区连通、限价与订单预算约束；
- 人口死亡（307,554）主要出现在缺粮格，且 births 不足以抵消。

这与 M2 一年期报告的旧结论同向：**货币单向往农村流、城市购买力枯竭、市场无法把余粮送到缺口**；
R0+R1+R2 改的是身份/账户/并行结构，**没有改需求、竞争、退出、GOV 再分配**，因此经济结果不应期待改善。

### 3.3 价格与市场

- 价格模式 `fixed`；201 个市场区；799 市场全活跃。
- 样本首都格：
  - grain reference 1 / bid 1 / ask 2；
  - 粮 supply 0（本区无卖单）、naturalNeed 3,902,832,500 毫、effectiveDemand 17,572,337 毫、成交 1,017,140,832 毫；
  - **needsButCannotAffordMilli = 0**，但 `unfilledBuy*` 为空、`unusedCapacityMilli=383,535,227`，说明还有运力/供给结构问题，不是单纯“没钱”。
  - cloth 大量 `no_buyer`（423M 毫未成交），fiber 因织物/农业不匹配出现 `no_budget`。
- 结论：市场仍大量“有货卖不出、有人缺粮买不到”，这是 R3 撮合/需求/成本排序/GOV 的落点。

### 3.4 债务与冻结

- debt 332 条、principal 10,495,732 毫；tick120 相比 tick0（0 条）已开始出现借粮；
- `interestDue` 累计 1,050,641 毫；`newBorrowing` 52,538,897 毫；`repaid` 43,093,806 毫；
- `frozen_goods` / `frozen_money` 全 0 ⇒ 市场轮末冻结净额归零；
- 经营者 `operatorConditions` 仍为 0（S3 未实现，无缩产/停业状态机）。

## 4. 对“单论经济系统修改”的评估

### 4.1 架构/工程层面

**正面**：
- 新身份/账户内核跑通：worldgen → 0→30 → 30→120 全程无崩溃；tick120 head=rev6 正常提交；
- tick0/tick120 人口、货币、商品在 economyHex 与 ownership 两个来源逐值对账；
- Membership 逐 lot 对齐；使用权不超容量；无负余额异常；冻结净零；
- 90 tick 156.4 s，满足“单次测试 ≤3 分钟”的操作约束。

**风险/未完成**：
- changeset 折叠探针与 API 在 allocation/debt 侧不一致（见 §2），需要 V 阶段专项复核；
- 仍是单线程运行；多线程收益为零（未接线、市场未并行）；
- `EconomyOwnershipTimeParticipant` 已 deprecated，但测试与旧路径仍会引用，V 阶段要统一。

### 4.2 经济语义层面

- 当前 R0+R1+R2 **没有改善**“总量足但分配坏”的核心问题：
  - 中位粮食满足率仅 38.3%；
  - 当前周期死亡 307,554，出生 99,482，人口 −1.76%；
  - 库存/需求在空间上严重错配；
- 这正是计划 S2/S3/S4 要解决的：新需求与试产、成本排序与竞争、经营者/家户状态机、GOV 实物税与再分配；
- 因此，**不能用本结果否定 R0+R1+R2**：它们的目标是“可迁移身份 + 守恒 + 线程安全结构 + 订单/执行器骨架”，不是最终经济平衡；
- 但也不能宣称它们“经济上有效”：目前只有结构跑通与操作时间达标。

### 4.3 性能层面

- 90 tick 1.738 s/tick；若按此线性外推 360 tick ≈ 10.4 min（仅粗估，后段会更慢）；
- 距 4 min 目标仍有明显差距；
- 下一步必须先做多线程接线 + 市场撮合并行 + P1.2/P1.3/P1.6，否则市场 74% 的串行热点不动，4 min 不可达。

## 5. 建议的下一步

1. **V 阶段专项复核**：`reconciliation` 里 allocation/debt 的 changeset-vs-API 差异，确认是探针仪器问题还是真实状态问题。
2. **立刻做多线程接线与市场并行**（见 `2026-09-28-multithreading-effect-diagnosis.md` §4）。
3. **经济侧继续按 S2→S3→S4 推进**：需求/候选/试产、成本排序/衰退/迁移/阶层、GOV 征粮与军队供给。
4. 重新跑 90 tick 时使用 warmed baseline，确保单次 ≤3 min；性能目标用 360 tick 的独立批次测，不用 90 tick 线性外推。

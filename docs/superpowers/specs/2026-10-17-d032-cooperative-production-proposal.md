## §2 建议的基本模型：一个生产实例，多家户分角色参与

小生产是同一个模型下只有一个参与家户的情形。合作生产中：

1. **生产方式定义**：技术投入产出与升级选项、可参与位置、经验规则、资格条件、收益分配规则，权威在 production。技术配方与制度/分配配置可以复用组合，不强迫同一种手工农业在每个阶层复制配方。
2. **具体生产实例**：稳定身份、方案引用、地点、进度和真实生产台账归 production；一次物理生产只算一份总产出。
3. **参与关系**：economy 登记“哪个 HouseholdId 在这个实例承担哪个位置，承诺/实付了什么资源，享有什么份额”。实际土地权利、劳动、原料、契约与收支归原持有域。成员可有多个家户；同户也可能兼具土地提供者与劳动者角色，但实际劳动/资产不能重复计。
4. **组织者**：可以是一个家户或组织主体，负责组织/经营，不因此拥有其他家户的经验、人口或全部收益。家户保留各自人口、财产、债务和经验。
5. 地主、中农、佃农可以是方案中供配置的角色/位置。家户社会阶层与在某实例中的角色要区分；拿到地主比例须有实际有效的参与/产权关系，不能仅凭“同 hex 的地主标签”自动获利。

该模型既能表达一座庄园多人共同生产，也允许多块独立生产地各有实例、上层组织统一分账；**不强制每 hex 只有一个大实例**，也不按“一个阶层一份总产出”拆出重复生产。

## §3 共同经验：建议同一经验种类、各家户数值独立

用户“不同阶层积累的生产经验算同一个”存在两种可能含义：

- **本提案推荐**：同一农业方式中的各阶层引用同一条“农业经验”定义，各家户仍有自己的经验值。地主户、中农户、佃农户不另造三条同义经验；一个户在多个合作实例中参与同类生产，累计到同一条账。
- 若用户指“整个合作产业只有一个经验数值”，则会新增组织经验账，涉及成员加入/离开后经验如何归属；它不能直接替代此前已定的家户经验与人口迁移平均。本文不擅自采用这一解释。

推荐口径下：

- 不因阶层身份设置隐含经验加成或惩罚；增长来源由方案配置的实际参与决定。
- 直接耕作、实际经营管理可以被定义为经验贡献。建议默认只按真实生产劳动增长；若要让经营管理也增长共同农业经验，应记录管理投入并配置换算，不能仅因收地租自动涨经验。
- 被动收租户仍可保存和衰减已有农业经验，但本 tick 没有相关贡献则不增；这是建议，待用户确认。
- 经验是人口迁移时需要加权平均的强度量。**建议**增长按家户参与强度/人均有效劳动归一化，避免同样全职生产，仅因人口更多就学习更快；具体分母、劳动口径与速度参数待业务确认，不把现有绝对 laborMilli 换算直接当最终规则。
- 专门经验 a、共用经验 b 与自定义公式继续保留；“各阶层共用经验条”不要求所有生产门类合成一个全能经验数值。
- 共同生产效率仍依据真实参与者及其相关熟练度计算；农业首期可按实际生产劳动加权，各户经验变化各归其户，组织者不替代全部劳动者熟练度。更复杂的工序/管理瓶颈须显式配置，不在这里默认加入。

## §4 收益模型由生产方式定义，具体收付由经济执行

### 4.1 定义与实际关系分开

**建议接受用户方向**：production 维护角色及比例等分配模型；economy 维护具体参与关系、实际投入、估值与分配账。通用分账执行器可以复用，但规则来源必须收口，不能继续让 RegimeRelations 的硬编码表覆盖方案配置。

定义不写实际 HouseholdId；实例参与关系把角色绑定到真实家户。生产模块不直接改账户，economy 不另存一份可独立覆盖的方案默认比例。若允许当地合同改变比例，建议作为方案公开的参数/分配配置表达并可追溯；是否允许此种差异由用户确认，本文不替用户取消旧的地方合同差异能力。

### 4.2 两层分配

**第一层：按角色分池。** 生产方式声明各位置从什么池取得多少比例。

**第二层：同角色多个家户分配。** 生产方式声明角色内的权重，例如按实际出工、实际出租土地、约定份额或人口；默认不把同角色每一户都发一遍该角色总比例。

比例示意（不是历史结论，也不是已定参数）：已确认可分配粮食 1000，地主位 20%、中农位 30%、佃农位 50%，角色池分别为 200/300/500。佃农位两户实际出工 3:2，则分别得 300/200；不是各得 500。一个户同时拥有土地与出工权益，可以从不同合法池取得收益，但同一笔劳动/土地不能重复作为投入或同一权重。

### 4.3 分配基数和顺序必须明确

建议先界定一份“本周期可分配池”，再按配置比例分配：留种、明确约定的垫资补偿或必要费用若优先支付，要有规则和实际来源；其余从同一份剩余池分。原料已真实消耗时，不得以分配计算为名再扣一次库存；不同商品不能直接相减。

同层比例针对同一池快照，不能先取 20%，再把原定 30% 偷换成“剩余的 30%”。规则必须说明：按毛产还是明确费用后的池、实物还是售后收入、比例之和及余数归属、角色无人时如何处理、固定租/工资与比例分成如何排序。

首期建议从**每种商品的可分配实物池**做起，角色比例合计全池，角色内用明确权重；保留既有固定租/工资模型的表达能力，不把所有制度硬改成一种分成形式。比例本身和这些参数由配置给定。

### 4.4 家户选择比较自己的预计所得

合作方案评估至少区分：整个实例预计总产出，以及某户在某位置预计取得多少、承担多少劳动/原料/租费。家户选择应比较**本户预计所得减本户负担**，不能把庄园总毛产当成每个参与户的利润。

经济应形成能凑齐必要资源和角色的合作候选，再统一分配；地主与佃农是同一生产过程的不同参与者，不能让他们分别以完整土地/总毛产各建一份重叠生产。

## §5 资格条件必须能指定参与位置

“经营者家户必须解锁”不适合作为所有合作方式的固定规则。应由生产方式声明**哪个位置/哪些实际操作人员**需要满足经验或外部属性条件。

农业首期建议：实际采用升级作业的家户满足相应资格；单纯出地/收租者不必掌握该作业。若需要“有合格带头者即可带其他人生产”，可显式配置关键岗位/覆盖条件，但不默认所有方案都允许大师带徒，也不默认每个普通参与者都要独立解锁。

组织经营者没有 HouseholdId 时，依实际参与名册解析条件主体；不能仅因组织本身没有家户经验，就把整个合作生产判为不合格。所有条件仍 fail-closed，缺必要参与者/属性时给具名拒绝；**改变的是主体模型，不是取消校验**。

此建议一旦确认，需要调整正在修复的 R3 经营者独占资格主体工程取舍；当前提案不直接改其代码或宣布已实施。

## §6 R2：建议本地资产事实 + 对合作实例统一分配

这几条路线可以组合，建议采用**资产有实际地点/身份 + 经济按可行合作候选统一分配占用**，不能把它当 A/B/C 互斥投票。

- 土地所有权/使用权描述真实土地及其所在地，不挂死在“某个技术配方”上；改用畜耕不应让同一块地凭空消失或复制。
- 工具等可移动资产按实际所在地、可用时段进入预算；跨地使用需要真实运输/迁移，不因同一经营者就瞬间共用全图工具。
- 实例提交具体资源需求，经济分配后给出实际占用；production 只消费分配结果。位置不同的实例不能拿到同一块土地；同地点多个实例也要争用真实剩余容量。
- 参与同一实例的地主/中农/佃农共同提供资源，该实例只登记一份实占，生产只发生一次。多个独立实例仍须满足占用总和不超实有。
- 占用期限按资源/方案明确：农业用地可能从播种到收获持续占用，工具可以按实际时段共享；不能一律每天清空占用，再让同一块已播种土地重复支持另一个周期。
- 可按收益与需求排序，领取可执行的最小资源包；劳动/原料不足而未实际使用的可释放资源继续分配，跨周期已锁定的资源不当成空闲。“先给每实例整池，再拿它证明已统一分配”必须删除。

这是建议的最终结构，**本轮仍不修 R2**。具体数据迁移与算法是后续工程设计，不要求用户选择类名；但会改变哪些资源真的能被使用，需要按确认的业务规则验收，不能要求错误的多实例复制结果保持不变。

## §7 待用户修改/确认的业务口径

本提案推荐以下起点，不是要求用户批准实现细节：

1. **共同经验**：同经验种类、每户独立数值；增长按实际参与强度，纯收租默认不涨，管理投入可配置计入。
2. **分成**：方式定义角色比例和角色内分配权重，实际关系限定受益家户；建议按明确的可分配池分配。当地合同是否可调整比例、调整范围由业务决定。
3. **资格**：由方案指定需要会技术的参与位置；组织者不替代全部操作人员，纯出资/出地者不默认要求学会操作。
4. **资产**：土地锚定地点、占用期间排他；可移动资产按实际可达性使用；多个实例共享可用资源时统一分配并回填。

**未做/未验证**：没有实现本模型；没有运行构建、测试或新数值模拟；旧测试载体的存在只作源码事实；没有提交/同步。本提案不替代已记录缺陷的修复证据，也不提前认定 R2 闭合。

## §9 后续讨论：阶层经验系数与劳动分配权重（2026-10-17）

**用户已明确的新增要求**：在同一个生产方式中，各阶层家户参与生产得到的经验量允许不同，须具体配置。经验增长系数与收益分配系数是两组独立参数；不因某角色收益比例高，就自动让它多获得经验。共用经验条、实际贡献去重、家户独立经验值等仍承接此前口径。

**收益公式尚待确认**：用户提出“劳动力×系数”，同时给出地主/中农/佃农劳动 n/10n/10n、系数 40%/40%/20%、总产出 1000，希望得到 400/400/200；字面公式与例子不相等，不擅自选其中一个覆盖另一个。

### 9.1 按实际劳动直接乘系数

```text
W_r = L_r × c_r
所得_r = 总可分配产出 × W_r / ΣW
```

三项权重为 0.4n、4n、2n，合计 6.4n；分配结果为 62.5、625、312.5。若保持此公式并希望在 n/10n/10n 下取得 400/400/200，单位劳动系数可取 4、0.4、0.2（相对权重，不要求系数总和为 100%）。

### 9.2 按标准劳动份数乘系数（控制方倾向，前提待确认）

如果 n/10n/10n 是方案规定的**各角色标准劳动需求**，可先把实际劳动折为完成的标准份数：

```text
标准劳动量 S = [n, 10n, 10n]
W_r = (实际劳动 L_r / 标准劳动量 S_r) × c_r
所得_r = 总可分配产出 × W_r / ΣW
```

三类都投入一份标准劳动时，权重为 0.4、0.4、0.2，得到 400、400、200。该解释同时保留用户例中的系数和结果，并允许实际投入不足/增加时按份数变化。**是否将 n/10n/10n 视为标准需求，仍须用户明确；不是已定实现。**

上述都是分配模型算术，不替代物理生产约束；家户投入、实际总产出和可分配池仍须真实。程序实现可用整数/定点与余数分配，不在本轮改变精度口径。

本轮用 Python fractions 精确核算（非业务测试）：

```python
from fractions import Fraction
labor = [1, 10, 10]
coeff = [Fraction(2, 5), Fraction(2, 5), Fraction(1, 5)]
w = [l*c for l, c in zip(labor, coeff)]
print([1000*x/sum(w) for x in w])
w = [Fraction(l, s)*c for l, s, c in zip(labor, [1, 10, 10], coeff)]
print([1000*x/sum(w) for x in w])
# [Fraction(125, 2), Fraction(625, 1), Fraction(625, 2)]

```

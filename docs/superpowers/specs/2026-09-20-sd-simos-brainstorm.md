## 0 一句话

新系统 **SDSimos**：**继承/复用** Social、Map、Unit 的既有接口，**规范化国家（Nation）与军队（Army）的交互**，并引入**决策人（Decision-Maker）**。

## 1 Nation（国家）

- 通过 `map.CreateRegion` 建一个**代表国家的区域**（= 带 Nation 标签的区域）。
- ★ **不变量**：带 Nation 标签的区域，**在 SDSimos 存在时不可被删除**。
- 机制**暂缺**（"先放着"）；**INFO 照常适用** ⇒ 可为国家加**自然语言总介绍**。

## 2 Army（军队）

- 通过 SDSimos/NAA 创建**带国家隶属**的军队单位。
- ★ **前置**：先**规范化 Unit**（见 §3）。

## 3 Unit 的进一步开发（Army 的前置）

### 3.1 编制拆分 / 合体

- **拆分**：允许用命令把**大编制集合单位**下的**单条指挥链单位**分离出来。
- **合体前置评估**：先评估该单位**是否有能力回到原本的大编制**；**有则额外创建一条"回归路径"**（Route）；
  **大编制移动时对应更新**（回归路径终点跟着走）。
- ★ **只有两者处于同一位置时，才能合体**。

### 3.2 状态系统

- 每个单位有**状态**：**移动 / 休整 / 交战**（目前只这三），**三者对应不同的移动速度**。
- ★ **合并时**，要合并的小单位**只能处于"移动"状态**。

### 3.3 单位交战（Combat）

- **命令**：设置两个单位开始交战。
- **交战详情** = **自然语言 + 编制单位集合**（应被记录）。
- **分阶段**：
  - 一场交战可**自由添加多个阶段**；
  - 为**单场交战**与**单场交战的每个阶段**分别加**唯一 key**；允许 INFO 记录。
  - ★ **单个交战状态允许添加独立的参与单位**（细化的、从大编制拆出的小单位）
    —— 用户例："第一阶段上侦察单位，第二阶段上先头多个团"。
- **交战博弈**：对**单个阶段**可**预设多种结局 + 对应可能概率**，也用**唯一 key** 管理；
  **可选择唯一一个结局作为实际结局**。
- **战损**：先在**交战状态模块内**记录**参与单位的战损**；再**以该战损为可用于时间线恢复的状态**，
  **为对应单位计算装备/人员损失**。
- **地点**：单个交战状态**必须记录 hex**；不同交战状态可换 hex，**hex 的对应状态也可变**
  —— ★ **目前只列计划，不实现**。
- **跨时间整合**：实际记录在**单个时间线状态**里的是**交战状态**；**多个跨时间的交战状态**合起来 = **"一场交战"**。
  用户自评："到这个份上其实只是一个 **tag 作用（防止重名）**，还是得有的"。

### 3.4 数据链统计与自定义

- "这个不用多说"。

## 4 决策人（Decision-Maker）

- ★ **未定**：要不要把 **AgentLib 下放**到这里（"这里我没有想好"）。
- 可为**单个国家**、**单个打国家标签的军事单位**添加决策；决策有**独立地址管理**。
- 单个决策地址包含：
  1. **归属**（"你总得告诉我这个决策是为谁做的吧"）；
  2. **INFO**（文本决策）；
  3. **具体 Command**。
- ★ **Command 的性质**：
  - **不直接对应**其他记录状态模块的**体现效果**；但可有**一个"最终体现效果"作为执行结果**；
  - ★ **该效果可以延期**："现在做决策，预定在**未来什么条件达成后，发生什么**"——**这个机制必须被模拟**；
  - ★ **体现效果与执行原文无关** ⇒ **单条 Command 必须自带 INFO 作为执行原文**；
  - ★ **单条决策 = 单条 Command**（"没必要额外搞一个 Command 集作为独立项"）；
  - 决策人有**一个归属**；**一个 Command 的归属可以是这个决策人能管理的东西，甚至还可以不是**；
  - ★ **Command 还要记录"判决"**：为什么文本决策能得出**格式化、数据化的最终效果**
    —— 该数据化效果**甚至可以是给其他地址改 INFO**。
- **预制 command**：未想好；等开模拟几轮再决定要不要"决策人做决策**立刻生效**的 Command"；用户倾向**没必要也不能**。
- **决策时机**：按**所属机构的决策效率**：
  - **Nation** → **行政能力** ⇒ 用**行政余额**限制（"不可能天天做决策"）；
  - **军队** → 打仗的**每一 tick（每一天）**似乎都要。
- **判决系统**：汇总**一个 tick 下各个"只有第一阶段"的 Command**，给出**第二、三段**（**判决 + 效果**）；
  可用 **GUI + 用户智力** 或 **Agent** ⇒ **还要做可读性优化**。
- **决策人 Agent 的工具范围限制**（限定"能看到什么"）：
  - **国家领导人**：**通用外交信息** + **自己国家里地块的部分信息**（"还可以做限制，不过目前不用这么细化"）；
  - **军队**：**范围内地形** + **判决 Agent 愿意透露的敌军信息** + **自家军队信息**；
  - "**信息系统也需要额外动脑筋**"。

## 7 ★ Unit 现状实测（探子 `bg_50d01d6f`，2026-09-20）——**五个结构性缺口**

| 缺口 | 现状（实测） | 对 SDSimos 的影响 |
|---|---|---|
| **① 无"集合单位"** | 编制是 `Unit.parent: SegmentedSeries<Optional<UnitId>>` 的**严格单父树**（`UnitState` 构造期拒环）；**没有子列表/多父/`Army` 容器**；"下属"只能全表反查 | "大编制集合单位"**没有现成结构** ⇒ 必须新增（`Formation`/子表）或约定"树即编制" |
| **② 无作战状态** | `Unit` **无 status/mode 字段**；`MovementStatus`(`IN_TRANSIT/ARRIVED/NEED_REPLAN`) 只是**路线进度**、由 `UnitMoves.evaluate` 现算不落库 | **移动/休整/交战 三态必须新增**（字段或命令） |
| **③ 无战损语义** | 有 `member:int` + `equipment:Map<String,Integer>`，但唯一入口 `unit.SetStrength` 是**整份替换**（非增量）；全仓无 combat/casualty | "按战损扣减装备/人员"**需要新增增量命令**（否则只能覆盖，无法表达"损失量"） |
| **④ `PlanRoute` 不容稀疏路点** | `Route(waypoints, path)` 类型**支持**稀疏，但 handler 写死 `new Route(waypoints, waypoints)` ⇒ **载荷必须逐格相邻** | ★ **"回归路径"要 A\* 补中间 ⇒ 载荷通道缺失**，须新增字段或新 handler |
| **⑤ `ReparentUnit` 只改单点** | 一次只能改一个单位的父；`DisbandUnit` 要求先改编下属；**不能整棵子树迁移** | 拆分/合体（改子树的父）**需要新操作** |

**其它既有资产（可复用）**：`unit.*` 命令共 **8 条**（Create/Rename/Reparent/SetStrength/PlaceAt/PlanRoute/CancelRoute/DisbandUnit），全部注册在一处（`simos-app/.../Shell.java:193-213`）；SPI 扩展位现成；`UnitAgentAttachPolicy` 已存在（单位可绑 agent）⇒ 决策人 tool-scope 有基础。
★ **unit 与 social 编译期互不可见**（enforcer 硬禁）⇒ **国家（= map 的 Region 标签）与军队（unit）的关联只能在 SDSimos / app 层做**。

## 8 追加需求（用户 2026-09-20 追加）

> 用户原话：「用户的输入不一定全是同一个角色——**允许通过多种渠道接入不同人的决策**，因此**应该留有自定义决策提交渠道**」

- **多角色**：决策提交者**不是同一个身份**（玩家 / GM / 多个指挥官 / 各军种）；每人的**可见范围**由其 `viewScope`（GM 配权）决定。
- **多渠道**：GUI / MCP / CLI / 外部 HTTP / 文件…**都要能接** ⇒ 需要一个**可插拔的"决策提交渠道"契约**。
- ★ **既有先例**（AgentLib `io.mosire.agentlib.approval`）：**`ApprovalChannel` 接口 + `HttpApprovalChannel` 实现** —— 决策渠道**照同一形制**做。
- ★★ **要点（设计时必写）**：
  1. **渠道 ≠ 身份**：渠道只负责"把**某个 actor** 的决定送进来"；**actor 身份必须由渠道声明的可代表集合约束**，渠道**不得冒充**任意 actor。
  2. **信任边界**：自定义渠道 = **新攻击面** ⇒ 要定**认证**（`AccessToken` 现成）+ **渠道可代表哪些 actor** + **留痕**（谁经哪条渠道提交，进 `verdictMeta`/事件）。
  3. **按 actor 取脱敏视图**：渠道**不能拿全量**，必须按该 actor 的 `viewScope` 取（与 R10/N6 同一条）。
  4. **并发**：不同 actor 同 tick 并发提交互不影响（乐观并发 `expectedRevision` 已有）；**同一 actor** 撞 **N12（1 令/tick 同事务强制）**。
  5. ★ **"人在环"与"Agent 在环"同构**：渠道只是**落点适配器**，不是新语义 ⇒ 与 **R9（人与 Agent 写同一落点）** 一致。
  6. **GM 本身也可经渠道**（配权也是一种决定）。
- 待办：进主 spec 的 **§十三 决策提交渠道**（并更新 §〇 裁定表）。

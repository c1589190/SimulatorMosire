## 一、架构总纲：**关系（relation）是唯一的权威记录**

三件事**必须分开**，不许互相推断（沿用 `POLITICAL_ECONOMY_DESIGN.md:96-107` 的"占有 · 控制 · 投入是三件事"，但**按你的裁定重新归类**）：

| 层 | 回答什么 | 归属（用户裁定） |
|---|---|---|
| **生产力** | 土地、工具、技术、**劳动能力** | 物质条件（**改造对象**） |
| **生产关系** | **谁占有**土地与工具、谁组织生产、经营者凭什么使用、剩余凭什么归谁 | **主体之间的关系**（**改造者**） |
| **上层建筑** | 国家维护哪些占有与契约关系、资源向谁流动 | 外生规则起步 |

### 1.1 核心记录：`ProductionRelation` 扩成"四面"

现有 `ProductionRelation(activity, operator, inputSupplier, rules, residualOwner)`（`economy-api/.../relation/ProductionRelation.java:86-91`）
只有"谁经营、谁出料、怎么分、余额归谁"，**缺三面**：

```
record ProductionRelation(
    IndustryId activity,
    ActorRef operator,                 // ① 谁**实际组织生产**
    Recipient inputSupplier,           // ② 谁出周转料（已有）
    List<CompensationRule> rules,      // ③ 剩余怎么分（已有）
    ActorRef residualOwner,            //    余额归谁（已有）
    // ── 本轮新增三面 ──────────────────────────────────────────
    List<AssetOccupation> occupations, // ④ **谁占有**哪些生产资料（种类 + 数量/份额）★ 不合并进 capacity
    List<UseRight> useRights,          // ⑤ 经营者**凭什么**使用（自有 / 租用 / 共同占有 / 其他 ← 明确枚举）
    LaborSource laborSource)           // ⑥ 这份劳动**怎么来的**（家庭自劳动 / 租佃 / 依附 / 自由雇佣）
```

配套两个新类型（都在 `simos-economy-api` 的 `relation` 包，与既有契约同族）：

```
record AssetOccupation(ActorRef holder, AssetKind kind, long quantity, int sharePerMille)
record UseRight(ActorRef user, AssetKind kind, UseBasis basis, Optional<ActorRef> grantor)
    // UseBasis ∈ { OWNED 自有, TENURED 租用, JOINT 共同占有, OTHER 其他 }  ← fail-closed 枚举
```

★ **两点必须守住**（对应你的裁 1）：
1. **`AssetOccupation` 是独立的一张表，不是把 `Industry.capacity` 改成 `Map<ActorRef, Long>`** ——
   后者只能表达"谁有多少"，**表达不了"地主所有、佃农经营"**（所有与经营分属两个字段）。
2. **`Industry.operator` 与 `ProductionRelation.operator` 目前是两份拼写点**（`EconomyData` 有构造期守卫强制二者相等）；
   本架构把**关系的 `operator` 定为唯一权威**，`Industry.operator` 降为派生/校验面（守卫保留，防漂开）。

### 1.2 分配必须**按关系**、不许**按名字**
现状：`feudal` 的地租规则写死 `ToCohort((hex, LANDLORD))`（`RegimeRelations.java:366-375`）——
**行名叫 landlord 就收租**，这正是你点名要改的："地租应支付给相应土地关系中的权利主体"。

```
改后：地租受方 = occupations[LAND].holder（该格土地关系里的权利主体）
      —— 它是 ActorRef（家户 actor / 庄园 / 其他），由**关系数据**给出，不由阶层名给出
      ★ regime 降级为"初始化关系的模板"：播种时把模板展开成显式 relations，此后**唯一权威是关系**
```

### 1.3 雇佣关系（你的裁 2：「成为商品的是**劳动力**」）
现有 `FIXED_MONEY_WAGE` **能**表达"一笔货币工资"，但**证明不了它对应实际雇佣量**。补两面：

```
LaborSource.EMPLOYED(employer, quantityLaborMilli, rewardRule)   // 谁雇谁、用多少劳动力、报酬怎么算
+ 一个不变量：EMPLOYED 的劳动量 ≤ 该雇主按 useRights 能支配的经营规模所需劳动
+ 产品归属：规则已定＝`residualOwner`（= 雇主），本轮只需**在读数里把"雇佣劳动创造的产出"单列**
★ 保留并存形态：FAMILY_SELF（家庭自劳动）· TENANCY（租佃劳动）· DEPENDENT（依附劳动）· EMPLOYED（自由雇佣）
★ 浮动工资与劳动市场**后做**（你已明确："有雇佣关系不要求先有一套动态竞价系统"）
```

## 二、改动清单（按"关系优先"排，每一步都可独立验收）

### 第 0 步（**先决**）：补回归网 —— 因为你要动的地方**今天没有网**
实测：**`MarketSettlement` 整类零测试**、**偿还链零测试**、**§6.1 主守恒式是纯注释（无一条测试逐项验算）**。
⇒ 动"分配/市场/债务"之前必须先补三条端到端判据，否则改动**静默漂开无人报错**：
1. **关系守恒**：`Σ 各主体所得 = 净产`（逐商品、逐周期），且"所得"逐条能追到一条关系；
2. **市场守恒**：货腿与钱腿成对（`Σ买方实付 = Σ卖方实收`）；
3. **债务守恒**：`Δ本金 = 新借 + 计息 − 偿还`（今天这条**无测试**，而它是裁 5 的前提）。

### 第 1 步：**占有关系**（裁 1 的最小实现）
- `ProductionRelation` 加 `occupations` / `useRights`（新类型 + 构造期守卫：数量 ≥ 0、份额 ∈ [0,1000]、`holder` 非 null）。
- **不动** `Industry.capacity`（它仍是"这块产业能投多少物质条件"）；两者关系 = `Σ occupations[kind] ≤ capacity[kind]`（新不变量）。
- `EconomyChangeSet` 加组件（**铁律 5**：`EconomyRoundTripTest` 的反射守卫会强制）；
  `EconomyCodec`、`EconomyPayloads`（创世载荷接受 `occupations`/`useRights`）、`ApiViews` 读口同步。
- **验收（一年期真档）**：① 每格 `Σ occupations[LAND] = capacity[LAND]`（不多不少，否则 fail-closed）；
  ② 地租受方 = `occupations[LAND]` 的权利主体（**改一条关系就换一个收租人**——这条判据能证伪"按名字发钱"）；
  ③ 田主与经营者可分离：构造一根"地主所有 + 佃农经营"的关系，跑一年，**产出归佃农、租归地主**。

### 第 2 步：**生产组织与劳动来源**（裁 2 + 补 M-4 缺陷）
- `ProductionRelation` 加 `laborSource`；`ClassSlot.laborParticipationPerMille` **接进计算**（修 M-4：
  配额预算从"毛额"改为"**按阶层参与率折扣后的可用劳动**"，即 `min(gross, Σ 各阶层行 × 参与率)`）。
- `EMPLOYED` 的守卫：雇佣劳动量 ≤ 支配规模所需；报酬规则复用 `FIXED_MONEY_WAGE`/`OUTPUT_SHARE`。
- **验收**：① 四档人均劳动**不再齐次**（地主 ≈ 100‰、贫农 ≈ 950‰，差 ~9.5 倍）；
  ② 一根雇佣关系跑一年：工人所得 = 规则约定、产品归雇主、且**在读数里能分开"雇佣劳动产出"与"家庭自营产出"**；
  ③ 家庭自劳动/租佃/依附三种形态**并存**且各自的可分配额不变（回归：`Σ allocated ≤ available` 仍绿）。

### 第 3 步：**再生产**（裁 3：两个不同的决定 + 否决 ⑦）
```
本期生产多少   = 在物质约束内，经营者决定实际开工规模     ← 保留 min(产能,劳动,投入)，**不加**预期利润函数
未来能生产多少 = 通过「维修 / 制造工具 / 建设施 / 开垦」改变生产条件
                 ★ 必须消耗商品 + 劳动 + 时间（**不许"盈余 × 系数 = 产能"**）
                 ★ 购买已有土地只改变归属，**不增加全社会土地总量**
```
- 新记录（最小）：`ReproductionActivity(kind ∈ {MAINTAIN, CRAFT_TOOL, BUILD, RECLAIM}, 投入商品表, 投入劳动, 工期, 目标产能增量)`。
- 落点：`Industry.capacity` 的**运行期写入**（今天是零写入 —— `v3-design:38` 明说"此后永不变动"）。
- 不同主体的目的差异**不写成一个函数**：由 `ProductionRelation` 的规则与 `operator` 种类自然表达
  （自耕农＝维持、庄园＝扩大收租基础、作坊＝增殖、公共＝供给任务）。
- **验收**：① 造一件工具：消耗纤维+劳动+一个周期，`capacity[TOOL] +1`，且**全社会纤维/劳动有对应减少**；
  ② 开垦：荒地 → 耕地，**全社土地总量增加**；③ 买地：`occupations` 变、`capacity` 不变（**这条能证伪"买地=增长"**）。

### 第 4 步：**产品归属的读数**（裁 5：四种现象分开）
- **只加读数，不改账**：逐主体、逐周期报告四栏 ——
  `财富积聚（库存+货币的净增）` / `扩大再生产投入（第 3 步的投入）` / `债权扩张（本金+利息请求权）` / `资本积累（仅当剩余**转化为生产资料**时）`。
- **`经营盈余` 不改名**：术语上**不**把固定价下的收支差直接称为"剩余价值"（你点名的边界）。
- 债权人侧**补齐**：计息时给债权人记一笔"应收利息增加"（今天**两侧都不记**：债务人只并入本金、债权人零）。
- **验收**：① 一年期报表能逐格给出四栏且**四栏之和 ≠ 任一单栏**（能看出你点名的区别）；
  ② 地租/利息/经营盈余**并存不互斥**（同一主体的三栏可同时非零）。

### 第 5 步：**索取（国家）**（裁 6：废二分，保"依据"）
- `SurplusClaim` 加 `basis ∈ {REGULAR_TAX 常规税赋, LEVY 临时征发, PROCUREMENT 政府采购, RATION 公共配给}`。
- `FlowRow.taxPaid` 从"恒 0 的槽"变成**有读者**（它本来就是本协议的槽，`aggregate-economy-v2-design.md:347`）。
- 国家主体用**已有的** `ActorKind.GOVERNMENT` + 一本 `GoodsAccount`（国库）；`WORLDGEN` 给三国各建一本。
- 执行规则**外生**（税率/征发令是 GM 数据，不建完整政治组织）。
- **验收**：① 四种行为各有依据、账上可分；② 同一批粮"按税征"与"按采购"**读数不同**（证伪二分）。

### 第 6 步：**阶级统计（派生）**（裁 0/4：先打通关系，再派生）
- 新读口（**不改任何账、不改 `CohortKey`**）：按**你的表**从"占有 + 劳动参与 + 生活来源"三件事导出类别——
  `地主（控制土地收益、主要靠地租、自身劳动次要）· 富农（自己劳动 + 经常雇工）· 中农（主要家庭劳动、不依赖出卖劳动力）· 贫农（独立经营条件不足、兼靠出卖劳动力）· 雇农/工人（缺乏独立维生条件、主要靠出卖劳动力）`。
- ★ **阈值与观察期写成"版本化查询口径"**（不是永久属性、不冒充原文公式）。
- ★ **不删 `ResidenceKind`**（你明确否决三轴合一：城乡回答"住哪里"、关系回答"怎么组织"、阶级回答"什么地位"；
  城镇可以有地主、农村可以有雇工、一个家庭可以兼三种活动）。
- ★ **阶级标签不再承担永久账户身份**（你点名的实现要点）：阶级变化时**库存/债务/关系必须连续**。
  本轮**最小做法**：账户键仍用现行 `CohortKey`，但**阶级变化 = 一次显式的"账与关系转移"操作**
  （把该群体的库存、债务引用、关系主体一并转给新类别的账户，**留一条转移凭据**）——不重写身份体系即可满足连续性。
- **验收**：① 同一份世界能同时读出"地主 × 城镇"与"雇农 × 农村"这种交叉（现行 `CohortKey` 表达不出）；
  ② 造一次阶级变化（负债失地）⇒ **库存与债务逐值延续**（无凭空消失）；③ 读数与旧标签**可对照**（旧标签降为初始禀赋）。

### 第 7 步：**结构变化**（裁 7：支持变化，**不预设唯一路线**）
- 只实现少数真机制：`负债 → 失地（occupations 转移）→ 佃户 或 雇工`；`债务减免 / 公共救济 / 土地政策` 反向。
- ★ **显式不写**："失地 ⇒ 自动资本主义"、"资本积聚 ⇒ 自动生产力增长"、"必然演化路线"。
- **验收**：① 同一初始世界，用不同政策跑出**不同**结构（证伪决定论）；② 报表能指出每次结构变化的**依据**（哪条关系、哪笔债、哪条政策）。

## 四、两条工程纪律（由本轮实测得出，必须写进实施）

1. **凡落在"市场链"与"偿还链"上的改动，先补判据再动**：这两条链**今天没有任何单测**
   （`MarketSettlement` / `repayDebts` / `LOAN_REPAYMENT` 命中 0）。⇒ 本架构的**第 0 步**是补三条守恒判据。
2. **死数据清理与本次改造分批**（不要混在一起）：安全子集（有测试可改、删的是读口能看见的死数据）——
   `ClassRow.money`（恒 0 却仍在发栏）· `ClassRow.effectiveDemand`（市场现算不看它）· `Industry.allocation`（结算明文称死数据）·
   `Industry.dailyInputPerUnit/dailyLaborPerUnit`（零读取点）· `Weight.EQUAL`（公式表必然抛）· `Basis`（旧档专用）。
   **不同批**做的：`Debt.dueCycle/defaulted`、`Transfer.settles`、多日静态入口（都在无网链上）。
3. ★ **幻影判别力第 4 例**（顺带记）：注释点名的 `EconomyRealScaleClothTest#probeFibreAccountsPerCycle`
   **在仓库里不存在**（全仓只命中那条注释）。⇒ 引用"某测试守着它"之前**先核它存在**。

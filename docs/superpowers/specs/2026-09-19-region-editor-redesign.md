# M8-R spec —— 区域编辑器重做（参照 GSimulator Province 编辑器）

> 状态：**待执行**。日期：2026-09-19。缘起：用户「**区域编辑器手感十分稀烂**」+ 四条要求（右键框边界创建 / 选中区域边界显示可拖拽小点 / 左键拖动改右键拖动 / 取消选区勾选模式 / 加合并·剔除按钮）。
> 取证：4 路（GSimulator 右键创建 / GSimulator 顶点拖拽 / GSimulator Province 全貌 / simos 现状）已完成，**结论见 §一**。

## 一 ★ 取证结论：用户的记忆准确，且指向 **Province（区域）编辑器**

| 用户要的 | GSimulator 的实际实现（**区域**，不是地形块） | 出处 |
|---|---|---|
| **右键框边界直接创建** | **右键拖拽自由套索**（不是轴对齐矩形）→ 从质心 seed **flood fill 内部** → 建区域 | `events.js:3-9`、`province.js:230-238,249-293` |
| **选中区域 ⇒ 边界可拖拽小点** | ★ **小点画在"边界 hex 的中心"**（`arc(x,y,5/zoom)`），仅对**选中编辑中**的区域渲染；拖动 ⇒ **增删 hex** | `render.js:335-346`（画）、`events.js:33-40,63-79`（拖） |
| **合并** | `⚔ 吞并`（**annex 语义**，不是几何并集）：hex 并入 dominant，被吞并方保留数据 + `annexedBy` | `province.js:296-392`、`MapService.mergeRegions` |
| **剔除** | ★ **没有"区域差集"按钮**——只有**逐格移除**（拖点 / MCP `remove_hex_from_region`）与 `🔄 重圈`（整份替换 hex 集合） | `events.js:71`、`MapService.removeHexFromRegion`、`province.js:166-179` |
| **是否有显式模式开关** | **没有**——由**按键**决定（右键=套索，左键=画笔） | `events.js:2-9, 92` |

**GSimulator 的 Province 模型**：`record Province(List<String> hexes, String color, String tag, String description, String annexedBy)` —— ★ **只有 hex 集合，没有任何多边形边界**；边界是**渲染时**由 `computeBoundaryHexes`（"有邻格在区域外的 hex"）临时算出的；**没有 name 字段**（名称 = `provinces` map 的键）。

★ **它创建/删除/改色都走"改内存 MapData + 整份 PUT 保存"**，只有 `merge-regions` / `rename-region` 两个专用端点。

## 二 ★★ 两个"我以为的障碍"被证伪（**必须记账**）

1. **控制器原以为"拖顶点要栅格化成 hex 集合"** ⇒ **前提错误**：GSimulator 的小点**本来就是 hex 格点**、拖动**本来就是增删格**。⇒ **simos 的 `Region` 硬约束（`boundary == RegionBoundary.of(hexes)`，构造期强制）与这套交互天然一致**，**不需要"多边形顶点"这种东西**。
2. **控制器原以为"合并/剔除需要新命令"** ⇒ **不需要**：两者都只是**换一个 hex 集合**，`map.UpdateRegion{regionId, hexes}` 完全够表达。

## 三 设计（simos 落地）

### 3.1 交互表（取代 M8 T10 的旧交互）

| 操作 | 语义 | 落点 |
|---|---|---|
| **左键拖动（区域编辑模式）** | ★ **保留**：逐格画/擦（**飞地**等非凸形状唯一手段） | 现有 `draftKeys`/`commitRegionPaint`（改为一条 `CreateRegion` 或 `UpdateRegion`） |
| ★ **右键拖动（区域编辑模式）** | **自由套索 → flood fill 内部 → 一条 `map.CreateRegion`** | 新实现（照 GSimulator `finishProvinceLasso`） |
| ★ **选中区域 ⇒ 边界小点** | 边界 hex 中心画点（仅选中编辑中的区域）；★ **拖动 = 增删格** | 新实现（照 `render.js:335-346` + `events.js:63-79`）；提交**一条 `map.UpdateRegion`** |
| ★ **合并按钮** | 临时选区 ∪ 选中区域 ⇒ `UpdateRegion{hexes: union}` | **无需新命令** |
| ★ **剔除按钮** | 选中区域 − 临时选区 ⇒ `UpdateRegion{hexes: difference}` | **无需新命令** |
| **删除** | 二次确认 ⇒ `map.DeleteRegion` | 已实现（T10） |
| **焦点区域原色 / 其它淡色** | 保留 | 已实现（T10） |

### 3.2 ★ 必须删掉的东西
- **取消"是否进入目标选区"勾选框**（`paintEnabled` 那个显式开关）——**模式由按键决定**，不靠勾选进入（用户原话）。
- 左键拖动语义**改为**"逐格画/擦"（不再需要"绘制开关"来启用）。

### 3.3 右键冲突（**必须按模式分派**）
- **常规 / 单位移动编辑**：右键 = `unit.PlanRoute`（现状，**不许变**）。
- **区域编辑**：右键 = 套索创建（新）。
- ⇒ 分派点在 `map.js` 的 pointer 处理 + `modes.js` 的模式判定；**要有断言**（按模式打印非 GET 清单）。

## 四 判据（M8-R 完成 = 逐条实测）

1. ★ **右键拖动 ⇒ 一条 `map.CreateRegion`**：拖一个闭合套索 ⇒ 提交**恰 1 条**、`head` +1、新区域 hex 集合 == **flood fill 后的集合**（给 hexCount）。
2. ★ **选中区域 ⇒ 边界小点出现**（可断言：点数 == `computeBoundaryHexes` 长度）；**非选中区域不画点**。
3. ★ **拖小点 ⇒ 一条 `UpdateRegion`**，hex 集合前后值可对（增格/删格各一例）。
4. ★ **合并按钮**：临时选区 ∪ 已选区域 ⇒ `UpdateRegion`，**结果 hex 集合 == 并集**（逐值）。
5. ★ **剔除按钮**：已选区域 − 临时选区 ⇒ `UpdateRegion`，**结果 hex 集合 == 差集**（逐值）。
6. ★ **勾选框已删除**（DOM 里不存在），左键仍能画格（一条命令）。
7. ★ **右键不冲突**：常规/单位移动编辑模式下右键仍是 `unit.PlanRoute`（**不退化**）。
8. **不退化**：T10 的重叠正例（重叠仍允许）、删除二次确认、焦点淡色、M9 块渲染、T7 白名单（区域编辑非 GET ⊆ 区域命令）、0 `pageerror`。

## 八 ★★ 裁定（2026-09-19，用户）—— 边框与区域边界

**用户原话**：「**区域边界太过于死板**，**地形区之间有黑色的间隔**，**区域中每一个hex都有边框，边框应仅存在于区域边界上**」+ 追问裁定「**只画区域边界**」。

### 8.1 裁定
1. ★ **逐格网格线全部删除**（现在每个 hex 都被描黑边 ⇒ 看起来到处是黑线/黑缝）。
2. ★ **边框只画在"区域"的边界上**；**地形块之间不画线**（不同地形只靠**颜色**区分）。
3. ★ **区域边界不要"死板"**：现在是**紧贴 hex 边缘的台阶**（逐格折线）；要**简化/平滑**（照 GSimulator `TerrainGeometry.simplifyBoundary` 的 **RDP** 思路，压掉冗余顶点）。

### 8.2 ⚠️ **必须先查清的事实冲突（不许跳过）**
- **M9 T13 的关账报告声称**：边框已"**沿块环一条 `Path2D`**"（`borderChunk=64`），**不再逐格**。
- **用户实测所见**：**每一个 hex 都有边框**。
- ⇒ **两者不可能同时为真**。**实现者必须先查清"到底是哪一层在逐格描边"**（候选：地形层残留 / 区域高亮层 / 网格层 / 选区预览层），**给出文件:行 + 证据（截图或 stroke 调用计数）**，**再动手改**。
- ★ **不许在未查清前假定 T13 的声称成立**（这正是"我验过了 vs 我记得是这样"要分开的场合）；若发现 T13 的声称有误，**如实记账**。

### 8.3 判据（追加）
- **判据 11**：地形/区域渲染路径**不再有逐格 `stroke`**（给可观测证据：stroke 调用数 / 逐格描边代码不存在 / 截图不再有格线）。
- **判据 12**：**区域边界被简化**——边界顶点数**显著小于**"逐 hex 台阶"的顶点数（**给数字**）；且边界仍**闭合**、仍**包住**该区域的 hex 集合（可从多边形反查/or 目视 + 截图）。
- **判据 13**：**地形块之间无线**（相邻不同地形块之间没有黑线；给像素采样证据）。

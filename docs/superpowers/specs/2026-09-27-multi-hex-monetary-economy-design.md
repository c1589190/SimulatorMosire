# 多 Hex、多币种货币经济系统设计

日期：2026-09-27。性质：基于当前会话中报表与实现调查提出的设计方案，尚未对仓库实施或进行性能实测。

## 1. 核心裁定

采用“主体分账、区域市场、稀疏运输网络、分层货币工具、事件驱动债务、统一原子结算”。

1. 商品存放在具体 Hex；资产与债权归属于稳定主体；阶层只是统计分类。
2. 币种定义计价单位；货币工具定义银币、国币或某家银行的存款，二者分开。
3. 同一币种可以跨国家使用；一个国家也可以接受多个币种。市场区、行政区和货币区不强制重合。
4. 不逐户全世界找买家；先聚合同格订单，再在区域撮合，跨区域只搜索少量相连市场。
5. 商品移动有运量、时间、损耗和费用；支付和货运是两个独立过程。
6. 普通借贷搬移已有财产；货币发行和银行创造存款走明确的专用结算类型。
7. 先让已有资金和真实产品形成循环，再启用国家发行和银行信用；发行不能替代运输、原料和企业收入。
8. 简化应减少参与者数量、撮合范围和结算频率，不删掉交易对手、产品去向和资金来源。

第一版范围：多币种钱包、经营者入市、跨 Hex 商品运输、有库存约束的换汇、双向债权、政府收支接口。完整银行存款创造随后接入；基础数据结构从第一版支持其身份。

## 2. 对当前调查的必要更正

### 2.1 贸易与粮食

用户提供的同周期汇总：缺口 10,129,798，余量 26,931,071，净余 16,801,273，余量/缺口约 2.66。这说明在该核算口径下存在总量调剂空间，尚不能证明缺粮只有分配一个原因。

还需核实：余量是否扣除了种子与保留库存；收获和消费是否同一时间窗；是否跨国且存在贸易限制；路线能否及时运到；经营者是否愿意出售；买方能否支付；运输损耗后的可达数量是否仍够用。

最大城市周期缺口 2,561,031，最大单格余量约 84,000；即使每个供应格都达到最大值、没有损耗，也至少需要 31 个这样的格，真实所需通常更多。120 天均摊是约 21,342 单位/天；不能用一次邻居转移代表这座城市的供给。

自给率是诊断读数，不是城市必须通过的“≥100%”创世门槛。城市可以依靠农业腹地；创世应检查进口通道、支付来源和首批到货前库存。

### 2.2 货币与信用

- 账户名为 silver，不足以证明商品货币已经实现。若没有含银量、铸造、熔毁或兑现约束，只能称为以银命名的记账货币。
- 信用额度等于“预计收入的一倍”，不等于“一个周期口粮”。收入与消费需求是两个量。
- 城镇缺粮，首先需要成为借款方并接触有余粮/资金的债权人；允许城镇放贷本身不会增加其借款可得性。
- 普通粮债不自动成为货币。只有满足可转让、可支付、被交易方接受等条件的支付工具，才进入相应货币统计。
- 政府支出可以来自税收余额、借入资金、出售资产或货币发行。不能把每一笔政府支出都当发行。
- 税收转入国库通常首先是余额转移；是否进一步注销相应货币，是另外一项制度与记账操作。
- 国家发行货币与商业银行创造存款是两套不同机制；不应把“国库允许负数”当成所有信用货币的统一原理。
- 私人流通余额、全部基础货币余额和银行存款余额必须分开统计；排除国库和准备金后，不能继续套用全部持有者的守恒式。

英格兰银行与欧洲央行对现代银行货币的说明支持“银行贷款同时创造存款”及“中央银行货币与商业银行货币分开”的概念。本设计不照搬特定国家全部制度。[1][2]

## 3. 最小领域对象

以下是逻辑对象，不要求分别新建 Java 模块或数据库表。先通过现有接口和切片实现；模块依赖需另查仓库，不能据此直接移动代码。

| 对象 | 关键内容 | 唯一职责 |
|---|---|---|
| CurrencyDef | id、名称、整数精度、记账单位 | 定义金额的单位 |
| MoneyInstrument | id、currencyId、kind、issuer、结算方式、兑现规则 | 区分基础支付工具与各银行存款 |
| FinancialAccount | 稳定 owner、instrumentId、余额、冻结额 | 记录某主体可支付的余额 |
| GoodsAccount | owner、hex、commodity、数量、冻结数量 | 记录实物所在地和归属 |
| Claim | id、债权人、债务人、计量对象、本金、应收利息、期限、利率规则、状态 | 一份债权同时生成双方视图 |
| MarketRegion | 成员 Hex、集散节点、报价币种、接收工具、价格表 | 定义撮合与报价范围 |
| TradeRoute | 起终点、货运能力、旅行时间、费用、损耗、通行规则 | 限定物流可行性 |
| FxDealer | 多币种库存、报价、价差、兑换额度 | 提供有资金约束的换汇 |
| ShipmentBatch | 路线、商品、发运/到达日、在途数量、收货分配项 | 表示已经离开发货地的商品 |
| SettlementBatch | 唯一编号、预留资源、全部变动分录、提交状态 | 原子提交一次结算 |

普通账户余额保持非负，且 `0 <= 冻结额 <= 余额`。债务不是钱包负余额，而是 Claim。允许借款时，先创建合法债权与相应余额变化，再消费。

同一主体可以拥有多个工具余额，例如持有国币和某银行的本币存款。这些余额是不同资产，不是同一份钱的重复副本。

对现有 GoodsAccount.money，可先保留对外兼容读口，但底层只保留一份余额权威。若未来独立金融切片，旧字段必须成为查询投影或完成迁移，不能两处可写。

### 3.1 币种不等于银行

| 例子 | CurrencyId | Instrument | 含义 |
|---|---|---|---|
| 帝国银元 | imperial_silver | silver_coin | 含银币支付工具，若启用金属机制则受铸造约束 |
| 帝国国币 | imperial_note | treasury_note | 独立计价的国家发行货币 |
| 甲银行的国币存款 | imperial_note | bank_a_deposit | 甲银行以国币计价的存款负债 |
| 乙银行的国币存款 | imperial_note | bank_b_deposit | 乙银行以国币计价的存款负债 |
| 侯国铜元 | margraviate_copper | copper_coin | 另一币种的支付工具 |

如制度规定国币与银币共享同一计价单位，二者可改为同 CurrencyId 下不同工具；但兑现比例、可兑额度与违约不能因共享单位而被省略。

跨币种兑换与同币种跨银行支付是两种操作：前者需要外汇，后者需要银行间结算。

### 3.2 资金位置与历史背景

记账位置不等于现实可即时支付的范围。

- 启用账户结算网络时，FinancialAccount 不随主体移动重建；可达性、结算时间和费用由支付网络规则控制。
- 启用实物钱币模式时，使用带保管地点的现金子账户；跨区钱币也进入在途保管账户，不能从遥远钱包即时付款。
- 第一版可在同一市场区抽象即时清算，跨区配置结算延迟；如暂时把跨区结算也设为即时，必须在场景配置和报表中标明这一简化。
- 金属货币若支持铸熔，铸币必须扣除金属商品，熔毁必须扣除钱币余额；不得让同一批银同时作为商品库存和钱币余额使用。

## 4. 统一结算与守恒

### 4.1 交易分类

| 操作 | 实物/支付余额变化 | 债权与发行变化 |
|---|---|---|
| 普通支付 | 付款者 -x，收款者 +x | 不改变该工具总余额 |
| 已有货币贷款 | 出借者 -x，借款者 +x | 建立同额债权/债务 |
| 粮食贷款 | 出借者粮 -q，借款者粮 +q，跨格则先入在途 | 建立粮债，不创造支付货币 |
| 国家发行 | 指定接收账户 +x | 该基础工具累计发行 +x |
| 国家注销 | 被注销账户 -x | 累计注销 +x |
| 征税到国库 | 纳税者 -x，国库 +x | 默认不注销 |
| 国库花已有钱 | 国库 -x，收款者 +x | 默认不发行 |
| 换汇 | 两种货币分别在客户与兑换商之间转移 | 不凭报价生成任一币种 |
| 银行贷款创造存款 | 借款者存款 +x | 银行贷款资产 +x、存款负债 +x；借款者贷款负债 +x |

发行人的权限仅适用于被授权工具与政策额度。发行登记不能通过任意转账或负余额自动触发。可以提供“发行并支付”的组合命令，但内部必须保留发行与财政支出两种经济含义。

基础工具按工具分别验证：

`所有持有账户余额之和 = 创世余额 + 累计发行 - 累计注销`

“所有持有账户”包括国库、银行准备金、商人、运输者、冻结与在途保管账户；冻结额属于余额的一部分，不再次相加。发行控制计数不作为可花钱包计入持有量。

银行存款按银行验证：

`外部客户存款账户合计 = 银行存款负债`

并验证银行 `资产 = 负债 + 权益`。多币种资产负债估值采用同一估值时点，汇兑估值变化记入相应权益/损益投影，不改写钱包原币余额。

全世界没有“一切货币总量永远不变”的总不变量。应明确区分基础货币、非银行持有现金、银行准备金与存款，不能把银行准备金和其支持的客户存款简单相加当作公众可花余额。

### 4.2 原子性和确定性

每一结算按“冻结资源 → 验证双方及路线条件 → 一次提交全部分录 → 释放预留”完成。商品交付、货款、运输费、换汇如互为成交前提，必须在同一结算批或明确的补偿流程内处理。

不得先给一方加钱、下一天再扣另一方；不得使用会话退出时整本覆盖的方法把已提交收入抹掉。

跨市场共享的钱包必须先分配预算或取得统一预留。地区并行不能各自看见同一余额并全部消费。

稳定排序键可采用 `(tick, phase, regionId, operationKind, stableActorId, sequence)`。同额订单通过明确比例分配及最大余数法处理；不能让线程完成顺序决定谁买到粮。

在相同初态、政策、随机状态和结束阶段下：一次推进360天，与三次推进120天，全部余额、库存、债权、在途和累计流水必须相同。批次边界不重置经济时间或改变经济行为。

## 5. 商品市场：主体预算、区域撮合、稀疏跨区交易

### 5.1 参与者

所有满足资格与结算条件的主体都可提交订单：家户、庄园、作坊、商人、政府、运输经营者。贫农、中农、地主等统计标签不承担硬编码资格开关。

家庭先提出消费需要；经营者提出投入需求、生产资料维护需求和产品出售意愿。交易主体必须拥有相应资金或可支配产品；不能直接把整个 Hex 的库存当公共池。

每个买单至少记录：主体、收货 Hex、商品、需求量、最高到货单价、最晚可接受到达日、预算与支付工具。每个卖单记录可支配库存、发货 Hex、最低出售价、供货时点和收款工具。

家庭订货量可用：

`max(0, 下次可补货前的消费预测 + 安全库存 - 现有可用库存 - 该时限前确定到货)`

预算独立计算，不用消费需求直接冒充信用额度。库存已经售出、作为生产投入冻结或处于在途的部分不得再次出售。

### 5.2 区域不是一个免费瞬移的大仓库

以交通连通性形成市场区，不强制按国界划分。每区有一个或少量集散节点，预计算成员 Hex 到节点的路线信息。区域边只连接实际可通达且允许贸易的邻接区域，必要时包含港口和河运连接。

区内报价和撮合可以聚合，但仍要计算从卖方到集散点、跨区、从集散点到买方的旅行时间、费用及能力约束。区内实际同地交割可即时，其他交割按路线到货。

第一版每个区域只考察直接邻接供应区；后续允许至多 L 条备选路线，或从实际存在的可达市场中选取候选。候选范围和失配须在报表里可见，不能把算法没搜索到当作世界没有余粮。

### 5.3 一轮撮合

1. 对所有订单冻结预算与卖出库存，按 `(region, commodity, price bucket/limit)` 聚合；保留订单来源索引。
2. 先匹配适合区内交付的订单，再把剩余报价送入跨区候选网络。该优先级是明确的近域优先近似，不保证全局最优。
3. 判断候选交易的到货价格、预计到货量、期限、边境规则和支付可行性。
4. 在有限轮数 I 内分配路线余量和卖方库存；共享道路按各商品重量累计占用能力，不能每个商品都独享整条道路容量。
5. 将聚合成交量按原始限价和预算分配回主体，复核到货单价未超过买方限价。
6. 原子结算发货、支付和费用，建立在途批次。未成交的冻结资源释放。

聚合只压缩搜索，不混同主体财产。固定次数局部撮合可能漏掉有利交易，应输出“未成交原因”和未利用的可达运力，不宣称求得一般均衡。

### 5.4 运输成本拆开

| 要素 | 经济作用 |
|---|---|
| 运费 | 货币转给运输主体，是其收入 |
| 运输实际投入 | 扣除运输使用的劳动、饲料、燃料或维护品 |
| 损耗 | 在途实物减少，计入损耗账户/流水 |
| 时间 | 形成未来到货，不能提前消费 |
| 运力 | 限定路线每段时间最多发运的重量 |
| 税费/关税 | 转给具体征收主体，单列依据 |

地形系数只能作为上述某项模型的参数；不得把无量纲的1.5系数同时当成运费、耗粮比例和速度惩罚。

基线合同：发运时买方支付货款和运费，货物所有权转给买方，实际进入其在途资产；卖方库存减少；到达时在途减少、目的地库存增加，约定由买方承担运输损耗。其他风险分担可以后续扩展。

按 `(route, commodity, dispatchTick, arrivalTick, riskRule)` 合并 ShipmentBatch，内部保留精简的主体数量分配项。不能为了聚合丢掉损失由谁承担的信息。

## 6. 价格、购买力与多币种兑换

### 6.1 商品价格

第一版每个区域、商品有一个本轮固定报价和有限买卖价差。订单按限价过滤，在下一次市场轮更新参考价格。

建议的简单适应规则：

`z = clamp((有预算且合限价的需求 - 可出售供给) / max(需求 + 供给, epsilon), -1, 1)`

`p_next = max(p_min, round(p * (1 + alpha * z)))`

alpha 可从每轮不超过5%的试验值开始，属于待校准参数，不是经验定律。用定点数实现。没有订单时保留旧价或采用单独陈旧报价规则；不在一次撮合内无限循环寻找均衡。

生理需要和有效需求分别记录。穷人没有购买力时，有效需求可能很小，不能因此报告“无人缺粮”。预留固定价格模式，便于先验证真实资金与物流，之后才开启价格调整。

### 6.2 多币种

一个市场区指定一种主报价币种，同时配置接受哪些支付工具。合同使用明确的计价币种；持有其他币种的主体需找到兑换渠道或得到卖方明确接受。

第一版采用固定/政策给定汇率，但换汇受兑换商真实余额限制。不存在“查到汇率即可凭空换到外币”的操作。

例：1银元=2铜元，兑换商收取铜元费用。买方付10银元；兑换商收到10银元并付出不超过20铜元扣费后的金额。两币种分别守恒，费用留在兑换商账上。兑换商铜元不够，则部分兑换或拒绝。

### 6.3 避免币种两两求解

以少量实际存在的中心兑换币组织报价树/稀疏兑换图，常见路径至多两跳；每一跳均有真实对手和库存，冻结全部腿后提交。若中心币不可兑换，则该路径不可用。

另设纯报表的估值基准，供跨币种比较；它可以与交易中心币相同，也可以只是统计单位。报表换算不产生交易、不保证兑换、不改变钱包。

若 e_c 表示每单位币种c折合多少估值单位，参考交叉价为 e_a/e_b，再加入公开价差。保持同一时点同一套参考价，避免只因舍入或互相矛盾的报价产生无风险循环获利。真实地区价差和运输套利可以存在。

第一版优先固定汇率、有限库存；之后可加入限幅、低频更新的浮动汇率。固定汇率维持失败时应拒绝/限量或触发政策变动，不能为守住汇率自动发行外币。

外币债务始终用合同币种记录本金。汇率变化只改变报表估值和筹资负担，不直接增加借款者钱包或改写原币本金。

### 6.4 定点单位

Amount 一律为整数最小单位，明确 `currencyId` 与精度。价格用“货币最小单位/商品最小单位”的有理数或定点比率，换汇采用有理报价并检查乘法溢出；必要处使用宽整数/BigInteger中间结果。

舍入残差由明确的清算尾差账户承接，或者保留到同一合同下次结算；不得在双方同时向下取整后让钱静默消失。市场聚合分配采用最大余数法保证合计一致。

## 7. 债务与银行

### 7.1 先做完整的已有财产借贷

Claim 是一份权威记录，债务人负债和债权人应收由它生成。计息只增加相应应收/应付，不自动增加可花余额；利息资本化须显式配置，仍不等于发行货币。

借贷额度分别受借款者未来可偿还收入、已有债务、期限和出借者资源约束。粮贷用可支配粮，货币贷用可贷货币。不同计量对象必须有明确估值规则，不能裸 long 混算。

不按阶级名称筛选放贷者。采用角色权限、可支配余额、风险规则和双方可达性。中农可以缺粮，城镇也可能有资金充裕的商人或机构。

基线可保留“用本期收入的某比例偿还”，但明确它是简化的合同条款；同时记录到期额、实际支付、逾期额。不能把永远偿还收入20%当成对所有贷款永久有效的自然规律。

违约至少经历 到期→逾期→重组/减记/最终豁免。债权人减记资产不必自动免除债务；最终豁免则必须同时终止双方相应请求权与负担并记录损失，不能只清借款人的记录。债权原额、减值和可追索额分别定义，避免在一份 Claim 中混用法律余额与会计净值。抵押物执行依赖产权与制度规则，在该机制未实现前不要生成无法执行的抵押承诺。

### 7.2 银行存款创造：第二阶段启用

银行工具身份在第一版保留，第二阶段加入资产负债表、贷款创建、跨行准备金清算与违约损失。

最小事件例：

| 事件 | 银行账 | 客户账 |
|---|---|---|
| 新发100本币贷款 | 贷款资产+100；存款负债+100 | 存款+100；贷款负债+100 |
| 同银行客户之间支付40 | 总存款负债不变，持有人变化 | 一方-40，另一方+40 |
| 用本行存款归还本金10 | 贷款资产-10；存款负债-10 | 存款-10；贷款负债-10 |
| 计提未付利息2 | 应收利息+2；按选定会计规则确认收入/权益 | 应付利息+2；可支付余额不变 |
| 同行存款支付银行利息2 | 存款负债-2；已计提应收利息-2 | 存款-2；应付利息-2 |
| 贷款核销5 | 贷款资产-5；权益/损失准备相应减少 | 按核销是否免除债务的规则处理；不能默认为已付款 |

坏账核销和债务法律豁免要分开：银行可以减记资产而债务请求权仍存在；双方最终免除时再终止 Claim。系统应明确采用哪一种，而不是让“核销”含义摇摆。

银行既有存款不会因某一笔贷款违约自动删除。银行支付工资、采购等可把自身收入对应的支付能力重新分配出去，不能将银行收息一律套成普通非银行之间的余额搬移。

跨行支付需减少付款行的结算资产、增加收款行结算资产，同时调整两行客户存款负债；同币种不意味着跨行准备金可以凭空出现。

扩展银行体系后，按币种汇总银行间净额，验证每家银行能履行其净借记义务，再原子提交整个可行清算批。不得在已最终交付商品之后，才以准备金不足撤销货款。简单第一版可预先按可用准备金限制跨行支付额度；完整多边净额在后续启用。

银行至少受资本/权益、信用损失、结算流动性和政策额度约束。可以先使用可配置的简化上限，不需要一开始实现整套现代监管标准，但不能只靠“允许存款账户增加”无限放贷。

## 8. 国家与货币发行

政府是普通经济主体，另有被制度授权的发行操作。Treasury（国库）和 Issuer（发行人）可以由同一 Actor 承担，但在结算类型上保持区别。

国家现金循环：收税→国库余额增加→支付公共工资/采购/救济→接收者余额增加。只有显式 ISSUE 增加工具总量，显式 REDEEM 才减少。

每个发行工具可配置：授权发行主体、每期上限、适用用途、实物/金属约束、兑换承诺、接收范围。政策选择可以是金属币、不可兑国币、可兑凭证；不能默认所有国库都能发行所有币种。

税种至少记录税基、税率、计税期、计价币种、接受的支付工具、纳税人和收款政府。实物税也可以复用商品转移而不增加货币。

国币被接受纳税可以构成其需求来源之一，但不能据此假定全国所有卖方都自动愿意按固定比例收取新币。市场接收规则和价格必须显式配置或逐步演化。

城市“工资只够3.8天”首先需要分解为企业缺销售收入、资金周转缺口、初始余额不足或生产停工。国家可以采购、救济和提供特定融资，不能将企业永久依靠财政发行续命写成默认闭环。

政治经济学报表应持续记录：谁取得货币、谁取得产品、谁承担债务和汇率损失、谁承担税负、发行受益者与价格变化。行业和阶层结果由实际关系与账目导出。

## 9. 时间安排与结算阶段

以下为可校准的初始配置，不是历史事实：

| 过程 | 建议初始频率 |
|---|---|
| 到货、消费、生产进度、人口机制 | 每日或精确到期事件 |
| 商品撮合 | 每5天；粮食库存低于阈值可触发追加轮次 |
| 工资发放 | 每5天或合同到期，事先定义工价对应的劳动量 |
| 生产收获 | 保持各产业自己的周期，例如120天 |
| 税收 | 每30天或收获时，按税制配置 |
| 债务计息与到期 | 合同事件；2%/120天不得误用成每5天2% |
| 价格/汇率更新 | 商品价每市场轮；汇率可更低频 |
| 快照 | 每30天及关键变更点；中间保存增量 |

基线日阶段：

1. 处理今日到货、生产完工与实物分配。
2. 执行到期工资等合同支付，确定今日可用余额；登记到期税债。
3. 在需要的市场日生成消费与投入订单，按信用规则处理本轮新增借贷和换汇预留。
4. 撮合并原子提交；本地即时交割可供当日使用，跨格货物按真实 ETA 入在途。
5. 消费与记录未满足需求，更新饥饿等累积状态。
6. 按明确优先级和保留额支付债税；处理逾期和利息事件。
7. 输出不覆盖历史的日/周期累计流水与快照。

这是“最低生存保留后偿债”的基线政策，不是适用于所有制度的自然顺序。允许配置强制税租优先等不同规则，并在报表展示其后果。阶段依赖要固定，批次调用不能重排。

饥饿后果依赖实际每日满足和累积状态，不能只拿周期末累计缺口当日扣人口。播种投入与口粮竞争须保留明确的经营决策/保留规则。

## 10. 性能策略与复杂度

### 10.1 减少搜索面

设 N为Hex数，A为聚合主体数，K为活跃商品数，R为市场区数，E为区域路线数，O为实际订单数，D为当日到期债务/到货事件数。

- 扫描与生成需求：约 O(AK)，只为有需求/可售货物的主体生成订单。
- 按市场商品排序撮合：约 O(O log O)；可用固定价格档降低排序成本，但必须复核原始限价。
- 跨区候选分配：固定 I 轮时约 O(I E K)，另加候选路线/订单索引成本；不是全局最小费用流最优解。
- 金融与到货事件：时间轮/到期桶约 O(D)，或堆实现 O(D log D)。禁止每日遍历全部历史债条。
- 不进行 N² 格对搜索，更不进行 A² 主体对搜索。

规模示意而非实测：N=10,000、每格8个人口聚合组时已有80,000组；K=5对应约400,000个主体商品检查。若R=200、区域边E约800，I=2，则跨区分配核心约8,000个边商品轮检查，实际还需计算订单排序、预留、落账与货物分配。

不能据这些计数承诺具体毫秒数。真实基准需要包含序列化、债条分布、跨行/换汇、运输拥堵和持久化。

### 10.2 缓存与增量

- 路线距离、ETA基准和路径权重缓存；道路、封锁、地形或运输技术改变时失效。
- 仅缓存不变的路线信息；共享运力和已冻结运量必须按当前轮更新。
- 债务按同债权人/债务人/计量对象/利率/期限/担保/优先级合并兼容分段。不能把不同期限和利率直接相加而丢掉合同。
- 已结清债务移出活跃索引，历史仅存摘要/事件，不再参加每日计算。
- 在途货运按路线、商品与到达日合批，保留主体份额。
- 余额累积到内存工作状态后提交增量，不每个tick序列化整个世界。
- 固定枚举/注册表映射成整数索引，活跃货币工具用稀疏结构；不建立主体×全部币种×全部银行的笛卡尔积。

### 10.3 并行边界

各区可以并行做只读需求分析、报价与候选生成。跨区匹配、共享预算与运力必须通过预留和阶段屏障协调；提交时按账户/资源确定性分区或使用单一有序提交者。

接入贸易后，不能再说“799格互不依赖”。可利用并行的是阶段内无冲突任务，跨格状态存在真实因果关系。

## 11. 观测与验收

### 11.1 每格粮食诊断

同时输出：

1. 生产自给率：同一预测期内本地净粮产出/消费需求。明确是否扣种子与生产损耗。
2. 可用库存覆盖天数：扣除冻结和不能及时到货部分，按当前消费速度计算。
3. 预计进口需求：预测消费及必要保留减去可用库存、确定到货和保守预测产出。
4. 有效购买力缺口：按当前可成交到货价计算的所需预算与可用预算之差。
5. 物流缺口：供应地确有可售余粮，但运输时间或能力不满足的数量。
6. 币种/支付缺口：缺少被接受的工具、外汇库存或支付清算能力。
7. 实际满足率与未满足人日：用实际交付与消费计算，不能用下单数代替。

把未成交主要原因记录为缺实物、缺购买力、缺外汇、缺运力、到货太晚、限价不合、贸易限制、算法候选未覆盖等。原因可以复合，统计时区分主要原因与重叠标签。

### 11.2 最小经济闭环场景

| 场景 | 必须出现的行为 |
|---|---|
| 两格同币种：农村有粮、城市有钱 | 实际运到后才能吃；钱到卖方与运输者，商品和费用都有来源 |
| 两格两币种，有兑换商 | 换汇两币种分别守恒；余额不足导致部分成交/拒绝 |
| 世界总粮够、道路运力不足 | 城市仍可能缺粮；系统报告物流瓶颈 |
| 有商品、有道路、买方没钱 | 缺购买力；不自动创造购买资金 |
| 作坊买农村纤维，再卖产品买粮 | 投入和产品均经经营者账户，能够形成销售收入循环 |
| 政府收税再支出 | 未显式发行注销时，该基础工具总余额不变 |
| 政府显式发行100、注销20 | 工具持有余额净增80，税收额单独统计 |
| 银行贷100、客户归还本金10 | 对应贷款与存款按规则变化；普通私人贷款不得复制此发行行为 |
| 同一天一次推进与分段推进 | 金融、实物、在途、债权和累积流量逐项一致 |
| 同一钱包同时在两个区买货 | 总支出不超过已预留预算，不出现负余额 |
| 银行坏账 | 银行承担损失，客户存款不因该坏账被无条件删除 |
| 全系统连续360天 | 能解释各币种余额变化、商品去向和债权变动，不能只验编译通过 |

这些是后续实现的行为验收条件，本文件未声称它们已经在当前仓库通过。

## 12. 建议落地顺序

| 阶段 | 内容 | 退出条件 |
|---|---|---|
| M0 | 修复推进路径差异、明确单位/统计窗口，补自给率与缺口原因 | 同初态同终点一致；现有表能对账 |
| M1 | 币种/货币工具身份、唯一金融余额、预留与原子转移；借贷补齐双方视图 | 多币种支付守恒，不能双花，债权债务同源 |
| M2 | 家户和经营者入市、区域撮合、在途与运输能力 | 两格粮布/纤维循环成立，不靠财政兜底 |
| M3 | 固定汇率的有限库存兑换商、多国接收规则 | 两币种跨区贸易成立，缺汇能被识别 |
| M4 | 国库、显式发行注销、税收支出、可配置价格 | 财政、发行、价格分别可解释 |
| M5 | 银行存款创造、跨行结算、损失与资本约束 | 信用扩张和金融风险都有对应账目 |
| M6 | 浮动汇率、更多贸易路径、复杂融资政策 | 只针对已确认的模拟需求增加复杂度 |

债权人侧入账放在M1，不应等国家发行之后再补。它是现有借贷正确性的条件。T0式读口值得做，但不应代替对单位、推进路径和双向账目的修复。

## 13. 当前范围之外

不在第一版求解全局一般均衡，不逐家庭逐商品建立跨世界竞价，不为每笔存款建立独立货币币种，不默认自由汇兑，不自动执行尚无产权依据的抵押，不用通胀公式直接改写钱包，不把新增货币当成新增粮食。

若未来需要严格的价值量、剩余劳动与阶级剥削统计，应另定义劳动时间、价值与市场价格的关系；本设计的财务利润和货币金额不能自动充当劳动价值量。

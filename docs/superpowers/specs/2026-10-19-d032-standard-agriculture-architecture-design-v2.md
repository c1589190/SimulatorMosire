## 1. 目标运行序列（唯一主链）

> 代码必须先按这个顺序跑；裁定、子设计和修复任务都嵌在这里，不从孤立裁定开工。
> 用 `S0..S8` 表示标准农业新序列；旧 M0–M9 只作历史，不再作为修复依据。

| 阶段 | 触发 | 做什么 | 读 | 写 | 失败/边界 |
|---|---|---|---|---|---|
| **S0 Social** | 每 tick | 结算出生、死亡、年龄、劳动能力、实际温饱；提供单户温饱线/人口 | Social 权威；上一 tick 温饱事实 | Social 切片；只读事实 | Social 失败 ⇒ 整次 advance 失败；经济不自行判死 |
| **S1 经济载入** | 每 tick | 载入活家户、土地持有、劳动预算、单户温饱线 | Social 投影、土地库存 | economy 会话投影 | 缺行/投影不一致 ⇒ 契约故障 |
| **S2 进入/迁移/组织** | 每 tick | 新户、迁移、土地取得/卖出后的生产组织重排 | 人口、土地、债务 | economy 会话 | 业务拒绝具名；不静默丢户 |
| **S3 生产位置选择** | 每 tick | 家户按纯库存财富降序 → `HouseholdId` 升序处理；有地户选择 `selfLand`/`hiredLand`，每个 `hiredLand` 独立创建雇佣位置并承担预期工资；所有家户按单位劳动净收益降序 → hex → employer → position 稳定序选择自耕/受雇/其他/无业 | 上一市场轮价格/工资、实际土地、劳动预算、库存 | 瞬态位置计划、`HiredLaborPosition`、劳动响应 | 受雇无正收益不占位；工单剩余量传给后续家户；禁止 Map 迭代序/墙钟/随机 UUID |
| **S4 生产日结算** | 每 tick | 实际播种/实际劳动；**每 tick 扣一次** `BASE_SUBSISTENCE + PRODUCTION_DAILY_EXTRA`，实际新播种时再额外扣 `PRODUCTION_INPUT` 种子；雇工劳动回传雇主；生成/更新 `DailyDemandBill`；记录实际播种面积与每日效率 | 实际土地、库存、劳动、工单响应 | 库存扣除、日需求账单、每日效率/实际播种读数 | 没种子只种可覆盖面积；日粮不重复扣；**生产轮不结算债务** |
| **S5 收获/毛产分配** | 周期末 | 按实际参与本周期生产的土地与 `B_cycle` 算 hex 毛产；记录毛产与成本责任账；按参与土地份额分给 owner | S4 每日效率、实际播种/参与土地、生产状态 | 毛产、库存/账本 | 有收获才判；效率损失按参与土地份额统一承担；**S5 不再次扣库存** |
| **S6 工资结算** | 每 tick 实际劳动后 | 每个雇主按本 tick 实际雇工劳动支付货币工资；不足成普通货币债；雇工不拿产出份额 | 工单/实际劳动、工资锚、雇主现金 | 工资支付/工资债 | 只货币；不拿库存抵工资；收获不决定工资是否应发 |
| **S7 库存/债务清算 + 市场** | 市场日 | 市场轮开头先做债务清偿（不是第二次每日消费）；随后在同一 `DailyDemandBill` 上生成只读 `marketPurchaseNeed` 并挂商品/土地需求单，不以库存/现金作为挂单门；卖实际剩余盈余；商品+土地同一订单簿；未付成交货款成普通债 | `DailyDemandBill`、实际库存、地价、运力、债务表 | 商品/土地/货币/债务/市场统计 | 本 tick 新工资债不进入本 tick 债务清偿；无供给不记债；自动订单按商品/方向合并 |
| **S8 Social 事实回传** | 每 tick 末 | 回传本 tick **S4 已发生的实际温饱/缺口**；Social 据此算下一 tick 出生/死亡 | S4 的本 tick 实际消费/缺口 | Social 事实槽 | S7 买入是未来库存，不能回头补本 tick 温饱；经济不自行判死/缩人口 |

### 1.1 因果顺序（冻结）

```text
S0 Social
→ S1 载入
→ S2 进入/迁移
→ S3 生产位置选择
→ S4 生产日结算（播种/日粮/劳动/日效率/需求账单）
→ S5 周期末收获与毛产分配
→ S6 工资
→ S7 市场轮：库存/债务清算 → 全部需求挂单 + 实际盈余 → 统一撮合
→ S8 Social 温饱事实
```

### 1.2 边界

- `tick0` 没有生产方式正常；创世只给定义/人口/固定土地/家户，不把“已选中 unit/roster”当成默认已生产。
- 生产轮（S3–S6）**不结算债务**；库存/债务清算只在 S7 市场轮开头。
- S7 的“库存/债务清算”只表示债务清偿（货币 → 库存 → 标量土地），**不是第二次每日消费**；S4 已扣的日粮/种子不得在 S7 再扣一遍。
- 本 tick S6 新生成的工资债不进入本 tick S7-M2 的还款候选；最早下一市场日 S7-M2 同池处理。否则会通过库存/土地间接实现工资抵物。
- S7 买入的货物是下一生产 tick 起的未来库存，不能回写本 tick 已完成的 S4 消费/温饱事实。
- 每次市场轮只开一次统一订单簿；商品和土地是同一撮合入口的订单变体。
- 生产轮没有产生的收入/库存不得由市场轮伪造。

## 2. 范围与非目标

### 2.1 本架构做

- 一个 hex 一个 `standard_agriculture` 生产总集；
- 土地、种子粮、口粮；
- 土地所有者按土地份额取得毛产；
- 有地户按利润选择自耕/雇人；
- 受雇作为位置进入统一贪心选择；
- 单户单日 `DailyDemandBill`；
- 生产轮 → 库存/债务清算 → 市场统一购买；
- 标量土地库存与任意数量抵债；
- 简单跨 hex 运力函数。

### 2.2 不做

- 研磨/加工/织布/手工业/贸易生产方式；
- 工具、耕牛、作坊、机器；
- 自增量农业进度系统；
- 旧档兼容/迁移；
- 复杂运力体系；
- 天气/文化/经验升级对产出的影响。

## 4. 核心数据形状

### 4.1 土地

```text
LandHolding {
  owner: HouseholdId
  hex: HexCoord
  quantityMilliMu: long
}
```

- LAND 不可生产，开局固定；
- 每 hex 的 `Σ owner.quantityMilliMu == arableMilliMu(hex)`；
- 可枚举每个 hex 的固定耕地量；
- 无 block id、无土地池；
- 市场订单 `(hex, side, quantityMilliMu, price/budget)`；
- 抵债/成交转移具体 hex 的任意数量；
- 0 价市场成交合法；债务清算中 0 价土地不冲本金、也不自动按无法确定的额度转移；
- 本轮取得土地只排除取得事件所在当前生产轮；下一生产 tick 可用，不得拖到下一市场轮；
- 土地被卖出/抵债时，该土地在本周期剩余时间退出生产；已记录的该土地日效率不再进入 `B_cycle`；买方/债权人从下一 S3 起可正常使用。

### 4.2 单 hex 标准农业聚合

```text
HexStandardAgriculture {
  hex
  totalArableMilliMu              // 固定上限，不因荒置变化
  landOwners: Map<HouseholdId, long>
  selfLandByOwner: Map<HouseholdId, long>
  hiredLandByOwner: Map<HouseholdId, long>
  sownLandByOwner: Map<HouseholdId, long>   // 本周期实际参与/播种量，≤ self+hired
  hiredPositions: List<HiredLaborPosition>
  dailyEfficiency: List<DailyEfficiencyRecord>
  cycleEfficiency: B_cycle
  grossOutput: Map<CommodityId, long>
}
```

- 一个 hex 仅一个 `standard_agriculture` 生产总集；
- 有地户把土地划成 `selfLand` 和 `hiredLand`；未划出/未播种的是荒置地，本周期不进入 `u/a` 与产出份额；
- 每个有地户的 `hiredLand` 生成自己的雇佣位置并承担自己的预期工资；
- 参与生产的土地所有者按实际参与数量取得毛产，不论自己是否劳动；
- 雇农不进入毛产分配；
- 该聚合是运行/只读组合视图，不是第三份可写权威：土地所有权、家户选择、雇佣锁、账单、工资/债务/市场归 economy；实际播种、日效率、`B_cycle`、物理毛产等生产状态归 production，经 contract 暴露。

### 4.3 雇佣位置与响应

```text
HiredLaborPosition {
  positionId: stable ordering key
  employer: HouseholdId
  hex: HexCoord
  landQuantityMilliMu: long
  requiredLaborMilli: long
  remainingLaborMilli: long
  wagePerLaborMilli: long   // 毫币 / 毫劳动；0 合法
  currency: CurrencyId
}

LaborResponse {
  worker: HouseholdId
  positionId
  suppliedLaborMilli: long
  wageEarnedMilli: long     // 实际劳动 × 锚率 + carry，按毫币向下取整
}
```

- 每个家户每次选择 `hiredLand` 都创建独立位置；
- 同 hex 任何有剩余劳动家户可响应；本地劳动约束不得放宽到同市场区；
- 统一按单位劳动综合收益降序 → hex → employer id → positionId 升序；同收益才使用该稳定序；
- 部分响应后剩余工单传给下一家户；
- 实际生产按实际响应劳动；未提供劳动不产生工资；工资锚键 = 市场区 × 生产方式 × 位置，缺锚具名失败，不得按 0 冒充；
- 工资每 tick 按实际劳动结算：只付货币，未付成普通 0‰ 货币债。

### 4.4 统一需求账单

```text
DailyDemandBill {
  day
  household
  lines: [
    {
      commodity,
      quantity,                 // 本行毛需求
      source: BASE_SUBSISTENCE | PRODUCTION_DAILY_EXTRA | PRODUCTION_INPUT | OTHER,
      providedFromStock,        // S4 已从库存实际提供
      marketPurchaseNeed,       // S7 在同一对象上计算的只读派生
      purchasedFromMarket,      // 本市场轮实际成交
      unmet                     // 无供给/未满足；不自动滚入下一市场轮
    },
    ...
  ]
}
```

- `BASE_SUBSISTENCE`：Social 单户温饱线汇总值；
- `PRODUCTION_DAILY_EXTRA`：生产方式额外日耗（小增量）；
- `PRODUCTION_INPUT`：种子等生产投入（播种日/未耕种面积）；
- **这是一个对象，不是多张表**：生产轮用同一账单记录 `providedFromStock`，市场轮在 S7-M2 完成后、同一对象上生成 `marketPurchaseNeed` 并购买；
- 不存在独立 `naturalNeeds`、独立 M5 消费表、独立 `SocialSurvivalFacts` 需求表；
- 种子是播种日/周期成本，作为同一账单的 `PRODUCTION_INPUT` 行，不混进每日生活口粮；
- 市场日对 `BASE_SUBSISTENCE` / `PRODUCTION_DAILY_EXTRA` 的派生覆盖“到下一市场轮”的 5 个生产 tick；`PRODUCTION_INPUT` 只取当前实际未耕种缺口，**不乘 5**、不按满计划重复采购；
- 已由 S4 `providedFromStock` 的数量不得再次挂成当前市场买盘；
- `DailyDemandBill` 每户每 tick 一份，是 economy 会话中的当前 tick 唯一副本；5 tick 派生只是同一对象的只读市场视图，不新增第二张 naturalNeeds 表。

### 4.5 每日效率

```text
required_i = a_i * v
e_i = min(1, w_i / required_i)
B_day = Σ_i (a_i / u) * e_i
B_cycle = Σ_d (u × B_day_d) / (u × cycleDays)
```

- `u` = **本周期实际参与生产的土地总量**（即各户实际播种/投入的 `a_i` 之和，不得超过该 hex 固定可耕总量）；未播种/荒置地不进入 `u`；
- `a_i` = 该户在本周期实际参与该 hex 生产的土地数量（已投入的自耕 + hiredLand 份额）；
- `v` = 当前生产方式每单位土地每 tick 所需劳动；
- `w_i` = 最终落到该户土地上的实际劳动（自耕 + 收到的雇工劳动）；
- 雇农劳动先回传雇主，全部家户劳动分配完后计入雇主的 `w_i`；
- 损失全 hex 按参与土地份额统一承担；
- `a_i = 0` 或 `u = 0` 不参与除法；`v <= 0` 视为生产方式定义故障；实际劳动超过需求时 `e_i` 封顶 1；
- 固定点整数除法与余数结转由实现架构账本写清，禁止浮点累加；
- 不做累计实际劳动版；
- 不做自增量进度系统。

### 4.6 毛产与两笔账

```text
hexGrossOutput = baseOutputPerLandTick * u * cycleDays * B_cycle
ownerGrossShare = hexGrossOutput * (a_owner / u)
```

其中 `u/a_owner` 均为本周期实际参与生产的土地量；S4 已按实际播种/日耗扣过库存，S5 **只记录毛产与成本责任账，不再扣第二次库存**。

顺序固定：

```text
1. 记录毛产 grossOutput（物理账）
2. 记录按责任主体发生的种子/日粮/生产投入成本账（实际库存扣减已在 S4 完成）
3. 按参与土地份额分配毛产给 owner
4. 每 tick 按实际雇佣劳动支付工资/记普通货币债
5. 市场
```

责任主体：

| 项目 | 责任主体 |
|---|---|
| 自耕土地种子/日粮 | 种田家户 |
| hiredLand 种子/生产成本 | 雇主（土地所有者） |
| 雇工日粮 | 雇工家户（由雇工位置产生） |
| 毛产 | 土地所有者，按土地数量份额 |
| 雇工工资 | 雇主家户；未付成普通货币债 |

不存在多户共享收入池；不存在租约/地租。

## 5. 市场与债务

- 生产轮先；生产轮不结算债务；
- 市场轮第一步：债务清算（货币 → 库存 → 标量土地）。本 tick S6 新工资债不进入本 tick 还款候选，最早下一市场日同池处理；
- 第二步：债务清算完成后，在同一 `DailyDemandBill` 上生成 `marketPurchaseNeed` 并挂需求单；**不以当前库存/现金作为挂单门**。基础温饱/生产额外项覆盖到下一市场轮的 5 个生产 tick，生产投入只取当前实际未耕种缺口，不乘 5；
- 第三步：卖本轮生产后的实际剩余盈余；实际盈余 = 库存 − 本户同一账单需保留的基础/生产需求；不得把同一户的同一商品同时挂成无净额的自买自卖；
- 商品与土地同一订单簿、同一撮合器；
- 需求单挂出后，无供给只记 `unmet`，**不记债**；有实际成交但买方现金不足时，未付部分才形成买方对卖方的普通货币债；
- 历史 `unmet` 只作为 S8/Social 事实，不自动滚存到下一市场轮；
- 自动商品订单按 `(actor, commodity, side)` 合并，不能 actor 级全删；土地订单按 `(actor, LAND, hex, side)` 合并；
- 跨 hex 先走确定性 `transportCapacity/price` 函数，不新增运输生产方式；土地产权转移无运费；
- 土地订单按 `(hex, side, quantityMilliMu, price/budget)`，无 block id；0 价市场成交合法；未定价与 0 区分；
- 债务清算中不自动用 0 价土地冲抵本金（价值为 0、数量无从由债务确定）；余债保留，0 价土地仍可在市场自愿成交。

## 7. 验收锚点

1. 一个 hex 只有一个 `standard_agriculture` 运行聚合；实际参与生产土地份额合计 ≤ hex 固定耕地，全部土地持有合计 == 固定耕地；
2. 每户每 tick 只有一张 `DailyDemandBill`；不存在独立 `naturalNeeds`/M5 第二套消费；
3. 账单同时包含 NaturalNeed、日耗生产额外项、种子/生产投入；市场统一购买全部需求；
4. 每 tick 扣一次日粮/生产额外项，实际新播种时额外扣种子；全部耕完种子需求为 0；没有种子只种实际覆盖面积；
5. 周期末才判收获；`B_day` 按实际参与土地加权，`B_cycle` 用逐日累计式；未种地不进入本周期 `u/a`；
6. 毛产先记录，按参与土地份额分配 owner，再付雇工工资/记债；雇工无产品份额；S5 不二次扣库存；
7. 自耕种子/日粮归种田户；hiredLand 种子/成本归雇主；雇工日粮归 worker 户且每户每 tick 只扣一次；
8. 每个雇主独立创建 hired 位置；工单按单位劳动净收益降序→稳定序消费，剩余量传下一户；工资每 tick 按实际劳动结算；
9. 市场轮债务清偿先于需求/挂单；生产轮不结算债务；本 tick 新工资债不进入本 tick S7-M2；
10. LAND 是 `(hex, quantityMilliMu)` 标量；0 价市场成交合法但不自动用于债务冲本金；下一生产 tick 可用；
11. 市场日前瞻 5 个生产 tick 的基础消费；生产投入不乘 5；无供给⇒unmet 不记债，有成交现金不足⇒普通货币债；
12. 自动订单按商品/方向合并；跨 hex 有非零简单运力；tick0 没有生产方式正常，不把预置 unit/roster 当已选生产。

## 8. 工程默认与不做

以下为控制方工程默认，用户可随时推翻；不是新的用户玩法裁定。

1. **需求账单写入者**：Social 提供单户基础温饱线汇总值，production 提供生产方式额外日耗/种子投入语义，app 组装唯一 `DailyDemandBill`，economy 持有当前 tick 唯一副本。
2. **工资时点**：S6 每 tick 按实际劳动结算；工资锚 = 市场区 × 生产方式 × 位置；缺锚 != 0；未付成普通 0‰ 货币债。
3. **市场周期**：`day % 5 == 0` 且市场表非空才开统一市场；无低库存追加轮/关账额外轮。市场日 S7 购买基础温饱/生产额外项的 5 个生产 tick 前瞻；生产投入只取当前实际未耕种缺口，不乘 5。
4. **购买与债务**：挂单不以库存/现金预筛；无供给 ⇒ unmet 不记债；有成交但现金不足 ⇒ 普通货币债；市场环节不得拿商品抵货款。
5. **同日工资债 cutoff**：本 tick S6 新工资债不进入本 tick S7-M2；下一市场日 M2 与普通债同池处理。
6. **土地与产出**：只有实际参与本周期生产的土地进入 `u/a_i`、产出份额和效率损失；未播种/荒置地无本周期产出份额；`a_i=0`、`u=0` 不参与除法，`v<=0` 为定义故障。
7. **跨日效率**：`B_cycle = Σ_d (u_d × B_day_d) / Σ_d u_d`；本周期 `u_d` 一致时有 `Σ_d B_day_d / cycleDays` 的等价读法，但实现保留逐日累计形式。
8. **纯库存财富**：钱 + 货物 + 土地市值；不扣债务；工具/作坊/机器不计入。
9. **稳定排序**：家户纯库存财富降序 → `HouseholdId` 升序；工单单位劳动净收益降序 → hex → employer → position；禁止 Map 迭代序/墙钟/随机 UUID。
10. **运力**：确定性 `transportCapacity/price`，至少相邻 hex 非零；运费有明确付款方与收款方，不得造币；土地无运费。
11. **数值**：土地 = 千分亩；金额 = 毫币；劳动 = 毫小时。`arableMilliMu(hex)`、`baseOutputPerLandTick`、`v`、`seedPerMu`、`cycleDays`、生产额外日耗、初始土地/地价/工资锚均为可配置工程默认；不得把用户示例的 120/1/1 当精确夹具。
12. **折旧**：标准小农业不接工具/耕牛/作坊/机器，也不保留旧 30‰ 农具折旧作为隐藏扣减。
13. **本批范围**：不接 fiber/weave/craft/trade/研磨；标准测试世界只保留标准农业 + 无业/必要占位。
14. **持久化**：不做旧档兼容；Alpha 直接重建新世界。所有状态同 revision 原子提交，失败零半提交。

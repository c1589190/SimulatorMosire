# WebUI 阶段修复 —— 用户实测缺陷（第 2 批）

> 来源：用户 2026-09-21 在**富世界实例（5817 / v17levant 复刻 / 59223 hex）**上试用后的实测反馈。**逐字记录，不改写。**
> 配套：`2026-09-21-webui-stage-fix-brainstorm.md`（第一批需求 R1~R13 + 用户裁定 §六）。
> ★ 本批**不是新功能**，是**已交付物的形态/交互缺陷**（与第一批同性质）。

## 一、用户原话（逐字）

> 「最大的一个问题，**区域查看、编辑模式的时候，hex地形底图保持高亮，导致区域根本看不清**；**GSimulator后期所带有的区域名称显示也没做出来**；然后就是**区域查看模式的选择区域查看功能做的不做完善**，点击一个tag，默认全部选中，**无法单独点击tag下具体的区域来以更高亮度查看**（**原定计划是点击一个tag以相等亮度查看这个tag下所有区域，点击选中tag旗下的一个区域，淡色显示同tag其他区域，高亮显示这个被选中区域**）；还有就是，**为啥不用截至n0008回合的最全所有区域？n0000的区域构成是缺的**，不过**这个得等修完前两项再说**。」

## 二、拆解（4 条）

| # | 缺陷 | 期望 |
|---|---|---|
| **U1** | 区域查看 / 区域编辑模式下，**hex 地形底图仍然高亮** ⇒ 区域看不清 | 进这两个模式时**地形压暗**（或等效的"地形让位给区域"），让区域填充/边界成为视觉主体 |
| **U2** | **区域名称显示缺失** | 地图上显示**区域名**（★ 形式待定：标签/居中文字/随缩放显隐）——★ **GSimulator 后期自带此功能**，是"没做出来"而不是"做了不好" |
| **U3** | 区域查看的**选择粒度只到 tag**：点 tag ⇒ 全部选中；**无法单独选 tag 下的某个区域** | ★ **原定计划**：<br>① 点 **tag** ⇒ 该 tag 下**所有区域等亮度**（现状即此，保留）<br>② 点该 tag 旗下的**某一个区域** ⇒ **同 tag 其他区域淡色 + 被选中区域高亮**（★ **当前做不到**） |
| **U4** | **源节点可能选错**：用了 `n0000`，而其**区域构成是缺的** | 应使用**截至 n0008 回合**的**最全区域**。★ **用户明说：这条等 U1/U2 修完再说** |
| **U5** | ★ **详情页三栏布局坏了** | 用户原话：「**所有详情查看页，左边的栏目占了一大块空白，右边被挤占到最边上一行了**」⇒ 左栏**过宽且空白**、右栏被 `space-between` 顶到最右。★ **待查是否 T7（决策模式新增左栏 section）引入的回归** |

## 五、用户实测缺陷（第 3 批：U 修完后仍存在 / 新发现）

> 来源：用户 2026-09-21 在 5817（252 区域富世界）上**再次实测**，附两张截图。**逐字记录。**

### 用户原话（逐字）

> 「首先，**左侧边栏的问题你还是没修**；其次，**即使在常规模式，区域名称也被显示了**；还有是功能性的，我希望在**区域查看/编辑模式下，点击一个地方，就自动选中拥有这个hex的最顶层区域**（其实就是防止有重叠区域）」

### V1 —— 左栏宽度不够 ⇒ **内容逐字折行**（★ U5 的修复反而改坏）

- 截图1（区域编辑模式）：左栏约 150px 宽、`terrain` 的值 `low_hills(低矮丘陵)` **竖排成单字列**、`q=-26, r=-72` 竖排、整段中文竖排，**还带竖向滚动条**
- ★ 根因方向：U5 的"侧栏按内容/不顶边"改动**没有兜住最小可用宽度**，也没有**防逐字折行**的约束

### V2 —— 区域名**恒显示**（★ U2 做过头）

- 截图2（**常规**模式）：地图上仍画着 `莱昂-卡斯蒂利亚王国` / `阿拉贡王国` / `法蒂玛哈里发国` / `马拉喀什苏丹国`
- ★ 期望：**区域名只在「区域查看」/「区域编辑」显示**（其余模式不画）

### V3 —— 点击 ⇒ 选中「拥有该 hex 的**最顶层区域**」

- 目的（用户原话）：**防止重叠区域**（一个 hex 多从属时不再全部等亮，而是取顶层那一个）

#### ★★ V3 的定义：**用户裁定 = 按「创建/定义顺序」，后定义的在上**（2026-09-21，用户答「1」）

**连带后果（必须记账）：**
1. ★ **推翻 M8-Q6**：当时裁定 `/api/map/hex` 的 `regions` 走**字典序**；现改为**定义序**（★ 这是**有意的语义变更**，不是笔误修正）
2. ★ **推翻 U3-2**（同批刚做的）："owner > 1 ⇒ 退回 group（全部等亮）" ⇒ 改为 **取顶层那一个**
3. ★ **模型须真能保留"定义序"**：现 `RegionIndex` 是 `hex → Set<RegionId>`（**无序**）⇒ 需核实 `GameMap.regions` 容器是否为有序 `Map`；否则要换结构（★ **不许**拿字典序冒充定义序）

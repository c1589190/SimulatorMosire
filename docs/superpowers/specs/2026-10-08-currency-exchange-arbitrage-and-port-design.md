## 3. 冻结的契约（世界必须长成什么样）

### 3.1 三样东西互相分离（**不可合并**）

| 概念 | 谁定 | 存哪 | 语义 |
|---|---|---|---|
| **法定币（legal tender）** | 政府的市场区（法律） | 市场区状态 | "本区官方只收哪种钱" |
| **记账币 / 计价单位（numeraire）** | 逐格市场表（现状） | `Market.numeraire` | 价表与成交的记账单位 |
| **持币（holdings）** | 家户自己的库存 | `HouseholdInventory.money` | 家户实际拿在手里的钱 |

★ 三者**允许不一致**（用户 §1.2「和其内家户实际上用啥货币没有直接关系」）。

### 3.2 一个统一抽象：资产与场所

```
Asset   = Commodity(CommodityId) | Money(CurrencyId)
Venue   = HexMarket(hex)                 // 现有逐格市场，价表 + 深度 + 单 hex 贸易成本
        | GovWindow(govId, marketZoneId) // 政府外汇窗口（官方汇率）
        | ProcurementWindow(govId, zone) // 政府采购窗口（商品 ⇄ 货币）
Exchange = (from: Asset, to: Asset, venue, maxQuantity, costPerMille)
```

**关键契约**：`Money` 与 `Commodity` 在任何算式里**同权**——同住一本账、同走转移腿、同一个守恒判据。
两种资产之间的"价格"统一写作"换出比率"。

### 3.3 家户价目表（HouseholdPriceTable）升为一等输入

- **形状**：`Map<Asset, long>`，计价单位 = 该家户的 `numeraire`；缺项 ⇒ 回落该家户所在市场区的默认价表。
  （形状复用 `DebtValuation.HouseholdPriceTable`，**不新造类型**。）
- **语义 = 保留价（reservation price）**：对**买入**是该户愿付的上限，对**卖出**是愿接受的**下限**。
- **它从哪来（本设计冻结三条来源，按优先级）**：
  1. **必要投入价**：生活保留（口粮）+ 生产必要投入 ⇒ 影子价 = 该户为"缺这一单位"愿付的价（高）；
  2. **库存饱和衰减**：库存越接近/超过目标保有量，保留价越低；
  3. **真实成交校准**：该户最近参与过的成交价（滚动均值）——**只能由该户自己的成交更新**，不看别人的价。
- **不变量 P1**：家户价目表**不是新权威**。它由"该户人口 / 家户结构（Social 的权威）+ 库存 + 自己的成交史"
  派生 ⇒ 必须可**重算**，不得成为独立的第二本人口/需求账（AGENTS §〇：Social 是人口与需求系数的唯一权威）。
- **不变量 P2**：家户价目表**不进状态**（第一版）：它是逐 tick 派生件。若实测证明"成交史校准"必须跨 tick 累积，
  再单独提状态组件方案（走 Codec + 往返不变式），**不许先把派生量塞进状态**。

## 4. 统一套利算法（一种算法，两种长相）

### 4.1 算法本体（每个家户、每个开市轮）

```
① 建图
   节点 = (场所, 计价物)
   边   = 资产 A → 资产 B，权 = 换出价值比：
          ratio(A→B, v) = sellPrice_v(A) × fx(A→B 若跨币种) ÷ buyPrice_v(B) ÷ (1 + cost_v(A→B))
          - 纯实物：fx = 1，cost = 单 hex 贸易成本 + 运费
          - 纯货币：A/B 皆为 Money，cost = 点差 + 手续费 + 风险溢价
          - 政府采购：B 为 Money 而 A 为 Commodity，分类记 PROCUREMENT

② 找环
   以本户持有资产为起点，**跳数上限 ≤ 3**，找正收益环（收益 = Π ratio − 1）；
   取收益最大的那一环。找不到正环 ⇒ 不动。

③ 取量（边际收益递减）
   收益(q) = q × [卖出均价(q) − 买入均价(q)] − 库存惩罚(q)
   q* = 使"多换一单位不再赚钱"的最小 q；q* ≤ 0 ⇒ 不动

④ 执行与落账
   每户每轮**最多执行一次**（吃一次深度）；
   每笔 = 两条转移腿（A 出 X + B 入 X×比率），逐资产守恒；
   **所有腿都必须能同时成立**，否则整笔具名拒绝（不许部分落账）。
```

### 4.2 库存惩罚 = 家户价目表（这才是"按家户自己的资源算"）

```
惩罚(资产) = 生活保留 + 生产必要投入 + (非本币 ? 外汇敞口上限 : 0) + (远地 ? 运输风险 : 0)
```

- 资产是**必需投入**（口粮 / 生产投入）⇒ 惩罚极大 ⇒ `q* ≈ 0`（**不卖口粮换钱**）。
- 资产**无需求且超额** ⇒ 惩罚小 ⇒ `q*` 大（积极出清）。
- 这**不是**新公式：现有 `AvailableStock` 已经钉住"可支配 = 余额 − 冻结"，且类注明写
  "必要生产投入与生活保留是决策层策略，落在 M2 的订单/保留算式里" ⇒ 本文的惩罚函数**就是**那个 M2 落点。

### 4.3 ★★ 生产也是一种兑换：一个"按划算程度排序，再依次分配资源"的贪心算法

**这是本设计的核心统一**（用户 2026-10-08：「把套利的交易模型和生产比较……套利同样要花费劳动力，属于一种
'在生产方式'，因此可以与常规的生产方式作比」「投入劳动力，先定个顺序，把根据现有资源核算后，最划算的先做，
不划算的后做，以此分配劳动力，不就行了？」）。

**任何活动都写成"换出比率"的一个边**：

```
生产（务农/作坊/商号）: 边 = (劳动 + 投入品) → (产出品)
套利 / 贸易        : 边 = (劳动 + 库存/资金 + 在途损耗) → (另一种库存/资金)
官吏/军俸/口岸     : 边 = (劳动) → (俸禄/工资，即货币或实物)
```

⇒ **"要不要做套利"和"要不要种地"是同一个问题**：把各活动的**收益率**放在家户自己的价目表上比大小。

#### 4.3.1 算法：排序 → 依次分配 → 分配完为止（不做截断点求解）

```
每个家户、每 tick：
  ① 硬约束先扣：生活保留（口粮 + 必要生活）从库存里划出，任何活动不得占用
  ② 按同一份资源快照，给每个候选活动算"收益率"（见 §4.3.3）
  ③ 按收益率**降序**排序（同率按 activity id 升序 ⇒ 确定性）
  ④ 依次给每个活动分配它所需的劳动与库存：
        能给多少给多少（受剩余劳动、剩余库存、该活动的规模上限三者中最小者约束）
        给完就扣减"剩余资源"
  ⑤ 资源分完 ⇒ 停止；后面的活动自然拿不到资源（"不划算的后做"= 排到队尾，通常轮不到）
```

★ **这就是用户说的"先定个顺序，最划算的先做，不划算的后做，以此分配劳动力"**，不需要解"套利收益率 =
生产收益率"那个方程，也不需要预先知道生产会分到多少劳动。

#### 4.3.2 为什么这个形态更好（它消掉了三个难题）

| 原难题 | 排序贪心下如何消失 |
|---|---|
| "套利计划必须知道生产的边际收益率"（互相依赖） | **不需要**：两者都只是队列里的一项，比较发生在排序那一刻，用的是**同一份快照** |
| "剩下的劳动继续务农"（要保证不被浪费） | **自然结果**：务农排在队列后面，轮到它时"剩余劳动"就是它的配额 |
| 日序 A/B 之争（投入扣减在劳动分配之前还是之后） | **不再存在**：劳动分配、库存分配、投入扣减是**同一次遍历**的三个动作，不再有先后之争 |

#### 4.3.3 收益率的口径（冻结）

```
收益率(活动 a, 家户 h) =
    [ Σ_产出 估值_h(产出, 数量) − Σ_投入 估值_h(投入, 数量) − 劳动机会成本 ]
    ÷ 该活动的稀缺资源消耗（劳动毫小时 / 库存 / 资金，取"最紧的那一项"）
```

- 估值一律用**该家户自己的价目表**（§3.3），缺项回落本市场区默认价表。
- 「最紧的那一项」= 该配方里消耗比例最高的稀缺资源 ⇒ 保证"每单位稀缺资源能赚多少"可比。
  ★ **实现方式由实现方定**（任选其一，但必须在账本里写明）：
  - **朴素版（推荐）**：按"最紧的那一项"归一 ⇒ 每个活动一个标量收益率，**一次排序**即可；
  - **严格版**：每次分配后按**剩余资源**重算收益率、重排（真正的边际贪心）⇒ 更准，但复杂度高、且必须保证
    重排的确定性（同率按 id）。★ 两版在"资源远多于活动需求"或"需求远多于资源"两种极端下结果相同，
    差异只在中间地带；**若实现方选严格版，必须证明重排不引入不确定次序**。
- **边际递减必须在收益率里体现**：套利吃深度 ⇒ 换得越多价越差；生产受土地/作坊/劳动上限约束。
  ⇒ 同一个活动被分到更多资源时，其**边际收益率下降**；若实现方选择"一次算一个平均收益率"，
  则必须在账本里说明**为什么不递减也能收敛**（否则会出现"全家套利、不种地"）。

#### 4.3.4 全部活动共用一个选择器（这是"一个算法"的落点）

**一个共同接口 + 一个排序器**，生产与套利实现同一个契约：

```
Activity {
  收益率(快照)                       // §4.3.3
  resourceNeed()                    // 本活动要哪些资源、要多少
  execute(分配到的资源) → 变更        // 产出入库 / 成交落账（两条腿）
}
```

- 现有 `ProductionMode` / 产业配方 = 其中一个实现；
- 套利（§4.1 的图与环）= 另一个实现；
- 官吏/口岸编制（若也走这条）= 第三个实现。
- **排序器只有一份**：`sort by 收益率 desc, activityId asc`。

★ 这一条同时把 **D-024 的"预期利润与需求现算"**接上：收益率里的产出估值与需求，就是 D-024 那个
"产业配方 + 市场价 + 可寻址需求"计算器——**不新增第二套利润率口径**。

**与现有代码的接口（已核，file:line）**：

- `HouseholdLaborCommitment(activity, laborMilli)` 以 `activity` 为键，**产业当日劳动 = 该产业名下全部配额的
  `laborMilli` 之和**（`EconomySettlement.java:104-105`、`:1420`）⇒ **"把劳动拆给多个活动"结构上已经支持**，
  套利只是**新增一种 activity**，不需要新的分配机制。
- 家户劳动预算 = `HouseholdEconomy.laborMilli`（Social 是唯一权威），超出部分按比例缩到预算内
  （`EconomySettlement.java:3752-3779`）⇒ 只需保证 `Σ(各活动劳动) ≤ 预算`。
- 生产投入现为**整批**消耗（`drawCycleInputs` / `rationContestedInputs` / `drawOneProductionProcessInputs`，
  `:1269/:1305`、`:4614`、`:4796`）⇒ 在排序贪心下改为"**先定该活动分到多少劳动与投入，再按此扣减**"，
  即投入扣减由**分配结果**驱动，而不是先于分配发生。

#### 4.3.5 决定性与快照纪律（硬要求）

- **同一份资源快照**：排序用到的所有投入（家户价目表、库存、劳动预算、各场所报价）必须是**本 tick 开始时
  的那一份**；★ **不得**在某活动执行后回头重排（那会让顺序依赖执行副效果 ⇒ 同一存档两跑不同）。
- 排序键 `(收益率 desc, activityId asc)`，**禁止**依赖 `HashMap` 迭代序。
- 活动执行产生的账户变更**按队列顺序落账**（先执行者先改价格，后来者看到的是被改过的价格——
  但**排序仍按快照**，这是刻意的：排序稳定、成交顺序确定，两者分离）。

### 4.4 政府在这张图里只是"报价特别好的摊位"

| 政策 | 在算法里是什么 |
|---|---|
| 官方汇率 `OfficialRate(buy, sell)` | 政府窗口这个摊位的**报价**（多两条边） |
| 结汇比例 `surrenderPerMille` | "外币 → 本币"这条边的**强制下限**（必须换这么多） |
| 禁运 / 限量 | 相应边的**不存在 / 上限** |
| 管制力（见 §5） | 政府摊位的**吞吐上限**；超出部分落到"走私边"（cost = 风险溢价） |

**不需要**单独的"垄断"机制：垄断程度 = 政府摊位吞吐上限能否吃下全部需求。

### 4.5 两个汇率并存

- **官方汇率**：持久状态（政府定、决策人工具 + GM 审批）。
- **实际汇率**：`marketRate(base, quote)` = 本区最近 N 笔外汇成交的**加权均价**，**不落盘**（读数量）。
- **两者的连接靠套利**：`officialBuy > marketRate` ⇒ 套利者买市场、卖政府 ⇒ 政府投放本币、市场价上行；
  `officialSell < marketRate` ⇒ 反向。**官方汇率只在窗口有量时才拉动市场价**（= 用户 §1.3-2）。

### 4.6 交易顺序与确定性（硬要求）

- 顺序：先剥"必须换的"（结汇强制）→ 再按**期望收益率降序**、收益率相同按**家户 id 升序**；
- **禁止**依赖 `HashMap` 迭代序；
- 先动手的人改变价格 ⇒ 顺序必须是内容的纯函数，否则同一存档跑两遍读数不同。

## 5. 口岸维护与管制（修正 v1 的误读）

### 5.1 两条独立输入，只在实际管制力上合流

```
管制标准 standard（政策，政府定）
      ↓ 换算
口岸劳动力需求 demand = f(过境批次 × 查验率, 结汇总额 ÷ 单位处理额, 禁运/限量集合大小)
      ↓ 与"实际编制劳动力"比较
行政效率 c = 实际编制劳动力 ÷ demand        // 客观：标准越高 ⇒ demand 越大 ⇒ 同编制下 c 越低
      ↓
实际管制力 enforcement = standard × c        // ★ 用户 §1.3「很低管制标准 ⇒ 需求少 ⇒ 同一批人效率可能反而提高」
```

★ 因此 v1 里"效率高 ⇒ 控制力强"是**错的**，本文改正：
`standard = 0` ⇒ `enforcement = 0`（无论 `c` 多高）；`standard` 拉满但编制不足 ⇒ `c` 低 ⇒ 仍管不住。

### 5.2 口径

- **量纲**：现有行政效率是**千分制且不封顶**（用户既有裁定"都不封顶"）。
  用户 §1.2 公式按千分制书写：`口岸效率‰ = (行政效率‰ × (1000 − 补偿‰) + 补偿‰ × 1000) ÷ 1000 × 满足率‰ ÷ 1000`；
  **不得**把行政效率钳到 `[0,1000]`（违反"不封顶"）。
- **补偿项**：`行政效率对口岸补偿` 现有形态里**没有先例**（现有 4 个静态修正全是**乘性**）⇒ 属**新增字段**，
  归**静态面**（`GovAdministrationPlan` 一族，GM 可通过既有 `simos.gov.setEstablishment` 口径修改），
  **不**归动态注入面（动态面是"他模块按 tick 注入"的语义，与此不符）。
- **满足率分母为 0** ⇒ 沿用现有口径（需求 0 = 1000‰，即"没人管也不用管"）。
- **是否吃超编开方**：沿用现有 `GovEfficiency` 的有效劳动口径（含超编开方），**不另立一套**。
- **第三维还是第二个 office 产业**：见 §10-3 待裁；**预算类别不加**（按支付性质分类，口岸走 `ADMIN_STIPEND` /
  `ADMIN_SALARY`）。

### 5.3 相邻边界计数

- 口径二选一，见 §10-2 待裁：
  - **(甲) 逐格暴露边计数**：对辖区 hex 集 `H`，逐格逐方向判"邻居是否在 `H` 内"，不在则 +1；
    ★ 共享边会被两侧各计一次 ⇒ 必须除以 2 或只在规范侧计；
  - **(乙) 相邻市场区种类计数**：邻居格的所属市场区 id 集合大小（"挨着几个别的市场区"）。
- **落点**：只能落**组合根（app）**——`simos-gov` 的 enforcer 禁 `simos-economy`；
  现成注入点：`PopulationEconomyTimeParticipant` 同一日循环里已经现算一份 `MarketTopology`
  （`:564`），而 gov 效率就在同一个类里算（`:1248`）。
- **没有现成函数**：`RegionBoundary` 有逐格暴露边算法但只吐**顶点环**；`MarketTopology.adjacent` 是
  **锚距**口径，**不是**用户要的"挨着就算"。

### 5.4 用商品稳定汇率（用户 §1.3-3）

- **政府采购窗口** = 第三种场所：`粮食/布匹 ⇄ 外币`，分类记 `PROCUREMENT`，与 `FX_EXCHANGE` 分开记账。
- **守恒**：国库**实物库存** ↓ / 外币 ↑，两条腿同笔；**不铸币、不造货**。
- **必须有一条保底库存线**：低于线则停止卖出粮食（否则政府会为汇率把国家饿穿）。
- **金/银**：作为**普通商品**自由买卖（不设固定价格）；两种货币的含金量比率只是**读数**，不是状态。
  ⇒ "通用金/银"落地为"一种大家都愿意接受的商品"，不需要任何特殊货币身份。

### 7.1 汇率/口岸阶段判据（阶段 2–3，先记不执行）

1. **单一世界、两币种**：A 国发币 `silver`、B 国发币 `gold`；两个市场区各自法定币不同；一口岸相邻。
2. **家户自动套利可观测**：给定官方汇率偏离市价，日志/读数显示**谁在哪个方向套了多少量**，
   且套利后**价差收窄**（不是被无限吃光）。
3. **商品-货币套利**：粮食在两区价差 > 运费时，出现"买粮 → 运 → 卖 → 换币"的多跳链条，链条**≤ 3 跳**。
4. **政府采购稳汇率**：政府用粮食买入外币后，实际汇率向官方汇率方向移动，且**国库粮食库存下降**、
   **外币储备上升**，总货币量不变。
5. **口岸效率的两个极端**：
   - `standard = 0` ⇒ 实际管制力 = 0（官方汇率对市场无影响），但 `c` 可以很高；
   - `standard` 拉满、编制不足 ⇒ `c` 低、走私（未被查验成交）比例上升。
6. **结汇强制**：`surrenderPerMille = 1000` ⇒ 家户外汇收入全部经官方窗口，市场外汇成交归零。
7. **守恒审计**：跑 N tick 后逐币种总量、逐商品总量与期初一致（差额只来自生产/消费/损耗的既有路径）。
8. **数值口径**：效率与汇率一律定点整数 + 明确量纲（‰ / 最小单位）；无浮点。
9. **活动排序可观测**（§4.3）：给一个"套利收益率 > 生产收益率"的世界，读数必须显示**套利排在队列前、先分到资源**；
   把套利机会抽掉（价差归零）后，同一批资源必须**全部落到生产**，且**生产产出恢复到无套利时的水平**
   （证明"剩下的劳动继续务农"成立）。
10. **套利吃不满劳动**：封建尺度下（交易劳动 ≪ 务农劳动），套利只应吃掉一小部分劳动预算；
    若出现"套利吃光劳动、生产归零"，判为**算法失败**（吃深度或机会上限没生效）。
11. **库存三用途不打架**：同一份库存，在"生活保留 / 生产投入 / 套利库存"之间按边际收益率分配；
    断言**生活保留永不被挤占**、**生产投入批次不被抽走**（对应 I14/I15）。

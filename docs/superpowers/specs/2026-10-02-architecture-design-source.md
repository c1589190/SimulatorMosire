## D-006 补裁（2026-10-02 用户口述）：人力/装备的数据形状
- **来源（用户原话）**：「人力类型就是一个<Object,long>排列的表，Object代表什么类型的人力，可以是String，不排除后续传代表人力的特殊数据结构；long就是人力有多少；一个部队自然可以拥有多种人力；装备也是，目前也没啥特殊的装备数据结构、人力数据结构，默认赋String搞自然语义记录」
- **裁定**：
  1. **人力** = `<Object, long>` 的**排列的表**：Key = 人力类型（当前用 `String` 承载自然语义，后续可换/传专门的人力数据结构，当前没有）；Value = 数量；**一个单位可拥有多种人力**。
  2. **装备**同形：`<Object, long>`；当前没有专门的装备/人力数据结构，**默认 `String` 走自然语义记录**。
  3. 现有 `int member` + `Map<String,Integer> equipment`（`Unit.java:50-51`）⇒ 目标形态改为"类型→数量"的表；人力与装备**同构**。
- **实现待定（机械细节，不改设计）**：表的**保序**语义与键相等/JSON 序列化口径（Object 键）；数量类型用 `long`（与现有 int 的边界换算）。
- **关联**：D-007（人物/家族用通用 Unit）；D-011（不兼容策略）。

## D-009 补裁（2026-10-02 用户口述）：自定义交战状态与 1-tick 交战记录

  5. **分带不预设数值**：`LatitudeBands` 只给接口与配置项，由 GM 工具设定；**未配置时明确降级为“全球北半球四季”**并在 `info`/读口里标注 `zoneSource: fallback`（不假装已分带）。地图南北轴 = `r`、负 r = 北（实现说明，已实测）。

## D-019 `simos-calendar` 模块依赖 = `simos-util` + `simos-map`（2026-10-02 用户口述）

- **日期**：2026-10-02
- **来源（用户原话）**：「这个模块的依赖是什么？我认为只需要Util和Map」
- **设计裁定（用户给定，最终版）**：
  1. **`simos-calendar` 主依赖 = `simos-util` + `simos-map`**；不得依赖 core/app/social/unit/economy/economy-api/actor/actor-api/gov/army/sd/ledger/agentlib。
  2. **依据**：`simos-util` 提供共享值类型（`YearFraction` 等）；`simos-map` 提供 `HexCoord`（季节分带要用南北坐标 `r`），并为后续“地形/气候影响季节”把同一依赖口留好。
  3. **依赖方向固定为 `util → map → calendar`**：`simos-util` 与 `simos-map` 的 enforcer 禁列表要补 `simos-calendar`，防反向依赖；calendar 自身禁一切领域/编排模块。
  4. **core 仍不依赖 calendar**（core main scope 规则不变，map 在 core 里也只在 test scope）；需要历法的领域模块（social/gov/app 等）**自己显式声明**。
- **边界（本批）**：season API 直接收 `HexCoord`（读 `.r()` 判带）；calendar 本批**不读** `GameMap` 地形/高度，地形气候是后续（依赖口已就位，不需新边）。
- **取代关系**：本裁定取代 D-018「实施说明」里“calendar 模块不 import HexCoord / 只依赖 util”的表述；D-018 原文不删，留作前一轮记录。

## D-020 GUI：时间线显示 tick + 具体日期；点 hex 显示该格季节（2026-10-02 用户口述）

- **日期**：2026-10-02
- **来源（用户原话）**：「GUI上的时间线要求显示tick的同时能显示具体日期，点击hex能看见这个格子的季节」
- **设计裁定（用户给定，最终版）**：
  1. **时间线**在显示 tick 的同时显示**具体日期**（儒略历年月日）；节点下方一行日期，节点 `title`/`aria-label` 与时间线 meta 行同带日期。
  2. **点击 hex** 在格详情里显示**该格的季节**（按该格 `r` 分带 + 当前/所选 revision 的 tick）；未配置分带时明确显示“按北半球四季（未配置分带）”，不得假装已分带。
  3. 日期/季节一律**服务端算好**（`CalendarService`）随既有只读接口下发，**不在前端重写一套儒略历/节气算法**。
  4. 两个宿主页同步：工作台 `index.html`（时间线 + 格详情）与旧页 `map.html`（格详情）；旧页无时间线。
- **接口口径（本裁定落地）**：
  - `GET /api/state` 的 `meta.timestamp` 增 `date`；
  - `GET /api/timeline` 的每个 node 增 `date`（同 tick 多条 revision 同日）；
  - `GET /api/map/hex` 增 `date` + `season`（含 `phase/name/zone/zoneSource`；可带 `solarTerm`）；
  - 仍**不落 revision、不加状态组件**；历史 revision 的点选按其 tick 算日期/季节。
- **边界**：本批不做“按季节给地图上色/图层”；战斗事件浮层（D-017）不动。

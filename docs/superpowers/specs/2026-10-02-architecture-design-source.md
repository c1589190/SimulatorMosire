## D-006 补裁（2026-10-02 用户口述）：人力/装备的数据形状
- **来源（用户原话）**：「人力类型就是一个<Object,long>排列的表，Object代表什么类型的人力，可以是String，不排除后续传代表人力的特殊数据结构；long就是人力有多少；一个部队自然可以拥有多种人力；装备也是，目前也没啥特殊的装备数据结构、人力数据结构，默认赋String搞自然语义记录」
- **裁定**：
  1. **人力** = `<Object, long>` 的**排列的表**：Key = 人力类型（当前用 `String` 承载自然语义，后续可换/传专门的人力数据结构，当前没有）；Value = 数量；**一个单位可拥有多种人力**。
  2. **装备**同形：`<Object, long>`；当前没有专门的装备/人力数据结构，**默认 `String` 走自然语义记录**。
  3. 现有 `int member` + `Map<String,Integer> equipment`（`Unit.java:50-51`）⇒ 目标形态改为"类型→数量"的表；人力与装备**同构**。
- **实现待定（机械细节，不改设计）**：表的**保序**语义与键相等/JSON 序列化口径（Object 键）；数量类型用 `long`（与现有 int 的边界换算）。
- **关联**：D-007（人物/家族用通用 Unit）；D-011（不兼容策略）。

## D-009 补裁（2026-10-02 用户口述）：自定义交战状态与 1-tick 交战记录

## D-024 候选生产方式的预期利润 = 配方 + 市场价 + 真实需求；不得用"有没有既存读数"当门（2026-10-06 用户口述）

## D-025 饥荒/城市衰亡合法：城市化率是派生量，不作为维持性判据（2026-10-06 用户口述）

## D-027 先跑通单个市场区：同币即同区；分单 hex 贸易成本与市场总调控；跨市场区暂缓（2026-10-06 用户口述）

- **日期**：2026-10-06
- **来源（用户原话）**：「你为啥这么急着做跨市场区，首先，如果两个市场区使用的货币一样，那两个市场区事实上就是一个，

- **设计裁定（用户给定，最终版）**：
  1. **同币即同区**：两个市场区若使用同一种货币，事实上就是一个市场区；一个国家内常常形成一整个市场区。
     市场区的边界来自货币/制度的真实差异（不同币种、不同市场制度/关税区、GM 显式划界），不是“城市节点 + 半径”。
  2. **跨市场区暂缓**：本批**不做**跨市场区 lane / 在途 / 承运 / 聚集节点生成；先把**单个市场区**的经济循环按既有裁定跑通。

  3. **单 hex 贸易成本与市场总调控必须分层**：
     - **单 hex 贸易成本**：货物在市场区内从一个 hex 到另一个 hex 的物流/通行成本（地形、道路、距离），逐 hex/逐段计量；
     - **市场总调控**：市场区这一层的聚合规则（参考价/限价、总供需撮合、配额/配给、税费/准入、开闭市等），按区施加一次；

  4. **单市场区循环的验收优先**：生产/劳动/投入/收获、区内跨 hex 成交（带单 hex 贸易成本）、市场总调控、消费/出生死亡、
     债务/利息/偿还、家户迁移（D-022/D-024）、流民（D-023）、饥荒与派生城市化率（D-025）必须先在单市场区跑通；
     merchant 跨区运费不是本批判据。
  5. **D-025 继续有效**：城市可因饥荒萎缩/归零，城市化率是派生量。

## D-030 市场信用：挂单即可借、钱优先借、借啥欠啥；还款货币第一、商品按数量降序（2026-10-06 用户口述）

- **日期**：2026-10-06
- **来源（用户原话）**：「没钱不能借钱吗，我有在经济循环里规定没钱的时候不能借钱吗」
  「借是什么都可以借，那还自然是什么都可以还啊，就是还款如果要换算，需要根据还的人那边的价格来」
  「借债事实上就是市场上没卖完的商品，只是这里的'商品'要加上能挂到市场上借的钱，依旧是钱优先借、后续的实物按量大到小被借」
  「利息和本金不分开算了，反正都是增量，能还多少还多少」
  「库存多不多应当单纯按数量排序，不过不管怎么样钱应该放在第一位」
- **设计裁定（用户给定，最终版）**：
  1. **市场供给双用途**：卖家挂到市场上的未售商品，同时就是可借商品；**不另建仓库、不复制库存**。
     货币持有人余额超过保留额的部分，可作为“挂在市场上出借的钱”（本批每轮瞬态派生，不新增持久组件）。
  2. **借款顺序**：买方先用自己的钱；不够先**借货币**（钱优先），用借来的钱买货；货币借不到/不够才**借实物**；
     实物按“可借数量降序”选取（同量按 id 稳定序）。没有可借头寸就不成交，不强制出借、不造资产。
  3. **借啥欠啥**：借粮欠粮、借布欠布、借银欠银；债务合同仍是 `(债务人, 债权人, DebtUnit, principal, terms)` 多条并存，
     家户债表天然是“欠谁什么、欠谁什么”的列表。**不拆利息/本金**：利息继续并入 `principal`，只有一个未偿总额。
  4. **还款顺序**：
     - 换算一律用**还款人（债务人）自己的价目表**；缺项回退市场区默认价目表；再缺该 medium 对这条债具名跳过；
     - **货币永远第一位**，先花完所有可用货币，再动商品；
     - 商品按**原始数量降序**（不按价值），同类内按 id 稳定 tie-break；
     - 债按**未偿总额升序**（不再区分利息/本金），tie 按债权人 id、债的单位 id；
     - 能还多少还多少，不足顺延下周期；冻结不越、一日口粮保留、余额不得为负。
  5. **信用约束**：复用并扩展 `DebtCapacityBook`；货币债与商品债都按市场参考价折成共同价值计入 headroom；
     任一债务不可定价 ⇒ 该户新信用 headroom 视为 0（fail-closed，不超借）。
  6. **守恒**：借贷/还款只发生账户间货币/商品转移；不铸钱、不造货；“生成债务合同”本身不碰余额。
  7. **旧数据**：本批行为变化升运行时版本（建议 `seven-hex-v3`），旧档直接作废、GM 重置。
- **关联文档**：`docs/superpowers/specs/2026-10-06-market-credit-and-repayment.md`（完整设计：市场出借头寸、撮合顺序、信用额度、还款算法、接口/验收/文件所有权）。

## D-002 中央政府不设全视野（中央—地方博弈是设计目的）
- **日期**：2026-10-02
- **来源（用户原话）**：「中央政府不应有全视野！！！本来作用就是让中央和地方博弈」
- **设计裁定**：中央 DM 不给全国视野；`NationScope` / 扩大中央 GOV jurisdiction 等路径**不得**用于"给中央开天眼"。

- **边界**：地方（省/占领区）决策人按其 GOV 辖区的有限视野运作；军队按位置 + 视野半径（`ArmyVision`）。
- **关联**：`AGENTS.md §十.2`；四线调查 C 线 C5。

## D-003 外交关系 = 自然语言边表（尽量小，先做语义）
- **日期**：2026-10-02
- **来源（用户原话）**：「外交关系，可以做一张用自然语言描述的，每个 Nation 对其他 Nation 的关系表，尽可能做的小一些，以边记录，现阶段先做自然语言语义」
- **设计裁定**：
  1. 关系按**有向边**记录：每个 Nation → 每个 Nation 一条边；
  2. 内容以**自然语言**描述为主，本阶段**不做**严格类型化的外交数值/状态机；
  3. 模型尽量小（不做大而全的外交子系统）。
- **边界与未定项**：存储落点、命令/读口形状、可见范围（GM/决策人）——待实施前补裁并追加到本条。

## D-004 称臣纳贡 = 特殊外交关系；不写死贡额；只做"给 XXX 政府钱"的工具
- **日期**：2026-10-02
- **来源（用户原话）**：「称臣纳贡是一种特殊的外交关系，具体交多少钱给宗主国，其实也是附庸国的意愿直接决定，不要在程序上写死，只做一个给XXX政府钱的Tool暴露给决策人，这个tool同样应适用于地方政府」
- **设计裁定**：
  1. 附庸/朝贡**不建**"贡额、周期、违约"等硬编码规则；是否纳贡、纳多少，由**附庸国决策人自己的意愿**决定；
  2. 只提供一个**支付工具**（"给 XXX 政府钱"），**暴露给决策人**（含地方政府的决策人）；
  3. "称臣纳贡"这一关系本身记入 D-003 的自然语言外交边。
- **边界与未定项**：工具名/载荷、付款人身份如何从决策人上下文派生、审批链口径（决策人调用是否走人工批准）——待补裁。

## D-005 谈判 / 联动裁决的记录位置
- **日期**：2026-10-02
- **来源（用户原话）**：「谈判和联动裁决的状态、情况记录可以记在外交边上，如果是多国谈判，可以额外开一个外交事件记录，记录每一tick哪些国家参与，具体是什么，自然是自然语言描述」
- **设计裁定**：
  1. **双边**谈判/联动状态 → 记在外交边上（D-003 的边记录）；
  2. **多国**谈判 → 额外开**外交事件记录**：逐 tick 记录**参与国**与**具体内容**，自然语言描述。
- **边界与未定项**：事件 id/生命周期/是否可追加修改——待补裁。

## D-006 通用 Unit 接口：任意人力类型 × 多种任意装备类型；Army 模块做格式化复写（★ 现状：未实现）
- **日期**：2026-10-02
- **来源（用户原话）**：「我不是给Unit做了，任意类型人力搭配任意类型装备的通用接口吗…………实际被做成什么样了…………我要的就是任意人力类型+多种任意装备的通用Unit接口，加上Army模块的格式化复写，难道没有吗………………」
- **设计裁定（用户意图）**：
  1. **Unit 是通用载体**：人力不是单一 `int`，而是**任意人力类型 → 数量**的组合；装备同样是**多种任意装备类型 → 数量**的组合；
  2. **Army 模块**负责"**格式化复写**"（具体语义待用户补裁）。
- **代码现状（2026-10-02 实测，详见待调查清单）**：
  - `Unit` 的组件是 `int member` + `Map<String,Integer> equipment`（`simos-unit/.../Unit.java:50-51`）；
  - 命令载荷：`unit.CreateUnit{member, equipment, …}`、`unit.SetStrength{member, equipment}`、`unit.ApplyCasualties{personnel, equipment{…}}`（`logs/command_catalog.txt`）；
  - "兵种"目前靠**多个单位**表达（`WorldgenInitializeTool`：根单位 + 每兵种一条 `unit.CreateUnit`）；
  - `simos-army` 只有 **1 个类** `ArmyVision.java`（视野派生，明确"不算战力"）；**全仓无"格式化复写"实现**；`ArmyFormation` 只有 `masterGov + role`（`simos-unit/.../ArmyFormation.java:18`）。
  - ⇒ **用户所述设计在代码中不存在，且在本仓 docs / .superpowers / git 历史中未检索到已记录版本**（这正是要建本原稿的原因）。
- **待用户补裁（补齐后才能实施）**：
  1. **人力类型的键空间**：自由词表（如"骑兵/步兵/民夫"）还是受控目录？与现有 `member` 的关系？
  2. **装备类型的键空间**：自由词表还是装备目录（品类/语义）？
  3. **"Army 模块的格式化复写"的确切语义**：Army 模块把什么写成什么格式？触发时机（立编制/每 tick/命令）？是模板套用、编制视图、还是对 Unit 载荷的标准化重写？
  4. **兼容与迁移**：现有世界档（`member:int` + 装备自由 map）如何迁移？旧命令 `SetStrength`/`ApplyCasualties` 的兼容口径？
- **关联**：D-007（人物/家族也用通用 Unit）；`docs/superpowers/plans/2026-10-02-open-bugs.md`（现状与证据）。

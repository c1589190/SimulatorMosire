## 4. 契约形状（冻结）

### 4.1 口岸的存在方式（G1）

**不新增"口岸格"状态**。口岸 = 市场区之间的接触面，由地图派生：

```
接触面 k = 一条“本区格 ↔ 外区格”的相邻边
暴露边条数 = 逐格逐方向判"邻居不在本区"的条数（★ 共享边两侧各计一次 ⇒ 除以 2 或只在规范侧计；
             口径照上位文档 §10-2 裁定 = 逐格暴露边）
```

★ **暴露边是纯函数**（由 `MarketZone.hexes` + `HexCoord.neighbors()` 算出），**不落盘**
（不落盘 ⇒ 无往返不变式负担、无第二权威）。

### 4.2 逐政府实际管制力（G2/G3）

复用上位文档 §5.1 的公式（**逐字，不另立**）：

```
管制标准 standard（政策，政府定）
   ↓ 换算
口岸劳动力需求 demand = f(过境批次 × 查验率, 结汇总额 ÷ 单位处理额, 禁运/限量集合大小)
   ↓ 与实际编制劳动力比较
行政效率 c = 实际编制劳动力 ÷ demand
   ↓
实际管制力 enforcement = standard × c
```

- **`c` 的口径**沿用既有 `GovEfficiency` 的**口岸维**（第三维，见 F2/F3；本批需把口岸维补上）；
- ★ **不封顶**（用户既有裁定“都不封顶”）；`demand = 0 ⇒ c = 1000‰`（“没人管也不用管”）；
- **落点**：`simos-gov` 算效率，**组合根（app）**把"口岸政策 + 效率"折算成市场区层的执行规律
  （`simos-gov` 禁 `simos-economy`，见 F3）。

### 4.3 市场区实际规律（G4/G5/G6）★ 本批的核心算式

**对某商品（或某种钱）c，在某市场区 Z**：

```
逐接触面 k（Z 与相邻市场区之间的每一段边界）：
    s_k = 该段所属政府对该类（商品 c / 币种 c）的**限制强度**（‰）★ 未设 ⇒ 0（G6）
    e_k = 该段所属政府的**口岸效率**（‰，来自 §4.2）
    enforcement_k = s_k × e_k ÷ 1000          （‰）
    openness_k    = 1000 − enforcement_k       （‰）★ s=0 ⇒ openness=1000（全开）
    w_k           = 该接触面的**暴露边条数**

市场区 Z 对 c 的：
   【规则】允许 ⇔ ∃k: s_k = 0（任一处不设限 ⇒ 放行）        ← OR，不是 min
   【总效率】E_Z(c) = Σ(w_k × openness_k) ÷ Σ(w_k)            ← 按能力加权平均
```

**★ 为什么是加权平均而不是 min/max**（用户 §1.5）：
货**从多路同时涌来** ⇒ 总效果 = 各路能力的加权平均。
- 全部放开 ⇒ `E = 1000`；
- 9 条路里 1 条放开、8 条全禁 ⇒ `E = 1/9` 量级（只那一条在走货）；
- 每条半开 ⇒ `E = 500`。

### 4.4 走私 = 规模现象（G7）

**不新增“走私者”实体、不用随机数**：

```
可正常进出的量 ∝ E_Z(c) × 总过境能力
走私的量     ∝ (1000 − E_Z(c)) × 总过境能力
走私的成本楔子 ∝ (1 − E_Z(c)) × 罚没基准
```

★ **这正是用户 2026-10-08 的原话兑现**：
「如果这个效率高，那么单个家户就更不倾向于用这种货币付款，因为如果付了要被抓」
⇒ 效率进"家户对外币估值"的**减项**（E 批已落 `CurrencyValuation`），**不需要另写“家户不敢用”的逻辑**。

### 4.5 ★ 架构红线（G8/G9，**本设计书的最高约束**）

| 层 | 谁 | 手段 | 落点 |
|---|---|---|---|
| **法律规定层** | 市场区 + 口岸/禁运 | GOV 决策人 → **经济模块的市场区机制**（直接调用） | `simos-app` 折算 + `economy` 的市场区状态 |
| **市场行为层** | **政府（行政家户）** | 像任何家户一样**挂单**：压价、收购、抛售、雇人、**委托指定家户** | 既有家户→订单→撮合→结算全链路 |
| **GM 行政层** | GM | 兜底：注资、改名、立区（既有命令面） | 既有 GM 窄工具 |

★ **禁止**：为政府的经济行为新增"政策层/补贴层/官营层"机制。
**“委托指定家户”** = 政府与那个家户之间的**合同/转移**（家户间行为），不是特权通道。

## 10. ★ 追加裁定（2026-10-10）：口岸限制的是"**市场选择**"，走私算在**供给层**

### 10.1 用户原话（**逐字照录，不改写、不缩写、不意译**）

> 我认为走私的计算存在于供给层，口岸首先限制的是市场选择，如果口岸运转管制，一批货物压根就不应该被市场区内的家户选上，包括商户

### 10.2 本条决定了什么

1. **机制形态 = 选择集过滤**（不是"成本楔子记在谁账上"）：受管制的商品**根本不进候选集**——
   市场区内的家户**与商户**都选不上它。⇒ §4.4 的"走私成本楔子"**降级**（见 §10.4 X-R7）。
2. **走私计算落"供给层"**：开放度 `E` 决定"想进来的量里有多少成为**合法供给**"（`正常 = 过境 × E`、`走私 = 余量`），
   这个拆分在**供给形成处**算 —— **不在家户需求侧、不在商号利润侧**。
   ⇒ 体系复核报告 `2026-10-10-port-merchant-consistency-check.md` 里控制方给的 **X2 建议（需求侧估值减项）被本条取代**。
3. **商户与家户同为主体**：商户也不能选受管制的货 ⇒ 商户决策步（M2）拿到的候选集必须**已经过滤完**。
   ⇒ 次序（复核报告 X5）细化为：**口岸过滤 → 商户决策步 → 承诺表 → 撮合**。
4. **币种维不受本条影响**：币种维的已落形态仍是"家户对外币的**估值减项**"（`CurrencyValuation:292`；
   依据是用户 2026-10-08 原话"付了要被抓"）⇒ **两维形态不同**：商品维 = 选择集过滤；币种维 = 估值减项。
   复核报告 X7 的"两维独立"要按这条读（独立**且形态不同**）。

### 10.3 落点（实测 file:line）

- **供给层 = 卖订单**：`MarketSettlement.planOrders(...)`（`:1114`）产出的 `PlannedOrders.sells`；
  读口与成交同源（`MarketReadout:707`："供给 = 卖订单 sellable 之和 …… 经 `MarketSettlement.planOrders`"）。
- **跨区候选供给的撮合路径 = `MarketSettlement.matchAcrossRegions(ctx, indexes)`**（`:4072`，由 `:1431` 调用）。
  ⇒ 过滤要作用在**跨区候选**上：**本区自产的货没跨边界，不受口岸影响**（否则等于"区内禁售"，那是市场管制、不是口岸）。
- ★ **精度要求**：**不许删卖单本身**（那会把本区买家的选择一起删掉）；
  要按"**买方所在区 × 该区规则**"在**候选配对处**排除，并留**具名归因**（读口要能回答"这批货为什么选不上"）。

## 11. ★ 追加裁定 2（2026-10-10）：**"走私"这一档取消**——没管住就是流入，按正常供给算

### 11.1 用户原话（**逐字照录**）

> 走私本质上不就是口岸没管住？没管住就是流入市场了，凭啥还要额外记录？按正常供给给家户算

### 11.2 本条决定了什么

1. **取消"走私"这一档**：不记走私量、不算走私成本、不开走私账。
   **没管住的那一份 = 流入市场的那一份 = 正常供给**（家户与商户照常选）。
2. **口岸的真实作用 = 节流跨区流入**（算式不变，语义钉死）：

```
想入区的量        transit
流入量（普通供给） = ⌊ transit × E ÷ 1000 ⌋        ← 家户/商户正常选，不额外记录
被管住的量        = transit − 流入量              ← 不进市场（家户与商户都选不上，见 §10）
E = 0（全禁 + 满效率）⇒ 一点也进不来；E = 1000（不设限/没人管）⇒ 全进
```

3. **★ 命名更正（控制方自查，如实记）**：设计书 §4.4 与代码把两侧**叫反了** ——
   `PortRegimeAggregation.split` 里的 `normal`（`= transit × E ÷ 1000`）**在本条口径下就是"流入/没管住"的那一份**；
   而 `smuggled`（`= transit − normal`）实际是**被管住的量**。
   ⇒ 术语统一为：**流入量（普通供给）/ 被拦下量**；"走私"一词只留在本设计书的历史节（§4.4/§10）里，
   **不进代码与读口命名**。
4. **撤掉的东西**（实测**零读者**，可整体删）：`PortRegimeAggregation.split`、`SmugglingSplit`、
   `SEIZURE_BASELINE_MILLI`（全仓含 test 的 `grep` 只命中它们自己的定义处）。
   **成本楔子不得进任何算式** —— 商号利润尤其不许加这一项。

### 11.3 三条裁定一起读

| 裁定 | 内容 |
|---|---|
| §10（本日第一条） | 口岸限制的是**市场选择**：被管住的货**不进候选集**（家户与商户都选不上） |
| §11（本条） | 没管住的货**就是正常供给**，不额外记录 |
| §4.3（原有） | `E` = 开放度（按暴露边加权平均）；**OR 规则决定"是否放行"（布尔读数），`E` 决定"放行多少"（节流比例）** |

### 11.4 关闭 / 仍开放

- **关闭**：X-R6（走私那份的归宿）= **就是流入的普通供给**；X-R7（成本楔子去留）= **撤**。
- **仍开放**：X-R8（只拦入区还是也拦出区；默认**入区**）、X-R9（与 `MarketRegulation` 的次序；
  默认 定价存在性 → 口岸节流 → 撮合）。
- **不受影响**：币种维（仍是"家户对外币的估值减项"，依据用户 2026-10-08 原话）；若也要改成"节流/选不上"，需另裁。

### 11.5 对 P-T1 的影响（再改写）

- 落点：`MarketSettlement.matchAcrossRegions`（`:4072`）的**跨区候选配对**处，按 `E` 节流成 `⌊transit × E ÷ 1000⌋`；
  **不删卖单本身**（本区自产货不受口岸影响）。
- 归因：被拦下的量只留**日志/报告**一条（诊断用），**不落状态、不进账本**。
- 清理：删 `split`/`SmugglingSplit`/`SEIZURE_BASELINE_MILLI`（零读者）。
- 判据：`E = 1000`（无政策世界）⇒ 候选集与结算**逐值不变**；`E = 0` ⇒ 该商品在该区**零候选**。

## 12. ★ 追加裁定 3（2026-10-10）：**出入两侧都设规则，两侧都要过**

### 12.1 用户原话（**逐字照录**）

> 出入都设规则拦，分别按口岸效率算，最终一批货要过境，不管是效率漏了走私的，还是通过的，都需要两边都过才能跨区；

### 12.2 本条决定了什么

1. **方向维**：市场区**既有入口规则、也有出口规则**，两侧**各自**按自己那一侧的政府口岸效率算。
   ⇒ **X-R8 关闭**：不是"只拦入区"，而是**出入都拦**。
2. **过境条件 = 两侧都要过**（串行两道闸）：

```
源区 A 对该类的开放度 E_A、目的区 B 对该类的开放度 E_B
        （各自仍按 §4.3 的 OR 规则 + 按暴露边加权平均算 —— 不变）
可通过比例        = E_A × E_B ÷ 1,000,000
流入目的区的普通供给 = ⌊ transit × E_A × E_B ÷ 1,000,000 ⌋
```

3. **"漏过一侧"不等于过境**：源区没管住（走私出去）的那一份，**仍要过目的区那一关**；反向同理。
   两侧都漏过的那一份才**流入市场**，且按 §11 就是**普通供给**（不额外记录）。
4. **只有一侧是市场区**（对面是三不管／无区）：**没有政府的那一侧开放度 = 1000**（没有口岸可管），
   实际由有规则的那一侧决定。

### 12.3 控制方口径裁定（实现口径，可被用户推翻）

- **串行 = 相乘，不是取 min**：用户原话"不管是……还是……都需要两边都过"说的是**两道闸依次都要过**；
  取 min 会把"另一侧也拦"丢掉（两侧各 500‰：相乘 250‰，min 仍 500‰）。
- **E 用区级**（即 §4.3 现有的"按暴露边加权平均"结果），**不**改成"只算 A–B 之间那一段边界"——
  与用户 2026-10-09"货从多路涌来 ⇒ 算一个总效率"的裁定同源。
  ★ 若将来要"只算 A–B 共享边界"，那是另一条口径（更贴单条 lane，但要改 §4.3 的入参），需另裁。
- **OR 规则的位置不变**：它决定"这一侧是否放行"（布尔读数）；实际能过多少仍由该侧 `E` 决定。

### 12.4 对 P-T1 的影响

- 落点不变（`MarketSettlement.matchAcrossRegions` 的**跨区候选配对**），但**节流因子**从 `E` 改为
  `E_源 × E_目的 ÷ 1000`；
- 数据来源够用：`PortEnforcementInput` 是"逐区逐类"的两张表 ⇒ 查两次即可
  （表里存的是 `1000 − E`，取 `E = 1000 − 该值`）；
- 判据补两条：① **两侧都 = 1000 ⇒ 逐值不变**；② **任一侧 = 0 ⇒ 该 lane 零候选**。

## 13. ★ 追加裁定 4（2026-10-10）：跨区过境要**收税**（出口税 + 进口税）

### 13.1 用户原话（**逐字照录**）

> 哦对了，供给不是还要额外算出口税吗？暴露给市场区外的价格可以直接加上了，然后进来的时候可以再加一笔；

### 13.2 本条决定了什么

1. **两道税、按方向**：
   - **出口税**：源区把货**暴露给区外**时**直接加在对外价格上** ⇒ 区外买家看到的报价 = 卖方当地参考价 + 出口税（+ 运费，运费由买方付）；
   - **进口税**：货**进目的区**时**再加一笔** ⇒ 目的区买家实付 = 当地参考价 + 出口税 + 进口税（+ 运费）。
2. **真收钱**（不是读数）：税额**转移进对应政府的国库**。
   国库 = **政府家户** `hh-gov-<govUnitId>`（权威来自 `Government.treasury()`，见 `EconomySettlement:8940`，**不按前缀猜**）——
   出口税进**源区**管辖政府、进口税进**目的区**管辖政府；**买方多付、卖方仍收原价，差额进国库**
   ⇒ **货币守恒不破**（是转移，不是销毁，也不是造币）。
3. **无政府的一侧没有税**（也没有口岸）：三不管那一侧税视为 0，与 §12.2"无政府 ⇒ 开放度 1000"同源。
4. **默认 0 ⇒ 旧世界逐值不变**（I-P8 照旧）；税**不影响"能不能过"**（那是 §11/§12 的节流），只影响**过境后的价格**。

### 13.3 现成钩子（实测，不必新造机制）

- `MarketRegulation.tariffPerUnit`：**已存在**的"商品 → 单位税费"表，类注明写 **"本批只累计读数，不搬钱"**；
- `MarketReport.regulatedTariffMilli()`（`MarketReport:170-320`）：逐票按**成交毛量**折
  `⌊量 × 单位税 ÷ 1000⌋`，且**读口已把它加进到货价**（`:173`）。
⇒ 本裁定 = 把这个钩子从"**读数**"升级为"**分出入两侧、真搬钱**"，机制形状不用另起。

### 13.4 ★ 与既有区级 tariff 的关系（别做两套）

`MarketRegulation.tariffPerUnit` 是**区级**的（按区施加一次、瞬态、不落盘、只读数）；口岸税是**跨区过境**的税。
⇒ 控制方建议：**合成一套、同一笔 fill 只算一次税**（区级那份 + 过境那份分开列，避免读口与国库双记）。

## 14. ★ 追加裁定 5（2026-10-10）：**币种维 = 挂单级"禁入/禁出" + 手续费**；规则形态灵活

### 14.1 用户原话（**逐字照录**）

> 以及你说的XR9是啥东西，货币交换的话，异种货币自然按手续费/规则来算啊，有一方不给过就不过，给这个挂单禁止进入市场，出市场……没有哪国会禁止本国公民在他国使用自己的货币吧？但是规则还是可以设置的，代表禁止本市场区货币被外国借贷（借贷走的也是市场挂单，恰好本国货币对于本国居民来说只能借贷不可能一块钱买一块钱，用货买钱倒是不知道可任意不可以）；我建议是规则可以灵活，从量从价都行

### 14.2 先回答用户的问题：X-R9 是什么（控制方回答，不是裁定）

**X-R9 = "口岸过滤与既有 `MarketRegulation`（GOV 定价行）的先后次序"。**
现状：`MarketRegulation` 是**区级**的市场总调控（参考价 / 限价 / 配额 / **税费读数** / 开不开市），

### 14.3 币种维的机制（本条裁定）

1. **异种货币按"手续费 / 规则"算**（不是估值折扣）：跨币种要收**手续费**，并受规则约束。
2. **挂单级过滤**：规则可以**禁止某类挂单进入市场（或出市场）** ⇒ 币种维与商品维**同形**（都是选择集过滤），
   且**两侧都要过**（§12 的两道闸对币种同样成立）：一侧不给过 ⇒ **该挂单不成交**。
3. **限制的对象是"市场"，不是"货币在境外的使用"**：用户明说"没有哪国会禁止本国公民在他国使用自己的货币吧？"
   ⇒ **不得**把规则实现成"本币不得在境外流通／不得被外国人持有"；
   规则的语义是"**本市场区**允许／禁止哪一类挂单进来、出去"。
4. **规则要能落到"挂单类型"上**：用户给的具体例子是"**禁止本市场区货币被外国借贷**"，
   并点明"**借贷走的也是市场挂单**" ⇒ 过滤的键不能只有币种，还要能带**挂单类型**（兑换 / 借贷 / …），
   否则这条规则**表达不出来**。★ 这是对现有 `currencyRestrictionPerMille`（只有"币种 → ‰"一个键）的**形状扩展**。
5. **"一块钱买一块钱"不成立**：本国居民的**本币**不可能用本币买本币（1:1）⇒ FX 撮合天然是**异币配对**
   （现有 `FxSettlement` 的 pair 机制正是如此）；本币对本国居民的作用是**借贷**（他们能挂的那类单）。

### 14.4 未决（用户明说"不知道"）

- **"用货买钱"**（商品**直接**换外币，而不是"货 → 计价币 → 外币"）：用户"不知道可不可以" ⇒ **未决**。
  现状：市场成交恒是"货 ↔ 该格计价币"（`SILVER_SPECIE`），跨币种要走 FX ⇒ 目前**走不通**。要不要开，另裁。

### 14.5 规则形态（回答 §13.5 的 T-1）

**"规则可以灵活，从量从价都行"** ⇒ 规则/税率的形态**两种都要支持**（每条规则各自指定从量"毫/单位"或从价"‰"）；
缺省 0 ⇒ 逐值不变（I-P8 照旧）。

### 14.6 与既有实现的关系（实测）

- 现有币种维 = `CurrencyValuation:292` 的**估值减项**（依据是用户 2026-10-08 原话"付了要被抓"）。
  本条把机制换成"**挂单禁入/禁出 + 手续费**" ⇒ **估值减项这条要不要撤**，需用户一句确认
  （控制方建议撤，否则同一件事两套口径：既打折又禁入）。
- `GovPortPolicy.currencyRestrictionPerMille` 现为"币种 → ‰"单键 ⇒ 要扩成 **(币种, 挂单类型)** 或加方向维（§14.3-4）。

### 14.7 对 P-T1 的影响

- 币种维从"注入估值减项"改为"**挂单过滤 + 手续费**"，与商品维共用同一套"两侧都要过"的实现；
- `CurrencyValuation` 的 `portEnforcement` 入参用途随之缩小/取消（若确认撤估值减项）。

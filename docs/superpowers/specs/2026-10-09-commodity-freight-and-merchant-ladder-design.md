## 4. 契约形状（冻结）

### 4.1 商品运费表（G1；★ 2026-10-09 用户裁定「甲」后**修正**）

> ★★ **修正记录（控制方）**：本节原写"商品运费**系数**（‰，乘在整条运费上）"，并据此让实现方在
> `TransportTariff.perMille` 加了第 6 个入参。**该方向是错的**——它撞上了早已存在的
> `MarketSettlement.commodityFreightBaseMilli`（`d7604ea5`，**非本批引入**）：那组常量**本来就是**
> "每件每程的基础运费"（粮/纤维 1、布 2、工具 3 毫），其注释原文即用户 2026-10-09 的口径
> 「**运费只和商品种类有关**」。⇒ 真相不是"缺商品维"，而是"**这张表被切成两半、一半锁在代码里**"。
> 用户 2026-10-09 裁定 **甲**：把它搬进状态表，GM 可改。

**目标形状**：

```
EconomyData 第 36 组件：commodityFreightBaseMilli : Map<CommodityId, Long>
  · 语义：该商品的**基础运费**（毫计价货币 / 商品单位 / 程）—— 与商品价格无关
  · 缺键 ⇒ 取具名缺省（见下）；值域 ≥ 0（0 = 该商品免基础费，是**明确**的，不是"说不出价"）
  · ★ 旧档缺该组件键 ⇒ **归一到"现行硬编码分档"**（粮1/纤维1/布2/工具3；未登记商品 ⇒ 1）
    ⇒ **旧世界逐值不变**（I-F1）
```

**公式（唯一拼写点，`MarketSettlement.freightUnitMilli`，逐字保留）**：

```
单位运费 = max(1, ⌈ 基础费(商品) × (1000 + 路线费率‰) × (1000 + 承运成本‰) ÷ 1,000,000 ⌉)
             ↑ 从状态表读（GM 可改）        ↑ 距离/地形           ↑ 商号档位
```

- ★ **撤销** F 批加在 `TransportTariff.perMille` 上的"商品系数"第 6 入参（那一维是方向错的产物）；
  `TransportTariff` 回到纯"距离/辐射/道路/城乡"维；
- `commodityFreightBaseMilli(商品)` 由**硬编码 dispatch** 改为**读状态表**（缺键 ⇒ 具名缺省 = 1）；
- **GM 命令** `economy.SetCommodityFreight`（形制照 `SetMarketPrice`：GM-only、具名拒、日志）：
  载荷 `{"commodityId":"grain","baseMilli":2,"reason":"…"}`；
  拒绝：未知商品 / `baseMilli < 0` / 与现值逐字相同（`freight-unchanged`）⇒ 具名拒且零 revision。

★ **后续（丙）**：将来要调"工具在长途中该不该更便宜"，用同一张表改数字即可——甲让这条路是通的。

### 4.2 工坊制品自然需求（G2）

- **布 + 工具**进家户自然需求（与粮并列）；**不**加 `fiber`/`iron`/`wood`（中间品，家庭直接需求弱）；
- **权威仍在 Social**（`SocialProvisioning`：全局默认 + 家户覆盖，键 `(AgeBracket, Sex, CommodityId)`）
  —— ★ 不许在 economy 侧另造第二本需求权威（既有不变量）；
- 系数取值须落到**设计书可读的常量**（本设计书给不出标定值 ⇒ 由实现方按"与粮的单位可比"给出**具名常量 + 理由**，
  并在账本列出"会改变数值行为的清单"）。

### 4.3 商号利润与“运力 = 劳动”（G3）

| 项 | 目标形状 |
|---|---|
| **运力来源** | `capacityPerRound` **由投入的劳动派生**（一单位劳动换一单位运力），不再是外生常量 |
| **收入腿** | ① 运费（帮人运）；② **买卖差价**（自己低价买、运到高价卖） |
| **同一趟三条赚法** | 跑腿（只有劳动）/ 自营（有本钱）/ 两头赚（本钱 + 富余运力）——**按手里有什么取舍**，不是三套逻辑 |
| **利润** | `利润 = 运费收入 + 差价收入 − 劳动机会成本（回家种地/作坊能赚的） − 本钱占用` |
| **家户选择** | 把"开商号/加入商号"作为**新的活动**进选择器，与 `PRODUCTION`/`ARBITRAGE` **同一排序键（收益率）** |

★ **关键**：排序键仍必须"**最划算的先做、不划算的后做**"（用户阶段 1 原话），不许给商人特殊优先级。

### 4.4 商号规模决定触达范围（G5）

- `serviceRadiusHex` 由**规模**（运力 + 本钱 + 雇工）**派生**；`tier` 只作**读数/日志分类**；
- ★ 但**本批不提高创世 tier**（那是世界配置，另批）；本批只把"半径由规模派生"这条链路做出来，
  让**成长中的商号能真的扩到隔区 lane** ⇒ F8 那个瓶颈才有解。

### 4.5 区域禀赋分异（G6）

| 层次 | 由谁定 | 落点 |
|---|---|---|
| **禀赋**（天生） | **地形/资源** | 世界生成器：地形 → 资源 → **各区可建产线不同** |
| **政策**（人为） | **GOV 决策** | GOV 命令面：产业补贴 / 禁运 / 官营 / 贸易枢纽（**本批只留接口与设计，不实现全部政策**） |

★ **不许**把“区域分工”做成硬编码常量表（那是外挂配置）；必须从**地形**推出来。

### 10.2 冻结的机制（= 商号决策步）

```
① 覆盖范围：商号用自己的服务半径筛出范围内的格 ⇒ 候选市场

③ 客户列表：为这些需求排序 ⇒ 第一级"理论可能客户列表"

⑥ 承诺与结算：这些单被标记"由本商号承运" ⇒ 买家付运费、商号收运费、货到手
```

## 11. ★ 追加裁定（2026-10-10）：**商号 = 提供运力的家户**；运力池 + 议价权排序 + 超出不计入价格表

### 11.1 用户原话（**逐字照录**）

> 商号的本质就是提供运力的家户，运力就是每一笔长途商品需要额外支付的，先把hex内商号的运力统计出来，然后再计算最多能有多少跨格商品，排序按照提供方的市场议价权给，多出来的不计入当前hex的家户商品价格表，然后商号自己买东西，在生产环节支付劳动力兑现运输，不就得了？

### 11.2 本条冻结的机制（**逐步取代 §10.2 的六步决策步**）

```

④ 分配顺序 = **运力提供方的市场议价权**（不是先到先得、不是货主挑）
⑤ **超出的部分不计入本 hex 的家户商品价格表**（不参与本格定价）
⑥ 商号**自己买东西**（自营买卖，钱货落在**家户账**上）
⑦ 运输靠**在生产环节支付劳动力**兑现（= 运力=劳动的落点）
```

## 15. ★ 追加裁定 5（2026-10-10）：**运力可计算、可按最低价购买**；购买走"**满足全部需求 + 没钱全算债务**"

### 15.1 用户原话（**逐字照录**）

> 算了，把运力也改成可计算的吧，就是单个家户每需求一个商品就算运力，算完之后算一下总共需要多少运力，按照市场上最低价的运力提供商买运力，注意"运力"过来同样需要运力，反正购买走的是满足全部需求+没钱全算债务，能跑通吗？

### 15.2 冻结的机制（控制方读解，逐条标出）

| # | 口径 |
|---|---|
| **K-A** | **运力可计算**：单个家户**每需求一个商品**就产生一份**运力需求**（按数量/距离计；与 §14"运力=派生量"同向） |
| **K-B** | 算完**汇总**出总运力需求（该 hex / 该区需要多少运力） |
| **K-C** | 向**市场上最低价的运力提供商**买运力（⇒ 运力有**报价**与**选择**，不是公式定价后的被动分摊） |
| **K-D** | **"运力"过来同样需要运力**（递归；**必须有终止规则**，见 §15.4 K-1） |
| **K-E** | 购买语义 = **满足全部需求**；**没钱全算债务** |

### 15.3 与既有裁定/机制的接口（实测）

| 接口 | 结论 |
|---|---|
| §11"分配按**提供方市场议价权**" | ⚠️ **与本条 K-C"按最低价买"冲突** ⇒ 必须统一（见 K-2） |
| §11"超出运力**不计入本 hex 价格表**" | ⚠️ **与本条 K-E"满足全部需求"冲突** ⇒ 必须统一（见 K-4） |
| §12 H-E"运力**不可储存转卖**" | ✅ **相容**：运力是**按次购买的服务**，买家不储存、不转卖 |
| **既有市场信用 D-030/D-031** | ✅ **方向一致**：`creditRound` 已经是"借款人侧**无额度上限**，唯一上限 = **放贷人可借池**"（`MarketSettlement.creditRound`；`MONEY_LENDING_AUTO_LIST`/`MARKET_GOODS_LENDING_ENABLED` 默认开；出借人保留额 `LENDER_MONEY_BUFFER_PER_CAPITA_MILLI = 12`）⇒ 本条 = 把"部分"扩到"全部" |
| 国库户 | ✅ 既有守卫保留：**明确授权 ≠ 加杠杆**（国库户不进信用撮合） |

### 15.4 ★★ "能跑通吗？"——能，但有 **4 条必须先钉的规则**（这才是答案）

| # | 洞 | 为什么必须先钉 | 控制方建议（可被推翻） |
|---|---|---|---|
| **K-1** | **递归没有终止条件** | "运力过来同样需要运力" ⇒ 无限回归 | **深度 1 + 固定附加费**：运力服务**含"上门"**（把承运者/批次带到发货格这一腿按**具名固定附加费**计入，**不再递归展开**） |
| **K-2** | **排序键冲突**：K-C 说"**最低价**"，§11 说"提供方**议价权**" | 两条都决定"谁能承接"，同时生效会互相打脸 | **价格是买方的选择键、议价权是运力稀缺时的分配键**：买方从低价起买；容量不够时由**议价权高的提供方**优先承接（两条各管一层） |
| **K-3** | **债务必须有债权人**（"没钱全算债务"） | 既有信用的上限是**放贷人可借池**（D-031）：池子空了 ⇒ 需求**就满足不了**，于是"满足全部需求"不成立。凭空记债又没有债权人 ⇒ 破坏账本语义与守恒 | **二选一，需用户裁定**：**(a) 维持 D-031**（满足到放贷池为止，不是"全部"）；**(b) 允许"赊购"**：债权人 = **卖家本人**（买家欠卖家），运力同理欠提供者 ⇒ 池子上限消失、"全部"成立，代价是**卖家被迫承担坏账** |
| **K-4** | **优先级冲突**："满足全部需求" vs "运力是硬上限（超出不计价）" | 运力不够时，那批货既"该被满足"又"运不过去" | **运力不足 ⇒ 未运走的部分：不成交、不成债、不计价**（"满足全部需求"限定在**运力够**的范围内）；被挡下的部分**不提价不压价**（§11 口径） |

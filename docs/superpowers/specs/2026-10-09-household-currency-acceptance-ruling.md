## 2. 本轮裁定（冻结）

| # | 裁定 | 依据 |
|---|---|---|
| **R1** | **家户对外币“什么都愿意收”，实际按自己的货币估值判断是否划算**；不接受“按闸门拒绝”这种实现 | §1.4 |
| **R2** | **家户怎么花外币，系统不管**——不设计“家户必须能去别处花”这类前置条件，也不要求任何估值口径方案 | §1.5「谁管家户怎么花掉啊？」 |
| **R3** | **没做口岸 ⇒ 事实上就是同一个市场区 ⇒ 自然统一汇率** | §1.5 |
| **R4** | **汇率问题等口岸做出来再看**（现在不预设摩擦参数、不做口岸楔子） | §1.5「等做出来了再看汇率问题」 |
| **R5** | **本币/外币的现实来源 = 政府收购 + 区域交换贸易** | §1.5 |
| **R6** | 三不管地带**允许任意货币流通** | §1.3-1 |
| **R7** | **跨区贸易保留**（不收窄） | §1.3-2 |

## 3. 要落的机制（实现契约）

### 3.1 E：家户货币估值 + 拆掉异币硬拒（★ 本批主线）

**现状**（`e0af5269` 核实）：

```java
// HouseholdValuationBook.java:100-101 —— 只有一个计价币，价目表只装商品
private final CurrencyId numeraire;
private final Map<HouseholdId, Map<CommodityId, Long>> reservationsMicro;

// MarketSettlement.java:3851 —— 异币一刀切拒（唯一拼写点）
if (sell.receiveCurrency == null || sell.receiveCurrency.equals(buy.currency)) return false;
// SellSlot.receiveCurrency = market.numeraire()（:5799），单一值、不可为 null ⇒ “放行”分支实为死路
```

**目标形状**：

```
HouseholdValuationBook
  numeraire                                  // 不变（本区计价币）
  reservationsMicro : Map<HouseholdId, Map<CommodityId, Long>>        // 不变（商品保留价）
  currencyValueMicro : Map<HouseholdId, Map<CurrencyId, Long>>        // ★ 新增：家户对每种钱的估值
```

- **量纲**：与 `reservationsMicro` 同一微刻度（`MICRO_PER_MILLI = 1000`）；
- **本币对自己的估值 = 面值 1:1**（★ 这就是 R3「自然统一汇率」的锚）；
- **成交判据（卖方侧）**：
  `买方付出金额 × 我对该币的估值 ≥ 我的保留价 × 数量` ⇒ 成交；否则**不划算**（不是“被拒”，
  归因用既有的市场性未成交理由，**不新增 `CURRENCY_MISMATCH` 语义**）；
- **删除**：`rejectCurrencyMismatch` 的硬拒语义（三条腿：现金 / 货币信用 / 商品信用）。
  ★ 三条腿必须**同一个拼写点**改造，不许留下第二条比较（现状已统一，保持）；
- **`SellSlot.receiveCurrency` 的处置**：定成“**本格默认收款币**”（不再是唯一可收），
  实际收款由成交时的估值比较决定；三不管格无默认（R6）⇒ 收当地存在的任意币。

**与“汇率统一”的关系（R3/R4）**：世界只有一种“可按估值换算”的行情 ⇒ 家户在任意两处的
估值比自然收敛到一组汇率。**本批不引入任何摩擦参数**（R4）。

**验收判据（正向）**：

| # | 判据 |
|---|---|
| E1 | 持铜家户**能从**银区卖方买粮（此前 `CURRENCY_MISMATCH` 必拒） |
| E2 | 成交价按**估值**：卖方收铜时，要求“铜的估值折回本币 ≥ 保留价”；估值越低，要的铜越多 |
| E3 | 本币对自己的估值 = 1:1（同币交易的成交价与改动前**逐值相同**） |
| E4 | **汇率自然统一**：同一时点，任意两币之间的成交比价在**各地区一致**（世界只有一种行情） |
| E5 | 三不管格：任意币都能成交（R6） |
| E6 | 跨区贸易**保留**（R7）：相邻区照旧撮合、ETA/运力/运费不变 |

**验收判据（负向）**：

| # | 判据 |
|---|---|
| N1 | 估值不足以覆盖保留价 ⇒ **不成交**，且归因是市场性理由（不是“币种不符”） |
| N2 | 旧世界（单币 `small-world`）**逐值不变** |
| N3 | 不许新增第二套币种比较（三条腿同一拼写点） |

### 3.2 D3：长跑崩溃（★ **硬前置**，先修）

**症状（控制方 2026-10-09 独立复现）**：三区世界 300 天推进，**day 270 崩**、服务停 tick 210：

```
day=270 ... MIGRATION_PLAN ... moves=43 organizations=163 modeHexProfits=117
day=270 WARN GUI_REQUEST_FAILED ... error=IllegalStateException
```

**根因（代码定位）**：`MarketSettlement.participantsFor` 的具名抛（`:5225`）：
生产单位的经营者家户消失/迁走 ⇒ 单位行未随之拆解或被重新指派 ⇒
`economicHouseholdOf(unitId)` 与 `householdsOf(unitId)` **双空**、而该 unit **有正资产** ⇒ 抛。

**要求**：修“经营者家户消失/迁移后，单位行的归属”这一条链路（拆解、或重指、或具名降级），
并给出**≥360 天不崩**的真实长跑证据。**不许**把具名抛改成静默跳过（那会把坏数据藏起来）。

★ **G3 复测的口径要改**（R3/R4 的直接后果）：现判据“跨区套利不随时间归零”是**在异币被硬拒的前提下**写的；

复测时按新口径判：**收敛后的汇率是否与各区相对物价一致**（若不一致才是缺陷）。

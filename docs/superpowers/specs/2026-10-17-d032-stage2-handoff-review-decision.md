## §2 批量执行：接受，不能只靠固定遍历顺序

### 2.1 一天内的共同条件

**裁决：同 tick 的生产效果取同一时点的生效条件，新增经验统一计入该 tick 结果；不能因实例处理先后改变另一实例本 tick 的熟练度。**

- 组合根取得明确世界 tick，调用本域逐 tick 驱动；既有经验按明确日序衰减一次，然后形成当 tick 的经验/熟练度等生产生效条件。
- economy 在这份生效条件下试算、统一分配；本 tick 各实例执行均使用同口径条件。
- 各实例按实际贡献产生经验增量，按家户×经验条归并并结转精度；达到门槛在当 tick 记入永久解锁。新增经验/资格用于后续 tick 的生产，不回头重算本 tick 已分配劳动。
- production 的当刻候选态可以包含已累计的新经验，供后续经济分配/迁移等阶段读取；**当前候选态**与**本 tick 生产生效条件**要区分，不能为固定条件而让迁移读到过期经验。
- 同家户同经验条分布在多个实例时，实际劳动不能重复计；分组/排列本身不应额外创造经验或生产增益。精度归并与稳定顺序须定义清楚。

这是落实统一 tick 与预测/实际同口径的工程日序，不新增独立时间推进者。若既有精确业务时序与该安排冲突，应带真实场景核对，不能任由容器遍历顺序决定效果。

### 2.2 批量入口与单项入口

- 接受批量驱动与“单实例一次执行代表一个生产日”。可复用单项 execute，但**允许必要的批次级准备、共享条件、经验归并和收尾**，不强制批量包装是零准备的字面纯循环。
- tick 身份必须由已有调度/引擎上下文明确提供；同实例同 tick 重复推进、同 tick 重复衰减都须检测，不能只在注释里说“调用者别重复”。
- 同一次 Advance 可能跨多个 tick：逐日依次执行；最终 production ChangeSet 仍从 Advance 起点到当前完整候选态派生，不得每日重置基态后只提交最后一天。
- 不同实例可共享家户和资产，批量不等于各 hex 自行取得整份资源；输入必须已通过统一预算与占用检查。

### 2.3 失败语义

**删除“批量不得短路”这项无条件限制。**

- 正常业务拒绝可以逐项具名返回，但被拒请求不得残留新实例、进度、经验、原料消耗或占用变更；其释放资源如何重新分配仍归 economy。
- 契约故障、公式错误、重复推进或跨域不一致必须终止本次候选计算，拒绝整个相关 Advance 提交；不能吞错继续、不能提交故障前的一半结果。
- 接口可以抛错并由组合根废弃候选态，或在本域回滚；选择哪种是实现细节。禁止在部分污染的 runtime 上继续收集回执并最终提交。

## §3 回执和视图：禁止写权限，不禁止不可变事实

**不接受“回执里出现推进后的实例就一定是可写视图”的推断。**

可以返回不可变、无可写别名的实例快照、ID、进度等必要事实，也可以通过当前候选态只读查询获取；二者都是合法契约。选取最简、不会陈旧和越界的形状即可，不要求实现方额外造回读流程。

禁止的是：把 runtime 内部可写 Map/可变对象暴露给 economy，或让 economy 修改本地副本后再当 production 权威写回。公开 record 的不可变性也要覆盖内部集合，不能只靠 record 名称。

B 批结束时必须删除 unitsWorkCopy 等经济侧推进/写回路径，删除旧公式/旧状态/重复定义；临时只读索引允许。判据看是否存在第二写入口，而非是否恰好使用某个类型名。

## §4 A/B 范围、旧构造器、串行化

### A/B 范围

A 批专注 production 语义与形状，必要契约值类型可落既有 economy-api，economy/app 只做机械编译修正，这个隔离可以保留。若新形状无法在该限制下维持旧消费者编译，控制方可以明确把最小引用收口与 B 合并同一 owner；**不准**让实现方通过删守卫、默认空地点、伪造进度或保留第二权威来“机械修编译”。

A 未装配到真实日循环时，交账只能写“生产侧实现/编译中间产物”；A 的语义也需要最终测试，不因先编译过就不可修订。B 在同责任区一次收口经济写路径、组件删除、公式退役、跨域守卫和所有推进路径；随后独立测试，期间停止争抢同一树 Java/target 的其他写入。

### 无 runtime 的旧构造器

runtime=null 且走到生产就抛错的构造器，只准临时存在于施工中间态。B 结束后，所有支持生产的有效入口必须显式获得合法 runtime；没有实际可用职责的旧重载应删除。不能以“免得改测试”为理由长期保留一个能编译、实际不能履约的入口。

真正只读或不涉及生产的独立用法可有明确窄接口，不得借此让生产写路径静默降级。测试由独立 owner 随最终公开契约更新，Alpha 不做无效旧接口兼容。

### 串行化

**允许按 hex 并行改为串行。** 既有货物运输到达、周期投入、消费/市场等业务日序不因此改变。

等价判据是**同一套新规则、相同基态与输入**下，串行和确定性归并的并行结果逐值一致；本轮本来就在修正错误生产公式，不能要求新公式结果等于错误旧公式结果。受修正影响的数值要用手算/独立判据解释，不把差异笼统归因于串行。

记录该串行方案是本批确定实现；未来若恢复并行，必须保持同 tick 生效条件、全局预算、候选态与归并语义，不为未来并行预先增加框架。

## §5 B 批硬性收口与后续验证

- 真正走 probe→分配→execute→回执，production/actor 等相关变更来自同一次真实候选计算；PRODUCTION 键存在但为空不能单独证明接线成功，合法无生产 tick 则允许空变更。
- economy 不 import production 非 contract 实现；组合根直接装配所需数据/引擎，不经 economy 的 runtimeDataOf 越界取内部状态。
- 库存实际消耗与产出、经验与进度、工资/租金/分成逐项可核对，跨域失败零部分提交。
- 两处仍推荐已失效铸币键的提示要清掉，同时保证原有 GM 可调生产率能力在 production 的新配置/命令归宿中被明确承接；新写入口若按计划后续交付，就写“该能力待后续”，不能仅删提示后宣布整体完成。
- 设计书若将 GM 写入口/GUI 放后续阶段，B 完成只代表接线阶段完成，独立测试验证相应实际范围；整个 D-032 交付仍须覆盖已要求的可配置、可写可查能力。
- 测试 owner 在实现统一交账后独立接手，新增判据包含：同户多实例调整遍历次序无额外熟练度收益；同 tick 重复推进被拒；单次跨多日与拆段推进一致；批量中途故障无半提交；不可变回执无法越权改权威；无效旧构造器及越界 import/旧写入口扫描；此前阶段 1 复核的生产数值、经验与共享方案判据。

以上由控制方继续细化接口、owner、证据和批次，不需要用户再批准工程安排。只有溯源后仍需改变用户玩法/权限/铁律的具体业务问题，才交用户；本轮没有这类问题。

## 3. 现状对照（实测，file:line）

### 3.1 土地与产能：现在是"资产存量 + 最紧约束"，不是"配额 + 拒绝"

- **本格可耕地已经从 map 的 hex 属性推出**：`EconomySeeder.landMilliMuOf(terrain) = MU_PER_HEX(3,100 亩) × 地形系数`，
  系数由 map 的 `TerrainType.food` 折算（`arablePerMilleOf(food) = food × 1000 / 3`）——`EconomySeeder:246 / :1920-1921 / :2346`。
  ⇒ **D1 的"从 map 读 hex 属性"这一半今天已在做**（数据源现成；缺的是"上限"这个**可见、可拒绝**的语义）。
- **土地以实物份额总账存在**：每个 `(industry, asset)` 的 `Σ OwnershipStake.quantity` 就是实物总量（`OwnershipStake:12-15`）；
  `Industry.capacity` 已降级为**旧档兼容位、生产路径禁读**（`Industry:24-25, :99`）。
- **规模 = 最紧约束**：`scale = min_k ⌊可用资产_k ÷ capacityPerUnit_k⌋ …`（`ProductionProcessBook:35-120` 的
  `usableAssets`/`capacityScaleOf`；`ProductionRecipe:26-35`）。可用资产**只按 operator 汇总**（所有权只决定收益归属）。
- **组织身份 = `(mode, position, household, hex)`**（`ProductionOrganizationId.idOf(...)`，`EconomyEnterpriseSettlement` 组织阶段）
  ⇒ 同一格**允许多个组织并存**，彼此靠"各自手里的份额"划界。
- **创世按比例预分**：主 unit 留 70%，其余 30% 按劳动权重用最大余数法切给家户副 unit（`SECONDARY_PER_MILLE = 300`，
  `EconomySeeder:420` + `splitIndustry`）。
- **后来者只能吃"闲置份额"**：`ExpectedProfitBook:779-794`（自有自营 + 同格可租闲置，判据 = `ModeMigrationPolicy.isIdleShare`）；
  迁移新建组织同源（`ModeMigrationSettlement` 的 `isIdleShare` 判据）。
- **触顶的现成表达 = `SHORTAGE` + 具名原因**：`ProductionEnterprise.Status{ACTIVE, SHORTAGE, SUSPENDED, EXITING}`，
  `SHORTAGE` 必须带 `statusReason`（`ProductionEnterprise:37, :51, :87-92, :125`）。
  ⇒ **D2 的"地到上限就不允许继续组织"机制上已有雏形**（拿不到份额 ⇒ 具名 SHORTAGE），
  但**没有"上限"这个显式对象**，也**没有"先来后到"这个序**（现状是"创世按比例预分 + 运行期吃闲置"）。

### 3.2 城市化/城区：**纯模型齐备，运行期零动作**（实测）

- map 的 `City` = `(id, name, at, region, props)`（`City.java:29`）——**没有面积/城区属性**；`HexCell` 只有 `height`；
  立即可用的 hex 属性只有地形（`TerrainType` 的 food/gold/stone/moveCost）。
- `CityLand`（纯值记录）+ `CityLandBook`（props 读口，9 个 `cityLand.*` 键）**零生产调用者**
  （实测全仓 grep：只有它自己的 Javadoc 与 `CityLand` 类注引用它；唯一用到 `CityLand` 类型的是 `CityMigrationReading`）。
  城区占用当量已冻结：`used = 人口/100 + 作坊数×2 + 商人城区当量 + 累计贸易量/1000`；压力 ≥ 800‰ ⇒ 进度 +1 ⇒
  满 200 ⇒ `capacity += 20`、`builtAreaPerMille += 20‰`（`CityLand:12-24, :66-91, :302-330`）。
- **城区占地从可耕地里扣**：`availableArableMu = max(0, arable − builtAreaMu)`（`CityLand:430-440`）。
  ★ 这正是 D10"独立池"的雏形——**但城区面积怎么长仍是"比例 + 压力自动扩建"**，且**未接日循环**。
- 迁移拉力 `MigrationPolicy.urbanPull`（`MigrationPolicy:7, :145`）+ 读数 `CityMigrationReading:86-107` +
  计划器 `PopulationMigrationPlanner`：**生产侧零调用者**（实测）⇒ **城市化迁移今天不在运行**。

### 3.3 工坊：无用地约束、无城区池、无城区加成

- 作坊数在**创世**由城镇人口派生：`workshops = 城镇人口 ÷ URBAN_CAPITA_PER_WORKSHOP(50)`（`EconomySeeder:336, :2017 一带`）。
- 作坊产能 = `WORKSHOP`（或 `TOOL`）**件数**（`ProductionRecipe:34-35` 明示"手工业的规模单位是**座**"），与土地无关；
  约束来自劳动与投入（纤维/铁）。
  ⇒ D3/D4 的"城区加成 / 优先占城区"**今天不存在**（城区当量只活在 P6 纯模型与商人 upkeep 口径里）。

### 3.4 加成机制：**现成挂钩，不必新造**

- `EconomyDayStepper.updateProductionModifiers(List<ProductionEfficiencyModifier>)`（`EconomyDayStepper:457`）+
  `ProductionEfficiencyModifier(unit, modifierPerMille ∈ [0,2000], source, reason)`
  （设计书 `2026-10-23-production-efficiency-framework.md` §5.1/§5.2）。
- 语义：**逐 tick 替换、不持久化**；值必须是**已持久化状态的纯函数**；未注入 = 1000‰ 中性；先例 = `GovEfficiencyModifier`（口岸管制）。
- 消费点：周期末按 `scale × Σ修正 ÷ cycleDays` 乘在**产出**上（同书 §6.2；`EconomySettlement:1477` 读该状态）。

### 3.5 流民：一等 mode，已有"转入/吸收"路径，但**没有"随时间加速"**

- `DISPLACED` 是一等 mode、两个位置（`DefaultProductionModes:111, :147, :150`）；创世播 50‰ 流民（`EconomySeeder:456`）。
- 自动组织**显式跳过 DISPLACED**：流民没有工作、不得被主动招募（`EconomyEnterpriseSettlement:323 一带`；D-023 #6）。
- 转变路径 = A 规则：无可行目标 ⇒ 人口转入（新建/已有）流民户；**没有**"失业越久越容易变流民"的计时器。

### 3.6 城市化率：今天 = 创世比例 + 派生读数

- 创世参数：`RegionSeedPlan.DEFAULT_URBANIZATION_RATE = 0.12`（`RegionSeedPlan:79-80`）；
  `SettlementGenerator` 按比例切 urban/rural 两池；`NationSetup/SettlementRequest.urbanizationRate ∈ (0,1)`。
- 运行期口径 = **D-025**（`docs/superpowers/specs/2026-10-02-architecture-design-source.md:409-416`）：
  "城市化率是派生量 `urban/(rural+urban)`；不作为维持性判据；城市可清零"。

## 4. 自洽性检查

**结论先说**：D1–D8 的**机制方向与经济切片现状同构**（池子 = 份额总账、触顶 = SHORTAGE、加成 = 效率修正、流民 = A 规则），
**不需要新造大机制**；但有 **2 处与既有裁定直接冲突**、**3 处口径未定义就会做歪**、**5 处连锁影响未定**（汇总为 §6 的 Q1–Q11）。

### 4.1 同构（好消息，三条）

1. **城区池 ↔ `CityLand`**：`used = 人口/100 + 作坊×2 + 商人当量 + 贸易量/1000` 已经是"城区容量 + 占用方"的现成口径；
   `availableArableMu = arable − built` 已经是"城区从可耕地里独立扣出"。D4"优先占城区"要修的**是"谁先占、怎么长"**，
   不是"有没有这个池"。
2. **加成 ↔ 效率修正**：D3/D4 的"城区产能加成"可直接表达为 `source="urban-district"` 的
   `ProductionEfficiencyModifier`（注入口、值域、纯函数要求都已存在）。
3. **触顶 → 流民 ↔ A 规则**：D2"不允许继续组织" + D8"变成流民"与现行"A 规则在无可行目标时转入 DISPLACED"
   是同一条链的两个端点。

### 4.2 冲突（必须用户裁定）

- **C-1：D10 与 D-025 冲突。** D-025 明文"城市化率是**派生量**"；D10 要"**独立池子**"，D9 要"非城区池也能增长"，
  D5 要"投资可增加" ⇒ 城市化**不再是纯派生量**。两者不能同时成立。⇒ Q1。
- **C-2："率"字二义。** 今天 `urbanizationRate` 是**人口比例**（创世切池参数），而 D1–D4 讲的是**地/容量池**。
  若实现者照"率"字做，就会**做回用户刚否掉的比例口径**。⇒ Q2（两者都要留，但必须分开叫）。

### 4.3 口径未定义（不定就会做歪）

- **U-1：池子的空间粒度。** 原话同时说"**从 map 读 hex 属性**"（逐格）与"**同一种农业算同一个非城市化地区**"（合并）。
  两种读法后果不同：
  - **模型甲（类型维分池、空间仍逐格）**：每个 hex 一个池；"同一个非城市化地区"= 所有农业共用**同一个"非城市化"池类型**
    （池按"生产方式类型"分，不按组织/产业模板分）。与现有"逐格份额 + 运费按里程 + 地随格"一致。
  - **模型乙（地区级池）**：一个 `Region` 一个农业池，组织可在区内任意格用地 ⇒ **用地所在地与户所在地分离**，
    距离/运费/格级守恒都要重新定义。
  ⇒ 【建议】采**模型甲**（与现状同构、改动最小）；但这是**用户设计语义**，须由用户裁定（Q3）。
- **U-2：D2 的"要的地取决于多少人农业生产"与现有规模公式的关系。** 现状：地是**存量**，规模 = min(地 ÷ 每亩需求, 劳动 ÷ 每单位劳动)。
  用户说法可读作**分配口径**（"人多 ⇒ 要更多地 ⇒ 更早触顶"），也可读作**第二种约束**（劳动→地需求正比）。
  ⇒ 【建议】读作**分配口径**（不改规模公式），否则等于给同一件事加第二套地口径，两套会打架（Q4）。
- **U-3：加成落在"产出"还是"产能上限"。** 现有 `ProductionEfficiencyModifier` 乘在**产出**上（§3.4）；
  D4 说的是给"**产能**加成"。若本意是"城区能多容纳作坊/多开产能"，那是**池子容量**的事，不是产出修正。⇒ Q5。

### 4.4 连锁影响（未定会埋雷）

- **L-1：两池都能长 ⇒ 要不要总上限？** 若"投资可无限提高城市化"，与 D-025 的用户原话（"中世纪哪有这么多城市"）相冲。
  ⇒ Q7（增长是否受地形/粮食/行政的 fail-closed 上限；上限写在哪）。
- **L-2：工坊"用地限制很小"到底是不是 0？** 若"非城市化区对工坊也无约束"，D4 的"只能算在非城市化区"就**没有落点**（无池可占）。⇒ Q9。
- **L-3："先来后到"要有确定性全序。** 现有惯例 = canonical id 升序；若要真正的"先到先得"（认领时刻序），
  必须**落盘一个单调序号**（否则同 tick 多个家户争同一池子无法确定，违反 I7 确定性纪律）。⇒ Q6（并须裁定**创世预分份额算不算"已先到"**）。
- **L-4：D8 的"随时间扩大速度"要新增持久状态。** 最省事的落点 = `ProductionEnterprise` 的 `SHORTAGE` 行加"连续未组织天数/加速档"
  （该行已按 `(mode,position,household,hex)` 存在且已持久化）；但**加字段 = 改状态形状** ⇒ 必须走
  Codec/ChangeSet/往返不变式（铁律 5），并**单独出约束设计书**。⇒ Q10。
- **L-5：D5 投资的钱从哪来、到哪去。** 本仓有**货币守恒**不变量 ⇒ 投资必须有收款方（否则等于销毁/造币，另有口径）。
  且用户 2026-10-09 已裁定：**政府经济动作 = 行政式家户命令，不新增政策层** ⇒ 投资若由政府发起，必须表达为对具名家户/组织的命令。⇒ Q8。

## 5. 两处用户记忆的核实结论

### 5.1 "自然增长机制我记得应该是写过" —— **写过，但没接线**

依据（§3.2，全部实测 grep）：

- **写了**：`CityLand.advance()` 的**压力驱动慢速扩建**（`CityLand:302-330`）、`MigrationPolicy.urbanPull` 的**城市化迁移拉力**
  （`MigrationPolicy:145`）、`CityMigrationReading` 的拥挤/人均贸易/商人密度读数。
- **没接**：`CityLandBook` **零生产调用者**；`PopulationMigrationPlanner` **零生产调用者**。

⇒ 结论：**"机制在纯模型层写过、运行期从未发生"** —— 与本项目已踩过的"机制存在、世界从不触发"同型。
若用户确认自然增长按 `CityLand.advance()` 口径接线，则 Q3/Q7 的裁定同时决定它的上限来源。

### 5.2 "之前说错了" —— **未找到被更正的原句**

见 §2.1：本会话留痕里没有"非城市化地区不能增加"的原话；最接近的**既有裁定**是 D-025 的"城市化率是派生量"。
⇒ 已列入 Q1，**不代用户认定**。

## 7. 批次预案（**仅预案**，未派单）

### 7.1 依赖次序（若 Q1–Q11 通过）

U0（约束设计书定稿）→ U1（池子状态 + 读口 + map 属性来源）→ U2（组织期：先来后到 + 触顶拒绝 + SHORTAGE 具名）→

### 7.2 每批次门槛（沿用 §一.5 / §一.8 / §一.10）

- 写码代理**只写生产代码、只过编译**；测试留最后统一做；控制方审后提交。
- 真实行为验证走**真实 world + 读日志**（AGENTS §七 2026-10-23 裁定：长跑测试不进程序化门禁）。

### 7.3 与商户/口岸的先后（【观察】，需用户定）

- 商户阶梯**依赖跨区价差**（`2026-10-09-commodity-freight-and-merchant-ladder-design.md` §10.4 已写死"没价差别做"）；
- 产业用地池/城区加成会**改变产能与供给** ⇒ 影响价差的形成。
⇒ 先做池子，供给被地约束压住，价差**可能**更容易出现；先做商户，则可能仍空转。**这是观察，不是裁定。**

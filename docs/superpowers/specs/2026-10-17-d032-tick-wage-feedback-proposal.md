## 1. 三个机制分开，形成真实反馈

1. **是否愿意上工**：允许不从业的家户，可以选择闲置，不能强迫把全部劳动填进任一有岗位的方式。收入和其他条件相同时，闲置避免无回报劳动投入。
2. **是否有能力上工**：当 tick 实际可提供劳动取此前已实现的营养/体力状态，不取“本次承诺工资足够高就立刻满体力”。真实缺粮影响后续劳动能力。
3. **地主是否愿意涨价**：已经观察到招工不足/有效劳动不足，提高工资预期能够改善供给且仍比自己的其他选择有利时，调整下一 tick 的报价。没有收益空间时可以停产/退出，不能强制所有地主无限涨工资。

因此形成反馈：

```text
低报价 → 不愿从业/实际口粮不足 → 后续可用劳动不足
→ 地主生产收益受损 → 有收益空间的地主提高后续报价
→ 实际支付改善 → 口粮改善 → 后续劳动能力恢复
```

每个箭头都需要真实发生，不能把承诺工资、已付款、买到粮和恢复体力视为同一件事。

## 2. 不从业设定与家户选择

每户可配置是否允许不从业；开启时，闲置以一个明确选择进入候选比较。闲置：

- 不提供生产劳动、不取得该劳动的工资/生产经验；
- 仍消耗既有基本生活需求，库存减少、欠缺和既有后续人口影响继续发生；
- 不生成免费食物、工资、救济或生产权益；
- 不占用该户的生产劳动配额；可否兼做其他可行活动由既有时间预算与资格约束决定。

对工资为零、无其他补偿且结果相同的雇工，建议优先闲置，避免无收益却投入劳动；这条应明确写进选择规则，不依靠偶然的 mode id 排序。工作若有额外需求/消耗则照实际配置计入，不能在本提案擅自强加新的热量常数。

**仅增加闲置不自动产生整户维生工资下限**：如果工作收入虽低但能减少生活缺口，而且额外劳动成本没有抵消收益，工作仍可能比闲置好。若要求“预计次 tick 口粮不足则一律不接受该工作”，那是一条额外的家户决策阈值，不是物理规律自动推出的结果。本提案建议优先采用真实存粮/可兑现补偿和渐变劳动能力，不默认新增不可调的全额维生工资门槛。

“次日口粮”评估包括已有可用粮、按时可用的现金与可实际买到的粮、可交付实物工资；不只看本 tick 工资是否独自覆盖全户。存粮充足者可暂时接受低工资。只有工资债权而无实际食物/可购买资源时，债权不能当作已经吃到的粮。

工资为零仍可作为报价，但在允许闲置的上述条件下不能再假定能免费获得劳动。

## 3. 一个 tick 内锁价，实际结果驱动下一个 tick

建议每 tick 的逻辑顺序：

1. **开始时**读取真实家户库存、劳动能力、已有权益/投入条件及当前报价；本 tick 报价确定，不用本 tick 尚未发生的收获/付款刷新体力。
2. **候选估算/选业**：雇主把当前工资报价与可供劳动的预计量计入该候选成本，再比较是否采用/保持组织者角色；劳动户比较从业、其他方式与允许的闲置。
3. **统一分配/生产**：对岗位、真实劳动、权益和投入做统一预算；候选预期不构成对同一工人的重复承诺，生产按实际劳动发生。
4. **给付与生活结算**：工资按本 tick 锁定报价和实际劳动计提；对应货币、可支付活动库存、剩余欠薪债务依 U16 处理。食物购买/交付和当日消费时序要明确，不能支付后无法赶上消费却假装已保障口粮。
5. **更新实际状态和后续决策**：经济报真实生活缺口给 Social，更新后续劳动能力/人口；地主根据观察更新下一 tick 报价。各模块只产生自己的 ChangeSet，按既定 Revision 提交。

地主调价的新行为不可以在本 tick 追溯修改已完成劳动的单价。收获和工资周期较长时，用明确的支付周期承诺评估；未收获的田里有粮不等于工人今天有饭。

## 4. 地主的调价策略建议：不用每 tick 从零重算

可配置的简单默认策略：

- 初始报价可以沿用该户上一报价；新进入者有当地已观察到的实际同类劳动支付参考时采用参考值。无参考时，用当地口粮篮子价格折算的初始参考或显式配置值，不默认让所有新地主从零启动。**初值是策略起点，不是维生工资保障**；零报价仍允许。
- 只有“有可执行生产计划，需要更多劳动，实际未招到/劳动不足，提高报价仍有预期收益”时才上调。
- 因原料、资格、权益不足而不能开工，不误判成工资不足；不能给不存在的岗位加价。
- 满足用工时先保持报价；确认更低报价仍可能有利时慢速下调。不能将“刚招满”当成无限过剩并立刻砍薪。
- 改价幅度、观察窗口和降低报价的等待期可配置；本提案不冻结参数。

示意公式：

```text
若缺工且有提高报价的收益空间：
  nextWage = wage + max(正的最小货币步长, 调价速度 × 当地参考工资 × 缺工比例)
否则保持，或在满足明确降价条件时小幅下降
```

不能仅用 wage × (1+速度)，因为 wage=0 时永远出不了零。真正的货币最小步长与工资精度一致，不用浮点随意制造不可支付的小数。

“收益空间”必须按实际可扩大产量和归本户的收益估计；不是保证涨价后仍赚钱的全知预测，也不要求世界给地主兜底。某户可以退出，而另一个成本/条件更好的家户选择地主方式；不能先认定所有有资格者都该当地主。

当前需求量指可行生产希望吸收的劳动，不把无法兑现的无限招工愿望写成缺工率。

## 5. 条件示例与不能保证的结果

示意：t 时工资 0，允许闲置的工户选择不干，地主实际缺工；t+1 有利润空间的地主上调报价。报价仍低且家户开始缺粮时，后续劳动能力降低；若后续实际支付足以取得食物，生活缺口缩小，劳动能力逐渐恢复。这个过程跨 tick，不在一个 tick 内无限重报直至“均衡”。

同时必须允许：

- 如果低工资仍吸引足够劳动，地主没有必然加价动力，工资不自动达到整户维生水平。
- 如果全地确实无可交付食物，或生产收益不足以支持劳动与其他投入，提高名义工资也不能凭空解决，可能停产/饥荒。
- 已经饿到没有劳动能力的家户，不会因为听到高工资立即恢复。本提案不偷偷增加预付、借粮或救济机制；是否需提前实物供给属于后续可选择的业务规则。
- 多地主同步涨跌和营养恢复滞后可能产生工资/用工波动；限制变化幅度和降价频率可减轻，但不能仅凭文字证明收敛。
- 不同家户存粮、可达市场和生产条件不同，同一地区也可能同时有闲置、低薪与缺工。

自洽指决策、资源、支付和时间因果一致，不是保证全体存活、人人盈利或工资必然收敛到口粮线。

## 9. 用户新增裁定：加价快速累加、降价缓慢加速（2026-10-17，U20）

具体工程默认建议（可配置，不冒称用户已指定系数）：

- 以本户可行生产需要的目标劳动和实际吸收劳动比较缺口；“招到人”按目标得到满足解释，不是刚来一个工人就降价。

## 11. 用户终决：欠薪不影响择业、不准预付、现金后按库存数量抵付（2026-10-17，U21）

§10 的两项提问均已裁定关闭，控制方关于兑付记录影响预期、先供口粮复工的两条建议不采纳。

### 11.1 欠薪记录不影响下一 tick 选业

家户选业不因该雇主历史欠薪或兑付比例，对当前报价增加信用折扣、信用黑名单或额外拒绝条件。不得把此前被否定的信誉机制换个名称加回。

这不抹掉已经发生的事实：未付工资仍是债权/债务；没有收到钱粮，就不能当作已满足口粮。实际库存/需求缺口及其导致的既有饱食度、人口、劳动能力变化照常发生。雇主预估费用仍计全部应付工资，不因实付不足而虚增利润。本裁决针对工资择业预期，不把全项目所有债务状态及其既有经济后果一律禁用。

### 11.2 不允许先供口粮或预付工资促成复工

地主不能在本次雇工尚未提供实际劳动时，先供口粮或预付报酬，以新增预付机制帮助复工。不新增预支工资/冲抵后续工资及由其产生的借款流程。

既有其他普通交易/债务机制不因本次拒绝预付而擅自删除，也不能借那些入口自动绕出等价的雇工预付。真实缺粮导致停工、无法恢复的结果允许保留，不自动生成救济/劳动力。

### 11.3 地主付款：先钱，后数量最多的活动库存，最后欠债

承接 U15–U16 的当地对应货币计价，付款顺序为：

```text
按实际劳动和当期报价计全部应付
→ 先支付地主可用的对应货币
→ 不足时按可支付活动库存数量从多到少抵付
→ 仍不足的差额形成欠薪债务
```

“库存最多”按用户字面解释为**数量多**，不改成总价值高、家户保留价低、口粮优先或自行配置的另一个优先表。只比较真实可交付的活动库存；再生产权益/已投入资料不在候选中。

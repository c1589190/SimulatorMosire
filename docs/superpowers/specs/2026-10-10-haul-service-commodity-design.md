## 2. 目标与非目标

### 2.1 目标

**把"跑商"从市场轮私有的平行机器，并回标准生产管线**：运输服务 = **一种普通商品**，
由跑商家户在**生产阶段**产出（劳动 + 工具），在**市场上被需要运货的人买走**，收益走**标准企业利润**。

### 2.2 非目标

- 不做"服务量纲"的新**持久状态组件**（见 §4：本设计**不碰铁律 5**）；
- 不改动口岸/税/汇率三层的既有契约；
- 不改任何标定值（数值待实现方给具名常量 + 理由）。

## 3. 冻结契约

### 3.1 商品

| 项 | 口径 |
|---|---|
| 身份 | 商品词表新增一项（**开放 String id**，`CommodityId` 本就是 `record(String)`）；**建议 id** `haul`（中文"运输"）。★ 命名待用户一句话 |
| 可储存？ | **成交即消耗（v1.2 修正，照用户原话"不可储存转卖"）**：产出进既有货物账，交付时走既有一族损耗落点（`market-haul-service`），**未卖出者本轮不被"存下来卖两轮"** |
| 进价格表？ | **进**（有牌价 ⇒ 可被买卖；缺价 ⇒ 不交易，照既有 `Market.prices` 口径） |
| 词表联动 | `EconomyVocabulary.allCommodityIds()` 加一项 ⇒ 口岸政策校验、运费表校验、GUI 读口**自动覆盖**（这些面按词表校验，无需另改） |

### 3.2 产业配方（`trade@hex`）

现状（实测 `EconomySeeder` 约 `:4159-4200`）：`capacity={CATTLE:100}`、`capacityPerUnit={CATTLE:1}`、
**`outputPerUnit={}`（空）**、`cycleInputPerUnit={CATTLE:{tool:100}}`、`laborWeightPerMille=0`。

冻结为：

```
outputPerUnit    = { CATTLE: { haul: H } }   // 每 1 规模单位每周期产出 H 毫运输服务；H 具名常量 + 理由
cycleInputPerUnit= { CATTLE: { tool: Y } }   // ★ Y 的单套化属 A3（见下）；A1 阶段**维持现状**，避免双扣
laborWeightPerMille = L > 0           // 劳动成为真实约束（现状 0 ⇒ 不施加约束）
capacity         = { CATTLE: 份额 }    // 保留（畜力/运力载体）
```

★★ **批次边界（v1.1 更正）**：`MerchantHaul` 的"趟耗"（1,000 毫工具/趟）直到 **A3** 才退役
⇒ **A1 阶段不得**同时让"产业周期投入"与"趟耗"都扣工具（会双扣）。工具消耗**单套化**（只留一套）
与"预留特例撤回"**都归 A3**；A1 只做 §7 表里 A1 那一行的内容。

⇒ **运力 = 该产业本周期可产出的服务量**（不再有"每轮瞬态运力池"作为权威）；
⇒ **生产资料预留自动成立**（§16）：产业声明了 `tool` 投入 ⇒ `necessary` 按标准路径覆盖，
**不再需要**"给跑商家户手工下夹一趟"的特例。

### 3.3 需求（★ 用户明写：**由其他已有商品的购买派生**）

| 项 | 口径 |
|---|---|
| 派生点 | **跨格/跨区货单**（需要运输的那部分）⇒ 该笔货**派生**一份运输服务需求 |
| 数量 | 沿用既有运费口径（基础运费 × 路线费率一族）折算成"服务量"，**不新造量纲**；单位换算留给实现方并写进账本 |
| 谁买 | **需要运货的一方**（现状 = 买方付运费）；买不到 ⇒ **该笔不成交**（fail-closed，沿用既有具名归因一族） |
| 价格 | 走**市场自然议价**（价格优先、同价按既有 canonical 序）；"按最低价提供者买"= 在服务商品的市场上按价择优 |
| 与既有"运力池分配"的关系 | 议价权/占比那套**退役**（它存在的理由是"没有服务市场"；有了市场就不需要） |

### 3.4 退役清单（平行机器）

`MerchantCapacityPool`（运力池/门槛/烧工具）、`CapacityQuote`/`CapacityQuoteBook`、
`CapacityDemand`/`CapacityDemandBook`、`MerchantHaul`（趟耗与理由）、`MerchantProfitBook`（平行利润读数）、
`LaneUnservedBook`/`LaneUnservedObservationBook`（为私有门槛服务的读数）、市场轮里的"趟"结算与
`CARRIER_FEE` 私有腿 —— **逐项要么删、要么降级为读数**；由实现方在账本列"删/留/降级"三分类及理由。
★ **CARRIER_FEE 的去向**：运输服务变成商品后，运费应以**服务商品的成交**表达；若为兼容读数保留，
必须**只作读数**、不得与商品成交**双记**。

## 4. ★ 铁律 5 与本设计的关系（**不触碰**）

**铁律 5** = "变更集从完整状态类型派生，且有**往返不变式**测试守卫：`apply(changeSet, base)` 逐字段重建 target"。
它约束的是**持久状态形状**（`EconomyData`/`SocialData`/`ActorData` 等的组件与字段）：
形状一改，必须同步 **Codec（序列化）+ ChangeSet（差分/应用）+ 往返不变式测试**。

**本设计不新增/不删除任何持久状态组件**：`haul` 只是既有 `Map<CommodityId, …>` 里的**一个新键**
（`CommodityId` 是开放 `record(String)`，词表是列表常量）⇒ **不需要动 Codec/ChangeSet/往返测试**。
★ 若实现方中途认为需要新组件 ⇒ **停手上报**（那就变成铁律 5 的活，要另写设计书）。

## 5. 不变量

| # | 不变量 |
|---|---|
| I-H1 | **货币守恒**：买运输服务的支出 = 卖方的收入 + 既有税腿（三层税照旧，每层一次） |
| I-H2 | **货物守恒**：服务商品的生产/消耗走既有货物账与损耗落点；不凭空造、不静默销毁 |
| I-H3 | **缺省中性（v1.2 修正）**：**无跑商家户 / 跑商模式未被选中**的世界 ⇒ 与改前逐值不变。★ 跑商家户**按预期收益自主投劳、不由当期实际需求门控**（与农业/手工业同口径：生产不看单；当期需求只在市场轮之后才存在，用实际需求门控劳动需跨阶段需求信号＝触碰铁律 5）；未卖出的服务按"不可储存"口径本轮消耗 |
| I-H4 | **确定性 I7**：全部排序/遍历是内容的纯函数；保序用 `LinkedHashMap` + `Collections.unmodifiableMap`，**禁** `Map.copyOf`/`Set.copyOf` |
| I-H5 | **不双重记账**：运费不得既走商品成交又走 `CARRIER_FEE` 私有腿 |
| I-H6 | **预留走标准路径**：跑商所需工具由**产业声明的投入**覆盖，不靠特例硬编码 |
| I-H7 | 五条铁律、模块边界、唯一写口、权限单调性不变 |

## 6. 验收判据

| T-H5 | **真实 world**：`MERCHANT_HAUL_TOOL_SHORT_AT_COMMIT` 一类"缺工具照运"归零；跨格成交回升到**由需求与运力共同决定**的水平（给对照） |

| N-H2 | 全仓不得再出现"走私/平行运力池门槛/双记运费"三族残留（grep 证明） |
| N-H3 | 两跑确定性：同 store 同参数两跑，状态 dump 逐字节相同 |

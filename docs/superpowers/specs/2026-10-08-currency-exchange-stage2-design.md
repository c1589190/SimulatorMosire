## 3. A 阶段契约（单市场区：货币身份 + 汇率 + 政府窗口）

> A 阶段的**世界形态**：**1 个市场区**（现状，`small-world` 19 格）+ **2 种货币**
> （`silver` 既有 + 新增一种，例如 `copper`）+ 1 个 GOV；政府国库**同时持有两种货币**
> （第二币种由创世注入，属 `INITIAL_ENDOWMENT`，**不是铸币**——用户 §1.1「铸币暂缓」仍有效）。

### 3.1 货币身份（A1）

1. `CurrencyDef` **加显示名**：`(String id, int scale, String displayName)`。
   - `id` 仍是**不可变身份**（余额/流水/债务/市场/订单的键 ⇒ 改 id = 换身份 = 违铁律 1）；
   - **改名只改显示名**，不动任何账、不产生新身份。范式对齐 `Region.id` + `Region.name` + `map.RenameRegion`。
   - 显示名**非空**、**不做唯一性约束**（两名同显名合法；身份仍靠 id）。
2. **词表入世界状态**：`allCurrencyDefs()` / `allInstruments()` 从"硬编码常量"改为**从世界状态读**
   （现状 `MoneyVocabulary.java:88/97` 是常量列表）。★ 这条是 B 的前置（3 区 3 币必须能逐世界不同）。
3. **DM 工具（需 GM 审批）**：
   - `gov.defineCurrency`（命名/定义新币种：id + scale + displayName）、
   - `gov.renameCurrency`（只改显示名）、
   - `gov.issueMoney`（**DM 定发多少** ⇒ 走审批链；落账＝国库余额增加 + `MoneyIssuance` 审计）。
   - ★ 三者**不得**标 `GmOnlyCommand`（否则决策人用不了）：权限由**审批链 + 身份派生**兜（照 `GovPayTool.java:55-58`）；
     且只能作用于**自己所属 GOV**（权限不得放大）。

### 3.2 FxOrder（A2）

```
FxOrder(owner, hex, side: BUY|SELL, base: CurrencyId, quote: CurrencyId, limitPrice, quantity)
   BUY  = 买入 base、付出 quote
   SELL = 卖出 base、收进 quote
   成交价 = quote per base（定点整数，最小单位）
```

- **汇率 = 成交价**：世界上**不存**"1 金 = 12 银"这种全局标量（不落盘）。
- 撮合复用现有引擎的**价格-时间优先**；标的维从 `CommodityId` 扩到 `(base, quote)` 对。
- 每笔成交 = **两条转移腿**（`base` 腿 + `quote` 腿），逐币种守恒。
- **每户每轮至多一次**（与阶段 1 的套利口径一致），吃深度（§4.4）。

### 3.3 官方汇率与实际汇率并存（A3）

| | 官方汇率 | 实际汇率 |
|---|---|---|
| 谁定 | 政府（DM 工具 + GM 审批） | **市场算** |
| 存哪 | **持久状态**（A：挂在 GOV 上；B：迁到市场区） | **读数**（不落盘） |
| 形状 | `(base, quote) → buyPerMille / sellPerMille`（微刻度定点） | 本区最近 N 笔 FX 成交的**加权均价** |
| 语义 | **只是报价**：只在窗口有量时才拉动市场价 | 本区实际成交价 |

- ★ **A 阶段的硬约束**：若 FX 成交笔数为 0，`marketRate` **无定义** ⇒ 必须显式返回"无读数"，
  **不得**回落到官方汇率冒充市场价（那是把政策价伪装成市场价）。

### 3.4 政府外汇窗口（A4）

- **双向**：家户拿外币来换本币，政府**必须接**（在储备与吞吐约束内）；家户拿本币买外币，政府**有储备时**接。
- **报价**（A 阶段简化：直接用官方汇率双边价，不引入口岸效率）：

```
bidP = officialBuy   // 政府买入 base（外币）付 quote（本币）
askP = officialSell  // 政府卖出 base 收 quote
```

- **三项约束（缺一不可）**：
  1. **储备上限** `R_max`：政府该币种库存 ≥ `R_max` ⇒ **停止买入**（只卖不买）；
  2. **储备下限 = 0**：库存 = 0 ⇒ **只买不卖**（不许卖空 = 不许凭空造外币）；
  3. **政府不许凭空持币**：每一笔都有对手方（家户）；无对手方 ⇒ 拒绝。
- **★ A 阶段政府第二币种从哪来**：创世注入（`INITIAL_ENDOWMENT`，记 `MoneyIssuance` 审计）。
  **A 阶段不做**铸币生产方式、不做商品采购窗口（那是 B 之后）。
- 家户侧：**持有外币但没有本币**的家户可以拿外币向窗口换取本币 ⇒ 这解决"外币花不出去"。

### 3.5 币种校验：异币商品成交必须**具名拒绝**（A5）

- `SellSlot` 补币种维（卖方法定收款币种）；
- 成交时**必须**校验：买方支付币种 == 卖方收款币种，**否则具名拒绝**；
- ★ 现状是**静默 1:1**（`MarketSettlement.java:3562/3581`）⇒ 这条从"静默错账"变"具名拒绝"是 A 的**硬判据**；
- 家户要用异币买东西 ⇒ **先兑换**（走政府窗口或市场 FX），**不许**直接异币支付。

### 3.6 收口 5 处跨币种 1:1 求和（A6）

§2.2 列出的 5 处，全部改为**逐币种分别算**；不能分别算的（如预算帽 `grain+cloth+silver`）必须
**具名拒收**或**显式声明"只按本币计"`（并在注释与日志里写清），**不得**默认 1:1 相加。

## 4. B 阶段契约（3 市场区 / 3 政府 / 3 货币）

### 4.1 测试世界（新增创世生成器）

- `WorldRegistry` 新增常量与 `GenesisProvider`（暂名 `three-powers`）：
  **3 个市场区 / 3 个 GOV / 3 种货币 / 至少 3 座城市（每区一城）**；
- 必须**确定性、无随机、无时钟**（`WorldRegistry` 的生成器契约）；
- 注册后 `run-small-world.sh` 同款脚本可 `--world=three-powers` 起；
- **行政区互斥**（上位文档 §10-1）：3 个 GOV 的辖区两两不相交，落**组合根 `MutationGuard`**（照 `RegionDeleteGuard` 形制）。

### 4.2 市场区 = 持久状态 + 命令面

- 市场区从"纯派生件"变**持久状态组件**（`EconomyData` 新组件 ⇒ 必须带 **Codec + 往返不变式**，铁律 5）；
- 字段至少含：`zoneId`、`hexes`、**法定币（CurrencyId）**、**发行政府（GOV 单位 id）**、`officialRate`；
- 命令面：**划界 / 退让 / 覆盖 / 合并**（用户 §1.2「退让市场区、覆盖范围、合并」）+ 设官方汇率；
- ★ 与既有派生逻辑的关系：`MarketTopologyBook` 的"城市+半径"派生在该世界**退役或降级为默认值**，
  一致性由**单一权威**保证（区→hex 由持久状态给，不再每轮现算）。

### 4.3 发行政府 ↔ GOV 单位连线；GOV 总疆域 → hex

- 新增"某 GOV 发行哪些货币""某货币的发行 GOV"的**可查询连线**（A 阶段挂在 GOV 上的官方汇率在此迁到市场区）；
- 新增「GOV 总疆域 → 全部 hex」公开函数（中央 = 下属行政区 + 直辖区；省级 = 本区；
  现状无此函数，`GovTerritory` 只给 RegionId 且明令不得进授权）。

### 4.4 跨区汇率套利（B 的验收目标）

- 3 个区各有法定币与官方汇率 ⇒ **跨区汇差**成为**结构性、可持续**的套利来源（阶段 1 的套利在单区内会自我终止）；
- 家户的统一算法（阶段 1 已落）**直接**把 FX 当成一种"边"：`(劳动 + 本币) → (外币)`；
- 政府窗口是这张图里的一个摊位：吞吐上限 = 储备与政策约束。

## 5. 不变量（A 与 B 共同；编号续接上位文档 I1–I15）

| # | 不变量 | 判据 |
|---|---|---|
| **I16** | **改名不改身份** | `CurrencyId` 与其所有键不受改名影响；改显示名后所有账逐值不变 |
| **I17** | **汇率不进状态** | 实际汇率只是读数量；世界上不存在"全局汇率"状态字段 |
| **I18** | **官方汇率 ≠ 成交量** | 成交量由窗口吞吐与储备约束决定；无 FX 成交时 `marketRate` 必须"无读数"，不得回落官方价 |
| **I19** | **异币支付具名拒绝** | 买方币种 ≠ 卖方收款币种 ⇒ 拒绝（不得静默 1:1） |
| **I20** | **逐币种守恒** | 每笔 FX = 两条腿；`Σ(每币种余额)` 逐币种不变；不得跨币种求和断言 |
| **I21** | **政府不凭空持币** | 政府每笔买入都有对手方；储备下限 0 ⇒ 不许卖空 |
| **I22** | **市场区单一权威**（B） | 一个 hex 属于哪个区由**持久状态**给定；`regionByHex` 不再是现算结果 |

## 11. 阶段 2 实测结论与 G3 未成立的根因（2026-10-08，控制方验收）

**世界**：`three-powers`（3 区 / 3 GOV / 3 币 / 37 格），创世即落持久区表（`authority=persistent`、`zones=3`）；
用 GM 命令设两区区级汇率（铜区 900/950‰、金区 1100/1150‰，各 Committed）。

**真跑 0→360（rev 3→15，零失败）**：

| 项 | 读数 |
|---|---|
| 外汇窗口 / 轮 | `FX_WINDOWS_ASSEMBLED` 80（恒 2 张：铜区、金区） |
| 外汇成交 | `FX_ROUND` 80 轮，**成交 14 笔**、成交量 20,223 毫 |
| **成交随时间衰减** | 按 60 天分段：**6 → 4 → 2 → 1 → 0 → 1 → 0** ⇒ G3 的"不随时间归零"**不成立** |
| 未成交归因 | `reserve_cap` **160** / `no_counterparty` 35 / `insufficient_funds` 4 |
| 守恒 | 逐币种总量 12 段**恒为** `copper 136,600 / gold 129,400 / silver 424,600` |
| 自转移错误 | 0 |

**★ 根因（一条，可证）**：`GovFxWindow.DEFAULT_RESERVE_CAP_PER_MILLE = 500‰ × 该币累计发行量`，
而创世/发行给国库的 copper = 100,000 毫 ⇒ 上限 = 50,000 毫 **小于国库实际持有 136,600** ⇒
**窗口自第一轮起就处于"储备触顶"状态 ⇒ 只买不卖（只吸收外币）**。
外币因此**只进不出**：家户拿不到外币 ⇒ 家户侧的"持外币换本币"通道没有货源 ⇒
价差被吃一次就再没有新价差 ⇒ 衰减到 0。

**这不是 bug，是参数与创世配置的组合后果**：`R_max` 与"国库初始禀赋"没有对齐。

**修法三选一（待裁定，属阶段 2 收尾 / 阶段 3 前置）**：

1. **对齐 `R_max` 与禀赋**：上限改为 `max(累计发行量×500‰, 初始禀赋)`，或按"国库 quote 可服务额"折算
   —— 最小改动，让窗口双向都有本钱；
2. **给窗口设干预额度**（每日/每周期吞吐上限）而不是总量上限 —— 更贴"政府维护汇率"的语义；
3. **让本地币真正流通**：GOV 的俸禄/工资按**本区法定币**支付（现状 `GovernmentUpkeepOracle` / 工资规则
   走的是 **银**，即 `BOOK_CURRENCY`）⇒ 本币进入家户、家户才有外币可换。
   ★ 这是**釜底抽薪**的一条：没有它，家户侧外汇市场的深度永远接近 0。

**家户侧 FX 挂单其实已经实现**（`FxSettlement.planHouseholdOrders`：持外币且本地法定币花不出去 ⇒ 折价卖；
有盈余本地币 ⇒ 按官价买），**所以缺的不是机制，是流通量与窗口的双向性**。
（控制方 2026-10-08 第 5 轮曾误记"家户 FX 挂单未做"，此处更正。）

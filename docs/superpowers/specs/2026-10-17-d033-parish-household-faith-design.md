## §1 用户已明确的业务规则

1. 文化模块当前负责单家户的文化定义记录及其宗教归属；结合 D-032，文化定义绑定单个家户、独有且不随人口搬运，不直接给生产效率加成。
2. 每个 hex、每种宗教类型可以有一个地方教区。落实为“至多一个有效教区”的唯一性约束；不会因为登记了某宗教就自动给所有 hex 创建机构。
3. 教区拥有一个用于收取信徒奉献的家户；这个家户使用普通人口与账户机制，不另建第二套钱粮账。
4. 信仰归属以完整家户为单位。同一家户内部不登记多个宗教的人口比例；不同宗教由不同家户表达。
5. 信徒家户按教区要求每回合向教会家户上供，形成额外需求/负担。金额或物资要求由教会政策给定，不乘地方政府行政能力比例。
6. 政府税收同时存在，是强制性征收，受地方行政能力影响。宗教奉献不能替代政府税，也不能直接复用政府行政效率来折算教会应收。
7. 教会须能给家户带来好处；具体好处由本轮调查提出方案，尚未由用户指定。
8. 择优信奉要体现为家户间人口流动。结合“完整家户单一宗教”，本记录将“其他异教徒教会会选择加入”理解为其他宗教信徒家户的人口流入目标教区的信徒家户，**不解释为教区机构本身改宗或兼并**。
9. 当前不以复杂民族、教育或神学系统为前置，不重新引入“文化标签直接提升生产效率”的旧 P2 路线。

## §3 建议的最小数据模型（待具体约束设计）

| 概念 | 所有权与内容 |
|---|---|
| 宗教定义 | culture：稳定 ReligionId、名称、自然语言定义；不因 religion 相同就共享家户文化配置本体。 |
| 地方教区 | culture：稳定 ParishId、所在 hex、ReligionId、收款 HouseholdId、奉献政策、利益/救济政策。按 (hex,ReligionId) 建唯一索引，ID 不用地址代替。 |
| 家户文化记录 | culture：HouseholdId 对应自己的自然语言记录/Info 引用及宗教/教区归属；文本可编辑，“不可迁移”不等于不可编辑。具体 INFO 承载及地址语法待接口设计。 |
| 信徒关系 | culture：以 HouseholdId 为键，至多归属一个宗教/本地教区；成员人口从 Social 现读，不维护第二本信徒人数权威。 |
| 教会家户 | Social 拥有家户/成员，actor 拥有库存与钱粮，economy 拥有经济状态；culture 只引用稳定家户身份。教区不是 Government 的子类，不为了收款而强造 GOV 单位。 |
| 财务计划与回执 | 奉献/救济政策各归领域；通过既有中性付款契约表达 payer/payee/商品/货币/账期/来源，持账方执行，给出应付、实付、缺额、实际收到的利益。 |
| 流动意图 | 源家户 → 目标家户、人口、领域原因和预算约束；不强制宗教流动必须换经济 mode。公共契约落点在实施前做依赖核查。 |

关系尽量只存一处：如果家户记录指向 ParishId，则 ReligionId 可由教区派生，不再写一份可能漂移的重复归属。是否允许“先有信徒宗教、当地尚无教区”及其显式无教区状态，留具体模型设计；缺教区绝不凭空造收款方或向远处任意教区转款。

机构收款户与信徒家户是不同角色。改宗人口流向信徒家户，不能默认全部流入教会收款户、自动成为神职人员。教区收款户是否也参与某种信徒义务需显式规定，自转不应生成账目。

## §4 奉献与税：不同制度来源，共用付款基础

### 4.1 奉献规则与实际支付

教区政策可声明固定每户量、人均量，或以后明确的经济基数比例；**具体税率/什一比例不硬编码**。首期建议选已有周期接口最容易承接的人均/每户粮钱请求。策略是建议，不是用户已经选定计费公式。

```text
教区要求 + 当期信徒人口/明确基数 → 本户当期应付粮钱
本户现有可用余额 + 明确的支付预算 → 实付粮钱及缺额
实付：信徒户减少 = 教会收款户增加
```

- 应缴由教会要求决定，不乘行政效率。实缴仍受账户余额/冻结等真实约束；教会要多少不等于能够凭空收多少。
- 优先复用 HouseholdPeriodicAdjustment / 现有周期执行体与原子转移。可由当前 culture 政策及人口派生当期请求，不逐户复制一份长期费率权威，避免人口改变后规则金额过期。
- 奉献是“有指定收款方的周期额外负担”。若还需要买粮来履行实物奉献，应先形成购入缺口，再把实物交给教会；同一份粮不能既按自然消费销掉、又转给教会。
- 普通 HouseholdDemand 可用于需要购买的商品目标，不能独自承担指定收款、履约和回执。
- 用同一资源预算处理政府税、生活/再生产和奉献；优先级须显式配置/明确，不暗加宗教无限信用、自动债务、负库存或税收豁免。
- 交不足的处理建议复用 PARTIAL/shortfall，不自动生成债务。是否欠缴累计、欠缴是否影响权益/成员资格仍待业务讨论。
- 期内到期规则、幂等来源标识、成员快照一致；额外市场轮、拆段推进、迁移不能让同一期重复收费，也不能用另一条 app 扣款路径重复执行。

### 4.2 既有政府税

政府征收继续走现有辖区、税率、行政效率和政府家户账户路径；本设计不重做税基，不把粮/银余额税擅自改成收入税，不新增宗教系数，也不把现行无上限行政效率悄悄截断。

文化只需拿到该户资源和应承担负担的相应事实参与净收益判断，不能在文化模块重算一套政府税。

## §5 教会给什么好处：建议先做真实资源互助

以下全是**控制方建议，尚待用户选择**。

| 好处 | 在系统内如何落地 | 建议阶段 |
|---|---|---|
| 粮食/物资救济、互助储备 | 教会收款户用实有粮钱，按公开政策给缺口家户转移；可以比较实际覆盖率与预计可得份额。人口健康/生存仍通过真实口粮缺口影响 Social，不直接加效率或减死亡率。 | 推荐首期 |
| 宗教活动/仪式服务 | 神职家户实际投入劳动及必要物资，形成有限的当期服务，满足家户的文化需求；需要新增明确的服务需求、供给/消费回执与估值语义。 | 可选后续，不默认已有 |
| 教育服务 | 类似不可储存服务的教学容量；真实提供并消费后，才可能影响文化域识字等状态。需要教学/学习劳动、覆盖量、重复消费与跨期语义。 | 延后，非本轮前置 |

推荐实物互助是因为它能用当前钱粮账户形成可核对的闭环：奉献筹资 → 教会储备 → 指定受助家户实收 → 缺口改变；不靠宗教标签凭空改变生产效率。

这不等于假设所有教会都必须提供同样救济，或每个信徒每期收回多于奉献。供给政策、覆盖对象、支出额度和收费由教区配置；不同家户因需求不同，对同一教会的预计好处也不同。用户没有指定宗教真实历史的统一福利清单，本记录不把建议写成历史事实。

### 5.1 救济不等于凭空创造收益

单看教会与信徒之间的内部转账，资源总量不会增加。若每户只比较“当期收到多少钱减交了多少钱”，长期净付款的家户可能持续退出，教会筹资与救济随之萎缩；不能声称仅凭救济就一定得到稳定的宗教竞争。

可讨论的补充有两类：一是对未来短缺风险的保障价值，不能只看本期是否领钱；二是家户确有宗教活动需求时，对真实服务交付的满足价值。前者需要明确风险/预期与保障预算，后者需要需求和服务容量，二者都不是已有机制，也不靠给每个信徒发一个固定正收益常数解决。教会自身生产、外部捐助等若将来纳入，也必须有真实来源。

因此首期救济闭环适合检验资金、权益和人口流动是否真实联动；完整长期宗教生态仍需选定需求、保障和收费规则。缺粮户与富裕户可以对同一教区做出不同选择，不要求每个教会对每个家户都净有利。

## §6 择优信奉：比较可兑现净好处，写入同一流动表

### 6.1 比较什么

建议给每个“源家户 h → 目标信徒家户 d / 所属教区 p”计算可解释的权益前景：

```text
宗教净吸引力(h,p)
  = 该户对预计可兑现好处的估值
    − 该户加入后的预计奉献负担
    − 明确配置且真实存在的参与成本
```

这是待设计的分项口径，不是已批准的具体速度公式。涉及不同商品/货币/服务时，必须使用明确且一致的估值单位；不得把粮数量、银金额、满意度直接相加。

- 应按迁移人口/人均口径比较同一尺度；不能因教会信徒总人口多，就把整个教会财富当作某一个迁入户的好处。
- 用真实余额、预算、服务能力和既有信徒承诺约束预计可兑现量；不能只比较教会宣传的政策上限。
- 容量分配应考虑候选迁入人口。多户同时申请同一教会时，共用资源预算，不能每户都预期拿到同一份全部储备。
- 账上实付与实际获得的救济/服务须留可回放回执；已在经济净收益中计入的负担/好处，不在宗教权重中重复加减。
- 人口增长后人均好处可能摊薄、收费提高可能降低净吸引力，从而形成内生约束；这些结果来自规则与资源，不额外硬加“宗教生产 buff”。

### 6.2 去哪里、怎么变化

1. 候选以真实 HouseholdId 为身份，承接 D-031 的本 hex 与相邻六 hex 范围。允许相同 hex、相同经济方式/阶层、不同宗教的家户同时作为不同目标。
2. 首期建议优先能保持来源经济条件的宗教目标，便于验证改宗本身；将宗教改善与经济改善组合的最终规则须通过同一共享流动表，不能再造独立人口总量。
3. 成员在源家户期间遵循源户宗教；源户一部分人口流入目标信徒家户后，目标家户仍完整属于自己的宗教。源户文化/宗教定义不被原地改写，目标文化配置也不按来源平均。
4. 无合适目标户但允许新建时，须明确创建目标宗教的新家户及其自己的文化定义，然后受理人口转移；不能复制来源文化配置就说已经改宗。
5. 携带经验、财产、债务继续按 D-032 通用分片/合并规则；宗教归属依目标文化配置。人口归 Social，钱粮归 actor，领域状态分别生成 ChangeSet，同一 revision 原子提交。
6. 宗教和经济只能在同一张候选表贡献各自因素；最后统一约束迁出总人数。不可一份人口先被经济迁走、又被宗教迁一次。
7. 宗教择优的首期不包含教区机构整体改宗/教会合并，也不把文化自然语言配置搬到另一户。

### 6.3 调度建议

在显式世界日/账期下统一处理：取得当期成员与政策快照 → 评估和执行费用/好处 → 形成可兑现结果/前景 → 经济与文化贡献共享流动表 → 统一执行人口分片/合并。

“结算后迁移、成员新权益从下一账期开始”是防同一期重复领/交的建议，尚未由用户裁定；具体日序要与既有市场/税/周期执行点核对。不能为了规避时间问题新增另一条不受调度的文化循环。

## §7 模块边界与数据流建议

| 责任区 | 应拥有 | 不能接管 |
|---|---|---|
| culture | 家户文化记录、宗教/教区、信徒归属、奉献与权益政策、宗教因素的流动计算 | 人口增减、账户直接改写、政府行政效率公式、生产效率倍率 |
| economy / 公共经济契约 | 资源需求/预算、履约计算、通用收付款与可用量语义、经济因素流动、估值事实 | 另存宗教成员权威、把所有宗教选择绑在 mode 切换上 |
| actor | 教会和信徒的真实库存、货币账户及守恒落账 | 宗教政策/教区关系 |
| Social / social-api | 家户稳定身份、人口成员及通用人口工单 | 文化配置与宗教归属权威 |
| production | 若后续启用服务生产，则负责对应劳动/物资/产出的方案定义 | 根据宗教名直接给生产倍率 |
| app/Core | 装配公共只读口、组织同一调度/候选态/提交 | 奉献额度、救济算法、净信奉收益等领域公式 |

culture 现有允许依赖不包含 economy/actor 实现。新增通道优先使用既有 economy-api 与 social-api 等公共契约，不为了方便让 culture 直接 import EconomyData 或 AccountSession。公共财务请求也不反向依赖 Parish 实现类型；来源只用稳定命名/ID 引用。

既有 StockDeductionService/周期执行器在 app，是可复用基础设施现场，不构成“新增教会领域算法也放 app”的授权。是否将其通用部分下沉，待依赖与文件所有权设计；不能顺手扩大成全仓无关重构。

## §8 分阶段规划（草案，不是实施派单）

| 阶段 | 责任区与交付能力 | 前置/验收重点 |
|---|---|---|
| A：模型与可寻址记录 | culture 建宗教、教区、独有家户记录/归属及命令、完整状态、codec/changeset；app 仅注册。 | 用户原话、唯一性、稳定 ID、完整家户归属；可回放，不以日志代替持久记录。 |
| B：奉献与财务闭环 | culture 给出政策；经济公共契约承接当期额外负担；复用周期支付和原子转移，输出实付/缺额。 | 不复刻税，不乘行政效率；无重复计费、无 sink 假收款、无负库存。 |
| C：最小可兑现好处 | 按用户选择的首期好处实现；推荐教会实物救济与受助回执。 | 支出受真实储备限制，受助可核对；不做无资金 buff。 |
| D：共享流动表与改宗 | 补 D-031 共享表；culture 与 economy 各算因素，Social 工单及通用领域拆合统一执行。 | 同格同经济条件异教家户可流动；不得压成 hex×mode 一条，也不得双算人口/收益。 |

仍遵守工作树隔离与既定无头 dsh 派单规则；控制方只调查、设计、派单和验收，不写生产代码。**本轮没有启动上述阶段。** 正式实施前要补实际载荷/接口、参与者时序、文件 owner 与完整验收；不可凭本文直接恢复旧文化倍率 P2。

### 首要验收场景

- 同一 hex、同宗教第二有效教区被拒；不同宗教可各有教区；一户不能登记多宗教人口份额。
- 同样奉献要求下，改变政府行政效率只改变税，不改变教会应付；两条实付都进入各自正确账户。
- 贫困户不足支付时应付/实付/缺额对得上；不得铸钱、转成无来源债务或让整个推进因普通缺钱失败。
- 教会支出受真实储备约束；多户受助不重复领取同一份粮；救济满足口粮后只有真实 Social 缺口链发生变化。
- 同 hex、相同经济条件的异教家户存在净好处差异时，可通过共享表产生迁移；保持其他条件一致以隔离宗教因素。
- 目标归属固定为目标宗教、来源剩余户仍原宗教；经验逐项加权，财产债务守恒，文化自然语言配置不复制/不平均。
- 没有目标户时按明确政策创建，或具名不流动；不得暗自改源户宗教，亦不得把普通迁入人口全塞进教会收款户。
- 同期额外市场轮、分段推进、存档恢复/重放不会重复奉献、重复救济或重复迁出。
- 若后续做服务，交付/消费量不超过供给和劳动；未消费不产生识字/需求满足效果，服务不能库存转卖。
- 拒绝与跨域失败零部分提交；改坏护栏须实际红、恢复并核哈希，不能仅写“理论可测”。

## §9 边界、建议与未验证

- 首期“好处”建议为救济；仪式/教育服务是可选后续。用户尚未选择具体清单。
- 奉献用每户/人均/财富或收入比例、期长、支付优先级、欠缴后果、受助范围与预算分配、净吸引力到速度的映射，仍须形成具体领域规则；本草案不强加 10% 什一税、统一历史宗教模型或任意固定参数。
- “其他异教徒教会加入”按信徒人口转入解释；机构整体改宗不在本计划。
- 文化配置独有不妨碍不同家户归属同一宗教/教区；共享宗教定义不等于共享家户文化记录。
- 宗教服务不必全部可折价为收益；若采用需求满足/非货币估值，需要显式效用与单位语义，不能把财务净收益假装成完整宗教效用。
- 不默认对所有普通 HouseholdDemand 加上“给指定教会付钱”的隐式副作用，不把会费和服务消费/救济转移算成同一笔。
- 本轮仅调查并写设计/规划、用户原稿与索引；未修改生产/测试代码、未派 dsh、未跑构建/测试、未提交/推送。文化首期缩小不表示旧生产倍率功能应继续实现。

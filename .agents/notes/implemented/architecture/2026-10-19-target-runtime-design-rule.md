# 目标运行设计先行规则（2026-10-19）

> **状态：已实施。** 规则已进入根 `AGENTS.md` §五.12、`docs/agents/02-一-并发.md`、`docs/agents/15-十四-目标运行设计与子设计嵌入.md` 与 `.agents/skills/target-runtime-design/SKILL.md`。

## 用户原话（逐字）

```text
还可以加一个关键目标原则，例如在修改什么什么模块/什么什么类型代码的时候，必须遵循怎么样的规范，或者某些细化设计；其他没啥问题，把如此原则加进AGENTS.md和其引导的技能集，记得在其中提醒办事的责任区子agent写中期设定也要遵循
```

## 决定

所有派单文档、设计文档、中期确认文档必须：

1. **先写目标运行序列**：目标世界里模块代码实际按什么顺序运行（阶段、触发、读写、数据所有权、失败语义、日志/测试锚点）；
2. **再写裁定附录**：用户原话/工程裁定按阶段做影响映射，不先堆孤立裁定；
3. **再写子设计嵌入与影响**：父阶段锚点、嵌入位置、输入输出、状态所有权、对顺序/预算/身份/持久化/失败/日志/测试的影响；
4. **责任区子 Agent 的中期设定也遵循**：`impl-ledger.md`/中期报告必须写父阶段、实际实现、偏离原因、影响表、未验证项；
5. **缺目标运行序列或影响表 ⇒ 派单无效**，子 Agent 有权拒绝。

## 理由

本仓已多次出现“裁定都对、组合起来断路”：土地需求没有从生产位置产生、商品/土地同轮但不是同一撮合器、`PositionPlan.landQuantityMilliMu` 恒 0。根因是文档先写孤立裁定、没有先把实际运行顺序写成可检查的父设计。目标运行序列先行使“某裁定落在哪个阶段、改变了什么、没改变什么”成为派单前的硬检查。

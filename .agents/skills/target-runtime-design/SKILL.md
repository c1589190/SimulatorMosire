# 目标运行设计与子设计嵌入

## 何时使用

- 新增/修改运行阶段、结算器、时间参与者、市场/债务/工资/生产流程；
- 改 `EconomyData`/`ChangeSet`/Codec/持久组件、跨模块接口、数据所有权；
- 写派单书、约束设计书、架构设计、中期确认、状态/交接文档；
- 给责任区子 Agent 派实现任务，或子 Agent 自己写 `impl-ledger.md`/中期设定。

## 硬规则

1. **先目标运行序列，后裁定与子设计。**
   文档开头先写“目标世界里代码实际怎么跑”：阶段、触发、顺序、读写、数据所有权、失败语义、日志/测试锚点。
   不得先堆孤立裁定项。

2. **裁定只做影响映射。**
   用户原话/工程裁定要保留，但每条必须写：
   `影响阶段 / 运行后果 / 不涉及阶段 / 是否被取代`。
   裁定不能脱离阶段单独施工。

3. **子设计必须嵌入父序列。**
   子设计开头写：
   - 父序列锚点（文件 + 阶段号）；
   - 嵌入位置（阶段前/后/内部）；
   - 输入输出与状态所有权；
   - 对父序列的影响（顺序/预算/身份/持久化/失败/日志/测试）；
   - 明确的非目标。
   子设计不得重抄整条父序列，不得另造第二套权威。

4. **改什么模块/类型，就按对应细化规范。**
   至少遵守：
   - economy tick/结算：阶段顺序、唯一权威、同 revision、INFO/DEBUG/TRACE、文件 ≤1000；
   - 统一市场：商品/土地同一订单簿/同一撮合入口，土地整块、区级价、新土地本轮不用；
   - `EconomyData`/ChangeSet/Codec：一个事实一个写口，组件/字段同步，完整往返，不写旧档兼容；
   - 债务/工资：本金只货币、无 Pledge/抵押、债权财富序、工资只现金、未付普通 0‰ 货币债；
   - production.contract：生产物理状态归 production，economy 不复制公式，预计/实际同源；
   - LAND：不进普通库存，按 `(hex, quantityMilliMu)` 标量持有/任意数量转移，无 block id；区级 `OptionalLong` 地价；0 价市场成交合法但债务清算中不自动冲本金；新取得土地在下一生产 tick 可用；
   - app：只编排/桥接，不实现领域公式；
   - Seeder/worldgen：只面向新世界，初始土地/锚/需求/roster 显式，不留旧阶级 mode/tenancy/rent 默认；
   - 测试：测试 owner 按目标验收锚点写，写代码 Agent 不写/不跑测试。

5. **责任区子 Agent 的中期设定也遵守。**
   子 Agent 写 `impl-ledger.md`/中期报告时必须包含：
   - 本责任区在父序列的哪个阶段；
   - 实际实现与偏离原因；
   - 对父序列的影响表；
   - 未做/未验证/blocker。
   只写“改了哪些文件、编译过了”视为交账不完整。

6. **派单门槛。**
   派实现任务必须给目标运行序列路径 + 阶段号 + 关键形状复述 + 子设计影响表 + 文件范围 + 编译/不跑测试纪律。
   缺目标运行序列或影响表 ⇒ 派单无效，子 Agent 有权拒绝。

## 文档修改方式（2026-10-19 用户裁定）

用户原话：

> 架构设计/修改文档不支持原地追加、改来改去，如果有新设计，较小规模就在原地改原文、后文记录原文是什么、为何改，而不是不改前文统一在后文追加，如果是大架构重设计和大裁定，应当直接开新文档，防止语义逻辑污染

硬规则：

1. **禁止 append-only 补丁式文档。**
   不允许“旧段落原文一字不改，文末再追加新流程/新模型/重新规划”，导致读者必须自己判断前后哪段有效。

2. **小规模修改：原地改原文 + 后文留修订记录。**
   直接修改目标运行序列/数据形状/公式中的原文；在同一文档后部的“修订记录”写清：
   - 原文是什么；
   - 为什么改；
   - 新决定是什么；
   - 用户原话/日期/来源。

3. **大架构重设计/大裁定：直接开新文档。**
   影响运行阶段顺序、数据所有权、跨模块契约、多个责任区，或会改变目标世界语义的，必须新建文档：
   - 新文档头部写 `本文取代：<旧路径>`；
   - 旧文档头部写 `取代者：<新路径> —— 本文仅作历史留痕，勿据此开工`；
   - 不得把新架构继续追加在旧文档末尾。

4. **判断标准**
   - 小：局部字段、局部公式、单个阶段内的实现默认、单个责任区的小修正；
   - 大：阶段顺序、状态所有权、跨模块契约、多个责任区、目标世界语义变化；
   - 拿不准时按“大”处理，优先新文档，避免语义污染。

5. **目标运行序列仍然先行。**
   小改也要保持“目标运行序列 → 裁定/影响映射 → 子设计”的结构；不得先写裁定再补运行链。

## 提醒

- 用户原话仍最高权威；目标运行序列不能覆盖用户原话。
- 发现设计/原话冲突：立即上报，不得自裁。
- 编译过 ≠ 验收通过；测试与变异自证按项目测试阶段规则执行。
